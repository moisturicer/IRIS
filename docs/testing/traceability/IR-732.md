## IR-732 — Fit the complete outgoing request within verified model capacity

**Basis and scope.** IR-732 under IR-715; authority ADR-049 §17, §20. Every AGENT request is measured as the serialized payload the dialect will send — instructions, tool schemas, complete history, tool results, opaque continuation and framing — against the capacity its adapter has verified for the pinned model, with output, reasoning, next-result headroom and one repair reserved first. Context occupancy, the AskRun allowance (IR-725's ledger) and stored Conversation size stay three separate quantities: occupancy is a token estimate from bytes, and the paid reservation stays byte-based. No schema change, no setting.

**Code.** `ai/agent/context.py`: `Capacity` (no field defaults; an adapter that declares none has unknown capacity, never a million), `Reserves`, `fit`, `pack` and `FittedAgentProvider`, which records a numbers-only `Status` per request (marked `estimated`). `LLMProvider.capacity(pin)` returns `None` by default; the recording provider takes declared capacities; `AdmittedAgentProvider` passes capacity through and refuses (`output_cap_exceeded`) a fitted completion cap above `AI_ADMISSION_MAX_OUTPUT_TOKENS` instead of lowering it, which would break the reserve it was fitted with; fitting and admission measure the same `dialect.serialize` text. `AgentExecutor` requires `Reserves`, fits every request before admission and maps a refusal (`capacity_unknown`, `reserve_exceeds_output`, `reserve_exceeds_context`, `request_bytes_exceeded`, `context_exhausted`, `compaction_required`) to `unavailable`; each status is logged with its run id and kept in a bounded list (`AgentExecutor.capacity_status` is the latest). `pack` answers a tool group whole and in order, keeping room for the markers of the results still to come and replacing any result that does not fit with an explicit `{"withheld": "exceeds_context", "bytes": N, "coverage": "none"}` marker, and refuses the group when not even the markers fit.

**Tests.** `apps/ai/tests/test_ai_runtime_context_contract.py` (25, no database, recording provider): the status measures the recorded payload byte for byte and splits it by part; ~90 KB of schema, history and opaque fixtures refuse a 2,000-token fixture and go out unclipped under a declared million-token fixture; unknown capacity, the byte limit, reserves held back before history and reserves the model cannot honour each refuse with nothing sent; a pin over capacity never moves to another model; opaque size is counted and its content never reaches the status; an oversized tool result is withheld by marker and absent from the next payload while the group stays complete; a large early result is withheld when keeping it would leave no room for the later markers; a crowded group is refused or asks for compaction; an incomplete or reordered group is never packed; the executor refuses over capacity as `unavailable` before transport. `apps/ai/tests/test_ai_runtime_admission_db.py` adds four on real PostgreSQL: the paid reservation covers the sent bytes while occupancy is the smaller estimate; a request that fits a million-token window is still refused by the run's AskRun allowance, unsent; a request over capacity reserves nothing; and admission refuses a fitted cap above its limit, unsent. The DB suites (`test_ai_runtime_admission_db.py`, `test_ai_runtime_agent_db.py`) ran green against the dev Postgres container, 26 tests. IR-727's and IR-725's tests now declare a fixture capacity and pass `Reserves`, because the executor requires both.

**Not done here.** No real adapter declares a capacity yet, so no vendor's window is verified; compaction (IR-734) does not exist, so `compaction_required` is only reachable when a caller opts in. The status is logged, not persisted or shown to readers (IR-735). `Capacity` is what an adapter declares; nothing yet checks a declaration against the vendor. Repacking withholds greedily in call order, not the best subset. With compaction available, a single result that does not fit is still withheld by marker; compaction is requested only when the group cannot be answered. Repacking means withholding whole results by marker; ranged continuations of a long result are IR-733. The executor still sends one turn with no tools; the tool loop that will call `pack` is IR-728.

**Status.** Implemented; awaiting review.
