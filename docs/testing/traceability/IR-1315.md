## IR-1315

No FR- id. Changes where [IR-971](IR-971.md)'s Add a requirement sits and how its form opens. What a requirement is and how it is saved are unchanged.

**Requirement:** On RDCO's Setup › Requirements & Templates, **Add a requirement** is on the section heading's row, for every record type. It opens the form as a popup titled "Add a requirement to <type>". Closing it by X, Escape, the backdrop or Cancel throws away what was typed with no question, so the next open starts empty. A new requirement is still added last. Edit on a row stays inline. (Ashlee, 2026-11-24.)

**Design:**

- The popup is the shared `Modal` (size `md`), with Cancel and Add requirement in its footer. Add requirement submits the form through `form=`, as in `OpportunityFormDialog`.
- The form is mounted only while the popup is open, so closing it is the discard.
- While a save is in flight the popup stays open and Cancel is disabled, as in `OpportunityFormDialog`, because a save already sent can't be taken back.
- `Modal` focuses its Close button first. This popup has one job, so the form then moves focus to Name. On close, `useDialogFocus` returns focus to the button.
- The page's warning line sits behind the backdrop, so a refused add shows its reason inside the popup instead (`Act`'s optional `onFailed`). That also keeps a stale warning off the page after the popup is closed.

**Implementation:**

- `frontend/src/features/setup/SetupPage.tsx`:
  - The heading row holds `AddRequirement`, and the block below the list is removed.
  - `AddRequirement` is the button plus the popup.
  - `RequirementForm` takes `dialog` for the popup layout. Its inline layout, used by Edit, is unchanged.
  - `Act` takes an optional `onFailed`.

**Test:** `SetupPage.test.tsx`, "adding a requirement (IR-1315)":

- The button is on the heading's row, before the list, and is the only one.
- The popup is named for the record type, with Name focused, and axe passes with it open.
- Cancel, Escape and X each close it with nothing sent. Reopening shows empty fields, and focus goes back to the button.
- A successful add closes the popup, shows the outcome and lists the new requirement last.
- A refused add keeps the popup open with the fields kept and the reason inside it, and passes axe. After Cancel no warning remains on the page.
- The three validation messages are unchanged.
- The Edit test now also asserts that no dialog opens.
- The add and validation tests moved from "the list RDCO keeps" into this block and now look inside the dialog, deliberately: where the form opens is what this ticket changes.
