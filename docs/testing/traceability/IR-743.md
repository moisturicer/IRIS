## IR-743

**Requirement:** The reader may cancel a pending download request on the paper page, sees RDCO's note beside Request again, and has a My Library view of their own requests

**Design:** Jira IR-743 (spec IR-672); ADR-048

**Implementation:** `GET /records/download-requests/mine/` (`DownloadRequestViewSet.mine`, signed in, any role) returns only the caller's own requests, newest first, from `reader_request_rows` in `apps/records/download_service.py`: cancelled requests and records outside `visible_to(user)` are left out, and the server works out each row's `state` (`pending`, `granted`, `declined`, `revoked`, `expired`) and `actions` (`cancel`, `download`, `request_again`; only a record's newest request offers any). No requester or reviewer is named. `PaperDownloadControl` adds Cancel request when pending and "RDCO's note: ..." ("No note recorded" when blank) when declined or revoked. My Library gains a Download requests tab for every reader (`DownloadRequestsView`, `?section=downloads`), so a non-author now sees Saved papers and Download requests as tabs. Download and cancel are shared hooks (`useDownloadCopy`, `useCancelDownloadRequest`)

**Test:** `apps/records/test_my_download_requests.py`; `download-requests-mine` in `apps/tests/access/table.py`; `PaperDownloadControl.test.tsx`; `MyLibraryPage.test.tsx`. Two IR-677/IR-410 assertions changed on purpose: a pending request now offers Cancel, and a non-author now has tabs
