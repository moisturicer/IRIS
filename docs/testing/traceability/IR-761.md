# IR-761

[Back to the matrix](../TRACEABILITY.md)

**Every Call reports its papers and event states, and leaves the board when it is Over.** Built to [ADR-050](../../adr/050-calls-for-papers-and-rdco-confirmation.md) decisions 6 and 7, with the owner's decisions of 2026-11-15 recorded on the Jira card. Written 2026-11-15.

## What changed

- **Two states, decided on the server** (`Opportunity.papers_state`, `event_state`), with their wording in `core.enums` (`CallPapersState`, `CallEventState`):
  - **Papers:** `accepting` ("Accepting papers") through the paper deadline, then `closed` ("Submissions closed").
  - **Event:** `upcoming` ("Upcoming") before the start date, `happening` ("Happening now") from the start date through the later of start and end, then `over` ("Event over"). A start date alone is a one-day event.
  - **End date with no start date:** never Happening now. Upcoming through that date, then Over (owner).
  - **No event dates:** no event state (`null`) until the Call is Over, the day after its paper deadline. It then reads plain "Over".
  - **A Call is Over the day after the latest date entered** (deadline, start or end), so a mistyped date can't end a Call early.
  - **An event can be over while papers are still accepted** (owner, decided during review): a deadline after the event reads "Accepting papers" and "Event over", and the Call stays listed until the deadline.
  - The states overlap: a Call can be Accepting papers and Happening now at once.
- **"Today" is Manila's date** (`timezone.localdate()`, `TIME_ZONE = Asia/Manila`), for the new states and for `days_left` and `is_closed`, which used the machine's date. The containers and CI run in UTC, so from 00:00 to 08:00 Manila time they read yesterday.
- **The board list leaves out Over Calls** (`OpportunityQuerySet.not_over`). This replaces the 30-day rule (`visible`, `HIDE_AFTER_CLOSE`, both removed). An Over Call stays in the database, and detail, edit, delete and the calendar download still reach it, so a poster can fix a mistyped date (owner).
- **The API read shape** gains `papers_state`, `papers_label`, `event_state` and `event_label`. `days_left` and `is_closed` are unchanged, because the current board reads them.
- **Calendar:** unchanged. It downloads the paper deadline; there are no in-app reminders.
- **Frontend:** the types only (`frontend/src/types/opportunities.ts`). IR-764 draws the two tags.

## Tests

- **`backend/apps/opportunities/test_call_states.py`:**
  - `CallStateTests` checks the papers state, the event state and Over on 25 boundary days, each as a literal. The Calls cover both event dates, start only, end only (with the deadline before and after the end), no event dates, an end before the start, a deadline after the event, and a deadline during the event (both states at once). It also checks every label, "Event over" beside "Accepting papers", and plain "Over" for a Call with no event.
  - `CallStatesApiTests`, with the clock frozen at noon on 2026-11-15 in Manila:
    - The list carries both states and labels.
    - The list leaves out a Call Over since yesterday by its deadline and one Over by its event. It keeps a Call on its last day by either date, one closed 45 days ago with its event ahead, and one with an end mistyped before its start, and one whose event is over while it still takes papers.
    - An Over Call's detail, calendar, edit and delete all still work, and moving its deadline puts it back on the list.
  - `ManilaDateTests`: at 17:00 UTC on the 15th (01:00 on the 16th in Manila), a deadline of the 15th reads `closed` with `days_left` −1, and a Call with no event dates due that day is off the list.
- **`backend/apps/opportunities/tests.py`, changed deliberately:** `OpportunityVisibilityTests` pinned the 30-day rule and read the machine's date. It now pins the Over rule in Manila's date.
- **Frontend:** `tsc` passes for `frontend/` and `e2e/`. Fixtures that build a Call gained the new fields (`CallsAndConferencesPage.test.tsx`, `e2e/smoke/support/screens.ts`).
- **Red first:** the state tests failed before the model methods existed, and the API tests failed before the serializer and the list filter.
- **Not done:** nobody has used the board by hand, and no screen shows the states yet (IR-764).
