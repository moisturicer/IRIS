# IR-931: review-dialog drafts are keyed by the signed-in user

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes. This closes a gap found by IR-916's sign-out tests, under IR-900 (frontend security and privacy hygiene).

**The gap.** The three review dialogs keep an unsent comment or reason in `sessionStorage` so opening the paper to read it loses nothing. The keys named the record but not the person, so after A signed out and B signed in on the same tab, B's dialog for the same record was pre-filled with A's text. Per-tab only; no credential involved.

**The change.** Each key now carries the signed-in user's id, as Paper Chat's does. Nothing is cleared on sign-out: every sign-out path, an idle timeout and a failed refresh included, calls `logout()`, and clearing there would destroy a half-written finding when a session expires, which is the case the draft exists for.

| Draft | Old key | New key |
|---|---|---|
| `decisionDraft.ts` | `iris_decision_draft:<record>:<outcome>` | `iris_decision_draft:<user>:<record>:<outcome>` |
| `officeReviewDraft.ts` | `iris_office_review_draft:<record>:<outcome>` | `iris_office_review_draft:<user>:<record>:<outcome>` |
| `revisionDraft.ts` | `iris_revision_draft:<record>` | `iris_revision_draft:<user>:<record>` |

With no signed-in user, read returns empty and write and clear do nothing. The old unkeyed keys are never read or removed: no migration, because `sessionStorage` is per tab and ends with it.

**What proves it** (each in the dialog's own test file, queried by role and accessible name)

| Acceptance criterion | Test |
|---|---|
| A's draft is not shown to B on the same tab; A gets it back on signing in again | "does not show A's unsent … to B on the same tab, and gives it back to A" |
| A draft is cleared on a successful submit, and B's submit leaves A's draft alone | "keeps B's … from touching A's draft", and the existing "forgets it once …" tests |
| No signed-in user: nothing read or written; the old unkeyed key is ignored, also after signing in | "reads and writes nothing with nobody signed in, and ignores the old unkeyed key" |

Files: `DecisionDialog.test.tsx`, `OfficeReviewDialog.test.tsx`, `RequestRevisionDialog.test.tsx`.

**Run (2026-11-06).** The three dialog files: 35 tests passed. `npm run test:changed`: 16 files, 331 tests passed. `tsc --noEmit` clean. ESLint on `paper-view`: no errors; one existing warning in `PaperViewPage.tsx`, a file this change does not touch. CI result is on the PR.

**Not covered.** "Idle expiry" is shown as sign-out then sign-in again with the store changed directly, not through the real idle timer. The sign-out path itself is IR-916's.
