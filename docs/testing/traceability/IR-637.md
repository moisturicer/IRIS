## IR-637

**Requirement:** An Excel import row is all-or-nothing: its Record, primary owner and authors are saved together or not at all

**Design:** Jira IR-637 (no ADR; decided 2026-10-29: rows stay independent, no whole-file validation)

**Implementation:** `RecordViewSet.import_excel` saves each row inside its own `transaction.atomic()` savepoint. Before, the three writes ran one after another, so a failed owner or author write left a **published** Record the log called skipped. A failed row now leaves nothing, the log names it (`Row N: skipped — <title> — <reason>`), `skipped` counts it, and the rows around it are still created

**Test:** `apps/records/test_excel_import.py::ImportRowIsAllOrNothingTests` (3 tests through `POST /records/import_excel/` with a real `.xlsx`): an author write forced to fail on the middle row leaves no Record, owner or Author from it while the rows before and after are created; a real Postgres error (an author name longer than its column, no mock) is rolled back with its row and the next row is still written; a forced owner failure leaves no published Record. All three fail with the savepoint removed. A write failure is logged on one line (`✗  Row N: not saved — <title> — <first line of the error>`), and a created row now names its sheet row too

**Evidence:** 2026-10-30, local Docker (rebuilt backend image): `apps/records` 258 passed

**Status:** **IMPLEMENTED**
