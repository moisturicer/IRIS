## IR-923 — Malformed input to the public sign-up and sign-in routes answers 400, not 500

**Basis and scope.** A defect found by IR-829's manual ASVS run (5.1.3 and 5.1.4, one defect) on 2026-11-05. It covers the three public routes that run answered 500 on. What each route returns for valid input is unchanged. No FR- id.

**What was wrong.**
- `GET /departments/?college=…` and `GET /courses/?department=…` passed the raw query value to an integer lookup. A value like `abc` or `1'` raised `ValueError`, so the response was 500.
- `POST /auth/login/` read `email` and `password` with no type check. A list or object reached the password hasher (`TypeError: Password must be a string or bytes`), and a body that wasn't a JSON object failed on `.get`. Both answered 500.
- All three are reachable signed out, so anyone could produce server errors and log noise.

**What exists now** (`apps/accounts/views.py`).
- `_id_filter` accepts only plain ASCII digits. Anything else (`abc`, `1'`, `1 `, `+1`, `-1`, `1_0`, `1.0`, a non-ASCII digit) answers 400, naming the parameter. An empty or absent filter still lists everything. An id too large for the column finds nothing (Django's own handling), so it answers 200 with no results.
- `LoginView` answers 400 "Email and password must be text." when the body isn't an object, or when `email` or `password` is present and isn't text. That happens before `authenticate`, so it writes no `FAILED_LOGIN` audit event and doesn't count towards the lockout. A list or object can never be a correct password, so nothing is lost by not counting it. The login throttles run before the view, so they still apply.
- A missing field is still an ordinary failed sign-in: 401 "Invalid credentials.", audited.

**Tests** (`apps/accounts/test_malformed_input.py`, at the HTTP API).
- `DepartmentFilterTests`: `abc` is refused; seven near-integers are refused; a 30-digit id finds nothing; a valid id still narrows the list.
- `CourseFilterTests`: `abc` is refused; a valid id still narrows the list.
- `LoginShapeTests`: the ticket's body (`{"email": ["a"], "password": {"x": 1}}`) is refused and not audited; a list body, a string body and number or boolean fields are refused; a missing password is still a 401 that is audited.
- Run against the original `views.py`, 15 of these fail and the 6 that guard unchanged behaviour pass.

**Verification.**
- Run locally on 2026-11-11 against PostgreSQL in Docker: `apps/accounts`, `apps/tests/test_access_matrix.py`, `apps/tests/test_enum_vocabulary.py` and `apps/tests/test_traceability_shape.py`.
- Not re-checked through nginx on the Core journeys stack, where IR-829 found it. The tests call Django directly, and nginx doesn't touch these bodies or parameters.
