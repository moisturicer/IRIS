## IR-568 Related works says why it is empty, without revealing hidden Records

**Design:** the IR-557 spec (user story 14, "Semantic extension") and [ADR-029](../../adr/029-proposal-similarity-and-collaboration.md) §5, which keeps record-vector similarity as the one mechanism. No ADR decides these states, so this file records them. IR-460's rule (a reader cannot tell "nothing exists" from "it exists and you may not read it") is applied here as it is to Ask IRIS.

- **Endpoint:** `GET /records/<id>/similar/` still returns `results` and now a `state` beside it, from `related_works()` in `apps/ai/similarity.py`. The ranking is the existing one: one seed vector, `_nearest` over `research_records(user)`, so the visibility predicate is unchanged and no second retrieval stack exists. `similar_records()` itself is untouched.
  - `ready`: at least one match.
  - `no_matches`: the seed is indexed under the active Embedding Space and nothing came back. The response is the same whether close candidates are absent or unreadable.
  - `not_indexed`: the seed has no summary vector anywhere.
  - `incompatible`: the seed has a vector, but none under the active space (another model's, or no active space).
  - `unavailable`: the comparison raised. This is a 503 with body `{"state": "unavailable", "results": []}`, logged server-side; no detail reaches the reader.
- **What is stated:** only the seed Record's own coverage. The seed is a Record the reader already opened, and an unreadable one is still a 404 before any state is computed.
- **Interface:** `SimilarPapers` moved out of `PaperViewPage.tsx` into `RelatedWorks.tsx` so it has its own tests. It says "No related works found for this paper." for `no_matches`, that the paper "has not been indexed yet" for `not_indexed`, that its "index is out of date" for `incompatible`, and shows an alert with "Try again" for a failure (any rejected request, including a lost connection). The old message claimed "indexing has not run for this repository yet" for every empty list; per the spec it no longer does. An answer without a `state` degrades to a list or to "no matches".
- **Not changed:** the Novelty check (`related-research/`, IR-312), which has its own `checked` flag.

**Tests:** `apps/ai/tests/test_similarity.py` (`SimilarEndpointTests`) covers each state at the HTTP boundary, the identical `no_matches` body before and after hidden draft candidates are added for the same reader (whole bodies compared, so a later extra field fails it) with the author seeing the drafts as `ready`, a 503 on a comparison failure, and the 404 for an unreadable seed. `RelatedWorks.test.tsx` covers each state's copy and its absence of any withheld-paper wording, retry, a lost connection, a missing `state`, a changed paper and axe on the ready, no-matches and not-indexed states.

**Status:** IMPLEMENTED. Not reviewed by a person yet. The backend tests were written and have not been run locally (no Django or Postgres environment here); they first run in CI. Frontend: `tsc` clean, the two affected test files and `npm run test:changed` pass. IR-441 (similar-records search depth) is untouched and waits on a real corpus.
