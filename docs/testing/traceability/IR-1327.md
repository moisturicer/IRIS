## IR-1327

**Requirement:** **The sign-in error pop-up and the Account locked pop-up close with an X in their corner, not a Close button.** No FR- id; requested by Hermoine Zozobrado, 2026-11-24.

**Before:** both pop-ups ended with a full-width **Close** button:
- `EntryErrorDialog`, shown for a wrong email or password, and also for a failed registration;
- `AccountLockedModal`, shown after too many wrong tries, or when an administrator locks the account.

**Implementation:**
- **New `components/ui/DialogCloseX.tsx`:** an X button in the dialog's top-right corner. It has the same 44px target and colours as `Modal`'s X, and its accessible name is "Close". Both pop-ups use it, and their Close buttons are removed.
- **The X is drawn as an inline SVG, not Font Awesome's `fa-times`.** That font loads from a CDN. In the smoke browser, which has no network, the icon did not draw, which left the pop-up with no visible way to close it. The inline X does not depend on the network.
- Escape, a click outside, and where focus returns are all unchanged.
- The Session expired pop-up keeps its "Sign in again" button, because that is an action, not a close.

**Test:** `EntryErrorDialog.test.tsx` and `AccountLockedModal.test.tsx` each gained "closes with an X rather than a Close button". It checks that the dialog's button named "Close" shows no text, and that the word "Close" appears nowhere in the dialog. The locked dialog's test also clicks the X and checks the dialog closes. The existing tests that close by the button named "Close" still pass unchanged, because the X keeps that name.

**Evidence:** 2026-11-24, local.
- Before the change, both new tests failed.
- After it, `npm test` passed: 255 files, 3804 tests. `tsc` and `eslint` are clean.
- The sign-in smoke tests (`e2e/smoke/auth.spec.ts`) pass.
- Screenshots of both pop-ups from the production build show the X in the top-right corner and no Close button.

**Status:** **IMPLEMENTED**; awaiting CI and review.
