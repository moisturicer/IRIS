## IR-788 — The System Admin's Account Deletion Requests page

**Basis and scope.** IR-788 under IR-779; authority ADR-051 decisions 8 and 9. It reads and acts through IR-785's API. No FR- id.

**What exists now.** `frontend/src/features/admin/AccountDeletionRequestsPage.tsx` at `/admin/account-deletion-requests`, listed as "Account Deletions" in the System Admin's Administration section (`lib/access.ts`, `router/index.tsx`).
- Each pending request is a list item named by the person, with their email, role and when they asked.
- Whatever blocks a request is listed in the server's plain words. Confirm is disabled while anything blocks it. Its description says RDCO or the person must clear the blocker, or, on the System Admin's own request, that another System Admin must decide.
- Reject opens a dialog whose submit button stays disabled until a reason is typed. The person receives that reason.
- Confirm opens a dialog that says it can't be undone, with Cancel focused first.
- A refused decision shows the server's `detail` in the dialog and reloads the list.
- Which controls are enabled comes only from `capabilities`. The page compares no role names.

**Tests:**
- `AccountDeletionRequestsPage.test.tsx`, 6 tests. They query by role and accessible name, and run axe on the list and on both dialogs.
- `access.test.ts` and `Sidebar.test.tsx` pinned the System Admin's nav to Users and Audit Log. Both now expect Account Deletions as well, a deliberate change for this ticket.

**Not done:** Settings' "Delete my account" is IR-787. Until it ships, a person can only ask through the API.
