## IR-1048

**Requirement:** A refused upload in Paper View shows the server's reason, and a refused active-content PDF says what to do; a failure with no reason still says "Please try again."

**Design:** Jira IR-1048

**Implementation:** `FilesSection.tsx`'s `uploadRefusal` reads the server's `detail`, then DRF's field-keyed message (`abstract_file`, `file`), then falls back. The manuscript goes up as a `PATCH` of the record, so its refusal carries only `{"abstract_file": [...]}`. `apps/documents/validators.py` words exit 4 as "This PDF contains unsupported active content, such as attached files or scripts. Save a copy without them (for example, with Print to PDF) and upload that."

**Test:** `FilesSection.test.tsx`: "shows the server's reason when it refuses the manuscript, not Please try again" and "still says Please try again when the upload fails with no reason"; the existing document-upload test still shows `detail`. `apps/documents/tests/test_bounded_pdf.py` asserts the new wording (four tests, changed deliberately)

**Evidence:**

- 2026-11-13, deployed site: uploading `sample8_v2.pdf` (an embedded C2PA file) as a revised manuscript showed "could not be uploaded. Please try again."
- 2026-11-15, locally: the new manuscript test failed before the change (no reason shown) and passes after; all 20 `FilesSection.test.tsx` tests pass; `tsc --noEmit` and eslint clean.
- `test_bounded_pdf.py` runs the inspector as a Linux subprocess and was not run on this Windows machine; CI is the record for it.

**Status:** **PARTIAL** until CI passes and the PR is reviewed
