# IR-1100: Admin queues: read past the first 20 rows (Download Requests, Account Deletion Requests)

**Requirements:** follow-up to IR-1076, epic IR-920. The matrix has no `FR-` row for these queues' paging.

## What was wrong

The API pages its lists, and the Download Requests and Account Deletion Requests pages read only `data.results`, so any row past the first page was unreachable and nothing said so. IR-1076 had already added a "Load more" to Delete Requests.

- Download Requests: `StandardResultsPagination`, 20 a page.
- Account Deletion Requests: `LargeResultsPagination`, **200 a page**, not 20 as the card says (`AccountDeletionRequestListView`). It truncates later, and the same fix applies. Page size is unchanged.

## What changed

- **`hooks/usePagedRead.ts`** (new): the first page under `useApiRead`, then `loadMore` reads the next page and appends it. A filter change or `retry` starts again from page one. A later page is cancelled with the first, and ignored if the first page it followed was replaced, so a stale page never replaces a newer one (IR-914). A failed later page keeps what is shown and says so.
- **`components/shared/LoadMore.tsx`** (new): the button and its error line, shown only while the server has another page.
- **`DownloadRequestsPage.tsx`:** moved from a bare `useEffect` read onto `usePagedRead`, with Load more. It now also gets the IR-914 behaviour Delete Requests has: a filter change cancels the read in flight, and a timed-out read is the "interrupted" state with a Retry.
- **`AccountDeletionRequestsPage.tsx`:** reads through `usePagedRead`, with Load more.
- **`DeleteRequestsPage.tsx`:** its own copy of the paging logic is replaced by the same hook and control. No behaviour change; its tests are unchanged.
- **API:** `listDownloadRequests` takes `{ signal }`; `deletionRequests` takes `page`; the accounts `PaginatedResponse` type gains `next`.

Not changed: `SessionsPage` (unpaged), `NoticesPage` and `RetentionPage` (each reads one latest item). No other admin list reads only `results`.

## Acceptance criteria

| Criterion | Evidence |
|---|---|
| More than 20 rows offers Load more and shows the rest; 20 or fewer shows no button | Download: "offers Load more when the server has another page, and appends it", "shows no Load more when everything fits on one page". Account deletion: the same two, in `AccountDeletionRequestsPage paging (IR-1100)` |
| A filter change starts from the first page | Download: "starts again from the first page when the filter changes". Account deletion has no filter; a decision's refresh does the same: "starts again from the first page after a decision refreshes the list" |
| A stale page never replaces a newer one (IR-914 kept) | Download: "cancels the read in flight when the filter changes…". Delete Requests keeps its existing cancel tests, now through the hook |
| Tests for each page cover the more-than-20 case | both pages, as above, plus "says so when the next page cannot be read, and keeps what is shown" on each |
| Traceability added | this file |
