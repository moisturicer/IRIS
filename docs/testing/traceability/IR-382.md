## IR-382

**Requirement:** **Groq dialect: the vendor's request shape behind the adapter, with citation-marker normalisation** — no FR- id; part H of IR-375's spec, and the seam part I (IR-384) adds OpenRouter to

**Design:** [ADR-036 §Amendment](../../adr/036-openai-compatible-inference-provider.md) (**one adapter per protocol**, vendor chosen per Inference task — so vendor difference is a collaborator, not a second adapter) · [ADR-008 §Amendment](../../adr/008-ai-degradation-to-fts.md) (a same-vendor fallback list, which is why a provider list has one dialect)

**Implementation:** `apps/ai/citation_markers.py` — the marker grammar (`MARKER`, `NUMBERS`, `SUFFIX`, `numbers_in`) held apart from both the parser and the dialect, at the same level as `regions.py`, so neither layer imports the other. **One definition, not two that agree today:** the bracket set and the suffix bound were each widened after a live failure, and a copy that missed either widening would let the dialect normalise a marker the parser then dropped · `apps/ai/providers/dialects.py` — `VendorDialect` (request extras, reading a streamed delta's text and reasoning channels, citation-marker normalisation) with `GroqDialect` as its only implementation; `dialect_for()` is **non-raising**, so OpenRouter and a self-hosted vLLM reach the default — which is Groq's, exactly what the adapter sent unconditionally before this existed · `apps/ai/providers/openai_compatible.py` — the transport is now vendor-agnostic: `extra_body` comes from `dialect.request_extras()`, the streaming loop reads deltas through `dialect.read_text`/`read_reasoning`, and `generate()` returns text the dialect has normalised. Error classification (IR-320) and the reasoning channel separation (IR-327) are untouched · `apps/ai/resilience/llm.py` — `LLMProviderConfig.vendor` selects the dialect in `_wrap`, and all three decorators forward `.dialect` the way they already forward `.model` · `apps/ai/inference/providers.py` — a Profile's vendor is what picks it · `apps/ai/answers/service.py` — `_parse` normalises the **joined** stream text before `parse_citations`, never per delta: `【1` and `†L1-L5】` are neither of them a marker. **Deliberately not changed:** `_MARKER` in `answers/citations.py` still matches the variants itself — it is the net for any provider reached without a dialect, and where the parser's own correctness is tested

**Test:** `apps/ai/providers/tests/test_dialects.py` (27 — Groq's `extra_body` and its absence when no effort is configured, reasoning on its own channel from either vendor attribute, each observed variant marker (`【1】`, `［1］`, `【1†L1-L5】`, `[1†L1-L5]`, `【1, 2】`) normalising to canonical form, an unclosed marker not swallowing the prose after it, a normalised variant resolving to its source through `parse_citations`, dialect selection by name and the non-raising default, and the adapter delegating request shaping, delta reading and normalisation to an injected dialect that is nothing like Groq's, and the dialect and the parser resolving to the one shared grammar object) · `apps/ai/answers/tests/test_service.py` (+1 — a variant marker split across two stream deltas still produces a matched citation) · the existing `test_llm_contracts.py` and HTTP suites pass **unmodified**, which is the refactor's own evidence

**Evidence:** `apps/ai` **1176 passed, 3 failed**; full backend suite **1850 passed, 3 failed, 2 skipped, 1 xfailed** (2026-09-29). All three failures are pre-existing and environmental, **verified by running the same three against a detached `origin/main` worktree with the identical `.env` and getting the identical three failures**: `test_llm_contracts.py`'s temperature and reasoning-effort assertions read the developer's own `backend/.env` (`LLM_TEMPERATURE=0.5`, `LLM_REASONING_EFFORT="high"`), and `test_startup.py`'s no-keys check does not clear `LLM_RESOLVE_MODEL`/`LLM_SUMMARY_MODEL`

**Status:** **IMPLEMENTED** — the seam only. OpenRouter's own request shape, data policy and native fallback field are IR-384
