## IR-273

**Requirement:** **The owner answers the open revision requests with a new version; only the requesting parties' clearances and seats reset** — ADR-003's clearance-aware resubmission on the adviser-first model, under both ADR-004 policies; touches FR-M5-03 (stable label only)

**Design:** [ADR-032 §5](../../adr/032-adviser-first-review-and-office-reviewer-pools.md), with its 2026-10-08 IR-416 hand-off and IR-273 Amendment (open points pending the project lead's review) · [ADR-003](../../adr/003-clearance-aware-resubmission.md) · ADR-004 · Jira IR-273

**Implementation:** `apps/reviews/new_version.py`: `submit_new_version` lets an owner of a new-model record with an open request, changed since the newest request (a manuscript other than the latest version's, an owner's `RecordUpload`, or `Record.details_edited_at`, `records/0016`, stamped only by an owner's real change), write v(n+1) through `write_version`, resolve every open request as `resubmitted`, reset the requesting parties' clearances (`CLEARANCE_AWARE`) or every clearance (`RESTART_ALL`), return the requesting parties' `done` seats to `in_review`, and record `resubmission_count`/`last_resubmitted_at` so `preserved` derives as before. Refuses 404 / 403 (not an owner) / 400 (legacy pipeline, no open request, nothing changed — naming what would count). `POST /records/<id>/new-version/`; record detail's `revision.new_version` (number, who re-reviews, which clearances are kept, why not yet) and `manuscript_unsubmitted`. The manuscript lock opens while a revision is asked for, to owners only; `/manuscript/` serves a non-owner the latest version's file until the new version is submitted, and withdrawing the last open request puts the submitted manuscript back. An owner's revised manuscript is extracted only when its version is submitted, so the chunks Ask IRIS answers from are always the submitted manuscript's (settled 2026-10-08). Requesting parties' reviewers are notified. Frontend: *Submit new version* in the owner's *Revision requested* banner (`create_version`, from the server's flag) with a confirmation naming who reviews it ("IERC will review v3. ITSO's clearance is kept."), *Upload revised manuscript* in Files (`replace_manuscript`), an "unsubmitted" label in Files and the reader, and the version picker offering the submitted latest version beside it

**Test:** `apps/reviews/test_new_version.py` (REST seam, one class per criterion, both policies via `WORKFLOW_TABLE`) · `apps/records/test_version_backfill_migration.py` (now writes through `0014`'s models) · `paper-view/NewVersionDialog.test.tsx` · `paper-view/FilesSection.test.tsx` · `paper-view/PaperViewPage.test.tsx` · `features/records/capabilities.test.ts`

**Evidence:** `test_new_version.py` and the reviews, records, notifications and documents suites run locally in a one-off backend container (one policy-sweep failure fixed by permitting `new_version.py`); frontend checks left to CI on the IR-273 PR per the team rule
