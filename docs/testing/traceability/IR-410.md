## IR-410 My Library absorbs My Workspace

**Design:** [frontend redesign spec §4.9 as amended 2026-10-11, and Appendix F F4](../../frontend_redesign_spec.md), following [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) and [ADR-003](../../adr/003-clearance-aware-resubmission.md).

- **Defaults:** authors open on their own research; everyone else on Want to read.
- **Grouping:** an author's research is grouped by who has each record now (Waiting on you first, then the Adviser, the offices, RDCO, drafts, finished work and a collapsed Archived), using only server fields. The status line is `workflow_state_label`. The next step appears only for the owner-action states `awaiting_resubmission` and `awaiting_document`.
- **Office review on the card:** each office that cleared the record is shown, marked *kept* when it survived a resubmission.
- **Actions:** Continue on a draft opens Publish. Respond opens Paper View at Review or Files. `/workspace` redirects here.
- **Retired:** the case cards, numeric counters, filter rail, client stage derivation and the Workspace components.
- **Reading:** saved folders, likes and history stay browser-local in a "Your reading" panel beside the research. *Superseded by IR-566 below: saves and Reading status are account-backed, likes are retired.*
- **Product context:** redesigned with the `impeccable` skill, which added `PRODUCT.md` (design context only; the ADRs remain the authority).

**Backend (Jira IR-410 comment 10547, settled 2026-10-07):** `GET /records/mine/` serializes with `MyResearchSerializer`, newest change first. It replaces Record detail, which cost about 15.6 queries per record there.

- **Fields:** id, title, type, authors, adviser name, `pipeline_status`, `workflow_state` and its label, `holders`, `cleared_offices` and dates.
- **Flat query count:** `tracker.workflow_facts(records)` gathers each workflow fact once for the whole list. It hands the facts to the same `derive_workflow_state` and reuses `clearance_state.is_preserved`, so the query count does not grow with the list's length.
- **Side effect:** IR-415's `my_seats` and `is_participant` leave the list.
- **Frontend type:** the rows are `MyResearchItem`, not `RecordDetail`.
