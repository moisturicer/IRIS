# IR-876: Outdated threads, suggested wording and the response to reviewers

**Requirements:** no FR- id. The rule is [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §7 (2026-11-04 amendment: *Outdated threads*, *Suggested wording*, *The response to reviewers*), its 2026-11-06 correction, and its IR-876 build notes of 2026-11-09. The suggested-wording check is [ADR-058](../../adr/058-each-version-keeps-its-text-and-its-files.md) §3.

Built in two parts: part 1, the backend (below), and part 2, the screens.

## Part 1: backend

What changed:

- **Placing** (`apps/reviews/placement.py`, pure): a thread's text is *found* in the new reading (`comparison.appears_in`), or the passage it was in is *changed* (the comparison pairs it with an edited passage, whose text it gives), or it is *removed*.
- **Per Version** (`apps/reviews/thread_places.py`): each later Version adds one `ThreadPlace` per open anchored thread, searched from the thread's place in the Version before. The original anchor never changes. The first *changed* or *removed* place makes the thread Outdated from that Version until it is resolved, and a removed passage is followed no further. Placing never resolves, reopens or answers a thread. It runs after each reading (`apps.records.tasks.read_review_text`) and after each submission (`apps.reviews.tasks.place_review_threads`), on the comparison's pair of readings, and does nothing until both exist.
- **Suggested wording** (`ReviewComment.suggestion`): a reviewer's, on an anchored thread only, and editable only while the thread is a draft. Accepting it is the *Addressed* answer, whose note defaults to *"Accepted the suggested wording."* Each place records the page the wording appears on in that Version (`suggestion_page`), the *found on p. N* hint.
- **The thread payload** carries `suggestion`, `place` (the newest place), `outdated_since` and `wording_check`: accepted wording looked for in the first Version placed *after* it was accepted, so a Version placed before the owner accepted is never read as the answer to it.
- **The response to reviewers** (`apps/reviews/response_letter.py`): the submit preview (`revision.new_version.letter`) assembles it from the open, sent threads of the requesting parties, *Must fix* first, with each answer or none. Submitting freezes it onto the new Version (`ResponseLetter`). `GET /records/<id>/response-letters/` serves every letter, newest first, whole, with the viewer's own party first, under `may_read_review` (404 otherwise). The access matrix has a `record-response-letters` entry.
- **Storage:** migration `reviews/0026` adds `ReviewComment.suggestion`, `ThreadPlace` (one per thread per Version) and `ResponseLetter` (one per Version).

## Part 2: the screens

What changed:

- **A thread card** (`threads/ReviewThreads.tsx`) reads *Outdated since vN* and says where its passage is now: *Found on p. X of vN.*, *Passage removed in vN.*, or a *Now in vN, p. X* section with the new text beside the original quote. Show in paper and the reader's marks use that place when it is in the Version on screen (`whereShown`, `threads/useThreadsWorkspace.tsx`), else the original anchor.
- **Suggested wording** shows on its thread. The owner can *Accept wording* (the Addressed answer) or decline it with a reason; once accepted, the card says whether the first Version after that has the wording and on which page (`wording_check`), and says nothing before such a Version exists. The composer offers an optional *Suggested wording* box on a reviewer's draft about a passage, after the severity choice.
- **The submit dialog** (`NewVersionDialog.tsx`) shows the response to reviewers being assembled, and its Submit is disabled, with the reason given, while a Must fix thread is unanswered. The page's *Submit new version* button now always opens the dialog, so the reason is read where the button that is refused sits.
- **Threads opens with the newest letter** (`threads/ResponseLetter.tsx`). A reviewer whose seat is on the newest Version lands on Threads when that Version carries a letter (`ReviewWorkspaceLayout.tsx`), once per letter, so they read it first. The letter is shown whole, the viewer's own party first, each answer as given or *No answer given*. A response of a shape it doesn't know shows no letter (CODING_STANDARDS F1).

**Evidence**

- `threads/ThreadPlaces.test.tsx` (13 tests): an edited passage is Outdated with its new text; removed; found and not Outdated; followed after going Outdated; wording shown, accepted, declined with a reason, found or not found in the first Version after it was accepted, and nothing said before one exists; offered on a passage and not on a general comment; the letter comes first, whole, and isn't shown when there is none. Two run axe-core.
- `threads/ThreadsWorkspace.test.tsx`: two new tests. A reviewer lands on Threads, on the newest Version's letter, and stays on the conversation when the letter belongs to an older Version.
- `NewVersionDialog.test.tsx`: three new tests on the letter preview and the disabled Submit.
- **Two existing tests changed deliberately:**
  - `PaperViewPage.test.tsx` (IR-273): it checked that the page's button was disabled. It now opens the dialog and checks that the dialog's Submit is disabled and described by the reason.
  - `ReviewThreads.test.tsx`, *adds an anchored Must fix draft by keyboard alone*: the new optional wording box is one more Tab stop, after the severity. The test now tabs through it.
- Run 2026-11-09 on Windows: `tsc --noEmit` clean; `npm run lint` 0 errors (its 3 warnings are on main); `npm run test:changed` 612 passed in 32 files.
