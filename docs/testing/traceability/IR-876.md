# IR-876: Outdated threads, suggested wording and the response to reviewers

**Requirements:** no FR- id. The rule is [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §7 (2026-11-04 amendment: *Outdated threads*, *Suggested wording*, *The response to reviewers*), its 2026-11-06 correction, and its IR-876 build notes of 2026-11-09. The suggested-wording check is [ADR-058](../../adr/058-each-version-keeps-its-text-and-its-files.md) §3.

Built in two parts: part 1, the backend (below), and part 2, the screens.

## Part 1: backend

What changed:

- **Placing** (`apps/reviews/placement.py`, pure): a thread's text is *found* in the new reading (`comparison.appears_in`), or the passage it was in is *changed* (the comparison pairs it with an edited passage, whose text it gives), or it is *removed*.
- **Per Version** (`apps/reviews/thread_places.py`): each later Version adds one `ThreadPlace` per open anchored thread, searched from the thread's place in the Version before. The original anchor never changes. The first *changed* or *removed* place makes the thread Outdated from that Version until it is resolved, and a removed passage is followed no further. Placing never resolves, reopens or answers a thread. It runs after each reading (`apps.records.tasks.read_review_text`) and after each submission (`apps.reviews.tasks.place_review_threads`), on the comparison's pair of readings, and does nothing until both exist.
- **Suggested wording** (`ReviewComment.suggestion`): a reviewer's, on an anchored thread only, and editable only while the thread is a draft. Accepting it is the *Addressed* answer, whose note defaults to *"Accepted the suggested wording."* Each place records the page the wording appears on in that Version (`suggestion_page`), the *found on p. N* hint.
- **The thread payload** carries `suggestion`, `place` (the newest place), `outdated_since` and `wording_check`: accepted wording looked for in the first Version placed *after* it was accepted, so a Version placed before the owner accepted is never read as the answer to it.
- **The response to reviewers** (`apps/reviews/response_letter.py`): the submit preview (`revision.new_version.letter`) assembles it from the open, sent threads of the requesting parties, *Must fix* first, with each answer or none. Submitting freezes it onto the new Version (`ResponseLetter`). `GET /records/<id>/response-letters/` serves every letter, newest first, whole, with the viewer's own party first, under `may_read_review` (404 otherwise). The access matrix has a `record-response-letters` entry.
- **Personal-data export:** a reviewer's suggested wording is exported with their review comments. `ThreadPlace` and `ResponseLetter` are declared as left out, with the reason (`apps/accounts/personal_data/registry.py`): one is computed from the paper, the other is the paper's review, holding several people's writing.
- **Storage:** migration `reviews/0026` adds `ReviewComment.suggestion`, `ThreadPlace` (one per thread per Version) and `ResponseLetter` (one per Version).

**Evidence**

- `apps/reviews/test_placement.py` (5 tests, pure): found on its new page, including in another section and whatever the case or line-break hyphens; changed, with the new text and its regions; removed.
- `apps/reviews/test_thread_places.py` (9 tests, database, the IR-873 PDF pair read by the real reader in this process):
  - an unchanged passage moves to v2; an edited one makes the thread Outdated since v2, beside the new text, still open and with its anchor unchanged
  - nothing is placed until both Versions are read, and then once
  - only open anchored threads are placed
  - the suggested wording is found on its page, or not found
  - at v3, an Outdated thread follows v2's text and stays Outdated since v2; a deleted passage reads removed
  - a finished reading and a submitted Version each queue placing
- `apps/reviews/test_suggested_wording.py` (7 tests): wording needs a passage and a reviewer, isn't allowed on a reply, changes while a draft and not once sent; accepting is *Addressed* with its note, and declining needs a reason; a thread shows its newest place and since when it is Outdated, or neither; the wording check reads the first Version placed after the wording was accepted, and nothing before it.
- `apps/reviews/test_response_letter.py` (7 tests): the preview assembles the letter from the answers; submitting freezes it, and a later answer leaves it unchanged; only the requesting parties' open, sent threads are in it; each reader reads it whole, their own party first; a 404 for anyone the review refuses; a Version answering no thread has none.
- Run 2026-11-09 on Windows against a throwaway pgvector container, with the access matrix, the authorization matrix, the enum vocabulary and the traceability shape.
- Regression, same day, against the same container: the thread, comment, new-version and review-text suites with the four new files: 191 passed, 8 failed. The 8 are `test_new_version` uploads refused with *"PDF checking is temporarily unavailable"*: the PDF checker runs only on Linux, and they fail the same way on main. CI is the gate for them.
- `flake8` clean on the changed backend files.
- **Migration on a copy of the dev database** (2026-11-10, restored into the throwaway container): it was at `reviews/0022`, and `migrate` applied 0023 to 0026 cleanly. 0026 then rolled back to 0025 and applied again. The copy holds 18 Versions and **no review comments**, so this shows the schema change applies to a real database, not how existing threads fare: every existing thread gets an empty `suggestion` and no place.
