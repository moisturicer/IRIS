## IR-1303

**Requirement:** On Sign in and Sign up, nothing that goes wrong moves the form. A failed sign-in or registration is said in a dialog in front of the form, styled like the account-locked dialog, instead of an alert inserted above or inside it. A field's error appears in a one-line slot already reserved under the field, so "Password is required." no longer grows the card. UI review items #36 and #37.

**Design:** Agreed with the frontend owner in the ticket's design session (2026-11-23): one shared dialog for both screens; an opt-in slot on the field primitives so other forms are unchanged; Sign up included, Reset password not. "Some of this form didn't load" stays inline, because it explains the empty dropdowns still on screen. An error long enough to wrap still grows the slot by one line; reserving two lines everywhere was rejected as too gappy.

**Implementation (frontend only):**

- `components/auth/EntryErrorDialog.tsx`: an `alertdialog` with the account-locked dialog's shell, named by its title and described by its message; Close and Escape close it, and `returnTo` says where focus goes.
- `components/ui/Input.tsx`, `components/ui/Select.tsx`: `reserveErrorSpace` keeps a 20 px slot (one `small` line) under the field for its hint or error. Off by default.
- `components/auth/LoginForm.tsx`: both fields reserve the slot; `passwordRef` exposes the password field.
- `features/auth/LoginPage.tsx`: every non-lock failure (invalid credentials with the attempt count, unreachable, unverified with the resend link, throttled, other) opens the dialog. Closing it returns focus to the password field. The failure is kept after the dialog closes, so a rejected credential still marks both fields invalid. The account-locked dialog is unchanged.
- `features/auth/SignupPage.tsx`: "Registration failed", "IRIS can't be reached right now", "The data notice changed" and "We brought you back to [step]" open the dialog; an unowned server error rides in the same dialog as a return. Closing it focuses the first field marked wrong, else the chosen role after a role refusal, else the step's submit button; while a dialog is open the page no longer moves focus itself. Every field, dropdown and the role refusal line reserve the slot. The data notice answers (shared with Settings) are unchanged.

**Test:**

- `components/ui/Input.test.tsx`, `components/ui/Select.test.tsx`: with the slot on, hint and error share one slot, and an empty slot stays and describes nothing.
- `components/auth/EntryErrorDialog.test.tsx`: role, name and description; Close and Escape close it and return focus where asked; no blocking axe violation.
- `features/auth/LoginPage.test.tsx`: every failure is an `alertdialog` and no live region is added to the page; Close returns to the password with both fields still invalid. Tests that sign in repeatedly now close the dialog between attempts, as a person must.
- `e2e/smoke/auth.spec.ts` (Playwright, CI): a rejected sign-in shows the `alertdialog` named "Invalid email or password" and stays on `/login`; `e2e/smoke/support/dialogs.ts` adds a "sign-in failed" case, so the dialog is axe-scanned in a real browser and counted by the dialog-coverage check.
- `features/auth/SignupPage.test.tsx`: each failure is an `alertdialog` with no alert in the page; closing it focuses the refused email, program, first name or role, or Register.

**Deliberate test changes:**

- About twenty tests that found the inline `alert` now find the `alertdialog`: the requirement changed, not the behaviour under test.
- `LoginPage.test.tsx`'s axes-lockout accessibility test built its `unlock_at` (now + 60 s) when the file was collected. The file takes 44–55 s locally, so on a loaded run the lock had ended, and its dialog closed itself, before that test ran. The reply is now built when the test runs.
