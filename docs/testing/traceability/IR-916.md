# IR-916: tests for the auth, session and API modules that had none

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes status. This adds test evidence for two rows that stay **PARTIAL**: **NFR-S6** (account protection; the browser's own counter and lock) and **FR-M6-01** (authentication; what sign-out clears and how a refused login reaches the screen). No product code changed. Parent: IR-893. Phase 1 of 2.

**The problem.** A same-name-test scan on `main` (2026-11-05) found no test file for 11 of 14 `src/api/` modules, all 8 hooks and four `lib/` modules. The ones that guard access and sessions came first.

**What proves it**

| Check | Where |
|---|---|
| Browser lock: three-strike limit, per-account counts, case and spacing folded so retyping cannot dodge it, unlock exactly when the time passes (one millisecond before it is still locked), corrupted storage reads as unlocked, a lock is independent of the attempt counter | `frontend/src/lib/authSession.test.ts` (NFR-S6) |
| Why a session ended: each of the five server codes has its own title; an unknown or hostile code falls back to inactivity and is never echoed into the URL; no redirect from `/login` itself | `frontend/src/lib/authSession.test.ts` |
| Sign-in persists only the refresh token, only in `sessionStorage`; `logout` and `clearTokens` remove it, both legacy keys (`refresh_token`, `access_token`) in both storages, and reading history; a rotated token is cleared too; sign-out leaves the browser's lock counters alone | `frontend/src/lib/authStorage.test.ts` (FR-M6-01) |
| Token claims: base64url with the padding dropped, every malformed shape is `null` and never throws, no `exp` counts as expired, expiry is exact to the second | `frontend/src/lib/jwt.test.ts` |
| `useAuth` follows sign-in, sign-out, a rotated token and a session ended elsewhere; `useRole` sets exactly one named flag per role, reviewer and staff flags per role, and Django staff or superuser grants both | `frontend/src/hooks/useAuth.test.ts`, `useRole.test.ts` |
| `ReviewAccessRoute` shows the queue only for `review_access.my_reviews === true`; every other value, no flag and a signed-out visitor go to Discover | `frontend/src/components/auth/ReviewAccessRoute.test.tsx` |
| `LoginForm` validation, what it hands to `onSubmit`, the password toggle, locked and rejected-credentials states, one submit while busy, axe | `frontend/src/components/auth/LoginForm.test.tsx` |
| Method, path, params and body of every exported call: `authApi` (10), `recordsApi` (61), `seatsApi` (9), `reviewsApi` (3), `documentsApi` (all); multipart field names and upload progress; blob downloads; a 400, 401, 403, 404 or 409 reaches the caller with its status and body | `frontend/src/api/auth.test.ts`, `records.test.ts`, `reviews.test.ts`, `documents.test.ts` |

The API tests replace axios's adapter (`frontend/src/test/apiAdapter.ts`), so the real request pipeline runs and the test reads what would go on the wire. Checked by mutation: misspelling `embargo-release` in `records.ts` fails the `releaseEmbargo` case (reverted).

**Already covered elsewhere, and kept:** `store/auth.store.test.ts` (a refresh that resolves after sign-out is discarded), `api/client.test.ts` (the 401 refresh), `lib/tokenRefresh.test.ts`.

**What this does not show.** The refusal cases stub the status, so they prove the caller receives it intact, not that the server returns it. Server-side lockout (axes, the 429 and `locked_by_admin`) is outside this change and keeps NFR-S6 **PARTIAL**. No test drives the sign-out sequence through the real UI (`AccountMenu` and `PendingApprovalPage` call `authApi.logout` and then the store `logout`).

**Findings.** Drafts in the review dialogs are not keyed by user, so a person signing in on the same tab sees the previous person's unsent text: **IR-931**. `lib/jwt.ts` decodes with `atob`, which yields Latin-1, so a non-ASCII claim would decode wrongly; unconfirmed, not ticketed.

**Run, and not run (2026-11-05, 2026-11-06).** The 11 new files pass together (242 tests), with `tsc --noEmit` clean and ESLint at 0 errors on them. A full `npm test` run before the review fixes gave 2085 passed and 1 failed: a 15 s timeout in `PublishDialog.test.tsx`, which this change does not touch and which is slow and flaky under load. CI's result is the PR's to report.
