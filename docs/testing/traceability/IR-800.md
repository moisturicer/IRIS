# IR-800: The Notices page, and registration, sign-in and Settings show the server's current notice

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** ADR-051 decisions 16 and 17, as amended by ADR-063 decision 9 (RDCO alone publishes; RDCO and the System Admin read), with ADR-054's single notice. Builds on IR-783 (the RDCO and System Admin sections) and IR-799 (the publish, history and impact endpoints). No FR- id.

**Where the ticket and the ADR differ:** the ticket says the page is "for RDCO and the System Admin". ADR-063 decision 9 later made publishing RDCO's alone, and IR-799's server enforces that. The ADR wins: both reach `/notices`, and only RDCO sees the publish form.

**What changed:**

- `features/admin/NoticesPage.tsx` at `/notices`, in RDCO's sidebar group and the System Admin's, and nobody else's (`notices` and `adminNotices` in `lib/access.ts`, one route).
  - It shows the current version and who published it.
  - Above everything, it says the data protection officer must approve the text before publishing, and that a published version can't be changed.
  - **RDCO:**
    - One large Notice text field, filled with the current text so it can be replaced by pasting.
    - **Preview** shows the text through the same `NoticeText` readers see, as "Version N · not published yet".
    - **Publish version N** is disabled while the text is unchanged or blank. It reads `GET /auth/notice/versions/impact/` and asks "Publish version N?", giving how many people must answer before they can keep using IRIS. Cancel sends nothing.
    - A 409 `notice_stale` shows the server's refusal, says which version is current now, keeps the paste and rereads the history. A refused text shows the server's reason against the field.
  - **System Admin:** the same current version and history, the line "Only RDCO publishes a new version.", and no form.
  - **Version history** lists every version, newest first, with its date and publisher, and each can be read in full.
  - A history response that isn't a list is treated as a failed read (CODING_STANDARDS F1).
- **One way to show a notice:** `NoticeText` renders the server's `text` as plain text with every line break (`whitespace-pre-wrap`), under a fixed "Data notice" heading with the version and date. Markup and addresses show as the characters they are; React escapes them and nothing makes links. Registration, the notice screen, Settings, the sign-in frame and the preview all use it.
- **Registration and sign-in:** `DataNotice.tsx`, the frame's Data privacy panel, now loads `GET /auth/notice/` instead of holding the interim text. The Terms panel no longer mentions an "interim" notice.
- **Settings:** the "Current disclosure notice" panel, built from `lib/dpaTerms.ts`, is replaced by `CurrentNoticePanel` ("Current data notice"), which reads the server's notice. Its old caption said the account's consent didn't confirm acceptance of the notice; ADR-054 now records a per-version answer, so that caption is gone.
- **Deleted:**
  - `lib/dpaTerms.ts`.
  - `components/compliance/` (`DpaConsentGate`, `DpaConsentModal`, `index.ts`, `DpaConsent.test.tsx`). No screen rendered the gate or the modal: the publish form had stopped asking for consent at IR-791, and the smoke suite's own dialog list recorded the modal as "Not rendered by any screen".
- `types/notice.ts`: `DataNotice` carries `text`, and the older `title`, `subtitle` and `sections` are optional. It gains `NoticeVersion` and `NoticeImpact`. `api/notice.ts` gains `versions`, `impact` and `publish`, and `current` takes an abort signal.
- e2e smoke: a `notices` screen (RDCO), a dialog case that opens "Publish version 2?", the signup screen's notice mock as `text`, the removed modal's `UNSCANNED` entry, and `/notices` in `matrixRoutes.json`.

**Changed deliberately:**

- `DpaConsent.test.tsx` was deleted with the modal it tested (named in the ticket).
- `SettingsPage.test.tsx`'s IR-123 case looked for the frontend's own notice wording ("external AI providers outside CIT-U") and the old caption. It now checks that the server's notice, version and date are shown beside the consent record.
- `LoginPage.test.tsx` looked for the interim text ("What IRIS keeps when you register"). It now mocks the server's notice and checks its text, version and date.
- `NoticeAnswerScreen.test.tsx`, `SignupPage.test.tsx` and `AiAnswerPanel.test.tsx` fixtures now carry `text`, as the server sends. Tests that waited for the old title as a heading now wait for the text. The "list item" check went, because the text is no longer split into lists.
- `access.test.ts` and `Sidebar.test.tsx` list every navigation entry exactly, and now include Notices for both roles.

No test was changed to make broken behaviour pass.

**Evidence (2026-11-08, Windows):**

- Vitest, `features/admin/NoticesPage.test.tsx` (12 tests):
  - the current version, its publisher and its text are in the field, the DPO and no-change rules show, and axe passes;
  - the preview shows the paste verbatim, with no link;
  - publishing asks first with the count of 41, and axe passes on the dialog; confirming sends `{based_on_version: 2, text}` and shows version 3;
  - Cancel sends nothing, and the confirmation says "1 person" in the singular;
  - an unchanged or blank text can't be published;
  - a stale publish shows the refusal, keeps the paste and offers version 4;
  - a refused text shows its reason;
  - the history reads every version in full;
  - the System Admin has no form and no impact read, and axe passes;
  - a failed read offers Try again, and a non-list response counts as failed;
  - at 360 px every button row wraps and nothing is clamped.
- `NoticeText.test.tsx` (3): line breaks kept; markup and an address shown as characters, not formatting or a link; a draft says "not published yet". It failed before `NoticeText` changed, then passed.
- `access.test.ts` gains "the Notices page is RDCO's and the System Admin's alone, at /notices".
- Full frontend suite: 184 files, 2,540 passed. `tsc --noEmit` is clean for the frontend and e2e. `npm run lint` shows 0 errors and 3 warnings, all in files this change doesn't touch.
