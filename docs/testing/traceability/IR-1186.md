# IR-1186: Users table drops its "Last active" column

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Part of epic IR-920 (S2 Frontend UI/UX Redesign).

## What changed

- The Users table (`/rdco/users`) no longer has a "Last active" column. It rendered `last_login`, which the API returns empty, so every row read "Never", including accounts that had signed in minutes earlier. That is a status the API cannot supply (PRODUCT.md). The table now has User, Role, Unit, Status and the row actions.
- `last_login` is removed from the `UserListItem` type, since nothing reads it. This reverses the "Last active" part of IR-1138's Users change.
- The ticket offered two outcomes: show real sign-ins, or remove the column. This is the second. Recording `last_login` at sign-in remains a backend decision (Jive) and is not made here; if it is made later, the column can come back with a test that a signed-in account's row shows its date.

## Tests

- `UserListPage.test.tsx`: new test that the table has no "Last active" column header and no "Never" text; the column-header test now expects five headers. The IR-1138 test that asserted the date and "Never" was rewritten on purpose and now covers Unit only.

- `npm run test:changed` ran 21 files: 328 pass, and `documentTitle.test.tsx` failed once under load (8.7 s) and passed alone (10 of 10). Not caused by this change.
