## IR-1312

**Requirement:** Publish asks what to do with the work however the author leaves it, not only by its own Close, Escape or backdrop (IR-1227). Browser Back/Forward, or any in-app navigation that drops `?publish=` (IR-1258), asks the same question Close would: "Stop the upload and close?", "Leave this submission?" or "Discard what you've entered?". With nothing entered it leaves without asking, and staying keeps the URL unchanged. Publish's own closing is never asked twice. Reload or tab close shows the browser's warning only while something would be lost. **Keep as draft** saves pending Details before it closes, and if the save fails it says so and stays open. No FR- id.

**Implementation (frontend only):**

- `features/publish/PublishDialog.tsx`:
  - `useBlocker` in `PublishFlow` holds a navigation that drops `?publish=` while `closingQuestion()` names a question (an upload in flight, a draft, or a type chosen). The same question then opens. Every leaving answer calls `leave()`, which runs `blocker.proceed()` if a navigation is held and otherwise closes. Staying calls `stay()`, which runs `blocker.reset()`. Publish's own close sets `leavingRef` first, so its URL change is not held.
  - A `beforeunload` listener (the pattern in `useReadingNote.ts`) is on only while an upload is in flight, a type is chosen with no draft, or on Details a save is running or failed, or a field the author changed is not yet on the server. Fields the author never touched don't count: a new draft's empty abstract never reaches the server either, and counting it would warn on every new draft.
  - **Keep as draft** awaits `autosave.saveNow()` with the button loading. On a failure the question says "Your latest changes weren't saved." and offers *Try again* and *Leave without saving*. On a conflict it says the draft was changed somewhere else, with *Keep editing* and *Leave without saving*. If a field the author changed still waits for Continue, it says "Some answers aren't saved yet: Continue saves them, or shows what needs fixing.", with *Keep editing* and *Leave without them*.
- `features/publish/autosave.ts`: `saveNow()` now returns `Promise<boolean>`: true when the save succeeded or nothing was pending, false on a failure or conflict. Also new are `unsavedFields()` and `isConflicted()`.
- `test/render.tsx`: `renderScreen` builds a data router (`createMemoryRouter` with one `*` route), as the app's `createBrowserRouter` is, because `useBlocker` throws under `MemoryRouter`. The screen reaches the route through context, so `rerender` still works.

**Test fix, made deliberately:** the default `draftDetail` fixture in `PublishDialog.test.tsx` had no `owners`. The API always returns it: it is required in `RecordDetail`, and the serializer lists it. Without it, a resumed draft held an owner list the server never had, so Keep as draft rightly reported an unsaved answer. The fixture now lists the author as owner. No assertion was changed.

**Test:** `features/publish/PublishDialog.test.tsx`, "leaving by Back, another page, reload or Keep as draft (IR-1312)":

- Back with a draft asks "Leave this submission?". *Keep editing* stays, with `publish=42` still in the URL. *Keep as draft* leaves.
- A navigation elsewhere is held, then completed once answered.
- Back with only a type chosen asks to discard. Back during an upload asks to stop, and *Stop and close* aborts the upload's signal.
- Back with nothing entered leaves with no question.
- Close asks exactly once, never a second time for its own navigation.
- `beforeunload` is cancelled only in the step-2 cases above: not with nothing entered, not once the upload is done, not once Details is saved, and not for a new draft's untouched fields.
- Keep as draft sends the pending PATCH before closing. With the PATCH failing it stays open and says "weren't saved", and *Try again* saves and closes. *Leave without saving* leaves. An invalid title gives the "aren't saved yet" question, and *Keep editing* stays.
- A new draft with only its title typed closes on Keep as draft. Checked to fail against the first version of this change, which counted untouched fields.
