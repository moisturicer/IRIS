# IR-1008: a thread's quote matches the Version's text whatever its spaces at line breaks

**Requirements:** no FR- id. A fix to IR-876's placing ([ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §7, *Outdated threads* and *Suggested wording*). The same matcher finds a thread's quote in the Changes tab (IR-873, ADR-058 §3).

## What was wrong

A thread's quote is taken in the browser with `range.toString()` (`frontend/.../threads/passage.ts`). That call drops the PDF text layer's line breaks, so the last word of one line and the first of the next are stored joined. The reader keeps a space there. `comparison.appears_in`, and `placement._touched` built the same way, collapsed whitespace but could not match across a *missing* space. So a quote over a line break was not found **even in the Version it came from**:

- a quote on an unchanged passage read *Outdated* / *Passage removed* instead of *Found*;
- a quote on an edited passage read *Passage removed* instead of *Now in vN* beside the new text;
- the suggested-wording check (*found on p. N*) missed wording that wrapped.

Found in a Docker test of IR-876 on record 32 with a read-only diagnostic that prints no paper text. Both quotes differed from v1's own reading only by spaces, one every 70 to 80 characters, where the lines wrap. Thread 23's quote differed from v2 in the same single place, so its sentence was unchanged, yet it read *removed*.

## What changed

- `comparison.locate(reading, text)`: the one matcher. It compares after `norm`, ignoring case and **ignoring whitespace**, across passages, and returns the `(section, passage)` pairs touched.
- `appears_in` formats what `locate` finds. `placement._touched` uses `locate` instead of its own copy of the matching.
- `COMPARISON_VERSION` is unchanged: it labels `compare()` output, which doesn't use this matcher.

## Evidence

- PR: https://github.com/moisturicer/IRIS/pull/660
- `apps/reviews/test_placement.py`, four new tests (pure). All four failed before the change and pass after:
  - a quote missing a line-break space is **found** where its text is unchanged, with its page and regions;
  - the same quote on an edited passage is **changed**, with the new text, not removed;
  - a quote across two passages, with no space between them, is found and touches both;
  - suggested wording across a line break is found (`appears_in`, the wording check).
- Run 2026-11-10 on Windows:
  - `test_placement` and `test_comparison`: 39 passed;
  - `test_thread_places`, `test_suggested_wording`, `test_response_letter` and `records/test_review_text_readings` (the Changes tab), against a throwaway pgvector container: 40 passed;
  - flake8 is clean.

## Threads placed before the fix

A thread's place in a Version is written once and never recomputed, so places written before this fix stay wrong. Nothing is deployed, so they exist only in development databases. A place is derived data and holds nothing anyone wrote. After pulling the fix and rebuilding, write them again once, from the repository root:

```powershell
@'
from apps.records.models import Record
from apps.reviews.models import ThreadPlace
from apps.reviews.thread_places import place_threads
ids = set(ThreadPlace.objects.values_list("thread__record_id", flat=True))
ThreadPlace.objects.all().delete()
print(len(ids), "papers,", sum(place_threads(Record.objects.get(pk=i)) for i in ids), "places written")
'@ | docker compose exec -T backend python manage.py shell
```

Checked 2026-11-10 on a migrated empty test database: *0 papers, 0 places written*.
