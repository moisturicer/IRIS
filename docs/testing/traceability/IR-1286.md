# Traceability — IR-1286

## IR-1286 — One transient model failure ends a whole Ask IRIS answer, and nothing logs why

**Basis and scope.** Bug against IR-860's adapter and IR-862's AGENT profile. On 2026-11-23 a local run ended "IRIS could not finish this question." after step 2's streamed request got HTTP 200 and then raised `TransientProviderError` within 1.3 s; the admission ledger shows 2 such attempts in about 700 since 2026-11-07. `AdmittedAgentProvider` already supported retries (IR-725), but the profile built it with `retries=0`, and nothing logged why an attempt failed.

- `OpenAICompatibleAgentProvider` logs each transient failure at WARNING: reason, HTTP status, the vendor error's code and message (200 characters, API key redacted), the generation id and the httpx exception type. Never the request, a passage or a header.
- `RUNS_AGENT_PROVIDER_RETRIES` (required, 0 to 3; `ai/.env.example` ships 1) is passed to `AdmittedAgentProvider`. Each resend is admitted and settled on its own, inside the run's allowance (ADR-049, IR-725).
- Streaming: a resend never repeats text the reader saw. `DraftSink.mark`/`rewind` forget a failed send's held text; if any of it was already published live, the error is marked `replayable = False` and is not resent, so that run still ends `provider_failed`. Under the default `RUNS_AGENT_CHECKS=enforce` nothing streams live, so every transient failure is resendable.

**Tests.** `backend/apps/ai/tests/test_ai_runtime_openai_agent_contract.py`: an error chunk after 200 is resent once and the answer streams once, with two settled tickets; two failures end `provider_failed` after two sends; live text then a failure is not resent and not repeated; held text from a failed send is dropped before the resend; `retries=0` sends once; the log line carries status, code, message and generation id but not the key, question, answer or Authorization header, for streamed and plain sends. `ai/tests/test_agent_profile.py`: the setting is required, refused outside 0 to 3, and reaches the admitted provider.

**Executed evidence (2026-11-23).** `pytest` in `ai/` (as CI's AI gateway job): 136 passed. `pytest apps/ai/tests -k "ai_runtime and contract" -n 0`: all passed. No paid provider call was made.
