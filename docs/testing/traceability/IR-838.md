# IR-838 — Extractor selection, provenance and a contract suite

**Affected requirement labels:** FR-M3-01 (PDF text extraction). Its matrix status does not change.

[Back to the matrix](../TRACEABILITY.md)

**Implementation:** `apps/ai/extraction/selection.py` chooses the Extractor from `EXTRACTION_BACKEND` (`docling` until IR-842) and is the only reader of it and of `DOCLING_*`; `AiConfig.ready()` refuses an unknown backend. `use_extractor(adapter)` replaces monkeypatching `documents.tasks._build_extractor`, which is deleted. `memory.py` is the in-memory Extractor. `ExtractedDocument` carries `Provenance(name, version, options)`, stored by the task on `PdfExtraction.extractor`, `extractor_version` and `extractor_options` (migration `documents/0016`, additive; existing rows stay empty) and shown only in the read-only Django admin. The legacy Docling adapter reports its name with an empty version (ADR-056).

**Contract suite:** `apps/ai/extraction/tests/contract.py` — reading order, top-left PDF-point boxes inside their page, pages numbered from 1 with sizes, one contiguous table run, `EmptyExtraction` on a blank PDF, `ExtractorUnavailable` on connect/timeout/5xx. `test_contract.py` runs it against the in-memory Extractor and shows each clause rejects a document that breaks it. Fixtures are four synthetic PDFs drawn by `tests/fixtures/layouts.py`; a test fails if a committed PDF differs from what its layout draws. IR-841 adds LlamaParse to the suite.

**Changed tests:** `test_celery_routing.py` discovered extractor tasks by the deleted `_build_extractor` name and now discovers them by `current_extractor`. `test_task_surface.py` adds `_build_extractor` to the deleted names. The task, kind, accepted-source and metadata-suggestion tests use `InMemoryExtractor` in place of their own fakes; no assertion was weakened.

**Evidence (2026-11-02, Linux `iris-backend` image, private test DB):** `pytest apps/documents apps/ai/extraction apps/ai/ingestion apps/ai/tests/test_celery_routing.py apps/records/test_metadata_suggestions.py apps/tests/test_traceability_shape.py` — 502 passed. Full suite: 5424 passed, 82 failed, 7 collection errors; the same 82 fail on the IR-831 base in the same environment (AI inference, runtime, admission and throttle tests reading the dev `.env`), and the 7 errors are `asyncpg` missing from that image. `EXTRACTION_BACKEND=nope manage.py check` refuses with `ImproperlyConfigured`. Bounded PDF intake needs Linux `RLIMIT_AS`, so the document tests do not pass on Windows. Migration `documents/0016` applied to a copy of the dev database (44 extraction rows, from `documents/0012` through IR-831's migrations): every row kept `extractor = 'docling'` with an empty version and options.

**Status:** Implemented; CI and human review pending.
