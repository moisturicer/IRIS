# IR-852 — Describe Figures for retrieval only, never shown to readers

**Affected requirement labels:** none change status. This makes Figures findable by what they show; it adds no reader-facing feature.

[Back to the matrix](../TRACEABILITY.md)

**Implementation:** ADR-056 decisions 9, 10 and 12, on top of IR-845's stored Figures.

- **Vision port.** `apps/ai/providers/vision.py` adds `ImageDescribingLLM.describe_image`, abstract like `ToolCallingLLM`. The OpenAI-compatible adapter sends the image as a data URL. Every decorator on a task's chain implements it: retry, circuit breaker, fallback, completion logging, and ADR-041 admission, which reserves the image at its encoded size.
- **Profile.** `describe_figure` gets `DataPolicy.ZERO_RETENTION`, which adds `provider.zdr = true` to OpenRouter requests. Django refuses to start if the task is configured on any other vendor. `CompositionRoot.figure_describer()` is its only caller, and returns `None` while the Profile is unset. `test_reserved_task.py` was changed deliberately: the task now has exactly one caller.
- **Describing.** `apps/ai/figure_descriptions.py:describe_figures` runs as the Celery task `describe_extraction_figures`, queued after a manuscript read that stored Figures. It describes each undescribed Figure of the current revision. The disclosure gate (`vendor_permits`) and the revision are re-read before every send. A failed send is retried by the task (three times, backing off). A refused admission stops the rest. A Figure with no stored filename is not sent. A description is written only while its Figure is still current, into `ExtractionFigure.description` (migration `documents/0021`). Any write queues a forced re-chunk.
- **Index only.** Shaping records each image item's filename on its element (`DocumentElement.figure`). When grounding omits an image's url, the name is taken from the page's image items, in order. `ingest_extraction` puts stored descriptions on matching elements, and IR-840's labeled chunker appends them to `text` and never to `content`. A description changes only its Figure chunk's `text_hash`, so only that chunk is re-embedded.
- **Superseded.** Descriptions live on the Figure row, which IR-845 deletes with its output.

**Tests:** `apps/ai/tests/test_figure_descriptions.py` (indexing seam: one description per Figure, `text` not `content`, uncaptioned kept, unset Profile, gate refusal, stale revision, a failure skipped, only Figure chunks re-embedded). `apps/ai/tests/test_figure_description_never_reaches_a_reader.py` (reader seam: a sentinel in the description is absent from the answer, its citation, the stream, search results, a transcript, an AI Overview, the Figure endpoint and the Record detail, and from every model prompt).

**Evidence:** run 2026-11-03 on a Windows 11 host, private test database `test_iris_852`, `AI_RESEARCH_LANE=off AI_JEV_ROUTING_ENABLED=False`, on top of PR #494 (IR-845, `dcd22620`).
- Full suite: 5,250 passed, 138 failed, 18 skipped.
- All 138 failures were rerun by test id on `dcd22620` without this change, and all 138 fail there too. They come from PDF intake, which refuses off Linux (IR-831), and from the dev `.env`.
- Mutation checks: with the description injection in `ingest_extraction` removed, both indexing tests that should fail do fail. With retrieval handing out `text` instead of `content`, the leak test fails.
- Migration `documents/0021` was applied only to empty test databases, not to a copy of a realistic one.

**Not verified:** no vision model was called, and no recording contains a raster figure. The grounded-image naming rule is therefore an assumption about LlamaParse's output. the request shape is unit-level only and no description quality was judged. **A citation on a Figure quotes its printed caption only, but the wire carries no link to the Figure image**; showing the image beside a citation is left to IR-293. An uncaptioned Figure that has not been described yet chunks to empty text, as IR-840 left it. Quote checks in Record comparison, briefs and `extract_evidence` still match against chunk `text`, which now includes the description. The model never sees a description, so a match is unlikely, but it is not tested. `describe_figures` opens no admission run, so it is limited only by the campaign and lane limits.

**Status:** Implemented; CI and human review pending.
