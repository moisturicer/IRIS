## IR-1191 — A thread's answer sits in its history, in date order

**Basis and scope.** IR-1191 under epic IR-920; authority ADR-032 §7 (the authors answer a reviewer's thread *Addressed* or *Declined*; answering never resolves it). No API change: the row is built from the thread's `answer` and its time.

**What changed.**
- `frontend/src/features/records/paper-view/threads/ReviewThreads.tsx`: the answer box above the replies is gone. `threadHistory` adds the current answer as one row, at `answer.at`, else the latest `answered` event's time (also the date it shows), else last; that event is not listed besides, so the answer is said once. An earlier answer, since replaced, stays as its "answered it" line. `AnswerRow` reads "<name> marked this Addressed" or "<name> declined this" ("The authors" with no name), the date, and the note, or "No answer given." It is told apart from a reply by an outlined icon in the avatar's place (a check for Addressed, a cross for Declined), its wording and a tinted row.
- The history list now spans the card in the Conversation's row shape (`review-box-replies`); the forms moved under it.
- **Departs from the AC "The thread's state badge ... is unchanged", at the owner's direction (screenshot, 2026-11-16):** the badge keeps its place and words but gains an icon (check / cross) and a dark outline once answered, and *Must fix* is filled maroon with a warning icon.
- Misc, asked for on this ticket: the guided-tour offer in `ReviewWorkspaceLayout.tsx` is one row ("New to the review workspace? A four-step tour shows where everything is.", then *Not now* and an outlined *Start tour*), wrapping when narrow.
- Unchanged: *Response to reviewers* and the New Version dialog.

**Tests.** `ReviewThreads.test.tsx`, "the authors' answer sits in the thread's history": an answer between two replies (and no second copy of its note, and no "answered it" line); a declined answer followed by a reply below it; an answer with no time dated by its event, with an earlier answer kept as a line; an answer with no note and no name. The badge is checked outside the list. Queries go through role and accessible name. `ReviewTour.test.tsx` passes unchanged.

**Runs.** 2026-11-16, locally: `npx vitest run` over `paper-view/threads/`, `ReviewTour.test.tsx` and `features/accounts`: 11 files, 155 tests passed. `tsc --noEmit` and eslint on the changed files: clean. After review fixes, `ReviewThreads`, `ReviewTimeline` and `Mentions` tests: 3 files, 49 tests passed. `npm run test:changed` (39 files) had one or three timeouts per run in untouched router and accounts tests, which pass when run alone. The whole suite runs on CI.

**Not checked.** The look was not checked in a running app; it is built to the ticket's prototype images.
