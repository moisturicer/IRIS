# IR-913: the Audit Log's filter options come from the API

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes. This removes a coupling between the backend and the Frontend CI job, and adds one read-only endpoint behind the access the log already has (ADR-051 §3).

**The problem.** `AuditLogPage.test.tsx` read `backend/apps/audit/models.py` with a regex and required every backend event type to be a filter option. A backend PR that added an event type failed the **Frontend** job until the frontend list was edited. It happened three times on 2026-11-05 (the IR-786, IR-794 and IR-797 branches).

**What changed**

- `GET /api/v1/audit/event-types/` returns every type as `{"type", "label"}`, in the order of `AuditEvent.EVENT_TYPE_CHOICES`. Not paginated. System Admin only, the same reader as the log and its export.
- The filter builds its options from that response. The frontend keeps only the *grouping* (`AUDIT_EVENT_GROUPS`): a type it groups appears under its group, a type it has never heard of appears under **Other**, and a type still grouped but no longer on the server is not offered. A stale key is therefore harmless, which is why the test no longer reads backend source.
- If the request fails, the select offers only "All events" and a note says so; the log itself still loads.
- The Event column names a type by the frontend's own wording, else the server's label, else the readable code.

**What proves it**

| Check | Where |
|---|---|
| The endpoint lists every choice with its label, in order; lists a type added to the choices with no other change; is not paginated; every listed type is accepted by the log's own filter; anonymous refused | `apps/audit/tests/test_event_types.py` |
| Only the System Admin reaches it (the other roles get 403) | `apps/tests/access/table.py` (the authorization matrix) and `apps/accounts/test_system_admin.py` |
| Known, unknown and stale types group correctly; empty groups and **Other** omitted | `frontend/src/lib/auditEventGroups.test.ts` |
| Options come from the API; an unknown type shows under **Other** and can be filtered on; a type the server dropped is not offered; a failed types request leaves the log usable with a note; an unknown event is named by the server's label | `frontend/src/features/audit/AuditLogPage.test.tsx` |

**Run, and not run (2026-11-05).** The frontend tests above passed locally (16 tests), with `tsc --noEmit` and ESLint on the touched files clean. **The backend tests were not run locally: there is no Postgres in this environment.** The Python files compile, and the backend result is CI's to report.

**Limits.** A new type shows under **Other** until someone adds it to `AUDIT_EVENT_GROUPS`. Nothing reminds anyone to. That is deliberate: the alternative is a failing build for a presentation choice.
