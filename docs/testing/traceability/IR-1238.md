## IR-1238

**Requirement:** **A conversation list that fails to load offers Try again, and every error shows once** — subtask 6 of the Ask IRIS redesign (IR-1229); no FR- id. No API change.

**Implementation:** `frontend/src/features/ai/`.
- `components/ConversationSidebar.tsx`: a failed list request shows one alert, "IRIS couldn't load your conversations. Your new questions still work.", with a Try again button that asks for the first page again. Search is disabled while the list is in error; the question box is untouched. This replaces the old "Could not load your conversations. Try again." text, which had no button.
- `hooks/useConversationHistory.ts`: records why the list failed (`search.failure`) and exposes `search.onRetry`.
- `runtime/trouble.ts`: the chat's failure classification, moved out of `RuntimeReader.tsx` and given a `kind`. Session ended (401), busy (429/503) and protocol mismatch / reload (406) are the connection-wide kinds.
- `components/RuntimeReader.tsx`: reports the chat's problem kind through `onProblem`; the "This conversation is not available." panel (404) is now an alert, so each error state is exactly one.
- `RAGChatPage.tsx`: when the chat and the list hit the same connection-wide failure, the chat says it and the list stays quiet (`search.quiet`); once the chat's problem clears, a list left in error asks again, so it is never silently stuck.
- Retry of a failed run is unchanged.

**Tests:** `RAGChatPage.listFailure.test.tsx` (page level, requests answered at the axios adapter: list error then success, a question submitted while the list is failing, one alert for each of session ended, busy (429 and 503), protocol mismatch and not available, failed-run Retry, list asking again after Reconnect; axe). `ConversationSearch.test.tsx` updated to the new wording and button. `RAGChatPage.runtime.test.tsx`'s stand-in server now answers the history list, which it used to fail unseen.

**Evidence:** `npx tsc --noEmit` clean; `npx vitest run src/features/ai` 34 files, 308 tests passed; `npm run test:changed` run before pushing; eslint on `src/features/ai` 0 errors (one pre-existing `exhaustive-deps` warning in `ConversationSidebar.tsx`). Contrast under jsdom is not checked and stays a manual check. Done requires review and approval (DEFINITION_OF_DONE §4).
