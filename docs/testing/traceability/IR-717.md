## IR-717 — Research grants and a verified reader identity

**Basis and scope.** IR-717 under IR-712; authority ADR-049 §5-7 (not yet committed to `main`). Identity prefactor only: no research-read policy switch (IR-718), no institutional writer transfer, no model call, and the existing reader routes are unchanged. Off by default (`AI_RESEARCH_GRANTS=False`).

- **Issue.** `apps/ai/grants/issue.py` signs three purposes that cannot stand in for each other: `record_read` (reader only, no Conversation or AskRun), `reader_run` (an existing AskRun owned by the reader, its Conversation and that Conversation's Record scope) and `ingestion` (one `IngestionJob` and its extraction hash; full job execution is IR-737). Claims carry identity and binding, never roles or a Record allowlist. A `reader_run` grant never outlives its run's `deadline_at`.
- **Entry point.** `POST /api/v1/ai/ask/runs/<uuid>/grant/` and `.../grant/renew/` (`apps/ai/views/grants.py`). A foreign or missing run is the same 404 and nothing is created; a client-supplied reader id is ignored; an ended run is 409 `ended`; a refused renewal is 403 `unauthorized`; grants off or not verifiable by PostgreSQL is 200 `unavailable` (no dead grant is handed out). Both routes are in the access matrix as `PRIVATE`.
- **Verification in PostgreSQL.** Migration `ai/0034` (SQL only, no model change) adds schema `iris_authz`: a key table, an HMAC-SHA256 over the built-in `sha256()` (no extension), and SECURITY DEFINER functions with `search_path = pg_catalog, pg_temp`. `verify_research_grant` checks signature, key and its retirement, audience, deployment, purpose, expiry (at most 900 s), and live facts: account active and unlocked, `credential_version` equal to the grant's generation, and the run, Conversation, scope or job still matching. `begin_research` binds a grant to the current transaction with a tag only the verifier can compute from the transaction id, so a raw or copied session setting establishes nothing; `current_reader()` re-verifies on every call.
- **Roles.** `manage.py provision_research_roles` (maintenance credentials) creates NOLOGIN `iris_authz_verifier` (owns the definer functions; reads the key table and only the columns verification needs), `iris_ai_runtime` and `iris_django_runtime` (bind and read identity only). `--check` reports problems. `manage.py install_research_grant_keys` installs keys; a non-active key verifies for at most one TTL (bounded rotation overlap), a removed key stops at once.
- **Generation.** The authorization generation is ADR-045's `User.credential_version`, so a password change or reset revokes research grants too.

**Tests.** `apps/ai/tests/test_research_grants_db.py` (8, real PostgreSQL, a throwaway LOGIN role in the restricted group): Django-issued grant establishes the reader; tampered, forged, unknown-key, wrong audience/deployment, expired, over-long, foreign run, other reader and wrong scope rejected; credential bump, cancelled run and deactivated account rejected live; no cross-purpose replay and a changed ingestion revision rejected; raw and copied session settings establish no principal; one pooled connection across commit, rollback, savepoint, failed retry and autocommit never carries a reader forward and refuses a mid-transaction switch; runtime roles cannot read keys, call internal functions, write keys, create functions, read password hashes, assume the verifier or alter tables, own no relations and carry no bypass; key rotation overlap. They skip with a stated reason when the test user lacks CREATEROLE. `test_research_grants_http.py` (5) and `test_research_grant_config.py` (11) cover the entry point and fail-closed startup.

**Not done here.** No table carries row security yet and no runtime role holds table privileges, so "no protected content crosses sessions" is shown for identity only; content protection is IR-718. Django still connects as the migration owner; moving it onto `iris_django_runtime` is a deployment change not made here. The FastAPI runtime does not yet call `begin_research`.

**Status.** Implemented; awaiting review.
