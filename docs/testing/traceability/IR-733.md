## IR-733 — Answer from full Manuscripts with honest reading coverage

**Basis and scope.** IR-733 under IR-715 (under IR-146). Authority: ADR-049 §9 and §17 and the accepted parent specification (ADR-049 is not yet on `main`, so no ADR in the tree backs this change yet). No FR-/NFR- id is affected. It covers IR-715 user stories 1, 2, 3, 4, 5, 6 and 9 as specified implementation work; that is not evidence the stories are done. It covers complete-document reading and coverage in the AGENT. There is no new extractor, and the whole corpus is never loaded by default. Compaction and recovery after eviction stay with IR-734/IR-736.

**Code.**
- **Tool** (`ai/research/tools.py`).
  - `ResearchTools.read_manuscript(paper, after=None, *, max_bytes)` reads the paper handle's active Manuscript in document order, under the run's grant (the row policy decides what is readable).
    - It starts at the beginning or just after `after`, a passage handle from an earlier read.
    - It returns as many passages as `max_bytes` holds. A passage costs its shown text JSON-encoded twice (once in the tool result, once as message content) plus a 200-byte frame allowance. The coverage block is charged up front: 800 bytes plus 8 per listed page.
    - What did not fit is reported as missing spans, never clipped.
  - **Cursor binding.** A cursor from another paper or revision is refused as `foreign_continuation`. A replaced source is refused as `source_replaced`. A cursor from another run, or a paper the reader can no longer read, is refused as `unknown_handle`.
  - **Overlap.** When a passage starts by repeating at least 24 characters of the previous passage's end, `PassageRef.overlap` records how many. Only the remainder is shown, but the passage, its handle, page and revision keep the whole text.
  - **What `Reading` reports.**
    - The passage count, the covered and missing spans with their pages, and the reported page count.
    - Pages no passage starts on. Such a page either had no text extracted or holds a passage continued from an earlier page; it is never claimed as either.
    - Formula and caption passages: their visual content is not interpreted.
    - The repeated characters omitted, the paper's title, and `continue_after`.
  - **Limits.** A Manuscript over 10,000 passages is refused (`manuscript_too_long`), not cut short.
  - **Journal.** The run journal gets the read's numbers and source revision, never its text.
- **Schema** (`ai/runs/migrations/0014_manuscript_read.sql`). Two invoker-rights functions for `iris_ai_runtime`, reading either an indexed revision (`index_job` payload) or Django's active chunk set, like `research_chunks()`:
  - `iris_ai.research_manuscript(chunk_set)` returns passages with their `element_kinds`.
  - `iris_ai.research_manuscript_pages(chunk_set)` returns the page count from the extraction's `page_sizes`.
  - Additive: no table or grant changes.
- **Agent** (`ai/agent/tools.py`, `ai/agent/executor.py`, `ai/runs/agent_profile.py`).
  - **Pin.** New pin pair `agent-research-3`/`research-3` offers `read_manuscript(paper, continue_after?)` beside every research-2 tool. `research-1`/`research-2` runs keep their exact tool sets, and the profile now pins `research-3`. The model cannot set the size, a start position or a byte limit: undeclared arguments are refused.
  - **Read size.** The executor sizes each read (`AgentExecutor.room`) to what is left after:
    - every reserve in the verified capacity (IR-732);
    - one more gathering exchange, plus the closing note;
    - a final answer and one repair, still within the run allowance (IR-728).
    
    10% more is kept back as a margin. Several reads in one group share the room.
  - **Tracking.** `Investigation.reads` keeps, per revision, the passages a tool returned (inspected), those the model was shown (visible), and those withheld by packing but reopenable by handle (recoverable). Packing tells the investigation which results it withheld.
  - **Behaviour change, every pin.** A gathering step that would leave no room to close and answer now closes research. A window already full (`context_exhausted`/`request_bytes_exceeded` at estimate) does the same instead of failing the run. Before this, a run near the edge failed in `pack`. A question too large for the window still ends `context_exhausted`.
- **Facts** (`ai/agent/assurance.py`, `ai/runs/store.py`). A delivered answer keeps one `reading_coverage` fact per cited revision the run read. It holds the title, passages, read, complete, pages, `pages_no_passage_starts_on`, formula and caption passages, `visual_interpretation: false` and `exhaustive: false`. Reopen and the `runs-reader-1` projection show it through `shown_facts`, with no Record ids. Reading one paper never licenses a completeness claim: the existing `completeness_overclaim` check still applies.

**Demonstration.** `test_the_agent_answers_from_the_middle_and_end_of_two_long_papers_then_reads_on_through_a_small_window` runs the real `AgentExecutor` (recording provider) through the routes:
1. Two synthetic 30-passage papers have a fact planted in the middle (page 5) and at the end (page 10). The agent resolves both, reads both whole, and cites all four. Reopened, each citation carries its Record, page, exact quote and the active revision. Each paper has a complete `reading_coverage` fact.
2. A third paper has an overlapping chunk pair and a page-11 gap. It is read through a 26,500-token fixture window in more than one stretch, each `continue_after` the previous, with nothing withheld.
   - The overlap is shown once.
   - The page with no passage is reported.
   - The reopened answer cites the closing passage at page 10, and its fact says complete with one page no passage starts on.

**Merge with IR-724 (2026-11-04).** IR-724 renamed `Investigation.results` to `reads: int` (the count of evidence reads), while this change had added `reads: dict` (Manuscript coverage). Git merged them without a conflict into one class where the dict silently replaced the count. Fixes:
- The coverage field is now `Investigation.readings`.
- IR-724's checkpoint (`ai/agent/checkpoint.py`) saves and restores `readings` and each passage's `overlap`, so a resumed run reports the same coverage and shows overlap once. A checkpoint without `readings` restores none.

**Review (2026-11-04).** A two-axis review (standards, spec) before commit led to these fixes:
- read cost now counts double JSON escaping and the coverage block;
- the "pages without text" claim is renamed and reworded, because a passage can run onto a later page;
- a non-object tool result no longer raises in `packed`;
- the Django branch of `research_manuscript_pages` checks the active source itself;
- a mid-run revocation test was added;
- a mid-run ORM write in a test now runs in a thread.

Left as recorded:
- `Reading.missing` is relative to one read; `read_so_far` is the union.
- The gather-loop change applies to every pin, not only `research-3`.
- One `Reading` is serialized in three places (journal, model body, fact).

**Not done here.**
- No compaction or eviction (IR-734, IR-736). Text read stays in the Conversation, so a paper larger than the window is read in part and says so. Recoverable content is tracked but re-reading after eviction is not built.
- Overlap detection is exact suffix/prefix matching of at least 24 characters. Near-duplicates and repeated table headers are kept.
- "Figures" are inferred from caption passages; the runtime has no figure records (IR-845's are Django-side). Formula and caption counts are whole-document, not per read.
- `PASSAGE_FRAME_BYTES` (200), `READING_FRAME_BYTES` (800), `MIN_OVERLAP_CHARS` (24), `MANUSCRIPT_PASSAGES` (10,000) and `ESCAPE_SHARE` (0.9) are untuned engineering defaults, not approved values.
- Nothing routes reader traffic to the AGENT, the reader UI does not render `facts`, no live provider call has been made, and no profile value is approved.
