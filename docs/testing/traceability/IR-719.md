## IR-719 — Find and read permitted Passages through local research tools

**Basis and scope.** IR-719 under IR-712; authority ADR-049 §5, §6, §9. Local, read-only research tools in the AI runtime, under the shared row policy. Keyword search only; exact counts (IR-750), context-sized full reads (IR-733) and disclosure fencing (IR-720) are not here.

- **Grant.** `reader_session` now reads what its reader may: migration `ai/0037` (SQL only, built from `0035`/`0036` so only the changed clauses differ) lets `research_record_ids()` serve the purpose and lets the grant carry an optional `rec`, a Paper Chat scope the policy applies. `POST /api/v1/ai/runtime/grant/` takes an optional positive integer `record_id` (else 400); it is not checked at issue, since an unreadable scope reads nothing, the same as a missing one. This replaces IR-722's "reads no Record". The owner chose this over a run-bound purpose on 2026-11-01; like IR-722's choice it departs from ADR-049 §6's run binding, and the amendment recording both is still to be written.
- **Tools** (`ai/research/tools.py`, `ResearchTools`): `search` (keyword; any query term matches; ranked by `ts_rank`), `open_passage`, `read_page`, `outline` (Django's `read_papers` section ids) and `semantic_search`, which is declared with `provider_operations = ("embed_query", "rerank")` and always answers `unavailable`/`provider_gated`. Each call is one transaction under the run's grant (`begin_research`) as `iris_ai_runtime`; the run row is held `FOR SHARE` to commit, and the call is refused `run_ended` once the run is stopped, its fence moves, or the grant is another reader's. A malformed `page` or `limit` is `invalid_argument`. Results carry `ok`/`no_match`/`partial`/`unavailable` with a reason code, Record and Passage references bound to a `Source` (Record, chunk set, extraction hash; `revision` = `<chunk set>:<hash>`) and page, coverage (`returned`, `total`, `truncated`, `inspected_records`) and their source dependencies. Each call is journalled as `tool` with its name, status, coverage and source revisions; never content. No tool calls a model.
- **Handles** (`iris_ai.research_handle`, `ai/runs/migrations/0002_research.sql`): random, bound to one run, expiring at its deadline and to the source they were read from. Unknown, forged, foreign, expired and now-unreadable handles are one `unknown_handle`; a replaced source is `source_replaced`, never resolved to the new revision. Deleting a Conversation removes its handles.
- **Scope.** A Conversation keeps the scope it began with (`conversation.scope_record_id`); a follow-up under another scope is `409 scope_mismatch`, and a scoped grant cannot reopen, inspect, stop or delete the reader's other Conversations (the same 404). Tools filter by it as well as the policy.
- **Citations** gain `revision`; the executor receives the tools (`answer(question, tools)`); the pinned schema is `0002_research.sql`.

**Tests.** `apps/ai/tests/test_ai_runtime_research_db.py` (10, real PostgreSQL, a throwaway login in `iris_ai_runtime`, Django-issued grants, a scripted executor through `POST /api/v1/ai/runs`): find a paper, open its Passage, read its page and outline, all bound to the active chunk set, with the citation's revision reopened; journal entries are names and codes; a bounded page is `partial`; another reader's draft and handles disclose nothing (`no_match`, `unknown_handle`, zero inspected); a handle fails in a second run and after expiry; Paper Chat search stays on its Record and a follow-up cannot drop the scope; a replaced source invalidates read handles while a fresh search reads the new revision; Stop refuses the next call; another reader's grant cannot use the run's tools; a Paper Chat grant cannot reopen or inspect another Conversation; outbound connections are captured (`BaseEventLoop.create_connection`) and all go to PostgreSQL, with any HTTP send failing the test. `test_reader_session_grant_http.py` deliberately replaces "reads no record" with three tests: the reader's readable set, a scoped grant's one Record (or nothing), and malformed scopes refused. `test_ai_runtime_runs_db.py`'s citation and pinned-schema assertions now include `revision` and `0002_research.sql`.

**Migration evidence.** On a copy of the dev database (62 Records, 16 accounts), 2026-11-01: `ai/0034`-`0037` applied, `0037` reversed and re-applied; functions still owned by `iris_authz_verifier`; `provision_research_roles --check` ok; `ai.runs.migrate` applied `0001_runs.sql` and `0002_research.sql`, then nothing; `iris_ai_runtime` may write handles and `iris_django_runtime` may not read them. The copy was dropped.

**Found, not fixed.** Django's `FullTextRetriever` keeps `rank > 0`, but `ts_rank` scores a non-matching passage `1e-20`, so it admits passages holding none of the query's terms (checked on PostgreSQL). The runtime tool matches with `@@` on an OR'd query instead.

**Not done here.** Embedding and reranking are not wired. `commit_final` does not check that a citation came from a handle of the run or a still-active revision, and reopen does not recheck a cited Record's visibility: both matter once a model executor exists (IR-728) and for revocation (IR-720). Nothing routes browsers to these routes and the reader UI does not call them. The grant must outlive the inline run (at most 900 s); renewal is not built. No capacity is measured.

**Status.** Implemented; awaiting review.
