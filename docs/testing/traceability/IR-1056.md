**Implementation:**
- `apps/ai/providers/batching.py`:
  - `window_for_embedding(..., section_keys=...)` ends a window that cannot hold the rest of the paper at the last top-level section break that still fits. When no break fits, or no chunk has a usable key, it cuts by count as before. A paper that fits in one window is unchanged.
  - `top_level_sections` names each chunk's top-level section: the first heading below what every keyed chunk shares (usually the title). Front matter under the title alone is its own section. A missing key is unknown and never forms a break.
- `apps/ai/indexing.py`: `embedding_windows(chunks, mode)` is the one place a caller picks the mode. `embed_active_chunk_set` uses it with the production mode.
- `AI_SECTION_ALIGNED_WINDOWS` (default **False**). Turning it on recomputes no stored vector. Re-embed with `backfill_embeddings --force` afterwards.
- `apps/ai/trials.py`:
  - a new variant option, `windows=count|section`. When it is unset the variant follows production;
  - the mode is recorded in the trial set's options, so it appears in `provenance.chunking`;
  - in a paper longer than one window, the same text gets a different vector under another windowing. Such a paper reuses only vectors from sets embedded the same way: active sets under the production mode, trial sets by their recorded mode, and pre-IR-1056 trial sets as count. A shorter paper reuses vectors whatever the mode.

**Test:**
- `apps/ai/providers/tests/test_section_windows.py` (no database) covers:
  - section labels with and without a title, front matter, missing keys, list-shaped stored keys, and a single-chapter paper;
  - the cut moving back to the last fitting break, the nearest break winning, and a break exactly at the limit;
  - the count fallback for an oversized section and when there are no usable keys;
  - an unkeyed neighbour forming no break;
  - an oversized chunk going alone;
  - a mismatched key count being refused;
  - a Hypothesis property: order kept, the budget held, and no section split while a break fit.
- `apps/ai/tests/test_section_aligned_embedding.py` (Postgres) covers:
  - indexing cuts by count with the setting off and at the section break with it on;
  - `windows` option parsing, and the default following production;
  - a section variant re-embeds a long paper rather than reusing count vectors;
  - a count variant still reuses the active vectors and never reuses a section variant's vectors;
  - a short paper reuses vectors in either mode;
  - provenance records the mode.

**Known limits:**
- Inside a top-level section longer than a window, the cut is by count. Subsection breaks are not preferred.
- The cut is greedy, one window at a time. It does not search for the global arrangement with the fewest split sections.
- A variant with no `windows` option resolves its mode from the setting at build time. A rebuild under another mode replaces the stored set.
- An incremental re-embed (no `force`) windows only the pending chunks, so the section labels come from that subset. Count mode has the same limit.
- Flipping the setting does not recompute active vectors. Until `backfill_embeddings --force` runs, a trial in the new mode would reuse the old active vectors as if they matched.
