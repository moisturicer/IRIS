## IR-380

**Requirement:** **The AI Summary runs as its own Inference task** — no FR- id; part F of IR-375's spec, and the first caller to move off `answer`'s model

**Design:** [ADR-036 §Amendment](../../adr/036-openai-compatible-inference-provider.md) (vendor and model chosen **per Inference task**, no silent fall-through to a default)

**Implementation:** `apps/ai/overview.py` — `_generate` asks for `answer_service(task=InferenceTask.SUMMARY)`, so a Record page's AI Summary reaches the `summary` Profile's model instead of the answer path's · `apps/ai/composition.py` — `answer_service()` takes `task` as a **call-time** argument, the same shape `record` already had, defaulting to `ANSWER` so every earlier caller keeps its model · `apps/ai/inference/providers.py` — a Profile whose Reasoning is hidden builds its adapters with `reasoning_effort=""`, which is "send no reasoning configuration", distinct from `None`, which inherits `LLM_REASONING_EFFORT` · `apps/ai/resilience/llm.py` — `LLMProviderConfig.reasoning_effort` carries it to the adapter · `apps/ai/providers/openai_compatible.py` — the resolution rule is extracted to `_resolved_reasoning_effort()` so both the `""` and the inherited case are assertable. **Wider than this ticket's own scope, named rather than left to be discovered:** `Profile.reasoning_visible` was resolved but consumed nowhere before this change, so every task built through `build_profile_llm` inherited `LLM_REASONING_EFFORT` whatever its own `_REASONING` setting said. The suppression is therefore a shared mechanism, not a `summary` special case — inert for `answer` (`reasoning_visible` is True, so it still inherits) and for `resolve`/`describe_figure` (no caller yet), and IR-381 is where visible Reasoning consumes the same field. **Caching and the wire are untouched**: one `RecordOverview` row per active `ChunkSet`, invalidated by a re-chunk or a `PROMPT_VERSION` bump, still deliberately distinct from the author's Abstract, no UI copy change. **A deployment-visible consequence, recorded rather than smoothed over:** `summary` inherits nothing (`_INHERITED_KEYS` names `answer` alone), so an upgraded deployment that sets no `LLM_SUMMARY_MODEL` gets `state: "unavailable"` on the overview and **no vendor call**, where it previously borrowed `LLM_MODEL`. That is the ticket's "stops borrowing the answer path's model" read literally and ADR-036's no-silent-fall-through rule applied; the unconfigured case is handled as the outage case already was — logged, never stored, retried on the next view — and `.env.example` says so at the `LLM_SUMMARY_*` block

**Test:** `apps/ai/tests/test_overview_http.py::SummaryRunsAsItsOwnInferenceTaskTests` (3, HTTP boundary with a real Profile resolution and only the adapter build replaced: the overview reaches `summary-model` while `answer-model` is configured and unused; the request carries `reasoning_effort == ""` even with `LLM_REASONING_EFFORT=high` set; an unconfigured `summary` reports `unavailable`, builds no provider and stores no row **while `answer` is configured and would have answered**) · `apps/ai/inference/tests/test_profiles.py` (+3 — hidden Reasoning sends nothing, shown Reasoning keeps the inherited effort, `summary` and `answer` build on their own models) · the 8 pre-existing `test_overview_http.py` cases unchanged, which is the "existing AI Summary tests pass unchanged" criterion

**Evidence:** `apps/ai/tests/test_overview_http.py apps/ai/inference/` → **31 passed**. Full backend suite **1791 passed, 2 skipped, 1 xfailed, 0 failed** (2026-09-28). The two `test_llm_contracts.py` failures IR-378 and IR-393 recorded as environmental were confirmed to be exactly that and are gone from this run: they read the developer's own `backend/.env` (`LLM_TEMPERATURE=1`, `LLM_REASONING_EFFORT=high`), and the suite is green with the documented defaults supplied — worth stating because this change touches the reasoning-effort path those two assert on. **Red first:** with the task switched back to `ANSWER`, the two model/reasoning cases fail; the unconfigured case fails once `answer` is given a provider that would have answered

**Status:** **IMPLEMENTED** — `summary` is wired, independently configurable and reasoning-free. `resolve` still has two live namespaces (the contradiction recorded on IR-378) and `describe_figure` is still reserved; deleting `llm()` is IR-388
