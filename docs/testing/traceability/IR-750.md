## IR-750 — Resolve selected Records and answer exact metadata counts

**Basis and scope.** IR-750 under IR-712; authority ADR-049 §5, §9, §15 (not yet on `main`, so no ADR in the tree backs this change yet) and the accepted parent specification. Requirements affected: no FR-/NFR- id; IR-712 user stories 6, 7, 8, 9, 14, 16 and 20. Split from IR-719: deterministic resolve and count tools and their reader integration in the AI runtime. Search and read stay IR-719's, and general agent execution stays IR-728's. Django's own `resolve_papers`/`aggregate_records` (IR-591) are untouched; the runtime ports their title tiers and filters because it cannot import Django.

**Code.**
- **Tools** (`ai/research/tools.py`, `ai/research/metadata.py`).
  - `ResearchTools.resolve(references, record_ids)` names papers by title (exact, then short title, then phrase, as Django's `title_matches`) or by Record id. It reads `records_record` under the run's grant, so the row policy decides what can be named. A reference matching several papers is `ambiguous`, with up to 5 candidates and a `truncated` coverage flag, never a silent choice. A Record the reader may not read is the same `none` as one that does not exist.
  - Each named paper gets a fresh run-bound `R` handle. A paper with no Manuscript read yet can still be named: its handle carries no source, and `read_page`/`outline` answer `no_match` (`iris_ai` migration `0012_metadata.sql` makes `research_handle.chunk_set_id` nullable for `R` handles only).
  - `ResearchTools.count(filters, group_by)` returns a typed `Count`: total, applied filters (Area/classification, PSCED, record type by catalogue name, case-insensitive; `year_from`/`year_to` on `year_completed`; `is_ip`), groups, ungrouped, Paper Chat scope, `relative_to` and the counted Record ids as private provenance. On every call it fetches the matching rows of `records_record` under the row policy and counts them exactly, so the population is each reader's own and a Paper Chat grant's `rec` confines it in PostgreSQL. Deleted Records are left to the policy, the one visibility predicate. There is no topic filter.
  - An Area no readable paper is in is an exact `no_match` with total 0. A catalogue name that does not exist is `unavailable`/`unknown_filter_value`, and one that matches entries differing only by case is `ambiguous_filter_value`, never a guess. Taxonomy names are global catalogue vocabulary, as in Django's `apply_filters`.
- **Grants.** `0012_metadata.sql` and `provision_research_roles` (`RUNTIME_METADATA_TABLES`, so `--check` reports a missing grant) give `iris_ai_runtime` SELECT on `records_classification`, `records_pscedclassification` and `records_recordtype`: names only, no Record. `iris_django_runtime` gets nothing new.
- **Agent** (`ai/agent/tools.py`, `ai/agent/executor.py`).
  - New pin pair `agent-research-2`/`research-2` offers `resolve_papers` and `count_records`. `agent-research-1`/`research-1` runs keep their exact tool set and instructions. `ai/runs/agent_profile.py` now pins new AGENT runs to the new pair.
  - Undeclared arguments (a scope, a reader, a record id, a topic) are refused as before.
  - The model receives the count as `{"kind": "exact_count", total, filters, group_by, groups, ungrouped, scope, relative_to}`, never the counted ids. No screening or brief writer runs behind either tool.
- **Assurance** (`ai/agent/assurance.py`).
  - A count's figures (total, groups, ungrouped) are supported numbers, and its taxonomy names may be quoted like titles.
  - A completeness phrase passes only in a sentence that states an exact count's **total**. A group's size or the ungrouped remainder never does, and a keyword-search number stated as a total is still `completeness_overclaim`.
  - Just before delivery, every count the answer states (its total or a group's size, latest count per question) is recomputed under current policy. A changed total or population ends the run `unavailable`/`source_changed`, exactly as a replaced passage does.
  - A run that only counted is now checked for numbers and titles too. Before this, the checks skipped any run with no passages or papers.
- **Facts** (`Result.facts`, `iris_ai.turn.facts`).
  - A delivered answer keeps an `exact_count` fact (with its population) only for the latest count per question whose total or group size it states, and a `keyword_sample` fact (`exhaustive: false`, cited papers) when it cites searched passages.
  - Reopen and the `runs-reader-1` projection show both kinds through one allowlist (`store.shown_facts`) without Record ids.
  - A Turn whose counted Records are not all still readable is withheld on reopen, the same way as a replaced source, and is kept out of later Turns' history. The run's own `sources_available` agrees (`COUNTED_UNREADABLE`, shared by both).

**Demonstration.** `test_two_readers_name_a_paper_count_an_area_and_get_a_sample_each_from_their_own_population` runs the real `AgentExecutor` (recording provider) through the routes for two readers, three Turns each:
1. "Which paper is this? Flood forecasting" is answered «Flood forecasting» via `resolve_papers`.
2. "How many Hydrology papers are there?" is answered from `count_records`. Each answer and its reopened `exact_count` equal `Record.objects.visible_to(reader)` over that Area, computed independently in Django: 2 for the other reader, 3 for the owner of a draft.
3. "Which of them study floods?" is answered from a keyword search, cited, and reopened as a `keyword_sample` with `exhaustive: false`. Its cited papers are a subset of what that reader may read: the draft is cited only for its owner.

**Not done here.**
- ADR-027's landscape floors (`corpus_facets`' minimum sample and unclassified share) are not ported: grouping by Area is the facet, with no floor.
- No `ai_readable` figure: the runtime has no disclosure decision yet (IR-720's guard withholds Record evidence from paid providers).
- The completeness rule is lexical. A keyword number that happens to equal an exact count's total in the same sentence would pass.
- **Acceptance criterion 3 and the demonstration are only partly met.** There is no semantic screening tool in the runtime, so the "semantic subset" here is the keyword sample, labelled `keyword_sample`/`exhaustive: false`. A classified-subset label for a real screener waits on that tool.
- A stored population grows with the reader's readable catalogue, and its ids stay in `iris_ai.turn.facts` after access is lost (they are never shown); no bound is chosen.
- `count` and `resolve` read every matching readable row per call; fine at today's catalogue size, unmeasured beyond it.
- Making `research_handle.chunk_set_id` nullable, so a paper with no Manuscript can be named, is a schema widening beyond the ticket's text.
- Nothing routes reader traffic to these routes, and the reader UI does not show `facts` yet. No live provider call has been made, and no profile value is approved.
- ADR-049 itself is not on `main`.

**Status.** Implemented; awaiting review.
