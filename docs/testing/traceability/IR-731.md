## IR-731 — Keep supported findings when a research tool fails

**Basis and scope.** IR-731 under IR-714; authority ADR-049 §15–16 (not yet on `main`) and the accepted parent specification. No FR-/NFR- id. Owns partial-outage behaviour in the AGENT loop. Long-context scenarios stay with IR-736 and human-reviewed quality with IR-755.

**The defect it fixes.** Before this change, an exception raised inside a research tool (a dropped connection, a timeout) escaped the loop. `RunService.execute` then ended the whole run `executor_failed`, and every finding already read was lost.

**Code.**
- **Containment** (`ai/agent/tools.py`). `Investigation.execute` turns an outage into `{"status": "unavailable", "reason": "tool_unavailable"}` for the model. An outage is an exception in `OUTAGES`: `OSError`, `asyncio.TimeoutError`, `asyncpg.PostgresError` and `asyncpg.InterfaceError`. The tool is recorded in `Investigation.outages`, and only the exception class is logged. The exchange stays whole: every call in a parallel group is still answered, in order.
  - A permission refusal (`asyncpg.InsufficientPrivilegeError`) ends the run `unauthorized`, as `unauthorized` and `run_ended` results already did.
  - Any other exception is a bug, not an outage, and still fails the run.
- **Four kinds of "nothing", told apart.** An outage is `unavailable`/`tool_unavailable`. A paper that can be named but has no Manuscript read is `no_match`/`no_manuscript` from `read_page` and `outline` (`ai/research/tools.py`, `NO_MANUSCRIPT`). Before this, it was a bare `no_match`. A search with no hits is a bare `no_match`. A paper missing a metadata value is a count's `ungrouped`, as in IR-750. Insufficient evidence is left to the model to say, and the checks below keep it honest.
- **Checks** (`ai/agent/assurance.py`).
  - A run whose only research failed is still checked; before this, the checks skipped any run with no evidence.
  - A new rule, `outage_absence`, applies once any tool failed. A sentence saying nothing matched ("no … papers/records/studies/matches/results", "zero …", "none", "nothing") fails unless it states an exact count's zero total. An outage therefore never becomes a zero count. "No more/fewer/less than" is not an absence. A clarification is exempt: it asks a question and claims nothing.
  - "Complete", "comprehensive" or "exhaustive (literature) search" and "searched all/every" are now completeness overclaims for every run. The negated hedge "not a complete search", which the limitation itself uses, is not.
  - Exact counts that succeeded still state their totals, and every IR-728/729/750 check still applies, the one repair included.
- **The limitation** (`ai/agent/executor.py`). A delivered answer after an outage ends with a fixed line, `assurance.outage_limitation()`. It names the failed steps in plain words ("reading a page", "counting records") and says the answer is not a complete search. The application adds it after the checks, so the model cannot drop it. It is part of the Turn's text, so live delivery, reopen and the `runs-reader-1` projection show the same thing. A salvaged answer carries both the IR-729 limitation and this one.
- **Recheck.** An outage while rechecking cited sources before commit ends the run `unavailable` (`tool_unavailable`) instead of crashing. A source that cannot be reached is not vouched for.

**Tests.**
- `apps/ai/tests/test_ai_runtime_partial_outage_contract.py` (20, no database, recording provider). It covers:
  - a failed read after a search, with the cited finding kept and the limitation added;
  - a failed count stated four ways as zero or none, each sent back for repair and never delivered, with no `exact_count` fact;
  - a parallel group mixing an outage, a `no_manuscript` read, a no-match search, a count with an ungrouped paper and malformed arguments. Each result is distinct and answered in call order, in three different orders;
  - an invented completion year refused;
  - three phrasings of a complete search refused;
  - a successful exact total still stated beside an outage;
  - a failing repair salvaged with both limitations;
  - a recheck outage ending `tool_unavailable`;
  - `unauthorized` still ending the run;
  - a clarification containing "none" still asked after an outage;
  - the "not a complete search" hedge passing;
  - a permission refusal ending `unauthorized`;
  - a `KeyError` propagating rather than being called an outage.
- `apps/ai/tests/test_ai_runtime_partial_outage_db.py` (2, real PostgreSQL, restricted runtime login, Django-issued grants, through `POST /api/v1/ai/runs`). The second paper's page read raises `asyncpg.ConnectionDoesNotExistError`. The tests check that:
  - the cited partial answer is identical live, reopened and under `runs-reader-1`, with its citation on the right Record and page;
  - no reason or validation code reaches any reader body;
  - a follow-up in the same Conversation sees only the cited paper as shown;
  - a draft that turns the outage into "No pond studies…" is repaired before anything is saved.
- **Deliberately changed:** `test_ai_runtime_metadata_db.py::test_a_paper_with_no_manuscript_is_named_but_has_nothing_to_read` now also expects the `no_manuscript` reason.

**Demonstration.** `test_two_papers_compared_with_one_read_failing_keep_the_cited_finding_everywhere` is the ticket's demonstration. Two permitted papers are compared, a later read fails for one of them, and the result is a cited partial answer with an accurate limitation that is the same after reopening.

**Evidence (2026-11-04).** From `backend/` with a local venv and throwaway settings values:
- `python -m pytest -n 0` over the six AI-runtime contract suites (partial outage, agent loop, metadata, context, agent, OpenAI agent): 184 passed.
- `python -m pytest -c ai/pytest.ini ai/tests`, without `test_embedding_provider_contract.py`: 67 passed. That file was not run because the borrowed venv lacks `pytest-asyncio`; it is untouched here.
- `flake8` on the changed files: clean.
- A two-axis review (standards, spec) found five problems, all fixed and tested above:
  - a clarification after an outage could end the run;
  - the limitation's own wording tripped the completeness rule;
  - `except Exception` hid local bugs and permission refusals;
  - the sentence loop was duplicated;
  - one name was unclear.
- The DB suite was collected (2 tests) but **not run locally**: this machine has no IRIS PostgreSQL. CI is the gate.
- The first CI run (PR #524) failed 2 of 1,549 tests in shard 4, both test defects.
  - The absence DB test searched "floods", which names only one paper, so its script's lookup of the pond paper raised inside the recording provider. The run then ended `executor_failed`.
  - The new DB module was missing from `testing/parallel.py`'s `ROLE_MODULES`, which `apps/tests/test_parallel.py` requires. The demonstration test passed on that run.

**Not done here.**
- **AC 5 is not met.** The deterministic contract results are not exported as an evaluation artifact labelled "contract evidence". No existing evaluation format for contract runs was found to extend, and inventing one needs a decision.
- **AC 4 is only partly met.** A01–A15 are not each exercised as a core-task case here. What is covered:
  - A09, end to end;
  - parts of A01 (comparison), A02 (shown order), A10 (repair) and A13 (no diagnostics);
  - IR-728/729/750's existing suites.

  No "replayed" or "exported" projection is tested. The runtime has no export route: `ai/runs/public.py` says export shares the reopen projection, which is what is tested.
- **AC 3 is partly met through saved Conversations.** Malformed calls and parallel groups with an outage run in the contract suite. Through the routes, only a parallel read group is exercised. Clarification under an outage has no new test; IR-728's clarification tests are unchanged.
- The absence rule is lexical. A phrasing such as "the pond paper reports no methods" is not caught. A true no-match from a different, working tool is refused too while any outage occurred, unless an exact zero count backs it.
- **A recheck outage throws away every finding.** It ends the whole run, including findings whose own sources were reachable. Salvaging around one unreachable source is not built.
- Only a raised outage counts. A tool that *returns* `unavailable` (`source_replaced`, `unknown_handle`, `invalid_argument`) is the model's to explain and adds no limitation line. `semantic_search`'s `provider_gated` is not offered to the AGENT.
- The DB test compares the plain and `runs-reader-1` reopens with each other and with the expected text; the submit response body is not compared with them.
- The ADR-049 sections cited as the basis are not on `main`, so a reviewer cannot check them there.
- An outage in `update_plan`'s journal write is contained like any tool failure; it is not distinguished from a research outage.
- Nothing routes reader traffic to the runtime by default, and no live provider call has been made.

**Status.** Implemented; awaiting review.
