## IR-1019 — Embargo reminders and retention cleanup run at the Manila hours they name

**Basis and scope.** A bug found in IR-705's code review (PR #680). It corrects when two scheduled jobs run: ADR-052 §9's embargo reminders (IR-814) and ADR-051 decision 19's retention cleanup (IR-794). What either job does is unchanged. No FR- id.

**What was wrong.**
- Both `CELERY_BEAT_SCHEDULE` entries converted Manila to UTC by hand, with the comment "Celery runs on UTC here".
- But Celery is configured from Django settings and takes `TIME_ZONE = "Asia/Manila"`. Importing `config.celery.app` reports `Asia/Manila`.
- So `embargo-reminders` (`crontab(hour=0)`) ran at 00:00 Manila instead of 08:00. `retention-cleanup` (`crontab(hour=19)`) ran at 19:00 Manila instead of 03:00, erasing personal data in the evening rather than overnight.
- Both entries' tests asserted those hours under the same mistaken comment.

**What exists now.**
- `embargo-reminders` runs at `crontab(hour=8)` and `retention-cleanup` at `crontab(hour=3)`.
- `CELERY_TIMEZONE = TIME_ZONE` is set explicitly, so the beat hours can't move with a change to either one.
- The schedule's header comment says every hour is Manila's.
- `production.py`, `celery.py` and the Compose files set no other time zone, so production uses the same one.

**Tests.**
- `apps/audit/tests/test_retention.py::ScheduleTests::test_beat_runs_it_daily_at_3_in_manila` and `apps/records/test_embargo_reminders.py::ScheduleTests::test_beat_runs_it_daily_at_8_in_manila` were **changed deliberately**. They asserted the wrong hours (`{19}`, `{0}`). They now assert `{3}` and `{8}`, together with `app.timezone == "Asia/Manila"`.
- `apps/tests/test_settings_validation.py::test_celery_keeps_djangos_time_zone_explicitly` checks that `base.py` names `CELERY_TIMEZONE = TIME_ZONE`.

**Verification.**
- Run locally on 2026-11-11 against PostgreSQL in Docker: `test_retention.py`, `test_embargo_reminders.py`, `test_settings_validation.py`, IR-705's `ExpiryTests` and `test_reminders.py` all passed. flake8 is clean.
- **The deployed server's time zone has not been checked yet.** This ticket requires it. Whoever has access runs this on the server and records the output on the PR:
  `docker compose -f docker-compose.prod.yml exec celery-beat python -c "from config.celery import app; print(app.timezone)"`
  It should print `Asia/Manila`.
