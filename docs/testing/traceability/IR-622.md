## IR-622 — My Reviews sorts and filters by due date, and shows overdue plainly

**Authority.** [ADR-043 §§1–6](../../adr/043-review-turnaround-reminders-and-escalation.md) (Manila working days, holidays excluded). IR-374's [redesign spec](../../frontend_redesign_spec.md) story 72 (the view kept in the URL, so back and bookmarks work), which this extends to sort and filter. [ui-ux/16 §5](../../ui-ux/16-paper-view-and-review.md) is updated to match.

**Implemented.** Every My Reviews row carries the deadline fields; a review row with no seat carries the empty payload, and a done seat is never overdue, even on an assignment still active for a colleague. The rows also carry `overdue_days`: Manila working days late, counted by the server because the browser cannot know the holiday table. `GET /reviews/mine/` takes `sort=due|waiting` (soonest due by default, undated rows last) and `overdue=1` on To review and In review. Done refuses both with 400, and `overdue` never narrows the counts. The page keeps both in the URL, shows *Due Fri 7 Nov* formatted in Asia/Manila and says overdue in words (*2 working days overdue*, or *Overdue* before a working day has been missed), with the badge's colour only repeating the text. No client code computes a date. Details: [deadline contract](../ASSIGNMENT_DEADLINES.md#my-reviews-ir-622).

**Evidence (2026-10-29).** The tests are `test_my_reviews.py::DueDateTests` (REST seam: the working-day count across a weekend and a holiday, both sorts, the overdue filter and its counts, a finished seat beside an open one, the 400s), `myReviews.test.ts` and `MyReviewsPage.test.tsx` (accessible tree and axe). Results:
- Against PostgreSQL, `pytest apps/reviews apps/tests apps/audit`: **554 passed, 11 skipped, 0 failed**. pytest's summary line did not print through the container stream, so this was counted from its progress output. The full backend suite could not run: the shared Docker engine ran out of memory under other sessions' suites. An earlier run of the reviews app showed two failures and two errors in migration tests; all four passed when rerun alone.
- `npm test`: **97 files, 1190 tests passed**. `tsc --noEmit` is clean, and eslint reports 0 errors (7 pre-existing warnings in untouched files). flake8 on the touched backend files is clean.

Five existing request-shape expectations in `MyReviewsPage.test.tsx`, and the `readView` / `viewSearch` expectations in `myReviews.test.ts`, were updated deliberately: the request and the view gained `sort` and `overdue`. The "never clips a long title" test asserts classes (no clamp, no no-wrap), following `entryHeadings.test.tsx`, because jsdom does no layout.

**Rendered check.** On a copy of the development database, at **1280 px** with real server data, the overdue row came first with *2 working days overdue · Due Tue 27 Oct* and the long title wrapped in full. **360 and 768 px were not checked in a browser**: the Docker port proxy kept dropping the dev server. That check is still owed.

A standards review and a spec review ran on the diff. The spec review found that a finished seat on a still-active assignment showed as overdue; that is fixed, with a test. The stale ui-ux/16 §5 is updated. Choices left for a reviewer: switching to Done and back resets sort and filter, and sort values are strings rather than an enum. No CI pass or human approval is claimed here.
