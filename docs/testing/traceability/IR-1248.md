## IR-1248

**Requirement:** Each screen's code loads when the screen is opened, not in the main bundle every visitor downloads. A sidebar or account-menu link prefetches its screen on hover and focus

**Design:** Jira IR-1248, from the local performance investigation (Ashlee Sean, 2026-11-20). One deliberate change from the ticket's "every page route except the shell": **Discover and Sign in stay in the main bundle**. A visit opens on one of them, and deferring the first screen would add a second, serial download before anything is drawn

**Implementation:**

- `frontend/src/router/lazyScreens.ts` (new): one registry of every deferred screen. It holds IR-749's fifteen and IR-1248's sixteen: My Library, Calls, My calls, Notifications, Settings, Profile, Edit profile, Person profile, My Reviews, Office console, Workflow analytics, Sign-up, and the four email/password recovery pages. Each is keyed by its `lib/access.ts` path, and `preloadScreen(path)` starts a download early and never rejects.
- `frontend/src/router/index.tsx` imports only LoginPage, HomePage and the error screens statically. Each newly deferred screen renders in `DeferredPage`, which keeps the shell and shows a spinner with a plain loading message (IR-1098).
- `Sidebar.tsx` and `AccountMenu.tsx` call `preloadScreen` on `mouseenter` and `focus`.

**Test:**

- `router/lazyScreens.test.ts`: the router's static feature imports are exactly LoginPage, HomePage and the two error screens. The guard refuses a new eager screen. `preloadScreen` resolves for the sidebar's paths and is a no-op for a path with no screen.
- `components/layout/Sidebar.test.tsx`, "prefetches a link's screen on hover and on focus (IR-1248)".
