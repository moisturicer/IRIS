## IR-1350

**Requirement:** The two remaining staff queues update without a reload.
- When a comment is reported, or its reports are closed (dismissed, removed by a moderator, or deleted by its writer), RDCO's and the System Admin's open **Reported comments** page and sidebar count show it.
- When an account deletion is asked for, cancelled, confirmed or rejected, the System Admin's open **Account deletions** page shows it.
- Nobody else is told.

**Design:** [ADR-073](../../adr/073-live-updates-by-server-sent-hints.md) §Amendment 2026-11-28, accepted by Lee Jasmin Adolfo on 2026-11-28 (PR #1034).

**Implementation:**

- **Backend:**
  - `apps/live/signals.py`:
    - `comment_reports_changed()` publishes `queues` to the RDCO and System Admin role channels;
    - `post_save` on `CommentReport` calls it;
    - `post_save` on `AccountDeletionRequest` publishes `queues` to the System Admin channel.
  - `apps/records/public_comments.py`: `close_reports` closes reports with a queryset `update()`, which sends no signal, so it calls `comment_reports_changed()` when it closed any.
- **Frontend:**
  - `features/admin/ReportedCommentsPage.tsx`: `useLiveRefresh(["queues"])` with a quiet read. A failed quiet read keeps the queue shown.
  - `features/admin/AccountDeletionRequestsPage.tsx`: `useLiveRefresh(["queues"], read.refresh)`.
  - The sidebar's Reported comments count already listened on `queues`. It now hears one when a comment is reported.

**Test:**

- `backend/apps/live/test_moderation_hints.py` (9):
  - reporting, dismissing, a moderator's removal and the writer's delete of a reported comment tell RDCO and the System Admin only;
  - deleting an unreported comment tells nobody;
  - asking for, cancelling, rejecting and confirming an account deletion tell the System Admin only.
- **Frontend:**
  - `src/features/admin/ReportedCommentsPage.test.tsx` (+3): a comment reported elsewhere shows after a `queues` hint; a failed live read keeps the queue with no alert; other topics are ignored.
  - `src/features/admin/AccountDeletionRequestsPage.test.tsx` (+2): a request made elsewhere shows after a `queues` hint; a failed live read keeps the list.
