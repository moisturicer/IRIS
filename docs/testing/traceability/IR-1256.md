# IR-1256: Deleting a draft asks in a dialog

[Back to the matrix](../TRACEABILITY.md)

**Requirement:** deleting a draft is confirmed in a pop-up, both from the Publish form and from My Library. In My Library, a draft has a red trash-can button next to *Continue draft*. Reported by Hermoine Zozobrado on 2026-11-21. No FR- id.

**Design:** this amends the wording of [ADR-009](../../adr/009-authorization-model.md) decision 6. Its rule is unchanged: a draft is deleted only after one confirmation. It also reverses [IR-1084](IR-1084.md)'s "no Delete on the Overview" for drafts.

## What changed

- **Publish form** (`PublishDialog.tsx`): *Leave this submission?* → *Delete draft* opens a `ConfirmDialog` over the form. It replaces the inline box that asked before. It says "“<title>” and its files will be removed. It can't be restored.", the same words My Library uses, and focuses *Cancel*. *Cancel* returns to *Leave this submission?*. The other closing questions stay inline.
- **My Library** (`DeleteDraft.tsx`, `SubmissionRow.tsx`, `LibraryOverview.tsx`): each draft row's *Delete* is now a red trash-can icon, with no fill or outline at rest and a *Delete draft* tooltip. Its accessible name is "Delete draft “<title>”". It sits beside *Continue draft* on the Overview as well as in *My submissions*, and a deleted draft leaves both lists.
- **A dialog over another** (`useDialogFocus.ts`): the open dialogs form a stack, and only the top one answers Escape and Tab. Before this change, Escape in the delete question would also have closed the Publish form underneath.

## Tests

| Test | Shows |
|---|---|
| `Modal.test.tsx` › *closes only the top dialog on Escape* | Escape closes the question and not the form, and the form hears the next Escape. It fails without the stack |
| `Modal.test.tsx` › *keeps Tab inside the top dialog* | Tab stays in the question. This is a guard: it also passed before the stack, because the two old traps happened to land focus in the question |
| `PublishDialog.test.tsx` › *with a draft saved* | The question is a dialog outside the form's dialog, with *Cancel* focused, and nothing is deleted until it is confirmed. *Cancel* returns to *Leave this submission?*. Escape closes only the question. A failure stays in the dialog |
| `MyLibraryPage.test.tsx` › *offers Delete draft as a red trash can…* | An icon alone, in `text-brand`, named for the draft. It asks before deleting |
| `MyLibraryPage.test.tsx` › *deletes a draft from the Overview…* | The Overview's draft row deletes after the same question and drops the row |

**Tests changed deliberately:**
- Three `PublishDialog` tests asked through the inline `alertdialog`, with *Keep draft*. They now ask through the dialog, with *Cancel*.
- The Overview test that said Delete is not offered there now expects it.
