## IR-1214

**Requirement:** **A paper's version menu shows whenever the paper has a version, listing "v1" alone when that is all there is.** No FR- id; a bug reported in team testing, 2026-11-17.

The ticket's title says the opposite ("shows even when the paper has only version 1"). Its description and acceptance criteria are followed here.

**Cause:** `PaperViewPage.tsx` drew the version menu only with two or more versions, or with one beside the owner's unsubmitted revision (`versions.length >= 2 || (record.manuscript_unsubmitted && versions.length >= 1)`). With v1 alone, the header beside the title showed the bare text "v1" and the Overview showed nothing. Papers' headers therefore looked different depending on how many versions they had.

**Implementation:** `PaperViewPage.tsx` draws the menu whenever there is a latest version. This applies in both places that used the old condition:
- the compact menu beside the title, in the bar, or in the reader's toolbar below 640px (IR-1092);
- the full menu on the Overview.

The bare "v1" label is gone. With one version the menu lists "v1 (current)", chosen. A reader shown no versions still gets no menu (IR-479). `VersionPicker.tsx`'s comment now says so.

"Compare versions" is the Changes tab, which `ReviewWorkspaceLayout.tsx` already treats as comparable only with two or more versions (IR-873, IR-1139). It is untouched.

**Test:** `PaperViewPage.test.tsx`. Three tests changed deliberately, because they asserted the behaviour this ticket reverses:
- "offers no picker with one version, or with none disclosed" became two tests:
  - "offers the picker with only v1, current and chosen": one option, "v1 · Submission · … (current)", value 1, axe passes.
  - "offers no picker when no version is disclosed".
- "puts the paper in one line" now expects the menu with value 1, not the text "v1".
- "keeps a single version's label in the toolbar" became "...picker in the toolbar": at 360px the menu is in the reader's toolbar, not in the bar.

The two-version tests (listing, choosing an earlier version, where the menu sits from 640px) are unchanged and pass.

**Evidence:** 2026-11-18, local.
- Before the change, the new single-version tests failed for want of a menu.
- After it, `features/records` passes, 59 files and 1036 tests.
- `tsc` is clean.
- `eslint` on `paper-view` reports one warning, already on `main`, at `PaperViewPage.tsx:543`, which this change does not touch.
- No e2e test refers to the old label.

**Status:** **IMPLEMENTED**; awaiting CI and review.
