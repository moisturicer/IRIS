## IR-862 — Workers run the pinned AGENT executor when a run's profile names it

**Basis and scope.** IR-862 under IR-714; authority ADR-049 and IR-714's Implementation Decisions. The worker builds IR-728's bounded AGENT Conversation on IR-860's chat-completions adapter, behind IR-725's admission, and chooses an executor per run from that run's stored pin. No reader UI change, no repair loop (IR-729), no new tool, no paid traffic, and no profile value is approved.

**Code.**
- **Profile** (`ai/runs/agent_profile.py`). `RUNS_EXECUTOR=agent` is the explicit switch. It requires:
  - `RUNS_AGENT_MODEL`, which must be listed in `AGENT_LLM_MODELS`, have a declared capacity and have a price in `AI_ADMISSION_PRICES`;
  - `RUNS_AGENT_BOUNDS`, with exactly `ordinary` and `deep`, each stating every `Bounds` field;
  - `RUNS_AGENT_RESERVES`, stating every `Reserves` field;
  - every `AGENT_LLM_*`, with data policy `no-training`;
  - every `AI_ADMISSION_*`, including a `research` lane.

  Any absent or invalid value raises `RunsUnavailable`, naming the key and never a value. The worker exits with that message, and the routes answer `unavailable`. The pin is the research pair (`agent-research-1`/`research-1`) on the configured endpoint, the `openai-compatible` adapter and the `chat-completions-1` dialect. No reader-visible selector exists.
- **Worker** (`ai/runs/worker.py`). `build()` always serves the deterministic executor. With the profile it also serves `AgentExecutor`, whose provider is always wrapped in `AdmittedAgentProvider` (purpose `agent`), and pins new runs to it. So both executors coexist during the cutover. `agent_provider=` replaces the vendor adapter, for tests only.
- **Selection** (`ai/runs/service.py`). `RunService.executors` maps name to executor. A worker claims only runs whose pinned executor, version and AGENT pin it serves (`claim_next(serves=...)`, `ai/runs/store.py`). Any other run stays queued for a worker that does serve it, or until its deadline expires it. That covers a deterministic-only worker in a mixed fleet and a worker upgraded to another model. It is never claimed or substituted, and it spends no attempt. A claimed run is answered by the executor its stored pin names, and the same check at execute still refuses a pin that changed under it as `unavailable`. Attempt accounting records the run's own executor (`executor=None` takes it from the pin).
- **Pinned bounds** (`RunService.pinned(depth)`, `RunContext.bounds`). The `Bounds` of the run's depth are persisted in `pinned.bounds` at submission. `_Run` uses them rather than the answering worker's. The allowance was already the persisted AskRun allowance. Admission is the shared campaign, with that allowance as the run's ceiling (IR-725).
- A researching run with no usable stored bounds is refused as `unavailable` rather than given the worker's, so no worker can widen one.
- The gateway's API process builds through the same `build()`, so with `RUNS_EXECUTOR=agent` it too needs the whole profile and builds (but never sends through) the admitted adapter; the public protocol then opens to readers, as IR-595's gate already intended for an AGENT service.
- `ai/tests/dispatch_worker.py`'s `SleepingExecutor` is renamed to the deterministic executor it stands in for. IR-723's runs are pinned to `deterministic`, and per-run selection would otherwise refuse them. No assertion changed.

**Tests.**
- `ai/tests/test_agent_profile.py` (gateway suite, no database), at seam 1, `build(settings)`:
  - a complete profile pins new runs to the agent, still serves deterministic runs, and pins per-depth bounds;
  - the deterministic profile needs no agent setting;
  - each of the 20 absent settings refuses and names itself;
  - an unknown executor refuses;
  - an unlisted, capacity-less or unpriced model, partial, zero, missing-field or non-JSON bounds or reserves, a non-http endpoint and a non-no-training policy each refuse.

  No message carries the API key.
- `test_ai_runtime_agent_db.py`'s IR-727 tests `test_a_run_is_never_continued_under_another_pin` and `test_an_agent_run_is_not_answered_by_a_worker_without_its_pin` are changed deliberately: such a run is now left `queued`, not claimed and failed `unavailable`. Their guarantee is kept: it is never answered under another pin, and nothing is sent.
- `ai/tests/test_runs_config.py::test_only_a_known_executor_can_be_selected` replaces IR-722's `test_no_paid_executor_can_be_selected`. This is changed deliberately, because IR-862 adds `agent`, which the profile tests above guard.
- `backend/apps/ai/tests/test_ai_runtime_executor_selection_db.py` (real PostgreSQL under `iris_ai_runtime`, the real ledger and guard, services built by `build()`, recording provider). Seam 2:
  - a deterministic and an AGENT run answered by one worker, each by its own executor and accounted to it;
  - a worker upgraded to another model leaves the old-pinned run queued, and a worker on that pin answers it;
  - a deterministic-only worker answers its own runs and leaves an AGENT run queued, unaccounted, for an agent worker;
  - stored bounds closing research win over the worker's;
  - a worker with a larger allowance cannot widen a run's;
  - a reconnect renews a lapsed grant and keeps the allowance;
  - cancel between tool steps ends `cancelled`/`stopped`;
  - revocation between steps, a refused provider and an invalid draft each end `failed`/`unavailable` with no Turn;
  - a hung attempt ends at the deadline.

  Seam 3, two independent `python -m ai.tests.agent_worker` processes:
  - a worker killed mid-attempt is resumed by another after its lease, under the same pin and allowance (two accounted attempts, both admitted for the pinned model and prompt);
  - two workers settle six AGENT runs with one reader's runs and the deep runs never overlapping.

  The module is in `testing/parallel.py`'s `ROLE_MODULES`.

**Run evidence.** The gateway suite ran locally: 78 passed. The PostgreSQL module was **not run locally**: Docker was not running and no Postgres was reachable. Its first execution is CI. The backend contract suites touched indirectly (IR-727, IR-728, IR-732) were not run locally either.

**Not done here.** No live provider call, no approved profile value, no deployment or traffic switch. Under admission, the guard still withholds every tool result (IR-725), so an admitted AGENT run can only answer without reading the repository until a disclosure decision exists. The demonstration's tool-step cancel stops the run before that refusal is reached. A run that no worker serves waits until its deadline expires it. Repair stays IR-729.

**Status.** Implemented; awaiting CI and review.
