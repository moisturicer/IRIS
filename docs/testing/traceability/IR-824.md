## IR-824 — An inventory of the sensitive data IRIS holds (ASVS 8.3.4)

Found by IR-617: no document listed the sensitive data IRIS creates and processes, with a handling rule for each kind. ADR-051 and IR-794 cover retention periods, not the inventory.

**Delivered:** [`docs/security/DATA_INVENTORY.md`](../../security/DATA_INVENTORY.md). For each kind of data it gives where it is stored, who may read it (the API rule), whether and where it leaves the deployment, and how it is handled. It covers research content, people, Ask IRIS, records of what happened, secrets, and server access, and ends with a table of every outside recipient.

**Sources.** Drafted on 2026-11-15 by Claude Code at Ashlee Sean's direction, from `main` at `ca273b99`:
- `apps/accounts/personal_data/registry.py`, which declares every model that relates to a person;
- the models and settings named in each row;
- `docs/security/SECURITY.md` §7–§9;
- ADR-045, ADR-049, ADR-051, ADR-056 and ADR-067.

**Fact-checked.** A review pass checked each claim against the code and found errors in the first draft, all fixed. It had described unmerged work (IR-819, IR-820, IR-926) as current, and listed office staff as reading only their own reviews when they read every record. It had also missed data: Adviser emails visible to every signed-in user, the downloader's identity in each PDF, titles and notes in emails and in the Celery broker, figure images sent to an LLM, LlamaParse keeping parse results, the Django admin as a reader, and backend logs probably holding query strings. The inventory now describes `main` as it is and marks pending work.
