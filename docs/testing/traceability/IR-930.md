# IR-930: a long unbroken run in an AI answer no longer freezes the page

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes. This closes the defect IR-917 observed and left open (IR-900, threat model IR-617): `remark-gfm`'s email autolink is quadratic on a long run of text with no space. The change is confined to `CitationText` and its helpers (the AI frontend area).

**Measured (2026-11-06, Node, `remark-parse` + `remark-math` + `remark-gfm` 4.0.1, 40,000 characters, no space, parse only).** It is not specific to `+`: any run containing `+`, `-`, `.` or `_` is quadratic.

| Shape | With `remark-gfm` | Without |
|---|---|---|
| `x+x+...` | 3.5 s | 10 ms |
| `x-x-...` | 3.5 s | 11 ms |
| `x.x.…` | 4.1 s | 9 ms |
| `a.b+a.b+...` | 5.4 s | 22 ms |
| `x_x_...` | 5.3 s | 0.23 s |
| the same text with spaces (`x+y x+y ...`) | 84 ms | 9 ms |

For `x+` at 5,000 / 10,000 / 20,000 / 40,000 characters: 102 / 219 / 781 / 3,514 ms. `remark-gfm` 4.0.1 and `micromark-extension-gfm-autolink-literal` 2.1.0 are the latest releases, so an upgrade is not available.

**Decision.** `CitationText` inserts a zero-width space into any run of non-space text longer than 512 characters before the parser sees it (`runLimit.ts`: `MAX_RUN_CHARS`, `breakLongRuns`). The email scan stops at the break, so each attempt is bounded and the total is linear. Parse-only, the same 40,000-character inputs take about 55 to 110 ms (`x_`: about 390 ms, which is remark's own emphasis cost without `remark-gfm`, not the autolink). A *full* `CitationText` render of 40,000 characters (React, highlighting, KaTeX included), in jsdom after the fix: `x+` 247 ms, `x-` 184 ms, `x.` 142 ms, `a.b+` 154 ms, `x_` 534 ms.

| Option | Gain | Cost |
|---|---|---|
| **Break runs over 512 characters (chosen)** | Fixes every separator. Bare `https://` links and emails keep linking. No dependency change | A cut run carries an invisible character when copied; the rare cases below |
| Drop the autolink literal extension | Removes the cost entirely | Loses bare-URL and email linking in answers, which the acceptance criteria keep |
| Upgrade `remark-gfm` | No code | No newer release exists |
| Accept | No change | A 40,000-character answer blocks the main thread for seconds |

**What a break can still touch.** Only a run longer than 512 characters with no space is cut; ordinary words, links and addresses are far shorter. In such a run:

- **A URL:** the break lands inside its target. The link element is still made, but its `href` carries the break and no longer resolves. This is the one place bare `https://` linking changes, and only for a URL over 512 characters.
- **A citation marker** such as `[12]` that straddles a cut stops matching and loses its chip. Streaming markers likewise.
- **A code line or a table delimiter row** with no space is cut.
- **A formula** is not affected: `remarkLimitMath` takes the breaks back out of a `math` / `inlineMath` node (both its value and the copy `remark-math` keeps for KaTeX) before the 2,000-character check and before typesetting. A first version did not, and a spaceless 601-character formula got a stray character inside the LaTeX; the review caught it and a test now covers it.

These are judgement calls, accepted because the alternative, parsing a run that long, freezes the page. The cap is one constant.

**What proves it**

| Check | Where |
|---|---|
| Ordinary text, links, a formula, a run of exactly 512 characters: unchanged | `runLimit.test.ts` |
| No stretch between breaks exceeds 512 for `x+`, `x-`, `x.`, `x_`, `x`, `a.b+` at 40,000 characters; removing the breaks returns the input; breaking is idempotent and measures from an existing break; no surrogate pair is split | same |
| **The quadratic behaviour fails a test if it returns:** rendering 20,000 characters takes less than 8x the time of 5,000 (best of three each) for `x+`, `x-`, `x.`, `a.b+`. Linear is about 4x, quadratic about 14x to 22x, so the check compares two sizes and does not depend on the machine's speed | `CitationText.hostile.test.tsx` |
| All text survives (breaks aside) and only text is created | same |
| A bare `https://` URL (with `+` in its query), a `mailto:` address, and a URL after a long run still link; a 470-character URL, bare and as a link target, keeps its exact `href` | same |
| A spaceless inline and displayed formula of 601 characters typesets with no break in the output; a spaceless formula over 2,000 characters is shown as its source with no break | same |

**Red first.** Against the unfixed `CitationText` the four ratio tests failed (for example `a.b+`: 13.8 against a limit of 8). The three formula tests failed against the first version of the fix, before `mathLimit.ts` was changed.

**Not covered.** No test covers a URL over 512 characters or a citation marker cut by a break; both are documented above. `PassageQuote` and other places that show manuscript text do not go through the markdown parser. jsdom timings are not browser timings, and the Node parse figures above are not render times: the tests compare ratios. `src/router/roleNavigation.test.tsx > opens /rdco/users for RDCO` failed once under load in the local `test:changed` run and passed alone (20 of 20); it does not touch this code.
