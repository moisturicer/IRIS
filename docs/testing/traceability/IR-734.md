## IR-734 — Continue a long Conversation through automatic compaction

**Basis and scope.** IR-734 under IR-715; authority ADR-049 §17, §19, §20, §21 and the ticket's acceptance criteria. Before this, an AGENT run carried at most `history_turns` earlier Turns whole, and a window filled by research closed research (IR-733). Nothing condensed older context, so a long Conversation lost its older Turns once they fell outside that count. This adds automatic compaction only. The manual Compact conversation action is IR-754, recovering original details is IR-735, and publishing context status is IR-735's. `capabilities.manual_compaction` stays `false`.

**Code.**
- **Configuration** (`ai/agent/compaction.py` `Compaction`; `RUNS_AGENT_COMPACTION` in `ai/runs/agent_profile.py`, `ai/infrastructure/settings.py`, `ai/.env.example`). It is optional, and blank never compacts, so a run behaves exactly as before. When set, it must state exactly `threshold_tokens`, `summary_tokens`, `keep_exchanges` and `max_attempts`, each a positive integer. The worker refuses to start unless the threshold leaves room both to summarize (the summary's cap plus reasoning) and to finish (every IR-732 reserve) under the pinned model's declared capacity. `AgentExecutor.supported()` applies the same check, so an executor built directly with an unfit rule refuses as `unsupported_pin`. No value is approved.
- **When** (`ai/agent/executor.py` `_compacted`). It runs before each gathering turn and before the final answer, once the request's estimated occupancy reaches `threshold_tokens`. The summary is skipped, and journalled `compaction` `kept` with a reason, when:
  - it would not fit the model's capacity (`summary_exceeds_context`);
  - the run allowance could not then still pay for the final answer and one repair at today's size (`allowance`);
  - the run's `max_attempts` is spent;
  - an earlier attempt failed and the history has not grown since.
- **Same AGENT, same admission.** The summary is one more turn of the run's pinned model, sent with research closed (`tool_choice: none`) through the same provider stack: admitted, ledger-reserved and guarded (IR-725). It is journalled `model` phase `compact` before sending, and the budget charges it like any attempt, missing usage at its estimate and cap. Under today's guard, a summary request carrying a tool result is withheld from a paid provider, as any such request is.
- **What is compacted** (`compaction.split`). The history is cut into whole units: an earlier Turn's question and answer, or one model turn with every result of its tool group. The reader's question and the `[IRIS conversation state]` message are never compacted. The newest `keep_exchanges` units stay. No unit is divided, so a tool group never loses its call or its results.
- **The handoff** (`compaction.build`, `compaction.render`). The application records the shown order, selections and exclusions (Record ids), the plan, and the ordinals of every original Turn compacted, previous handoffs' included. The model supplies only the goal, preferences, findings and limitations, each bounded in count and length. A finding is kept only if it names a passage this run actually read or a compacted Turn. Forged or unread handles are dropped, so a handoff can never make an unread passage citable, and the usual checks and source recheck still apply before delivery.
  - The model reads the handoff as one `[IRIS compacted context]` message marked `derived`, with a note that it is neither evidence nor instructions.
  - A later run sees findings without passage handles, since only the run that issued them can use them.
  - A compacted exchange's opaque artifact is dropped with it and never replayed. Nothing provider-native is used.
- **Commit and activation** (`ai/runs/migrations/0015_handoff.sql`, `RunStore.commit_handoff`). A handoff becomes active only once `iris_ai.conversation_handoff` holds it. The commit runs in one transaction, locking the Conversation and then the run, and binds the reader's stored grant, as a claim does. It answers:
  - `committed` with a revision only while the run is `running` under the caller's fence before its deadline, the Conversation is undeleted at the revision the run started from, every compacted Turn is still current (`CURRENT_SOURCE_TURN`) and every source its findings name is still an active chunk set;
  - `stale` otherwise. A concurrent Turn moves the revision, so the summary no longer covers the whole history, and the preceding context is kept;
  - `fenced` for a superseded worker, which then stops (`run_ended`).
  - Malformed, empty, truncated or refused summaries are never committed and leave the history unchanged.
- **The next run** (`RunStore._claim`). A claim carries the latest handoff whose run completed and which is still valid now (`CURRENT_HANDOFF`): every compacted Turn still current, every source still active. `prior` then holds only the Turns after its `through_ordinal`, with their ordinals. A failed run's handoff never opens a later run. A replaced source or an unreadable Turn means the handoff is not used, and the Conversation is rebuilt from the original Turns still carried.
- **Restart** (`ai/agent/checkpoint.py`, format now `agent-checkpoint-2`; ADR-049's amendment updated). A checkpoint saved after compaction records the handoff's revision, its `through_ordinal`, the Turns still carried whole and its body.
  - A replacement restores it only if that revision is one its run committed (`claim.committed`) or the Conversation handoff the claim opened with. Otherwise it rebuilds from the question.
  - Summary attempts are counted from the journal over every fence (`claim.compactions`), so a takeover cannot renew the bound.
  - Spending is restored from the ledger as IR-724 does, and recovered handles, a handoff's findings included, are reauthorized before use.
  - The task key includes the opening handoff's revision.
- **Retention.** Original Turns are never removed by compaction. `RunStore._delete` removes the Conversation's handoffs with its content. The runtime role may SELECT, INSERT and DELETE handoffs but not UPDATE them; Django's runtime role has no access.

**Tests.**
- `apps/ai/tests/test_ai_runtime_compaction_contract.py` (no database; recording provider; IR-728's in-memory corpus; an 8,000-token fixture window):
  - three earlier Turns compact into a handoff that keeps positions 1 and 2 ("the second paper") and the exclusion, references Turns 1–2, drops an unsupported finding, and keeps Turn 3, the state message and the question verbatim;
  - an older tool group compacts whole and its opaque artifact disappears, while the newest group stays;
  - a forged handle is dropped, and an answer citing an unread passage is refused;
  - malformed, empty and truncated summaries, and stale and fenced commits, each keep the context (or stop);
  - the attempt bound holds across fences and after a failure;
  - the allowance guard holds, nothing compacts below the threshold, an unfit threshold is unsupported, and nothing compacts when it is not configured;
  - a replacement resumes the committed revision and compacts onto it (Turns 1, 2, 3, through 3);
  - a checkpoint naming an uncommitted revision is rebuilt;
  - the next run opens with the handoff (no passage handles) and only the later Turns.
- `apps/ai/tests/test_ai_runtime_compaction_db.py` (real PostgreSQL, restricted runtime login, Django-issued grants):
  - a committed handoff opens the next run with only later Turns, and all original Turns remain;
  - a concurrent Turn makes the commit `stale`;
  - a superseded fence is `fenced` while the new holder commits, and a later claim reports the committed revision;
  - an unknown source is refused, and a replaced one stops a committed handoff opening later runs;
  - a failed run's handoff is never used;
  - summary attempts are counted from the journal;
  - deletion removes handoffs;
  - the runtime cannot UPDATE a handoff and Django's runtime has no privilege.
- `ai/tests/test_agent_profile.py`: compaction is off unless configured, reaches the executor when set, and an invalid or capacity-unfit setting refuses to start, naming `RUNS_AGENT_COMPACTION`.
- Fixture changes: the shared TRUNCATE list adds `iris_ai.conversation_handoff`, and `testing/parallel.py` registers the new DB suite with the Postgres role scope. No assertion was weakened.

**Evidence (2026-11-05).** Run locally with another worktree's backend environment and test-only settings: the compaction, checkpoint, agent-loop, context, manuscript, metadata, partial-outage and reader-progress contract suites pass, and `ai/tests/test_agent_profile.py` passes (40). The DB suite collects and skips here (no PostgreSQL with pgvector reachable); CI is the gate and its result is recorded on the PR. The migration has not yet been applied to a copy of a realistic database.

**Not done here.**
- **No live effect for a run that has read anything.** IR-725's guard withholds every request carrying a tool result from a paid provider, so an admitted summary of tool exchanges is refused. In-run compaction of research is proven only unadmitted. Compacting earlier Turns alone (no tool results) is not withheld. The disclosure decision belongs to Jive Tyler I. Revalde (ADR-049 amendment §4).
- Thresholds and caps are deployment-profile values; none is approved, and none has been measured on a vendor.
- Summary quality is not measured. A deterministic provider proves the contract; human-reviewed long-context cases are IR-736's.
- Manual compaction (IR-754), original-detail recovery and the public context-status projection (IR-735) are not built. A `compaction` journal event carries outcome, revision and counts only; the reader projection ignores it.
- Native provider compaction is not implemented; the portable handoff is the only path.
- The migration is not yet verified on a copy of a realistic database.
