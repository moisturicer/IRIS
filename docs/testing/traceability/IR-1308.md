## IR-1308

**Requirement:** On the Notifications page, a notification with somewhere to open is itself the link: selecting anywhere on its row goes there and marks it read, instead of a separate *Open* button. A notification with nowhere to open is not a link and keeps its *Mark as read* button. No FR- id.

**Design:** Asked for by the frontend designer from a screenshot of the page ("instead of a button open, just make the card clickable"). The row shows a light background on hover and a chevron on the right as the affordance; the keyboard focus ring is inset so the list's rounded, `overflow-hidden` frame does not clip it.

**Implementation (frontend only):**

- `features/notifications/NotificationsPage.tsx`: `NotificationRow` wraps the dot, message, date and resolved pill in a router `Link` when `notificationHref` gives a destination; its accessible name is that text ("Unread: …, 19 Nov"), not "Open: …". The `ButtonLink` *Open* is removed. The page description now reads "Select one to go to its record."

**Test:**

- `features/notifications/NotificationsPage.test.tsx`: the link tests now find each row's link by its message rather than by "Open: …", and no longer expect the text "Open". Changed deliberately: the button they named no longer exists. The record link still goes to `/records/42` and marks the notification read; a Call's notice still links to its server target with no *Mark as read* button; a settled notification is still openable.
