## IR-910

**Requirement:** **Every routed screen is opened at 360, 768, 1280 and 1745 px in CI; the page must not scroll sideways, the screen's primary action must be reachable, and table-heavy screens have a documented small-screen behaviour** — no FR- id; subtask of IR-897. Supports **NFR-U3** (WCAG 1.4.10 Reflow), which stays **PARTIAL**

**Design:** Jira IR-910 · [`../../engineering/RESPONSIVE_LAYOUT.md`](../../engineering/RESPONSIVE_LAYOUT.md) · [`../../../e2e/README.md`](../../../e2e/README.md)

**Implementation:** `e2e/support/viewport.ts` (`measureOverflow`, `checkReachable`, `describeTable`; `a11y.reflow360` now calls `measureOverflow`, so the journeys and the matrix share one definition of "scrolls sideways"); `e2e/smoke/support/screens.ts` (one row per routed screen: role, mocked API, heading, primary action, table); `e2e/smoke/viewport-matrix.spec.ts` (one test per screen and width); `e2e/smoke/support/matrix-reporter.ts` (writes `test-results-smoke/viewport-matrix.{json,md}`); `.github/workflows/frontend-smoke.yml` (prints the table in the run summary; `e2e/support/viewport.ts` counts as a smoke-tier file). **Fixed by it:** a scroll container that is not `position: relative` lets an `sr-only` cell escape and widen the page, which made Users, Role Requests and Admin Users scroll sideways at 360 and 768 px. `DataTable` and the Role Requests, Download Requests and Delete Requests wrappers (the last two drawn with a row so the matrix backs the change) are now `relative overflow-x-auto`; Role Requests was `overflow-hidden`, which cut its table off

**Test:** `e2e/smoke/viewport-helper.spec.ts` (6 tests: the measurements fail on a page that overflows, on a control past the edge and on a covered control, and pass on a table that scrolls inside its own container). `frontend/src/router/viewportMatrix.test.ts` fails when the route table and `frontend/src/router/matrixRoutes.json` disagree, and `e2e/smoke/viewport-coverage.spec.ts` fails when `screens.ts` and that file disagree, each in both directions (each test reads only its own stack, CODING_STANDARDS X1). The matrix was seen to fail on real defects before the fix: the first complete run reported Users (RDCO), Role Requests and Users (System Admin) at 360 and 768 px, 296 and 140 px of page overflow on the Users screens and a cut-off table on Role Requests

**Evidence:** 2026-11-06, local, headless Chromium: `npm run build` in `frontend/`, then `npx playwright test -c playwright.smoke.config.ts --workers=4` in `e2e/`: 124 passed in 2.4 min (108 matrix checks over 27 screens, 6 helper tests, 2 coverage tests, the 8 IR-904 specs); the matrix reported 0 px overflow and a reachable primary action in every cell, and the six table screens (Users twice, Role Requests, Audit Log, Download Requests, Delete Requests) fitting or scrolling inside their card, never cut off. `tsc --noEmit` clean in `e2e/` and `frontend/`; `npm run lint` 0 errors. `npm run test:changed` in `frontend/`: `roleNavigation.test.tsx` failed twice in the parallel run and passed 20 of 20 on its own; no code it covers was changed here, so it is read as a load timeout on the lazily loaded pages, not a result. **Not yet seen on GitHub Actions:** the step-summary table and the artifact upload are unrun

**What this does not show:** The API is mocked, so screens are measured with a few hand-built rows; a long unbroken value from real data can still widen a screen (IR-921's cause). Dialogs and the Publish wizard are not routes and are not in the matrix. Contrast and touch-target size are not measured. Visual snapshots are not taken (optional in the ticket, a team decision). A person has not checked every screen, so NFR-U3 is unchanged

**Status:** **PARTIAL** until the workflow has run on a pull request and a reviewer has seen the table in its summary
