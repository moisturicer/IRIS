# IR-1189: My feeds leaves Discover

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). No ADR decided saved feeds' place on Discover (IR-577 recorded its decisions in its own traceability file), so none changes. Retiring saved feeds altogether is out of scope: it is a product decision that needs an ADR and its own ticket.

## What changed

- **Discover shows no My feeds.** The My feeds menu, its save, rename and delete dialogs, the open-feed bar ("Feed: …", "Save these filters to this feed", "Leave feed"), the stale-feed correction panel and the "could not be checked" panel are gone. A reader narrows the list with Sort and Filters only. The phone toolbar row is now Sort, Filters and, for an author, Publish.
- **Discover no longer reads the reader's feeds.** Nothing in the frontend calls `/library/feeds/` any more.
- **An old saved-feed link still opens.** `?myfeed=N` is removed from the address on arrival; the link's own filters stay and run as ordinary Discover filters. The results are no longer held back while a feed is checked, because there is no feed to check. `scripts/query-keys.json` keeps `myfeed`, noting it is read only to be removed.
- **Deleted, because only My feeds used them:** `features/discover/MyFeeds.tsx`, `store/feeds.store.ts`, the saved-feed helpers in `discoverQuery.ts` (`feedQueryOf`, `feedSearchParams`, `sameFeedQuery`, `feedCriteria`, `FeedLabelOptions`), and the `feeds`/`createFeed`/`updateFeed`/`deleteFeed` calls with the `SavedFeed`, `FeedQuery`, `FeedQueryKey` and `FeedStale` types in `api/library.ts`.
- **Nothing on the server changes.** `SavedFeed` rows, the `/api/v1/library/feeds/` endpoints and their tests (IR-577) are untouched, so no reader's saved feeds are deleted.

## Tests

- **Added** in `DiscoverPage.test.tsx`, "Discover without My feeds (IR-1189)": no My feeds button, save-filters action or feed bar; an old `?myfeed=5` link with filters keeps the filters in the address and the list request, loses `myfeed`, and lists papers.
- **Removed deliberately**, because the controls they tested are gone: `MyFeeds.test.tsx`, `store/feeds.store.test.ts`, the "saved custom feeds (IR-577)" block in `DiscoverPage.test.tsx` (15 tests), and in `discoverQuery.test.ts` the "saved feeds use Discover's own query (IR-577)" block and the year-range wording cases, which tested `feedCriteria`. The year range in the list request is still tested.
- **Changed deliberately:** the phone toolbar tests no longer expect a My feeds button (an author's row has 2 buttons, was 3; an office reviewer's has 1, was 2). The `libraryApi` mock drops the feed calls.
- **e2e smoke:** the three My feeds dialog cases (save, rename, delete a custom feed) are removed from `e2e/smoke/support/dialogs.ts`, and the `/library/feeds/` mock is removed from the shared fixtures and the Discover screen. The smoke harness fails on any `/api` request nobody mocked, so a Discover that still asked for feeds would fail it.
