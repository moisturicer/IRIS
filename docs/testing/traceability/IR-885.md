## IR-885 — Ask IRIS researches at deep depth by default

**Basis.** Owner decision, 2026-11-04, recorded in ADR-049's amendment (IR-884).

**Code.**

- `ai/runs/config.py` names `DEFAULT_DEPTH = "deep"`. The submit route and `RunService.submit` use it, so a submission that names no depth runs deep with the deep deadline and Bounds. One that names `ordinary` keeps it.
- `RuntimeReader` starts on deep in Ask IRIS and Paper Chat. The checkbox now reads "Thorough research", because "Be more thorough" made no sense ticked from the start. Unticking it asks the next question at ordinary depth.
- The `iris_ai.ask_run.depth` column default stays `ordinary`: an applied migration is not edited, and every insert names a depth.

**Tests changed deliberately.**

- `RuntimeReader.test.tsx` asserted that ticking the box asks deeply. It now asserts the box starts ticked and the request is deep, and a new case unticks it.
- `test_ai_runtime_dispatch_db.py` names `depth="ordinary"` in two places that relied on the old default; what they check is unchanged.
- `runtimeReader.recorded.json` records `deep`, because the e2e question names no depth.

**New.** `test_a_question_runs_deep_unless_it_names_ordinary` (real Postgres) and `test_a_submission_is_deep_unless_it_names_a_depth`.

**Local runs (Windows, 2026-11-04).** `test_ordinary_capacity_is_protected_and_deep_work_completes` and `test_queued_multi_paper_loop_exposes_actual_live_tasks_before_delivery` fail the same way on unchanged `main`, so CI decides them.

**Not done.** No limit value changes. Most runs now share `RUNS_DEEP_CONCURRENCY`, and a deep deadline past `AI_RESEARCH_GRANT_TTL_SECONDS` ends a run `unauthorized` until IR-880. Both are for IR-861's record to account for.

**Status:** **PARTIAL** — implemented and tested; review pending.
