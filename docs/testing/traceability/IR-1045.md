## IR-1045

**Requirement:** **A reviewer can discard an unsent Request Revision draft** — follows IR-272 (the reason is kept across navigation), IR-143 and IR-931 (drafts belong to the signed-in user); no FR- id

**Design:** [07-review-clearance.md](../../ui-ux/07-review-clearance.md) (the Request Revision copy is unchanged) · Jira IR-1045

**Implementation:** `RequestRevisionDialog`: a **Discard draft** button in the footer, shown only while the reason box is not empty and disabled while a request is being sent. It empties the box, calls `clearRevisionDraft` for the signed-in user and record, shows an info toast "Draft discarded." and returns focus to the box. No API call: nothing was sent. Cancel still keeps the draft and a successful request still clears it.

**Test:** `paper-view/RequestRevisionDialog.test.tsx` (the button is absent until there is text; discarding empties the box and the saved draft, returns focus and never calls `requestRevision`; the IR-931 per-user cases still pass, so discarding one user's draft does not touch another's)

**Evidence:** 2026-11-12, worktree: same run as [IR-1044](IR-1044.md) (`tsc` clean, `eslint` 0 errors, `npm run test:changed` 1,107 of 1,108, the one failure an unrelated `NotesPanel` load flake). **Not seen in a browser** (no Docker or PostgreSQL here).

**Status:** **PARTIAL** — implemented and tested in jsdom; not yet seen in a browser, awaiting CI and review
