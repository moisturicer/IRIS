# IR-921: Paper View reflows at 360px

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes status. This is a fix found by the **NFR-U3** reflow check (WCAG 1.4.10), which stays **PARTIAL**: the journeys' `a11y.reflow360` has to pass on screens 01 and 05 in a CI run before this row says more, and no person has checked every screen.

**The problem.** Paper View's Overview scrolled sideways at 360 CSS px (234px on journey screen 01, 146px on 05). The one cause reproduced here is `VersionPicker`'s native `<select>`: it is as wide as its longest option ("v2 · Revision after review · Nov 5, 2026 (current)") and sat in a flex row that could not shrink it. The ticket also named the routing table and governance rows; the Status row it named was removed by IR-525, and the others could not be made to overflow on this branch except by an unbreakable reviewer name or Classification, which are now guarded.

**What changed**

| Place | Change |
|---|---|
| `VersionPicker.tsx` | Select and its row get `min-w-0` (the select also `max-w-full`), the label `shrink-0`. The compact reading-header picker is unchanged. |
| `PaperGovernance.tsx` | Values get `min-w-0` and anywhere-wrapping, so a long value wraps inside its row. |
| `ReviewRoutingTracker.tsx` | The seat list wraps anywhere, so a long reviewer name cannot hold the table wider than its card. Not table-wide: that moved the desktop columns (84/113/35px to 61/135/35px) and risked breaking inside a party name, so it was dropped. |

**What proves it**

| Check | Where |
|---|---|
| The select, its row, the governance value and the seat list can shrink; the compact picker and the table keep their old shape | `frontend/src/features/records/paper-view/reflow360.test.tsx` (4 tests). jsdom has no layout, so these hold the cause, not the scrollbar. |
| 360px, in a real browser: horizontal overflow 74px before, 0 after; still 0 with a 70-character unbroken name in a seat, a governance value and the selected version | Manual, 2026-11-06, Paper View of a seeded Submitted paper opened as its owner, with the version, revision-request and tracker responses decorated by a throwaway local proxy. Nothing was written to the database. |
| Desktop (1280px) unchanged: tracker columns 84/113/35px before and after, select 358/359px | Same session |

**Screen 05 is not explained.** With the revision-request panel and its *Submit new version* button also rendered, the page before this change overflowed by 75px, and only the version select stuck out; after it, 0px. Screen 05 shows no version picker (one version, no unsubmitted revision), so this fix very likely does not clear 05. The elements the ticket lists for it (a `gap-1.5 min-h-11` button, a bold governance `dd`, the routing table, all about 460-472px) were not reproduced: the `dd` is gone since IR-525, the button matches the disabled Post button in `CommentsSection`, whose row already shrinks, and the table fit its card. Something that is not a leaf in these three components is still unknown.

**What this does not show.** No Core journeys run was made, so the acceptance criteria that screens 01 and 05 pass `reflow360` and their accessibility checks are **not yet met**; they need the CI journeys run, whose culprit list for 05 is the next lead. The decorated data is built from the ticket's description, not copied from a journey, so the 234px and 146px figures were not reproduced exactly (74px with shorter labels). The ticket's "same button" (`inline-flex gap-1.5 min-h-11`, right edge 472px) was not found: no such control overflowed here. If the journeys run still reports overflow on screen 05, its culprit list names the element.
