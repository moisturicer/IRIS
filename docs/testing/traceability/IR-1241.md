## IR-1241 · Discover thumbnails are a small first-page image, not the whole paper, and audit nothing

In Discover's one-column list, each row's thumbnail used to download the whole manuscript
(`/records/<id>/manuscript/`) and draw page 1 in the browser with pdf.js, and that endpoint
writes a `DOWNLOAD` audit event on every call. A page of 12 rows downloaded up to 12 papers
and logged 12 "downloads" nobody made, again on every return to Discover. A regression of
IR-1130, brought back by IR-1141. The decisions are on the card (settled 2026-11-19).

**Implementation:**
- `GET /records/<id>/first-page/` (`RecordViewSet.first_page`): `get_object()` through
  `visible_to`, then the file this reader is served (`versions.served_manuscript`). 200 the WebP
  (`private, no-store`, `nosniff`, `inline`); 202 `first_page_pending`; 404 `no_manuscript` or
  `first_page_unavailable`; a reader without access gets the 404 of a missing record. No audit event.
- `apps/records/first_page.py`: the cache lookup the view calls (it never reads the PDF), keyed by
  the served file's SHA-256 (`first-page:v1:image:<sha>`, 30 days), a pending marker set with
  `cache.add` (10 minutes) so only one request queues the drawing, and a failed marker (1 day).
  A manuscript with no fingerprint yet is `first_page_unavailable` rather than hashed in the request.
- `tasks.draw_first_page`, routed to `extraction`: re-reads the served file, refuses one whose hash
  no longer matches, and draws page 1 in the IR-830 sandbox under its existing limits
  (`PDF_EVIDENCE_WALL_SECONDS`, `PDF_EVIDENCE_MEMORY_MIB`, `PDF_VALIDATION_MAX_PAGES`).
- `apps/documents/pdf_evidence/first_page.py`: the sandbox child, as `crops.py`: pypdfium2 draws
  page 1 at 192 px wide, Pillow writes WebP at quality 70, after `RLIMIT_AS` and `confine()`.
- Frontend: `recordsApi.firstPage`; `lib/firstPages.ts`, a session map of object URLs and "none",
  emptied and revoked on every `sessionEpoch` change and fenced against answers from an earlier
  session; `PaperThumbnail` shows an `<img>` and no longer loads pdf.js.

**Behaviour changes to note:**
- A record whose only file is a `RecordUpload` (no `abstract_file`) used to be drawn from that
  upload; it now shows the outline (`no_manuscript`), because the image is of the served manuscript.
- The first person to see a paper gets the outline once, while a worker draws it.
- Outside Linux the sandbox refuses (`sandbox_unsupported`), so a Django run directly on Windows
  shows outlines; under Docker it draws.

**Deliberate changes to existing tests:** `PaperThumbnail.test.tsx` mocked `manuscriptBlob` and
pdf.js and asserted a canvas. It now mocks `firstPage` and asserts the `<img>` and outline states,
because the component no longer reads the manuscript or draws on a canvas.
