## IR-638

**Requirement:** A cell value the system cannot accept skips its import row and says why

**Design:** Jira IR-638 (no ADR; decided 2026-10-29)

**Implementation:** `apps/records/services.py`: `parse_excel_import` only reads the sheet, and `check_import_row` decides. Title is required. A year is blank or a whole number from 1900 to next year (read strictly: a spreadsheet's `2021` or `2021.0`, not anything Python's `float()` accepts), and Year Completed is not earlier than Year Accomplished. Record Type, Classification and PSCED Classification must match an existing name ignoring case (`ImportChoices`, looked up once per file); blank Classification and PSCED stay blank, and a blank Record Type is Project (a database without Project says so rather than quoting a value nobody typed). Before, a bad year became blank, any number passed, and an unknown name was saved as no Record Type, Classification or PSCED. Every problem in a row is reported on one log line, naming the column and the value, and for names the accepted ones. The importer docstring no longer claims an unknown Record Type "defaults to Project". The template's sample Record Type is the stored `Thesis / Research`, and its notes row (IR-315's "Required" record) is now skipped, since "e.g. 2024" is not a year

**Test:** `apps/records/test_excel_import.py::ImportRefusesValuesItCannotAcceptTests` (8 tests, real `.xlsx` through the endpoint): non-numeric years (`20O4`, `2_024`); years outside 1900 to next year, with 1900 and next year accepted; Completed before Accomplished; unknown Record Type listing the accepted names; unknown Classification and PSCED listing theirs; case-insensitive names with blanks kept; one row with five problems reporting all five while the next row imports; and the downloaded template importing its sample and skipping its notes row. Created and skipped counts are asserted in each. The pre-existing missing-Title test is unchanged

**Evidence:** 2026-10-30, local Docker, on top of IR-637: `apps/records` 266 passed; 2026-10-31, after moving IR-563's Origin and Publication Year checks into `check_import_row`: `apps/records` 300 passed

**Status:** **IMPLEMENTED**. Not changed: the template's sample Classification and PSCED names exist only where someone created them, so on a database without them the sample row is skipped with the accepted names listed
