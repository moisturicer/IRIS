## IR-409

**Requirement:** **The Publish dialog offers the manuscript's own title and abstract as chips** — no FR- id; F3b of the IR-374 frontend redesign spec (§4.5 client behaviour), the client half of IR-406's prefill and assistance toward NFR-U2

**Design:** [IR-374 spec](../../frontend_redesign_spec.md) §4.5 · ADR-008 (no invented confidence)

**Implementation:** `features/publish/prefill.ts` (new) `usePrefill` polls `GET /records/<id>/metadata-suggestions/` while Details is shown: at once, every 2 s while `pending`, every 5 s after 20 s, never past 90 s (`nextPollDelay`); it stops on `ready`/`failed`/`unsupported`, on leaving step 2, on closing the dialog, and on a new upload. **It starts again each time Details is entered**, which closes IR-406's first known gap from the client side: a retrying extraction that reads `failed` and later succeeds still offers chips when the author comes back to Details. A request that fails reads as `failed` (the neutral line), never as an error. Each successful upload bumps a generation that forgets the old file's suggestions and dismissals and drops any reply still in flight for it. `PrefillChip.tsx` (new) is a `group` named *Suggested title*/*Suggested abstract* that reads "Found in your PDF" and the text, with **Use** and **Dismiss**; over a field holding the author's own words the action reads **Replace with suggestion**. Nothing is ever filled without that click. The provisional file-name title counts as the dialog's, not the author's; a resumed draft's saved title counts as the author's, since the file name is no longer known. `pending` shows "Reading your PDF…" under both fields (a still icon, not a spinner, for reduced motion) and disables neither, announced once through one `role=status` line; `failed`/`unsupported` show one neutral line; `expired` (90 s) shows nothing. No confidence value anywhere. `MetadataForm` gains one optional `fieldNotes` slot and knows nothing of prefill, so *Edit details* is unaffected. Submission never depends on it

**Test:** `features/publish/prefill.test.ts` (13, fake timers): the 2 s/5 s/90 s schedule as calls made; stops on each terminal state, on inactivity and at 90 s (`expired`); a rejected request reads `failed`; restarts on re-entry after `failed`; a new generation forgets suggestions and drops a stale reply · `features/publish/PublishDialog.test.tsx` › "prefill from the manuscript" (15, accessible tree): chip only for non-null; Use fills (title and abstract), moves focus, and the chip does not return when the filled text is edited; one polite status line announces it; Dismiss leaves the field; typed field offers Replace and is not overwritten; resumed draft's title offers Replace; pending line with fields enabled; no poll after Back; neutral line, no alert, on `failed` and `unsupported`; Jira's re-entry case (`failed` → Back → Continue → chips); a replaced manuscript offers the new file's suggestion only; submit succeeds with the suggestions request failing; no confidence text, axe clean with chips shown

**Evidence:** 2026-10-29, local: `npx vitest run src/features/publish/prefill.test.ts` **13 passed**; the Publish dialog file **54 passed** (39 existing + 15 new); `npm test` **1266 passed, 101 files**; `npm run lint` 0 errors (no warnings in touched files); `npm run build` green. **Red first:** the hook tests failed with no module, and all 13 dialog tests failed before the wiring while the 39 existing ones passed. One dialog test was corrected deliberately: it dropped a second file without pressing *Replace file*, which the drop zone requires once a file is uploaded

**Status:** **IMPLEMENTED** — nothing is VERIFIED until a person reviews it; the in-browser check against a real Docling extraction is not yet recorded

**Superseded in part by [IR-833](IR-833.md):** Publish now fills a reliable title and abstract in, with Undo, offers labelled authors, keywords and publication year, and replaces the 90-second stop with a backoff that ends in *Check again*. The never-overwrite guarantee is unchanged.
