# IR-1187: Discover: one sort dropdown replaces the For you / Latest / Trending tabs

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). [ADR-062](../../adr/062-personal-discovery-recipe-signals-and-snapshots.md) §Amendment 2026-11-16 (Proposed): Best is the For you feed under a new label.

## What changed

- **One Sort control** (`DiscoverOrderSelect.tsx`), first in the toolbar row: a native `<select>` with the visible label "Sort" and four options, Best, Newest, Most viewed and Trending. The feed tabs (`Discover feed` group) and the results header's Sort select are gone. The results header keeps only the live count.
- **Mapping**, as the ticket assumed: Best is For you (`/records/for_you/`); Newest is Latest by `-created_at`; Most viewed is Latest by `-access_count`; Trending is the server's `trending` ordering. `orderOf` and `withOrder` in `discoverQuery.ts` derive the order from the existing `feed` and `sort` keys, so the URL's spelling is unchanged and saved feeds are untouched.
- **Old links land on the matching option**: `?feed=for_you` is Best, `?feed=trending` is Trending, `?feed=latest` is Newest, `?sort=viewed` is Most viewed. A tab link that also carries a sort (`?feed=trending&sort=viewed`, reachable before by choosing Most viewed and then a tab) opens the tab, whose list ignored that sort anyway, and the URL is corrected to drop it. The tabs never sent that sort anywhere it was used (the For you endpoint reads no `ordering`), so no list changes.
- **Behaviour kept from the tabs:** choosing Best clears the search box, and typing a search leaves Best or Trending for the catalogue, as before.
- **One thing a reader no longer gets back:** the tabs remembered Latest's sort, so Most viewed, then For you or Trending, then Latest (or a search) came back to Most viewed. Now Best and Trending are orders in their own right, so leaving them lands on Newest.
- **Left as it was (not changed here):** a saved feed made on Trending is stored as `sort=viewed` (IR-577), so it reopens on Most viewed (all-time views), not Trending's 30-day ordering. With both now side by side in one Sort, the difference is visible; whether a feed should store Trending is a separate decision.
- **A reader with no Areas** who picks Best gets the server's Latest fallback with "Choose an Area to get recommendations. Showing the latest research for now." (ADR-062 decision 3). This was already the behaviour and is now tested under that criterion. The default order for everyone stays Newest.
- **Sort is always shown**, including over a failed read and an empty list. It used to hide there, but it is now the only way to leave an empty Best.
- **Wording:** "is back in Best", "the papers you saved still shape Best", "You can still browse the newest research", and My feeds' "To save these filters as a feed, sort by Newest, Most viewed or Trending."

## Tests

- `discoverQuery.test.ts`, "one sort for Discover (IR-1187)": the four labels in order; each old link reads as its option; a tab link carrying a sort lands on the tab and is rewritten without the sort; each option produces the same `feed`/`sort` and list `ordering` as the tab or sort it replaces, and round-trips through the URL.
- `DiscoverPage.test.tsx`: the four options in one Sort, opening on Newest, with no tab buttons; Sort's visible `<label>` is its accessible name, Tab reaches it and a change keeps focus; each old link lands on its option; Best with no Areas shows the latest research and says so.
- **Existing tests changed deliberately**, because they queried the tabs or the header Sort: the phone-toolbar tests (row holds a Sort combobox, not a `Discover feed` group; buttons 7→4, and 6→3 for an office reviewer; Sort is 44 px); the chosen-segment test now covers Papers / People only; the control-height test checks Sort instead of the feed track; "Sort in the results header" became "no second Sort in the header"; "no Sort over a failed read or an empty list" became "Sort stays there"; every `For you` / `Latest` / `Trending` button click became a `selectOptions` on Sort; reset-wording assertion reads "Best". In `discoverQuery.test.ts`, the saved-feed test no longer expects a `sort=viewed` saved from For you: that combination cannot be chosen any more and is now parsed away. `MyFeeds.test.tsx` checks the new hint.
- **Limits.** jsdom does not emulate arrow keys on a native select, so keyboard operation is asserted as focusability by Tab and a change keeping focus. The control's look was built to the existing Sort select's style. The reference screenshots the ticket mentions were not available.
