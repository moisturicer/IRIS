## IR-571: Paper Chat runs on the shared Conversation client, and its old lifecycle is deleted

**Requirement.** IR-552 user stories 14 to 16. The Record workspace's Paper Chat behaves like the full-page Ask IRIS when sending, switching, receiving late answers and showing sources, and the frontend has one Conversation lifecycle.

**Implementation.**
- `PaperChatDock.tsx` (the Django path) no longer loads, sends or keeps a transcript itself. It runs on `useConversationClient`, the client Ask IRIS uses.
  - Finding the paper's Conversation (or one named by a citation's return address) goes through the client's new `openFound`, which drops a lookup the reader has moved past, or one that an answer landed during.
  - A paper with no Conversation yet shows none (`showEmpty`). The first question creates or reuses the default (`create({record, reuse_default: true})`, IR-561), hands it to the client, then sends.
  - A late answer, or its failure notice (`note`), lands in the Conversation that asked, never in the paper now on screen. The other paper's composer is free meanwhile.
  - Paper Chat now offers Stop and Retry for a queued run, and follows a run still answering when it opens, exactly as the full page does.
- `send` takes `widen`, so "All papers" is still the reader's choice per question, and mints the request id it passes to `askStream`.
- Deleted: `hooks/useAskStream.ts`, Paper Chat's own hook, and the dock's `sendQuestion`, `conversationFor` and transcript state. `streamAnswer` (the event handling) stays.
- The runtime path (`RuntimePaperChatPanel`, IR-863) is untouched.

**Stop and disconnect.** Paper Chat asks over the same `/ai/ask/stream/` as the full page, so whether it is on IR-548's durable run path is the server's switch (`AI_DURABLE_ASK`), not a choice the panel makes.
- On a queued run, Stop is offered, and a `run_cancelled` ends the answer as the reader's own stop ("You stopped this question"), with Retry, not as a fragment.
- Without a run, no Stop is offered, because there is nothing for the server to cancel. A connection that drops keeps what streamed and shows the partial notice ("cut off before it finished"). The two are distinct messages.

**Tests.** `PaperChatDock.test.tsx` › "Paper Chat on the shared Conversation client (IR-571)", 5 tests: a late answer stays out of the paper on screen and is there on return; Stop on a queued run ends as a confirmed stop; a dropped connection is labelled partial and offers no Stop; Retry of an ended run; following a run still answering on open. The retry and follow tests failed before the change. The other three describe behaviour the old hook already had and pin it. All 21 existing dock tests pass unchanged.

**Retired tests.** `features/ai/hooks/useAskStream.test.tsx` moved to `features/ai/conversation/answerStream.test.tsx`: its 29 tests of `streamAnswer`'s event handling are kept, run through a small test harness in place of the deleted hook. Two assertions went with code that no longer exists: `cancel` (Stop now goes through the client, covered by `RAGChatPage.test.tsx` "stops a run when the reader asks" and the new dock Stop test) and the hook's `detach` clearing its own state (the client clears state in its `finally`).

**Behaviour change.** Closing the Paper Chat panel while an answer is arriving now stops following it, as leaving the full page does. A queued run carries on; a request-bound answer is stored by the server as a partial one.
