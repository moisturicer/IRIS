# IR-1349: "Don't show tours again" for the student tours

[Back to the matrix](../TRACEABILITY.md)

**Requirement:** Lee Jasmin Adolfo (project lead and frontend owner) decided this on 2026-11-28, from a clickable prototype. It adds one thing to IR-1342 and changes nothing else about it. The decisions are recorded on IR-1349. There is no ADR and no FR- id.

- Every student tour card shows a **Don't show tours again** tickbox. The Review workspace tour (IR-997) does not.
- It is one account setting. **Settings › Help › Guided tours** shows the same tickbox at the top, so it can be turned back on there.
- While it is set, no student tour starts by itself on any page or in Publish. Help's *Take the tour* links still start one.
- The label says *tours*, not *this*: each tour already shows once, so the tickbox only matters for tours not yet seen.
- IR-1342's decision 4 holds: tours are taken again from Settings › Help only, and pages have no tour button.

## Design

**Backend**
- `User.tours_off` (boolean, default false), added by migration `0026_tours_off`. No data migration: accounts from before IR-1342 have already seen every tour.
- The only write is `PUT /users/me/tours-off/` with `{"off": true|false}`, through `apps/accounts/tours.set_off`. It acts on the signed-in account alone and writes nothing but `tours_off`. Anything but a JSON boolean is a 400, so `"false"` is never read as set.
- Read-only on `/users/me/`, absent from the administrators' `/users/`, and in the personal data export (ADR-051 decision 13).

**Frontend**
- `GuidedTour` gained an optional `optOut` prop (label, checked, onChange), drawn as a tickbox above the buttons. The Review tour passes none, so it is unchanged.
- `useStudentTour`:
  - A tour does not start by itself while `tours_off` is true. `?tour=` from Help still starts it.
  - The card's tickbox starts as the account has it. Whatever it holds is saved when a tour that showed a step closes (Skip tour, Escape, Done, or leaving the page), and only if it changed.
  - Ticking it raises an info toast: "Tours won't start by themselves. Turn them back on in Settings › Help.", with **Open Settings**, which goes to `/settings?tab=help`. Unticking it raises no toast.
  - A failed save puts the store back and raises an error toast.
- `features/onboarding/toursOff.ts` holds the label, the Settings address and `saveToursOff`, which updates the store at once (so the other place it is shown agrees) and reverts it if the server refuses.
- `GuidedToursHelp` shows the tickbox first, with a line saying what it does, and saves as soon as it changes. A status line says it was saved, or that it could not be.
