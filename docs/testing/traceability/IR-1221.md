## IR-1221

**Requirement:** **Paragraphs of long reading text are justified, with hyphenation; short text, titles and controls are not.** Requested by Ashlee Sean on 2026-11-17, beside IR-1218 (the Full Text Rule) and IR-1219. No ADR: it is a visual rule, recorded in `DESIGN.md`'s Full Text Rule, point 4. No FR- id.

**Decided by Hermoine Zozobrado, 2026-11-18:** justified at every width, phones included. The ticket allowed left-aligning below `sm` if a phone's gaps were distracting. The 360 px check below showed wider gaps and more hyphens than on a laptop, and Hermoine chose to accept them. So there is no breakpoint and no container query: the text fills whatever box it has.

**Implementation:**
- **One utility,** `.text-justified` in `frontend/src/index.css` (`@layer utilities`): `text-align: justify` and `hyphens: auto` (with `-webkit-hyphens`). `frontend/index.html` already declares `lang="en"`, which hyphenation needs.
- **Where it is applied:**

  | Text | File |
  |---|---|

  | An open revision request's reason, on the Overview | `records/paper-view/PaperViewPage.tsx` |
  | The AI Overview's paragraphs (`[&_p]:text-justified` in `OVERVIEW_MARKDOWN`) | `ai/components/answerLayout.ts` |
  | Help's paragraphs (`[&_p]:text-justified` on the section body) | `help/HelpPage.tsx` |
  | A call's description | `opportunities/CallDetails.tsx` |
  | The data notice's text | `auth/notice/NoticeText.tsx` |
  | Conversation comments | `records/paper-view/CommentItem.tsx` |
  | Thread bodies, suggested wording, the author's answer, replies | `records/paper-view/threads/ReviewThreads.tsx` |
  | Timeline entries (`CommentBody`) | `records/paper-view/ReviewTimeline.tsx` |
  | The response letter's comment and answer | `records/paper-view/threads/ResponseLetter.tsx` |

  | The tracker's request messages, rejection reasons, revision reasons and routing reasons | `records/paper-view/ReviewRoutingTracker.tsx` |

  The two variant classes were checked in the built CSS: `.\[\&_p\]\:text-justified p` is emitted beside `.text-justified`.
- **Not applied:** titles, headings, labels, buttons, badges, table cells, form fields, and short one-line text. Text clamped to a few lines is not justified either: its last visible line isn't the paragraph's last, so it would be stretched. That covers a list card's abstract preview (`ResearchCard`, left as it was after a local look at Discover at 1280 and 360 px) and a call's description on the board, which is justified only where it is shown whole (`CallDetails.tsx`, `clampAbout`). Removing that clamp is IR-1219's (the Full Text Rule). A justified paragraph's last line stays left-aligned, so a one-line comment looks as it did.
- **`DESIGN.md`:** the Full Text Rule gains point 4, which says which text is justified and which is not.

**Code review (two axes, 2026-11-18), and what changed:**
- Standards: `text-reading` read like a size token or the `reading` container, so it was renamed `text-justified`. A person's name was taken out of the code comments; the decision stays in `DESIGN.md` and here. A call description clamped to two lines broke the Full Text Rule and was justified; it now is not (the clamp is IR-1219's). Left as is: the repeated screen lookup in the smoke spec, and the repeated class string.
- Spec: review text in the tracker, a timeline note, the Publish abstract and two admin texts were added (table above). Left as is: Discover's previews (clamped), `DESIGN.md` point 4's length, and the matrix's use of PARTIAL.

**Tests:** `e2e/smoke/full-text.spec.ts`, *justified reading text*, at 360 and 1280 px. It opens the paper view and reads the abstract's computed style: `text-align: justify` and `hyphens: auto`. No unit test: jsdom computes no Tailwind CSS, so a vitest test could only check for a class name.

Written first and failed at both widths (`"align": "start"`). After the change: `full-text.spec.ts` 3 passed, its IR-1203 test included.

**Visual check (local, 2026-11-18):** smoke-tier build (`npm run build`, mocked API), Chromium. The real paper view with a ~180-word abstract, and the Help page's first section, each at 360, 1280 and 1745 px. Screenshots are local only and not committed.
- **1280 and 1745 px:** both edges straight; word gaps barely wider than normal; a hyphen on about one line in three.
- **360 px:** both edges straight; some lines show visibly wider gaps (*"ings crossed agronomically derived"*), and about every other line ends in a hyphen. Accepted by Hermoine, as above.
- **Help:** paragraphs justified at all three widths, and the section heading unchanged.

**Trade-off:** WCAG 1.4.8, at AAA level (IRIS targets AA), advises against justified text, because uneven word gaps slow some readers, for example people with dyslexia. Hyphenation keeps the gaps down. This is a design choice the team accepts, not an AA failure.

**Not checked:**
- Firefox and Safari: only Chromium was looked at. All three support `hyphens: auto` for English.
- Ask IRIS answers, profile bios and saved replies were left out: they are not in the ticket's list.
- The review surfaces (threads, timeline, letter) were not screenshotted. They use the same utility as the abstract.
