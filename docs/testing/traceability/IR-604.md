## IR-604

**Requirement:** **Each paper gets a one-sentence hook, written with the Overview** — no FR- id; part H of IR-425's spec, needed by IR-567's Discover card

**Design:** [ADR-015](../../adr/015-voyage-embedding-and-reranking.md) (the disclosure gate applies to a stored hook as to the overview)

**Implementation:** `apps/ai/overview/hook.py` — `HOOK_INSTRUCTION` and `split_hook` (the `HOOK:` line is taken off the reply before citations are parsed; markers and markdown are stripped; a hook over 145 characters is dropped, never cut) · `apps/ai/overview/service.py` — the same completion yields the overview and its hook, `hook_for()` serves it only from a ready row at the current `PROMPT_VERSION` behind `vendor_permits()`; `PROMPT_VERSION` 5 · `RecordOverview.hook` (migration 0031) · `ai_hook` on the record list and detail serializers, the list queryset joins `ai_overview` · `cardHook()` in `discoverUtils.ts` falls back to the abstract's first sentence

**Test:** `apps/ai/tests/test_overview_hook.py` (split, length limit, one completion, regeneration clears the hook, list and detail payload, fallback `null`, not-ready and old-version rows, gate refusal, hidden draft gives a 404 and no hook) · `frontend/src/features/discover/cardHook.test.ts`

**Evidence:** Run locally 2026-10-16 against the dev Postgres: `test_overview_hook.py`, the overview tests and `apps/records` pass. **Red first:** the module failed to import before `hook.py` existed

**Status:** **IMPLEMENTED** — one completion also carries the hook, so the whole paper is sent once; an unreadable hook line costs only the hook. `PROMPT_VERSION` 5 makes every stored overview regenerate, so cards use the abstract fallback until then; `ai_hook` on `/ai/search/` and chat Record cards is left to IR-575 and IR-577; a hook is not re-checked against `content_hash` on read, only reset when chunking claims a new generation
