# IR-1138: RDCO tools follow the prototype, with queue counts in the sidebar

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Part of epic IR-920 (S2 Frontend UI/UX Redesign).

## What changed

- `GET /dashboard/queue-counts/` (`QueueCountsView`, RDCO only) returns the pending download, delete and role request counts. Role requests count verified accounts only, as the Role Requests queue lists them.
- The sidebar reads it once for RDCO, again when the address changes and when a queue page calls `queueCountsChanged()` after a decision (`lib/queueCounts.ts`). Role, Download and Delete requests each show a count with the accessible name "N pending"; nothing at zero or when the read fails. Any other role never asks. The older role-requests read and its "waiting" wording are gone.
- Pages follow the prototype: Import records (three step cards over one upload area), Users (description, search placeholder), Role requests (description, "No role requests" empty state), Download requests (description, Approve primary, Decline quiet), Delete requests (description, Decline quiet; Approve deletion stays the danger button), Notices (publish form beside a "Live now" panel).

## Tests

- `backend/apps/records/test_queue_counts.py`: empty queue, RDCO sees only pending, student and ITSO refused, anonymous refused.
- `Sidebar.test.tsx`: three counts, none at zero, none on a failed read, falls after a decision without a reload, Student, ITSO and System Admin never ask.
- `RoleRequestsPage.test.tsx` changed deliberately: "All caught up!" became the "No role requests" heading.

## Evidence and limits

- Ran locally 2026-11-15: Sidebar, admin, accounts and Import page tests (131) pass; `tsc --noEmit` clean.
- **The backend test was not run locally** (no database or `.env` in this worktree); CI is its first run.
- **Not checked in a browser.**
- Added after the first pass, each with its backend:
  - **Delete requests tabs** Pending, Approved, Declined and All with counts (`GET /records/delete-requests/counts/`, RDCO only; `?status=all` lists everything). This reverses IR-1076's "no tab that mixes the two": an action still appears only on a pending row, and the test that asserted no All tab was rewritten on purpose.
  - **Users** Unit (department, else college), Last active (`last_login`) and a role filter (`?role=<name>` or `office`).
  - **Notices Save draft**: one server-side `NoticeDraft` (migration `accounts/0023`), RDCO only via `/auth/notice/draft/`, restored when the page opens and removed by a publish. Never a version and never counted in the impact.
  - **Import records** takes a UTF-8 `.csv` as well as a sheet, authors split on `;` or `,`, a `File Name` column naming PDFs uploaded in the same request (`pdfs`), and a `check` mode that writes nothing and lists every row's problems. A named PDF becomes the record's manuscript through `manuscript_changes` and `reset_manuscript`, as `load_corpus` does, so it is sent to extraction like any upload; the record is embargoed with its AI answer unset, so nothing reaches AI until RDCO releases it. The page checks first, and Generate stays off until a check finds a row to import.
- Tests added: `test_user_list_columns.py`, `test_notice_draft.py`, `DeleteRequestStatusCountsTests`, `CsvAndPdfImportTests`, and page tests for Users, Delete requests, Notices and Import.
- **None of the backend tests ran locally** (no database or `.env` here; PDF validation also refuses off Linux). CI is their first run, and the PDF attach path especially has had no real run.
- Still not built: the prototype's "IRIS reads the abstract from the PDF" (`backfill_abstracts` is a command, not part of the import), and Adviser and Program columns in the import sheet.
