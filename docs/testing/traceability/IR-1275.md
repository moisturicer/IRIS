# IR-1275: SRS v2 and SDD v2 (MVP as built)

**Requirements:** none changed status. Documentation only.

`docs/SRS-v2.md` and `docs/SDD-v2.md` describe the MVP as built at commit `a46d7fc4`, as thesis deliverables. They are derived from `docs/adr/` and the code; where they differ, the ADRs and code win. `docs/SRS.md` and `docs/SDD.md` are untouched, as the v1 record, and CLAUDE.md's freeze still applies to them.

Every status line in SRS v2 is copied from `TRACEABILITY.md` at `a46d7fc4`. No row of `TRACEABILITY.md` was changed, and no label was renamed. SRS v2 Appendix A maps v1 IDs to v2 IDs and to this matrix's labels, including the labels the matrix reuses with a different meaning (for example FR-M6-02).

Also in this change:

- **ADR-010 amendment, Proposed**: production is one AWS EC2 instance running the Compose stack. It awaits Ashlee Sean's approval.
- **Six new figures** (`docs/diagrams/srs-sdd-v2/`), drawn by the Section D renderer. V-1 and V-2 correct D-16 and D-17 for ADR-067, ADR-074 and ADR-052's 2026-11-21 amendment. Section D's renderer gains two optional environment variables (`DIAGRAM_SRC`, `DIAGRAM_OUT`); unset, it renders Section D byte for byte as before (checked by re-rendering D-16 and seeing no file change).

Contradictions found while writing are listed in SRS v2 §4 (Known Gaps), not reconciled here. One of them, for the matrix's owners: row IR-667 says system settings are RDCO's only, but the code (`SystemSettingView`, `IsSystemAdmin`) and ADR-051 decision 3 give them to the System Admin.
