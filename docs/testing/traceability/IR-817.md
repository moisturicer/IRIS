# IR-817: Paper View shows a paper's embargo and offers Extend, Release and KTTO's release

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** ADR-052 decisions 5, 6 and 11, and decision 18 for who sees it. No FR- id.

**The card:** `frontend/src/features/records/paper-view/EmbargoCard.tsx`, an "Embargo" card in Paper View's Record details rail, under Institutional Governance, on the Overview tab. It shows the state and date to whoever the API sends `embargo` to, and nothing to anyone else.

- **Unknown:** "Not answered". Nobody has said, so the paper stays out of the AI.
- **None:** "No embargo".
- **Active:** "Under embargo" with the review date, and a line saying the date is a reminder and the embargo lasts until someone releases it.
- **Released:** "Released", with the date it was due for review.

**Controls, each from `capabilities` alone.** The card compares no role names.

- `set_embargo`: "Set embargo", or "Change date" on an active one. It opens a dialog with a date field whose minimum is today in Manila. When the paper is "no embargo" or released, the dialog warns first that text already sent can't be recalled, and the server's own notice shows after saving.
- `release_embargo`: "Release embargo", which asks first. The dialog says the text can then go to outside AI companies, unless an IP mark or missing consent still holds it back, and that this can't be undone.
- `release_ip`: "Release IP mark", which asks first in the same way and says the paper stays marked as IP.
- **A viewer offered no release,** a student owner for example, sees "Only the paper's Adviser or RDCO can release it" on an active embargo.
- **A refusal** shows the server's message in the dialog: `fieldError` for the date, else `errorDetail`. A refused release also reads the record again, so an offer the server has withdrawn goes away.
- **After any act,** Paper View reads the record again (`reloadRecord`), so the state and the offers update.

**KTTO's release is shown too,** a choice made while building this. `RecordDetailSerializer.ip_release` is `{released, released_at}`, sent for a marked paper to the same people as `embargo` (`may_read_embargo`), and null otherwise. Institutional Governance shows it as an "IP Release" row, and now has an accessible name.

**Tests:**

- `EmbargoCard.test.tsx`: each state's wording, which capability turns on which control, both dialogs, the warnings, the server's errors and notices, cancelling, and axe on the card and both dialogs.
- `PaperViewPage.test.tsx`: the card in the rail, a release that reloads the record, the governance row, and the card and both dialogs at a 360 px workspace with axe.
- `apps/records/test_ip_release.py::WhoSeesTheReleaseTests`: who receives `ip_release`.

**Evidence, 2026-11-03:**

- **Failing first:** `WhoSeesTheReleaseTests` failed before the field (`KeyError: 'ip_release'`). `EmbargoCard.test.tsx` failed before the component existed, and the three page tests failed before the card was in the rail.
- **A real server, on a copy of one developer's dev database** migrated forward and given `seed_demo`'s answers, over HTTP as `student@`, `adviser@`, `rdco@`, `ktto@` and `itso@cit.edu`:
  - The embargoed demo paper was offered Set to the student, Set and Release to the Adviser, Release to RDCO, and nothing to KTTO or ITSO.
  - The student's release got 403. The Adviser's worked, a second got 400 "This paper isn't under an embargo.", and holding it again returned the can't-be-recalled notice.
  - On a published IP-marked paper, `ip_release` was null to a student who doesn't own it, and offered only to KTTO. RDCO's release got 403. KTTO's worked, the offer went away, and a second got 400.
- **Frontend suite:** `npx vitest run --maxWorkers=2` passed 1,746 of 1,747. The failure was this change's: `readingStandards.test.ts` refuses pixel font sizes, and the card's dialog used `text-[14px]`. It now uses the scale's `text-sm`, which is 14 px, and the test passes. `tsc` is clean, and lint reports nothing in the changed files.
- **Full backend suite:** left to CI. On Windows about 134 tests fail for reasons outside this change (`resource` is Unix-only; `pytest-xdist` is missing), so the Linux run is the record. The affected tests (`test_ip_release.py`) and `flake8` pass locally.
- **360 px:** jsdom computes no layout, so the tests prove the controls and dialogs work and pass axe at that width, not that nothing overflows. A look in a real browser at 360 px is still to be done.
- **Review:** a standards review and a spec review ran on the diff. They led to the released wording ("Held until" read as if the paper had been held to that date), the release dialog's condition on IP and consent, a refused release reading the record again, a named `IpReleaseResult` type, and `ip_release.detail_payload`.

**Known limits:** Built to work now, and Adolfo may restyle it. The card shows on the Overview tab only, and folds away while Ask IRIS is open, like the rest of the rail.

**Status:** Implemented; awaiting review.
