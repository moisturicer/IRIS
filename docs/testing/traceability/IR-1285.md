## IR-1285 — Ask IRIS works after `migrate` without re-provisioning the research roles

**Basis and scope.** IR-1285 (bug). Observed 2026-11-23 on a local stack at main 82705eef: every Ask IRIS question ended "IRIS could not finish this question.", the run `failed`/`unavailable`, the worker logged `unauthorized`. No ADR change: this restores the access ADR-049 and IR-1227 already describe.

**Cause.** `ai/0049` (IR-1227) made `iris_authz.research_record_ids()` read `records_record.added_by_id` and left the grant to `provision_research_roles`, which the Compose `migrate` service never runs. The function is SECURITY DEFINER as `iris_authz_verifier` and backs every `reader_session` read, so it raised `permission denied for table records_record` and every runtime tool call failed. `provision_research_roles --check` still printed `research roles: ok`: it never checked column grants.

**What exists now.**
- Migration `ai/0052_verifier_reads_added_by` grants the verifier SELECT on every column `research_record_ids()` reads (`records_record`, `accounts_user`, `accounts_role`, `records_recordowner`), skipped when the role does not exist, as `ai/0050` and `ai/0051` grant theirs. It is kept on reverse, like those.
- `provision_research_roles --check` reports each column in `VERIFIER_COLUMNS` the verifier may not read; a table or column this database does not have is not reported.

**Tests.**
- `backend/apps/ai/tests/test_verifier_column_grants_db.py` (real PostgreSQL): with `added_by_id` revoked, `--check` fails naming the column; `0052`'s SQL restores it and `--check` passes; on a database without the verifier role it does nothing.
- Unchanged and passing: `test_research_grants_db.py`, `test_research_read_policy_db.py`.

**Runs** (2026-11-23, Windows 11).
- The three files above: 31 passed.
- On a copy of the dev database (at `ai/0051`, `added_by_id` revoked to match the failing stack): `--check` reported `cannot read records_record.added_by_id`; `migrate ai` applied `0052`; `--check` then `ok`; reversed to `0051` and reapplied cleanly.
- flake8 (as CI) on the changed files: clean. `makemigrations --check`: no changes.
- CI runs the full suite on the pull request.

**Not done here.**
- The `migrate` service still does not run `provision_research_roles`; a future function reading a new column must grant it in its own migration.
- A paid provider stream that breaks mid-answer (`provider_failed`, seen once while reproducing this) is not addressed.
