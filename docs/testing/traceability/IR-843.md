# IR-843: Docling retired

**Requirements:** FR-M3-01

ADR-056 decisions 1 and 8, and its Deployment Impact. LlamaParse is the only Extractor.

## What was removed

- The `docling` service in `docker-compose.yml` and `docker-compose.prod.yml`, and the `docling/` build (`Dockerfile`, `compose.yml`, `iris_gpu_cap.py`, `patch_docling.py`). There is no `docker-compose.override.yml` in the repository.
- GPU detection, `DOCLING_VARIANT` and `--refresh-gpu` in `scripts/setup_env.py`, and `DOCLING_VARIANT` in the e2e environment.
- `DoclingExtractor`, `docling_mapping.py`, every `DOCLING_*` setting and the Docling wording in the Celery routing comments. `scripts/benchmark_docling.py` and its test went with the adapter they called.
- The unused Docling request schemas in `ai/api/schemas.py`.
- `reextract_manuscripts`' refusal while the backend was Docling, and `configured_backend()`, which only that refusal read.
- IR-738's `ai/ingestion/extract_worker.py` launcher and its image, chosen by the project owner on 2026-11-04. Its only Extractor was Docling. The worker core, `ai/ingestion/extraction.py`, stays and takes any Extractor. `LocalSource` moved into it.
- From the generic chunking path: repeated-furniture detection (IR-247), stranded page numbers and the roman-numeral folio rule, hyphen rejoining, and the context path's numbering floor and unnumbered-heading placement (IR-242, IR-248, IR-314).

## What stayed, and why

- **Depth from numbering** (`chunking/numbering.py`). The ticket lists it for deletion, but ADR-056's IR-859 amendment keeps it and moves it into LlamaParse shaping, where `shaping.py` reads it. The ADR wins, so only the context path's copy was deleted.
- **Hyphen rejoining is deleted.** IR-851's run found no broken words in LlamaParse output, only Docling's ([report](../../evaluation/runs/20261103-ir851-llamaparse-six/report.md)).
- **Running headers and footers by label** and **excluded sections**: they read labels and names, not Docling's output.
- **The `page_header`/`page_footer` kinds**: structures Docling stored before this ticket still carry them.

## Startup

`EXTRACTION_BACKEND` accepts only `llamaparse`, now the default. The project owner chose, on 2026-11-04:

- With `DEBUG` off, Django refuses to start without `LLAMAPARSE_API_KEY` and a dated `LLAMAPARSE_VERSION`.
- With `DEBUG` on, it starts. `current_extractor()` then returns `UnconfiguredExtractor`, which raises `ExtractorUnavailable`, so a read fails without sending anything.

The e2e stack runs production settings, so `e2e/scripts/make-env.mjs` now writes a placeholder key.

Changed rather than retired:

- `test_chunking_a_normalized_document_drops_removed_artefacts_but_keeps_content` no longer feeds a split word or a stray page number.
- The no-content-loss property no longer interleaves page numbers.
- `test_celery_routing.py` was renamed from Docling to "extractor".
- `test_container_egress.py` no longer expects a `docling` service.
- `test_dev_ports.py` expects four published ports, not five: Docling's is gone.
- Changed deliberately, not to make the tests pass: four tests now supply LlamaParse settings, because production startup requires them.
  - `test_transport_security.py` and `test_client_address.py` start the production settings in a subprocess.
  - The two `test_django_startup_runs_the_check` tests (research reads and research grants) call `AiConfig.ready()` under pytest's `DEBUG=False`.
- `test_selection.py`: the `use_extractor` tests now assert that the unconfigured stand-in comes back after the block.

New tests in `test_selection.py`:

- `test_an_unknown_backend_refuses_to_start` (Docling is now the unknown value)
- `test_llamaparse_is_the_only_backend`
- `test_development_starts_without_a_llamaparse_key`
- `test_production_refuses_to_start_without_a_llamaparse_key`
- `test_an_unconfigured_extractor_fails_the_read_as_unavailable`

## Evidence

All runs were on Windows, on an isolated test database, with `AI_RESEARCH_LANE=off AI_JEV_ROUTING_ENABLED=False`. Run on 2026-11-04.

- **Full backend suite on this branch:** 147 failed or errored.
- **The same 147 on unmodified `origin/main`:** 138 failed there too. Almost all are PDF intake answering "PDF checking is temporarily unavailable" on this host, which is environmental, not from this change.
- **The other 9 were caused by this change and are fixed above.** Re-running the failing set together with `apps/ai/extraction` and `apps/ai/ingestion` showed no failure beyond the 138. A later run of `apps/documents`, `test_reextraction`, `test_runtime_extraction` and `test_celery_routing` showed none either.
- **`docker compose config`:** validates for `docker-compose.yml` and `docker-compose.prod.yml`.
- **Not run:** the e2e journeys, and the frontend build (its edits are comments only).
