## IR-1209

**Requirement:** **Selecting text in the paper reader stays on the text being dragged through** — no FR- id; a bug reported in team testing, 2026-11-17

**Cause:** a page's text layer is transparent spans over the canvas, with gaps between them (margins, leading, the space between columns). Over a gap the pointer is over no text, so the browser resolved the selection's end to whatever text came next in the layer's DOM order: the next line, the other column, the rest of the page. pdf.js's own viewer (`TextLayerBuilder`) prevents this with an `endOfContent` element in each layer and a `selecting` class while a selection is made; IRIS draws its layers with pdf.js's bare `TextLayer` (`lib/pdf.ts`, IR-353), which has neither. The watermark (IR-1128/IR-1198) and the review-thread and citation overlays take no pointer events and were not involved.

**Implementation:** `frontend/src/lib/textSelection.ts`, `bindTextSelection(layer)`: a port of `TextLayerBuilder`'s selection handling (pdfjs-dist 6.3). Each bound layer ends with an `.endOfContent` element; a press, or a selection reaching the layer, marks it `.selecting`; pointer release, window blur, a key release outside a drag, or a cleared selection puts every layer back. In browsers that still resolve gaps by DOM order (Chromium before 148, Safari) the element is moved to just after the text where the selection ends, stepping out of a Find `<mark>` so it never lands inside a word; Firefox and Chromium 148+ skip the move, as in pdf.js. One set of document listeners serves every layer. `index.css` adds pdf.js's two rules: the element sits below the page, and covers the whole layer behind the spans while `.selecting`. `PaperPdfReader.tsx` binds each page's layer once its spans are drawn and unbinds on cleanup.

**Test:** `lib/textSelection.test.ts` (9, jsdom): one end element after the text; `.selecting` from press to pointer release; only the pages the selection touches; the element moved after the selection's end; stepping out of a find match; reset on a cleared selection and on window blur; no move in Chromium 150; unbinding removes the element and the listeners. **Real drag, in Chromium:** `e2e/smoke/text-selection.spec.ts` with a two-column PDF (`twoColumnPdf` in `e2e/support/pdf.ts`): a drag along one line ending over the gap between the columns selects only that line, and a drag across two lines of one column ending over the gap selects only those lines. Highlights, Find, citations and the watermark: the existing `features/records/paper-view` suite.

**Evidence:** 2026-11-18, local, Playwright's Chromium 153. Built **without** the fix, both drag tests failed: the one-line drag selected "Left column line one" and "Left column line two". Built with it, both passed, 5 runs each (`--repeat-each=5`, 10 of 10). `npm test` **237 files, 3455 passed** (3 skipped); the whole smoke tier (`npm run test:smoke`) **444 passed**; paper-view tests 56 files, 986 passed; `tsc` and `eslint` clean. Not checked by hand: Safari and Firefox, and a real two-column thesis.
