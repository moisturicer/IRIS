# IR-366: Close the frontend palette guard

**Requirement:** IR-357 palette rollout; IR-366

IR-366 closes the staged white / black / stone / maroon rollout.

The six remaining shared `gray` / `slate` files are converted to `stone`, touched literal maroon values are replaced with `brand` tokens, and `src/test/palette.test.ts` no longer contains `NOT_YET_CONVERTED`, `GREY_NOT_YET_CONVERTED`, or a translucent-white exception list.

The guard now checks every frontend source file with no palette allowlist. It rejects:

- off-palette hue utilities;
- `gray` / `slate` colour utilities beside the canonical `stone` grey;
- see-through white backgrounds.

Executed evidence:

- RED: 1 failed / 11 passed after removing the allowlists first; the failure named exactly the six remaining second-grey files.
- GREEN: palette guard 12 / 12.
- Regression proof: a throwaway `bg-red-500` in `StatusBadge.tsx` made the guard fail and name that file/class; reverting it returned the guard to green.
- Full frontend: 130 files / 1,703 tests passed.
- TypeScript, lint, and production build passed.
- Routed-screen headless Chromium visual pre-pass completed; screenshots are PR review evidence.

`docs/ui-ux/01-design-system.md` now describes the palette as applying to the whole interface and names the guard as enforcement. `14-component-inventory.md` records that the staged exception lists are gone.
