## IR-1184

**Requirement:** **A keyboard user can skip the sidebar to the page's content** — WCAG 2.1 AA 2.4.1 Bypass Blocks; no FR- id; found by a keyboard-only pass, 2026-11-16

**Cause:** the sidebar comes before `main` in the app shell and there was no skip link, so a user tabbed through every sidebar stop (about 16 for RDCO) on each page before reaching content.

**Implementation:** `frontend/src/components/layout/AppShell.tsx`. A "Skip to content" link is the first element of the shell, so the first Tab on a loaded page lands on it. It is `sr-only` until focused, then a fixed white-on-maroon chip (`bg-brand`, `text-white`) at the top left above the drawer and backdrop, with the shared `FOCUS_RING`. Its click handler focuses `main` itself (no hash change, no router involved); `main` gained an id and `tabIndex={-1}` (a focus target, not a tab stop) and `focus:outline-none`, since it is a region, not a control. While the phone drawer is open the page behind it is inert, and so is the link.

**Contrast:** `#6B0F12` against `#FFFFFF` is **12.34:1**, computed with the WCAG relative-luminance formula (axe cannot check colour under jsdom). Required: 4.5:1. The link's own focus ring is the existing maroon ring on a white offset.

**Test:** `AppShell.test.tsx`, "skip link" (3): the first Tab focuses the link by role and name, and Enter puts focus on `main`; the link comes before the sidebar (the second Tab reaches the sidebar, and after Enter focus is outside it); and after a route change, with focus back at the document, the first Tab is the link and Enter lands in `main`. Hidden-until-focused is a CSS state jsdom cannot see and is not asserted.

**Known limit:** nothing moves focus when a route changes. After a click on a sidebar link, focus stays on that link, so the next Tab goes to the next sidebar item; the skip link is the first stop after a load, a reload or back/forward, and again once focus is reset to the page. Moving focus on every navigation would be a separate decision.

**Not checked by hand:** a real browser, Safari and Firefox, and a screen reader.

**Status:** **IMPLEMENTED**; awaiting CI and review.
