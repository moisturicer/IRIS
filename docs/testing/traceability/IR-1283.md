# Traceability — IR-1283

## IR-1283 — Edit profile: a photo change enables Save and is saved only by Save

**Basis and scope.** Bug against IR-933's Edit profile page (`/profile/edit`), which holds IR-699's photo field. The photo uploaded as soon as its crop was confirmed, and Remove photo deleted it at once, while Save counted only the name, bio and research interests. So a photo change left Save disabled, and Cancel could not undo it. Now `PhotoCropDialog` only returns the framing, `PhotoField` shows the framed photo (or the initials, after Remove photo) as a change not yet saved, and `EditProfilePage` sends it with Save after the name and the fields. Cancel sends nothing. This alters IR-699's "the photo saves when the crop is confirmed" and IR-933's "the photo saves as soon as it is cropped". The API (`src/api/profile.ts`) is unchanged.

**Tests.** `src/features/profile/EditProfilePage.test.tsx`, through the accessible tree with axe: a cropped photo is shown, uploads nothing and enables Save, and Save uploads the framed square and sends nothing else unchanged; Cancel after a crop uploads nothing; arrow-key framing reaches the upload on Save; a refused photo shows the server's message on the page and Save stays enabled; Remove photo deletes only on Save; Cancel after Remove photo keeps the photo.

**Executed evidence (2026-11-23).** `npx vitest run src/features/profile`: 3 files, 62 tests passed. `tsc --noEmit` passed; eslint on `src/features/profile` reported nothing. The full suite is left to CI. Changed deliberately: the server's photo refusal was asserted inside the crop dialog, and is now asserted on the page after Save, because the upload moved there.
