## IR-1051

**Requirement:** **Trial chunk sets: `eval_retrieval` measures a chunker or extractor variant without replacing the live chunks**. Subtask of IR-980, no FR- id.

**Design:** [ADR-033](../../adr/033-hybrid-retrieval-and-passage-selection.md) §5 (a technique is switched on only after a harness run) · [ADR-067](../../adr/067-unstructured-replaces-llamaparse.md) · Jira IR-1051

**Implementation:**
- `ChunkSet.trial_variant` / `trial_spec` (migration `ai/0047`). The constraint `trial_chunk_set_is_never_active` means a trial set can never be active. A second constraint allows one trial set per record per variant.
- Every reader path reads the active set and is unchanged: Django retrieval, the AI runtime's research tools, the AI Overview, similarity and the status count. `apps/ai/retrieval/scope.py` lets `TwoStageRetriever` and `FullTextRetriever` read a trial set instead. Only `CompositionRoot.for_trial` sets that, and only `eval_retrieval --variant` calls it.
- `apps/ai/trials.py`:
  - parses `NAME=<extractor>:<strategy>:<options>`;
  - chunks each record's stored extraction in memory, so dry-run and plan cost nothing;
  - carries vectors over by `text_hash` and embeds only the rest, behind the indexing disclosure gate and outbound fence;
  - applies heading trail on/off/shuffled after chunking;
  - records the chunking provenance for run files;
  - deletes trial sets.
- `eval_retrieval --variant/--token-ceiling` honours `AI_EMBEDDING_TOKEN_CEILING`. Every run file records `provenance.chunking` (variant, extractor, strategy, options, tokenizer), including runs on the active set.
- New command `cleanup_trial_chunk_sets --variant NAME | --all | --dry-run`.
- `reextraction.rollback` no longer treats a trial set as the previous version to restore.

**Test:** `apps/ai/tests/test_trial_chunk_sets.py` covers:
- the variant grammar;
- trail off/shuffled/on;
- a trial set cannot be made active;
- trial sets stay out of reader paths: Django vector and full-text retrieval, the status count, similarity and the AI Overview;
- only a trial root retrieves the trial set;
- rollback skips trial sets;
- an identical variant embeds zero chunks;
- trail-off embeds only the changed text;
- a rebuild sends nothing;
- a name reused for a different spec is refused;
- a different extractor is skipped, not re-read;
- an embargoed paper is not embedded;
- provenance;
- cleanup removes only trial sets;
- command dry-run, the ceiling refusal, and a variant run and an active run both writing provenance.

`apps/ai/tests/test_ai_runtime_research_db.py::test_a_trial_chunk_set_is_never_searched_or_read` covers the runtime `search` and `read_page` tools.

**Evidence:** 2026-11-14, worktree, local Postgres: the new file plus the new runtime test, 33 passed, none skipped. The full backend suite was not run locally; CI runs it.

**Not done:**
- the heading trail on/off/shuffled run on the proxy corpus. It spends Voyage credits and must be run by a person; the run file goes under `docs/evaluation/runs/` with the proxy-tier caveat (ADR-023);
- migration `ai/0047` has not been run against a copy of the dev database.

**Status:** **PARTIAL**. Implemented and tested; awaiting the committed trail run, the migration check on a dev-database copy, CI and review.

**Known limits:**
- Trial vectors share the HNSW index with the live ones, so while trial sets are stored they take part of every scan. Run the baseline with the same trial sets present and clean up afterwards.
- Comparing extractors needs two stored extractions per paper, and `PdfExtraction` keeps one manuscript extraction per record. A variant naming another extractor skips those papers rather than re-reading them (IR-989 needs that storage first).
- A carried-over vector was computed with the live set's neighbours as context.
- The ingestion idempotency key still ignores options; trial sets do not go through ingestion, so they do not depend on it.
