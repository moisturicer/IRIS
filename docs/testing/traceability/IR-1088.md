# IR-1088: One button component, with a legible disabled state

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Audit findings VIS-04 (one action, two button shapes) and CMP-05 (illegible disabled buttons) ([`frontend_ui_audit_spec.md`](../../frontend_ui_audit_spec.md) §4.10). Relates to IR-1043 and IR-1038, neither of which has landed.

## What changed

- **`Button` is a pill.** Every text size (`sm`, `md`, `lg`, `full`, and a new `page`) is `rounded-full`, in sentence case, with its weight carried by the size so no two classes fight over it. `page` is the 44 px page action the Publish footer used as `PILL_PRIMARY`/`PILL_SECONDARY`. `ButtonLink` shares it. **The `icon` size keeps the 0.75 rem radius**: `DESIGN.md` gives reading controls that shape and a label-less glyph is a different role from a labelled action.
- **One disabled look.** Desk Stone fill (`stone-200`) with Faint Ink text (`stone-500`), 3.8:1, on every variant and size, replacing `disabled:opacity-50` (a faded maroon button) and the `full` size's own `stone-100`/`stone-700` override from IR-533.
- **`disabledReason`.** A visible line after the button, tied to it with `aria-describedby` (a caller's own description is kept), shown only while the button is disabled and not merely busy (`loading` has its spinner). It is a sibling on its own line, not a wrapper, so a row that wraps at 360 px still wraps.
- **Callers.** `PublishDialog.tsx` and `ManuscriptStep.tsx` use `Button` and `ButtonLink` for every action (footer, close-confirm, retry, reload, check again, replace file, open paper). `SettingsPage.tsx`: Change password (was uppercase and tracked, `rounded-lg`) and the Your profile link. `ImportRecordsPage.tsx`: Generate, and Download template, which was a link-styled button inside a sentence and is now a button under the list. `NoticesPage.tsx`: Publish version says why it is unavailable.
- **Publish's Continue validates on press.** On step 1 it is never disabled for what is missing. Pressing it with no type, no manuscript, or an upload still running shows the field's error (`role="alert"`, `aria-invalid` on the type group) and goes no further; the error clears as the field is fixed and when the step is left. It is disabled only while it is saving, with its spinner.

## Tests

- `frontend/src/components/ui/Button.test.tsx`: pill and no uppercase in all five variants and all five text sizes, the 44 px `page` size, `ButtonLink` as a pill, the disabled look in every variant and at `full` (and no `opacity`), the 3:1 contrast of Faint Ink on Desk Stone computed from the two hex values, the reason shown, described, absent when enabled or busy, merged with a caller's description, and no click while disabled.
- `frontend/src/features/publish/PublishDialog.test.tsx`: Continue is enabled with nothing chosen and names both missing fields without creating a draft; the type's error clears when a type is chosen while the manuscript's stays; pressed mid-upload it says the upload is running and works once it finishes.
- `frontend/src/features/settings/SettingsPage.test.tsx`, `features/records/ImportRecordsPage.test.tsx` (new), `features/admin/NoticesPage.test.tsx`: pill shape, reason line and its disappearance, and the template button.
- **Changed deliberately:** four `PublishDialog.test.tsx` assertions expected Continue to be `disabled` while the type or manuscript was missing (the continuation, the "stays disabled until the upload succeeds" test, resuming with no file, and Publish another). The behaviour changed on purpose (acceptance criterion 3), so each now presses Continue and asserts the error instead. `src/test/fontSizeAllowance.ts` lowers `ImportRecordsPage.tsx` 8 to 7 and `SettingsPage.tsx` 19 to 18, which the guard demands when a file shrinks.

## Evidence

- Run locally 2026-11-14: `tsc --noEmit` clean; eslint on the changed files no errors; `npm run test:changed`: 101 files, 1,620 tests passed, after the review fixes. The full suite is left to CI.
- **Not checked:** a browser or a signed-in session, how every other `Button` caller looks as a pill (the radius change reaches all of them, by design), and Faint Ink on Desk Stone by eye. The 3.8:1 figure is computed, not measured on screen.
- **Departures from `DESIGN.md`, recorded:** every `sm`/`md`/`lg`/`full` Button is now a pill, where Shapes gives controls 0.75 rem and only page actions, chips and the Ask IRIS icon the pill; the audit decided one shape for one action (VIS-04), and `DESIGN.md`'s Buttons line now says so. A disabled ghost has a Desk Stone fill, which Ghost's "no outline, no fill" did not. `outline` keeps its `border-stone-300` and `hover:bg-stone-50`, not `PILL_SECONDARY`'s ring and `hover:bg-stone-100`, and `Button` has no `shadow-card` where `PILL_PRIMARY` had one, so the Publish dialog's primary actions lost that shadow.
- **Known gaps:** the Publish flow's other steps, `ReviewStep.tsx`, `PrefillChip.tsx`, `PublishDetailsPreview.tsx` and `PublishSuccess.tsx`, are outside the ticket's file list and still use `PILL_*` or raw buttons, so the flow has two implementations until they move. Publish's Back and the prefill line's Check again are disabled only while something is saving, with no reason line. Over 40 files in all still use `PILL_PRIMARY`/`PILL_SECONDARY` class strings, which draw the same pill (`DESIGN.md` now says so). Settings' own tab buttons are navigation, not actions, and keep their shape. The reason line is left-aligned under its row, including under Change password, whose button sits at the right. `Button`'s `sm`/`md`/`lg` font sizes are still pixel values: that is IR-1038.
