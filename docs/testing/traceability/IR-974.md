## What changed

- **`GET /documents/guidelines/`** (`setup_views.GuidelinesView`), for anyone signed in, read only. Every record type in order, each with its description, the Manuscript row (description, Template name) and the requirements RDCO lists on Setup, in RDCO's order (`setup.listed_slots`). A hidden requirement and a slot made for one paper's document request never show. Setup's own fields (`position`, `in_use`) are not sent: `shown_requirement` and `shown_record_type` build what a reader sees, and Setup's payload adds to them, so the two can't drift.
- **Downloads:** the existing routes, unchanged. `record-types/<id>/manuscript-template/`, `slots/<id>/template/` (IR-971) and `adviser-templates/<id>/file/` (IR-975), each an attachment.
- **Advisers' Templates:** the existing `adviser-templates/` list (IR-975), which only holds Templates whose Adviser is active, unlocked, verified, undeleted and still an Adviser. **That guarantee is tested in IR-975** (`test_adviser_templates.py` `WhoseTemplatesShowTests`), not again here: Guidelines reads the same list and adds no filter of its own.
- **The search by Adviser** filters that list in the browser, by part of a name. The owner chose this on 2026-11-19 over a server filter (decision 2a in the plan): no new query key, instant as you type, and a hidden Adviser still never appears because the server left them out. The whole list downloads each time, which suits CIT-U's tens of Advisers; hundreds would want a server filter.
- **Frontend:**
  - `/guidelines` (`features/guidelines/GuidelinesPage.tsx`, client `api/guidelines.ts`). One stacked section per record type, with jump links (`/guidelines#thesis-research`), chosen by the owner over tabs. Each row shows its name, the Required or Optional label, its description and a download where there is a Template.
  - The page says only the manuscript is needed to submit. Advisers' Templates sit in the Proposal section, grouped by Adviser, with the search.
  - A failed read says so and offers Try again; an Advisers' Templates failure leaves the requirements on screen.
  - An address naming a section (`/guidelines#project`) scrolls to it once the sections have loaded. The browser's own jump happens before they exist.
  - The Required/Optional badge is one component, `features/setup/RequirementLabel.tsx`, shared with Setup.
  - It changes nothing: its only controls are downloads, the search and Try again.
- **Links:**
  - **Sidebar:** Main, after Calls & Conferences, for every role, the System Admin included (decision 7 says every signed-in person).
  - **Help:** "Publishing your research" links to it.
  - **Publish:** the manuscript step links to it **in a new tab**, so reading it never closes the dialog, and to the chosen type's section once a type is picked. Pointing out the chosen Adviser's Templates in Publish is IR-973's (decision 6).
- **Smoke tier:** the `guidelines` screen in the viewport matrix and the full-text check, with long names, file names and links.
