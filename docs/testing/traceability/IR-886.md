## IR-886 — Find permitted Passages by meaning and metadata through the agent's search

**Basis and scope.** IR-886 under IR-712; authority ADR-049 and its 2026-11-07 amendment, which records the owner's four decisions: one combined `search`, reranking behind `RUNS_RERANK_MODEL`, on by default, and paper-first plus flat vector reads fused with keyword results by rank. Query-time search only: document embedding (IR-751), space upgrades (IR-752, IR-739) and exact counts (IR-750) are out of scope.

**What exists now.**
- `ai/research/tools.py::ResearchTools.hybrid_search`. It resolves the filters first, so an unknown one costs nothing. Then it makes one admitted query embedding through the send guard, and reads keyword, paper-first and flat candidates under the run's grant and the same row policy and filters. It merges them with `fuse_by_rank` (a port of Django's), optionally reranks, then rechecks every Passage under the grant before issuing run-bound handles. `signals` reports each part: `ok`, `off`, `provider_gated`, `provider_failed`, `embedding_space_changed`, `withheld` or an admission reason. Coverage `total` is always unknown, so a result stays a sample.
- The first semantic search pins the run's Embedding Space. A later search after a promotion reports `embedding_space_changed` and pays for nothing.
- The rerank sends passage text only when `SendGuard.eligible` admits every candidate source; otherwise it reports `withheld` and keeps the fused order. `ai/research/rerank.py` holds the Voyage adapter.
- `ai/agent/tools.py`: the `research-5` `search` spec (`HYBRID_SEARCH`) takes the filters. Shown signals use a fixed vocabulary, and `ai/admission/guard.py` accepts it, plus the filter refusals, as content-free control output. `ai/agent/executor.py` adds `agent-research-5`/`research-5`; `ai/runs/agent_profile.py` now pins new AGENT runs to it. Runs pinned to research-1 through research-4 keep their tools.
- `ai/runs/worker.py::search_providers` builds the query embedder, the shared admission ledger, the reranker and the configured send guard only when the AGENT profile and `VOYAGE_API_KEY` are set.

**Tests.**
- `backend/apps/ai/tests/test_ir886_hybrid_search_db.py` (real PostgreSQL, restricted `iris_ai_runtime` login, recording providers). Covers: a meaning-only match whose paper falls outside the 20 paper-first candidates; keyword answering with the provider missing, and a no-match reported as such with meaning search `provider_gated`; a term-only match with meaning search on; year filters narrowing every signal, an unknown Area refused explicitly and before any spend, and one `query` reservation in the research lane; a draft Passage closest to the query returned to its owner and never to another reader; Paper Chat scope; a space promoted mid-run refusing meaning search with no second embedding; `EXPLAIN` of both vector reads showing a function scan and no HNSW index, even with sequential scans disabled; a rerank withheld by the default guard with nothing sent or reserved; and an approved rerank reordering results with one `rerank` reservation.
- `backend/apps/ai/tests/test_ir886_hybrid_search_contract.py` (agent seam, recording model). Covers: research-5 offers one filtered `search` and passes the filters through; research-4 keeps keyword search and refuses filters; a keyword-only no-match tells the model meaning search was unavailable and passes the guard's control check; an unlisted reason is shown only as `unavailable`; malformed filters are refused before any search; and an unknown filter value reaches the model and passes the guard.
- Updated deliberately: `ai/tests/test_agent_profile.py` and `test_ai_runtime_executor_selection_db.py` expected the default pin `agent-research-4`; it is now `agent-research-5`.

**Not done here, and why.**
- **The comparison against keyword-only search has not been run.** The ticket asks for one on the labelled question set. No runtime run exists, and whether the set holds questions whose answer is absent from the title and abstract was not checked. At the owner's direction the feature ships on anyway (ADR-049 amendment, decision 3).
- **No paid provider was called.** Recording providers prove the contracts, never capacity or answer quality.
- **Rerank sends nothing in production.** The guard admits Record text only for an approved development proxy manifest, so `withheld` is the expected production outcome until the disclosure decision is made.
- **The space pin is per worker attempt.** A run resumed by another worker pins again at its first search; vectors from a non-active space are still never read, because the read functions return only the active space.
- The ticket's independent two-reader demonstration with a live provider has not been performed.

**Evidence, 2026-11-08 (Windows dev machine, private test database).** `test_ir886_hybrid_search_db.py` and `test_ir886_hybrid_search_contract.py`: 17 passed. `ai/tests`: 112 passed. The full backend suite (`-n 4`) had 152 failures. About 120 are `PDF checking is temporarily unavailable` in documents and records tests. These tests use the PDF inspection subprocess, which is unavailable on this machine, and this change does not touch them. The AI-runtime failures were rerun on the unchanged merge-base `04caa6d6`. Grant renewal (10), dispatch (1), executor selection (3), reader progress (1), runtime extraction (1) and shared processes (1) fail the same way there. They fail through a probe-login `InvalidPasswordError` and a claim that returns nothing, so they predate this branch. The two pin tests were updated deliberately to expect `research-5`.

**Review follow-ups not done here.** `embedding_ledger` also admits reranks. The admit, send and settle sequence is repeated in `_query_vector` and `_reranked`. The signal vocabulary is defined in three modules. With no provider and no keyword hit the top-level status is `no_match`, and only `search.semantic` says meaning search did not run.
