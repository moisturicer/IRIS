# IR-792: AI says the owner did not consent when asked about a No paper

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** ADR-054 decisions 6 to 8 (decision 15 for the third-party reader). Builds on IR-791, whose gate already refuses a No paper with `Reason.NO_CONSENT`.

**What is built:**

- **One refusal a reader is told.** `apps.ai.policy.reader_refusal(record)` returns `"no_consent"` only when the paper stores a No (`Record.ai_consent is False`) and the gate refuses it for consent. It never returns another reason, so an embargo or IP mark is never named (ADR-052). A paper with no stored answer is refused but is not reported as a No.
- **AI Overview.** `GET /ai/records/<id>/overview/` returns `{"state": "unavailable", "overview": null, "reason": "no_consent"}` for a No paper, owner included, before any assembly or model call. The paper page says "The owner did not consent to AI use of this paper, so nothing is available for AI." with no Try again button.
- **Paper brief.** `POST /ai/records/<id>/brief/` and `cached_brief` return `reason: "no_consent"` instead of `disclosure_or_access`, only to a reader who can open the paper.
- **Unchanged and now tested:** a stored comparison including a No paper is withheld whole, a general question's model-bound sources never include a No paper, a person who said No still gets Yes papers, and the outside PDF reader refuses a No paper.

**Not in this ticket:**

- **Paper Chat and single-paper questions** run in the AI runtime (`ai/`) since Django's answer routes were retired. That runtime withholds all Record evidence from providers until it has a disclosure decision (IR-725), so nothing reaches a vendor, but it does not yet tell the reader why. That belongs with the runtime specs (IR-712 to IR-716).
- **Collaboration matching** is not built (IR-310 is a Proposal).
- **The development bypass** criterion is moot: `AI_DISCLOSURE_BYPASS_FOR_DEVELOPMENT` is no longer referenced in `backend/apps`. CLAUDE.md still describes IR-317's bypass as live; that contradiction is recorded here, not corrected in this ticket.
- **General Ask IRIS in the runtime.** The test covers Django's source selection, which no live route uses. The runtime's research tools read under the reader's grant with no consent check, so a No paper's passages may reach a run; IR-725's guard keeps them from any provider.
- The generic unavailable message still says the model could not be reached, including for an embargo. It does not name the embargo, so ADR-052 holds, but the wording is inaccurate.

**New tests:** `backend/apps/ai/tests/test_no_consent_refusal.py` (real rows, real gate, deterministic fakes). Generation is queued, never run in the request, so "no vendor receives anything" is shown as nothing queued and nothing stored, with commit callbacks executed and a Yes paper as the control that does queue. Covered: the overview for a reader and for the owner, a No and embargoed paper naming consent and never the embargo, an embargo alone and an unanswered paper giving no reason, the brief, the general path at source selection, an asker who said No, the stored comparison, and the outside reader. Frontend: `PaperAiOverview.test.tsx` shows the consent line, with no retry and no embargo wording.
