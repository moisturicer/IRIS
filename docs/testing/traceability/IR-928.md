## IR-928 — The verification link keeps its secret in the URL fragment

**Basis and scope.** IR-928, from IR-829 (ASVS 8.3.1), decided by Ashlee Sean on 2026-11-05. Model: the reset link (ADR-045 §3, `apps/accounts/recovery/delivery.py`, `ResetPasswordPage.tsx`). No FR- id.

**What exists now.**
- `apps/accounts/services.py::send_verification_email` links to `{FRONTEND_URL}/activate#uid=<uid>&token=<token>`. A fragment is never sent by the browser, so the secret stays out of server logs, `Referer` and proxies.
- `POST /api/v1/auth/activate/` (`ActivateConfirmView`, name `auth-activate-confirm`) takes `{"uid", "token"}` as JSON and runs the same `activate_user`. One refusal body (`Invalid or expired link.`, 400) for every failure, `Cache-Control: no-store`, no authentication attempted (a stale bearer token cannot cause a 401). A secret in the query string is not read.
- `EmailVerifyPage` reads the fragment once (exactly `#uid=…&token=…`, nothing else), posts it through `authApi.activate`, replaces the address bar with `/activate` and sets `<meta name="referrer" content="no-referrer">` while mounted.
- **Links already emailed keep working.** Emails sent before this change carry `/activate/<uid>/<token>`. Their tokens are Django's default (`PASSWORD_RESET_TIMEOUT`, not overridden: 3 days). The SPA route `/activate/:uidb64/:token` is kept and now sends the path's secret in a body too, then replaces the address. `GET /api/v1/auth/activate/<uid>/<token>/` is kept, marked deprecated, for a bundle cached across the deploy.
- **Retirement.** The deprecated GET route, its URL, the SPA path route and nginx's `/activate/` locations are removed once 3 days have passed since this ships, or sooner when IR-643's single-use verification replaces both (ADR-045 §8). Nothing removes them automatically; [IR-937](https://citiris.atlassian.net/browse/IR-937) does.
- **Backstop.** `core.logging.RecoveryRedaction` and nginx's `iris_safe` log format and `/activate/` locations are unchanged.

**Tests.**
- `backend/apps/accounts/test_activation_fragment.py`: the emailed link carries uid and token in the fragment and nothing in the path or query; following it verifies the account; the body endpoint verifies once and notifies RDCO once, refuses a wrong token, an unknown uid, and any body that is not two strings with the same answer, ignores a query-string secret, rejects GET, sets no-store, ignores a stale bearer token; a pre-change path link still verifies; the redaction filter still hides legacy paths.
- `backend/apps/tests/access/table.py`: `auth-activate-confirm` declared public.
- `frontend/src/features/auth/EmailVerifyPage.test.tsx`: posts the fragment's uid and token, removes the fragment, sets no-referrer, makes no request for six malformed fragments, and the deprecated path form posts in a body and replaces the address. `frontend/src/api/auth.test.ts`: `activate` is a POST with a body. `entryHeadings.test.tsx` mounts the real route.
- `e2e/`: `verify()` and the lifecycle spec follow the fragment link.

**Verification.** Frontend: the three touched test files (65 tests), `tsc --noEmit` and eslint on the touched files passed locally. Backend: not run locally (no Django or Postgres in the author's environment); the files compile. The run is CI's, recorded on the PR. The e2e specs were not run. ASVS 8.3.1 is to be re-run on the stack after deploy.

**Not done here.** Removing the deprecated route, after the 3 days ([IR-937](https://citiris.atlassian.net/browse/IR-937)). IR-643's resend and single-use verification. `SECURITY_CHECKLIST.md` 8.3.1 stays Partial until the legacy route is removed.
