## IR-395

**Requirement:** **An exact term finds its papers — keyword and vector search fused behind a switch** — no FR- id; part E of IR-390's spec, and the first of ADR-033 §5's six switches to be built

**Design:** [ADR-033 §1](../../adr/033-hybrid-retrieval-and-passage-selection.md) (two independent searches over the whole visible catalogue, merged **by rank position** before reranking, keyword search **not** restricted to the vector candidates) · §5 (lands behind a setting defaulting to today's behaviour) · §Security Impact (a second candidate source, **no** second visibility predicate)

**Implementation:** `apps/ai/retrieval/fusion.py` — `fuse_by_rank(lists, key)` is the merge as its own pure unit: rank 1 of every list, then rank 2, keeping each item's best position, deduped by the caller's key. **No weight, threshold or `k`**, which is the whole reason for this shape over adding normalised scores — ADR-033 rejected normalisation because its constant is fitted to the queries it was chosen on, and a constant is a parameter that has to be tuned on questions. IR-399's sub-question merge and Listing questions reuse the same unit. `KeywordFusionRetriever` is a decorator returning `inner_result.with_passages(...)`, so `degraded`, `mode` and `embedding_space_id` carry through (the IR-279 contract) · `CompositionRoot._candidates` puts it **inside** `RerankingRetriever`, so the merged set passes the disclosure gate and the reranker exactly as the vector set does — reranking and everything after it are unchanged · the keyword half is the **same** `FullTextRetriever` the ADR-008 outage path uses, reading IR-393's stored `search_vector` column, so visibility is one `visible_to(user)` filter rather than a second copy · `AI_KEYWORD_RETRIEVAL_ENABLED` and `AI_RETRIEVAL_FUSION_ENABLED` in `config/settings/base.py` and `.env.example`, **both default False**. **Two settings, one technique**, as `apps/ai/evaluation/techniques.py` already said: neither half does anything alone — searching the keyword index and discarding the result is a query paid for nothing — so the decorator joins the stack only when both are on, and the harness warns (it does not refuse) that two switches moved. **Design decisions recorded rather than left to be read out of the code:** the keyword result's `degraded=True` is **not** adopted, because on the healthy path it would tell a reader the vendor was out while it was answering normally; an already-degraded inner result is passed straight through unfused, since it *is* full-text search and fusing it with full-text search buys a query and no candidates; and a fused passage carries its **merged position** as its score, because a `ts_rank` (~0.06) and a cosine similarity (~0.8) in one list would make the field mean two things at once and `presentation.record_sources` reads it for a record card's headline score

**Test:** `apps/ai/retrieval/tests/test_fusion.py` (24 — `RankMergeTests` (6) on fixed lists with **no database**: the interleave, the first list breaking a tie, an item in both lists emitted once at its best rank, a longer list continuing, empties, and identity coming from the caller's key · `ExactTermTests` (3, DB) — the acceptance criterion, asserted in both directions: the paper holding only the exact term is **absent** without fusion and **present** with it, and what the vector path already found is kept. How the miss is reproduced is stated in the class docstring rather than hidden: `DeterministicEmbeddingProvider` hashes words, so it cannot blur a token the way Voyage does, and the miss is reproduced through the other bound on the vector path — stage 1's candidate record set · `KeywordPathVisibilityTests` (4, DB) — a stranger's draft never returned by the keyword path, a readable record not carrying its forbidden neighbour, an anonymous user getting nothing, and owner/adviser/staff **not narrowed** either, since a source returning less than `visible_to` allows is a second predicate just as much as one returning more · `DecoratorContractTests` (6) — mode and space surviving, the keyword path's degraded flag not adopted, a degraded inner result passed through **with no second query**, a vendor failure still propagating so degradation stays `DegradableRetriever`'s decision, the caller's limit bounding the fused list, and the fused score monotone with the merged order · `SwitchTests` (5, DB) — asserted on the **composed stack**, not on the settings module, since a setting read and then ignored would pass a settings assertion: absent by default, present with both on, absent with either half alone, and both switches reporting `implemented` to the harness registry) · `test_degradation_crosses_the_seam.py` — `KeywordFusionRetriever` added to `DECORATORS`, so the enumeration guard covers it · **four tests retargeted, not deleted:** `test_eval_harness.py::test_the_command_refuses_a_technique_that_is_not_built_yet` and three in `test_techniques.py` asserted "fusion is not built yet", which this ticket is what falsifies. Two moved onto whichever techniques are still unbuilt (so they survive IR-396 and IR-397 rather than breaking again), one onto the value rather than the setting's absence, one onto `relevance_cut_off`
