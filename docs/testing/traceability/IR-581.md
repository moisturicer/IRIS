# IR-581: Ask about a verified text selection

**Requirements:** IR-553 User Stories 14–16, ADR-049 (AI-owned runs), ADR-065 §8 (the shared selection menu). The matrix has no `FR-` row for this.

## What changed

**Page.** The paper's selection menu (ADR-065 §8, built by IR-583) gains *Ask about selection* wherever Ask IRIS is offered. It opens Paper Chat with a chip naming the paper, the Manuscript version and the page over an editable question ("What does this passage mean?" when the box is empty). Nothing is sent until Send. The chip can be removed first. A refused selection is explained on the chip and the question stays in the box. A question asked about a passage replays it above the question, or says it is no longer available.

**Runtime.** `POST /api/v1/ai/runs` takes an optional `selection` `{record_id, manuscript_revision, page, quote}`. `ai/runs/anchor.py` checks it under the reader's own grant, inside the admission transaction, before anything is stored:

- the Record must be the grant's Paper Chat scope (`selection_out_of_scope`);
- the reader must be able to read an indexed source for it, so visibility and the disclosure gate are PostgreSQL's (`selection_unavailable`);
- the revision must be the one that source was indexed from, `iris_ai.research_source_revision` (`selection_version`): an older or unsubmitted upload is refused, never answered from other bytes;
- the quote must start on that page of the indexed chunks, compared without layout (`selection_unverified`). A chunk is labelled by the page it starts on, so the chunk that runs onto a page counts for that page too. The check is only as precise as the chunks.

Each refusal is a 422 naming its code, in both protocols. The selection is part of the request identity. It is stored on the run (migration `0021`), copied by a retry, and copied onto the Turn. The worker checks it again under the grant the run holds when it starts. Only a passage that still holds reaches the model, as `SELECTION_PREFIX` (quoted as paper text under research-11). Otherwise the model is told the passage could not be used (`SELECTION_WITHDRAWN`), and its text is never sent. Run status and reopen show it while the paper is readable (`current: false` once replaced) and `{available: false}` otherwise. Deleting the Conversation clears it.

| Criterion | Evidence |

| Chip names Record, version and page; removable before Send | `AskAboutSelection.test.tsx` "fills an editable question …", "asks without the passage once the chip is removed" |
| Server verifies quote and anchor against extracted content and current permission | `test_ai_runtime_selection_contract.py`; `test_a_tampered_selection_is_refused_and_nothing_is_stored`, `test_an_unindexed_or_unreadable_paper_is_refused` |

| Travels with the durable run, replays safely, degrades on change or revocation | `test_a_verified_selection_reaches_the_model_and_replays_with_its_turn`, the replaced and revoked tests above; page test "replays the passage …" |

## Limits and decisions for review

- **Page precision is a chunk's.** The chunk that runs onto page N counts for page N, so a quote from the end of page N−1, claimed as page N, is accepted when it lies in that chunk. A quote two pages away is refused. Tightening this needs per-page regions on chunks.
- **No new prompt version.** `SELECTION_PREFIX` and `SELECTION_WITHDRAWN` are reader-context messages, like the Paper Chat note, sent only by a run admitted with a selection. The instructions and tool schemas a pin digests are unchanged, and a run without a selection sends the same bytes as before. If ADR-049 §14 is read to cover these messages too, they belong under a research-12 pin.
- **An owner's unsubmitted upload** is refused, and the chip says why. Switching to the submitted version from the chip is not built.
