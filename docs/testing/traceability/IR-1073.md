# IR-1073: Every page has its own browser tab title

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Audit finding NAV-01, WCAG 2.4.2 level A ([`frontend_ui_audit_spec.md`](../../frontend_ui_audit_spec.md) §4.1), and VIS-03 for the two crumbs.

## What changed

- **One owner of the tab.** `RouteTitle` sits at the root of the route table, above the shell, and sets `document.title` to `<page> · IRIS` from the deepest route's `handle.title`, else its `handle.crumb`. It is above the shell so the public pages (sign in, sign up, email verification, password recovery) are named as well; the ticket's approach said "in the shell", which would have left them as "IRIS".
- **Routes with no crumb carry a `title`** in their handle: the public pages, `records/:id` ("Paper", the name until the paper loads) and the not-found screen. `Breadcrumbs` still reads only `crumb`, so no breadcrumb appears that did not before.
- **Pages that know more say so** through `usePageTitle` (`hooks/useDocumentTitle.ts`, state in `store/pageTitle.store.ts`): a record uses its paper's title, a conversation its own title (Ask IRIS and an earlier Django conversation), My Reviews adds the work waiting on the reader, "My Reviews (3)", and drops the count at zero. A new chat has no title, so it keeps "Ask IRIS". The override clears when its page unmounts, so one page's name never outlives it. An override cannot be done from the page with a plain effect: children's effects run before the shell's, so the route's name would overwrite it.
- **Crumbs:** "Workflow Analytics" is "Workflow analytics" and "Import Records" is "Import records". The sidebar label and the page headings are not part of this ticket and are unchanged.

## Tests

- `frontend/src/router/documentTitle.test.tsx`, through the real route table:
  - navigates to Discover, a record, My Reviews, a public page (sign in), an unknown address, a conversation and a new chat, and asserts `document.title` each time;
  - moves from a record to another page and asserts the paper's title is gone;
  - moves from one record to another that is still loading and asserts the first paper's title is gone;
  - walks every page in the route table (redirects excepted) and fails if one resolves no name, so a route added later without one is caught.

## Evidence

- Run locally 2026-11-14: `tsc --noEmit` clean; eslint on the changed files reports no errors (one existing unused-directive warning in `PaperViewPage.tsx`, not from this change); `npm run test:changed`: 17 files, 370 tests passed. The full suite is left to CI.
- **Not checked in a browser or with a screen reader.** The tests assert `document.title`; what a given screen reader announces on navigation was not heard.
- **Known gaps by design:** a conversation not yet in Ask IRIS's history list keeps "Ask IRIS" until the list loads. My Reviews counts only work waiting on the reader (`to_review`).
- **Not covered:** a crash drawn by the standalone error screen (outside the shell) keeps the title of the page it crashed on. The access-denied screen shows the title of the page it guards.
