# IR-1277: Record types keep one order: Proposal, Thesis / Research, Project

[Back to the matrix](../TRACEABILITY.md)

**Requirement:** every list of record types shows Proposal, Thesis / Research, Project, in that order, however often a type is edited. Reported by Hermoine Zozobrado on 2026-11-23, when Publish on the demo server listed Project first. No FR- id.

**Design:** no ADR change.

## Cause

`RecordType` had no ordering, and `GET /records/record-types/` (Publish's type choice) returned `RecordType.objects.all()`. With no `ORDER BY`, PostgreSQL returns rows in storage order, and updating a row stores a new copy at the end. So a type RDCO saved on Setup (IR-971) moved to the end of Publish's list. Setup and Guidelines ordered by `pk`, so they did not show it.

## What changed

- `RecordType.position` (default 100) and a default ordering of `position`, then `id` (`records/models.py`).
- Migration `records/0044_recordtype_position` sets Proposal 1, Thesis / Research 2 and Project 3, matched by name, since an older database's ids need not follow the workflow order (`records/0006` removed a *Research Paper* type). Any other type keeps 100, so it comes after them, oldest first. Reversing it drops the column.
- Setup and Guidelines (`documents/setup_views.py`) use the default ordering instead of `pk`, so all three lists agree.
- The API is unchanged: `RecordTypeSerializer` still returns only `id` and `name`.
