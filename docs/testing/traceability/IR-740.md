## IR-740 — Collect and rescore the new runtime through IR-605

**Basis and scope.** IR-740 under IR-716; authority ADR-049 (§24 and the 2026-11-04 amendment, decision 3) and the ticket's acceptance criteria as read from Jira on 2026-11-05. The repository's local copy of the ticket (`docs/superpowers/specs/2026-10-31-ai-runtime/tickets/20-ir-740.md`) is **stale**: it lacks the two criteria moved from IR-731 on 2026-11-04. Native blockers IR-728, IR-863 and IR-861 are Done. It extends IR-605 (`eval_replay_conversations`, `eval_conversations`, `eval_campaign`, `eval_review_packets`); it adds no framework, no new run-file format and no reader engine selector. Held-out case authoring (IR-753) and real paid campaigns (IR-755) are separate.

**What changed.**
- `evaluation/engines.py` (new, pure): the runtime's identity (`ai-runtime-1` engine, `runs-reader-1` transport, `runtime-rows-1` schema, arm `runtime`) and the comparison of **effective** conditions: the model that actually answered (from the physical attempts when there are any, else the configured one, trimmed and case-folded, whatever the shape of `model_ids`), the allowance without identity-only keys (`campaign_key`), the cache state, and the question, corpus, policy and rubric digests. Three modes: `architecture` (all equal), `model` (only the models differ) and the new `capability` (only the allowance differs, and it must).
- `evaluation/runtime_replay.py` (new): `RuntimeSeam` (submit, status, cancel and reopen over one client, either the reader's edge `/api/v1/ai/runtime/*` or the gateway with a per-request grant) and `collect_case_runtime`, which writes IR-606's row shape from the runtime's public projections. Citations keep the runtime's order. Busy, cancelled, failed, overdue (cancelled by the collector), unreadable-source and open-reservation outcomes are retained, never dropped.
- `evaluation/replay.py`: `collect_run` takes a case collector, protocol, identity and declared runtime facts (defaults unchanged), and every run file gains an `evidence` label. `CampaignAttempts` rows gain `reserved_cost_usd`, `owner`, `purpose` and `purpose_version`; `RuntimeAttempts.for_run` reads a run's attempts from the shared ledger by `airun:<run id>` and `owner = 'ai'`.
- `evaluation/campaign_report.py` and `conversation_scoring.py`: `runtime` is an arm with its own engine and protocol, `capability` is a mode, conditions are compared by `engines.mismatches`, and spend adds attempt **purposes**, turn **outcomes**, attempt **states** and **reserved** cost beside the existing reported and unreported figures. A measured arm lists its allowance and identity.
- `eval_replay_conversations --runtime-url`: the collection command for the runtime; fake or real is declared by the operator (the service is not this process).
- Docs: `docs/evaluation/general-tools/replay.md`, `campaign.md`.

**Acceptance criteria.**
1. *Explicit identity, real seam, not controller-v1.* Engine, transport and schema are recorded in the manifest and required by the campaign preflight for the runtime arm; a runtime run labelled `controller-v1` or `public-1` is refused. Collection goes through submit, status polling and reopen. `test_ir740_runtime_collection_db.py` drives the real gateway routes on restricted-role PostgreSQL with Django-issued edge grants. **CI result for that file: see Evidence.**
2. *Old readers, denominators, review and baseline evidence preserved.* The committed review fixture (`fixtures/review/`) rescores to the same hand-counted numbers (3/4 completion, 5/6 claim support) after this change, in the existing `test_review_campaign.py` and again in `test_runtime_smoke.py`. No existing test was modified. Old run files have no `evidence` or `identity` key and are read as before. The only behaviour change to old scoring: a dedicated `campaign_key` in `limits` no longer makes two otherwise equal budgets unequal.
3. *Effective models, matched preflight, unequal conditions rejected.* `test_runtime_engine.py` and `test_runtime_campaign.py` refuse unequal corpus, models, data policy, limits and cache and show a fallback-served model differing from the configured one. The unequal-budget refusal is also made through the real `eval_conversations --score` command in `test_runtime_smoke.py`.
4. *Capability and model reported separately; failed attempts, purposes and usage retained.* `--mode capability` is refused for equal allowances or other differences and its report names each allowance and states the gain is not credited to the architecture. `spend()` keeps failed, cancelled and capped turns, purposes, attempt states, reported, unreported-reserved and reserved cost, missing-usage turns, and cold and warm apart.
5. *Deterministic end-to-end smoke.* `test_runtime_smoke.py`: collect through the command, build the review packet, score the reviewed packet, rescore the baseline fixture, refuse the unequal budget. It proves transport and contracts only.
6. *(Moved from IR-731) Contract results in the existing run file, labelled.* Every run file carries `evidence`; a fake one is `contract`, `human_reviewed: false`, `quality_evidence: false`. No new format.
7. *(Moved from IR-731) A01–A15-compatible core tasks, safe replayed and exported projections, stable order, malformed calls and clarification through saved Conversations.* **Partly done.** The DB test runs one saved Conversation with a malformed tool call, a cited answer and a clarification Turn, and shows live, reopened, replayed (new grant) and exported projections equal and allowlisted, with the runtime's citation order unchanged into the packet. The 15 families of `general_tools_contract_v1.json` are written as a descriptive script, not as something a runtime can execute, so **A01–A15 were not each run through the runtime**; that needs either an executable driver for that pack or case-by-case scripts, which is a decision for Jive.

**Denial across export (left unverified by IR-735).** `test_a_source_made_unreadable_after_collection_is_denied_in_reopen_export_and_packet` collects, then makes one cited paper unreadable: the reopened Conversation and any re-export lose the answer and quotations and mark the run's sources unavailable; the earlier export builds a review packet that withholds the turn for a reviewer who can no longer read the paper; a new collection exports no text from it. There is still **no reader export route** in the runtime; "export" here is the IR-605 run file and packet, as ADR-049's amendment defines it.

**Evidence.**
- Local (Windows, Python 3.14, Django installed into a scratch folder, **no usable PostgreSQL**): the 47 new dependency-free tests (`test_runtime_engine`, `_campaign`, `_replay`, `_replay_command`, `_smoke`) pass, and so do the neighbouring dependency-free suites they could affect: `test_campaign_report` (42), `test_conversation_scoring` (11), `test_review_campaign` (10), `test_campaign_command` (10), `test_conversations_command` (4), `test_conversations_review` (12), `test_conversations` (9), `test_replay_contract` (7) and the three contract-pack tests. flake8 is clean on the changed files.
- **Not run locally:** `test_ir740_runtime_collection_db.py` and the existing database-backed IR-605 suites (`test_replay`, `test_replay_diagnostics`, `test_replay_command`, `test_review_packets`), which exercise the changed `collect_run`, `CampaignAttempts` and packet code on the Django path. The local PostgreSQL rejects the credentials available to this session and there is no restricted `iris_ai_runtime` login. They rely on CI.
- CI: recorded in the PR.

**Not verified / not done.**
- No real-provider collection through `--runtime-url --providers real`: the ledger reading is proved against the recording provider's admitted attempt only, and the command's real branch is not exercised. No live provider call, spend or deployment was made.
- The command cannot see the runtime deployment: provider mode and model are declared by the operator. A deployment that is really paid but declared `fake` would record no spend. The ledger can detect it only when a campaign key is supplied.
- Effective models come from the `llm` attempts only; embedding and rerank models are not compared.
- Review packets from the `eval_review_packets` command (database-backed readability) for a runtime run were not run; the pure `build_packets` was.
- Independent human review of any runtime answer has not happened; nothing here is quality evidence.
- The `code-review` pass found and this change fixed: capability repetitions under one label could differ in allowance; a capability report could mix code versions; `cache_state` would have refused cold and warm repetitions inside one arm (now each label must run the same set of cache states); a status poll that failed left the run active (now cancelled). Left as judgement calls: the real-provider admission block in `_runtime` repeats the Django branch's, and `collect_case_runtime` is long. Faults (the A09 outage family) and diagnostics are Django-path features and are ignored for the runtime.

**Status.** Implemented; awaiting CI and review.
