# IR-1039: Administration, Settings and sign-in screens use the type roles

**Requirement:** `docs/frontend_redesign_spec.md` section 4.12 (type scale); IR-452 (named type scale); IR-1038 (the 14 px mapping, `docs/ui-ux/01-design-system.md` section 1 "Type").

Slice 1 of 4. 110 arbitrary font sizes in 17 files become type roles: 12 px to `text-label`, 13 px to `text-small`, 14 and 15 px to `text-body`, 16 px to `text-heading`, and the one 32 px to `text-display`. The 17 files' entries leave `src/test/fontSizeAllowance.ts`, so the IR-1037 guard fails if one returns.

Files: `accounts/{UserListPage,RoleRequestsPage}`, `admin/{DownloadRequests,DeleteRequests,AccountDeletionRequests,Sessions,Retention}Page`, `settings/{SettingsPage,YourDataPanels,settingsParts,AiAnswerPanel}`, `auth/{EmailRequestForm,ResetPasswordPage}`, `components/auth/{AuthAlert,LoginForm}`, `records/ImportRecordsPage`, `components/records/DownloadRequestModal`.

Ticket note: the ticket calls RoleRequestsPage's `text-[32px]` a title. It is the empty state's check-circle icon; the page title comes from `PageHeader`, already on the roles. The icon becomes `text-display` (28 px), 4 px smaller, the nearest role. The only `font-display` headings in scope (the auth forms) already used `text-display`.
