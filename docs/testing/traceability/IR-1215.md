## IR-1215

**Not done, pending the owner's decision:** the ticket also asks for the site root `/` to go to the landing page. For an account with review work the landing page is My Reviews, so `/` still shows them Discover (see Implementation).

**Requirement:** A person whose session is still valid who opens the login page is sent to their landing page, or to the saved page when their role may open it, without signing in again. A person whose session has ended still gets the form

**Design:** Jira IR-1215 (requested in team testing, 2026-11-17). Builds on IR-1207's `canOpenPath`

**Implementation:** `frontend/src/features/auth/LoginPage.tsx` renders `<Navigate>` to `destinationFor(user)` when the store is authenticated, the same choice a completed sign-in makes (IR-1207). `AuthBootstrap` renders no page until the session is restored, so the check never sees the moment before a refresh. A ref set during this screen's own sign-in stops the redirect from racing `handleLogin`'s navigation. The site root `/` is Discover and was already shown to a signed-in person; it is not redirected, because the sidebar's Discover link is `/`

**Limit, not changed here:** the refresh token lives in `sessionStorage` (`lib/authStorage.ts`, kept there so closing the tab ends the session on a shared machine). So this works within a tab, such as typing the address again or opening `/login` in it, but a new tab or a restarted browser starts signed out. Keeping a session across tabs would move the refresh token to durable storage and is a security decision outside this ticket

**Test:** `frontend/src/features/auth/LoginPage.test.tsx`, "where the login screen sends you": a signed-in KTTO account at `/login` lands on its landing page with no form; at `/login?next=/records/42` it lands on the paper; a signed-out visitor still gets the form; a real `hydrateAuth` whose refresh the server refuses leaves the form showing with no redirect; the Password Changed dialog still shows. The existing session-ended tests (IR-1081, IR-1197) still pass
