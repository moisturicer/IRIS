## IR-1217

**Requirement:** Help leaves the sidebar. Settings offers a clearly labelled Help link that opens the same Help page (`/help`, unchanged). The sign-in pages keep their own Help link, because a signed-out person can't reach Settings

**Design:** Jira IR-1217 (team testing, 2026-11-17). Undoes IR-1085's sidebar footer link (NAV-04)

**Implementation:**

- `frontend/src/components/layout/Sidebar.tsx`: the footer's `HELP_ITEM` link is removed, and the footer holds only the account menu.
- `frontend/src/features/settings/SettingsPage.tsx`: a "Help" link (`pathFor("help")`) follows the three section tabs in the "Settings sections" list. It is styled like the tabs, but it is a link rather than a fourth tab, because it leaves Settings.
- `/help` and `EntryFrame.tsx`'s sign-in Help are unchanged.

**Test:**

- `frontend/src/features/settings/SettingsPage.test.tsx`, "offers Help in its section list, as a link to the Help page (IR-1217)": the link is named, points to `/help`, sits beside the three tabs without being one, and Enter opens the Help page.
- `frontend/src/components/layout/Sidebar.test.tsx`: "Help is not in the sidebar (IR-1217)" replaces the IR-1085 footer tests; it checks every role and the collapsed rail.
- The account menu test and the 44px target test no longer expect a Help link. These were changed on purpose.

**Evidence:**

- 2026-11-18, locally: the new tests failed first (9), then `vitest run src/features/settings src/components/layout src/features/help` passed (151). `tsc --noEmit` and `eslint` are clean.
