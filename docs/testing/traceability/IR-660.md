# IR-660: Registration accepts only the institution's email domain

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** a pilot access control under IR-655; no direct ASVS 4.0.3 Level 1 item, and no FR- id.

**What changed:**

- `REGISTRATION_EMAIL_DOMAINS` (`config/settings/base.py`): comma-separated, read through `email_domains`, which lower-cases each domain and drops a leading `@`. Empty accepts any domain, which development may use.
- `config/settings/production.py` reads it with `required(...)`, so production refuses to start without it, as it does for `ALLOWED_HOSTS`.
- `RegisterSerializer.validate_email`: the part after the last `@`, lower-cased, must equal one of the domains exactly. `cit.edu.evil.com`, `evilcit.edu` and a subdomain such as `mail.cit.edu` are refused. The message, on the `email` field, names every accepted domain: "Register with your institutional email address, ending in @cit.edu."
- The rule lives in registration only, so existing accounts and `seed_demo` logins (made through the ORM) are never re-checked.
- Documented in `backend/.env.example`. CI's production-boot step sets it, and now also proves an empty value is refused. `e2e/scripts/make-env.mjs` writes `REGISTRATION_EMAIL_DOMAINS=cit.edu` into the core-journeys stack's environment, whose journeys all register `@cit.edu`.
- Frontend: nothing names the domain. The signup page already shows a server refusal on the field it names, so the form shows the server's message word for word, and `config/institution.ts`'s `emailDomain` stays unread. The server's setting is the one source, as the ticket's note asks.

**Evidence (2026-11-08, Windows, a pgvector test database of this session's own):**

- `apps/accounts/test_registration_domain.py`, 7 tests:
  - the domain registers in any case;
  - Gmail, `cit.edu.evil.com`, `evilcit.edu` and `mail.cit.edu` are refused on `email` with the message, and no account is made;
  - several domains are all accepted and all named;
  - an empty setting accepts any domain;
  - an existing account outside the domain still signs in;
  - `email_domains` normalizes case, a leading `@` and blanks.
- Run with `apps/accounts/test_notice.py` and `apps/tests/test_notice_block_every_route.py`: 45 passed, 19 subtests.
- Production settings, loaded the way CI's boot step does, with `REGISTRATION_EMAIL_DOMAINS` empty: refused with "REGISTRATION_EMAIL_DOMAINS is not set. It has no default". CI's step checks that they boot with it set.
- Vitest, `SignupPage.test.tsx`, "shows the server's institutional-domain refusal on the email field, word for word (IR-660)": passed.

**Not done here:** a deployment must set the value in its `backend/.env`. Nothing chooses the domain for it.
