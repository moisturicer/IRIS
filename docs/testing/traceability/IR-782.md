## IR-782 — Django's admin site moves to /django-admin/, so nginx stops taking IRIS's /admin/ pages

**Requirement:** ADR-051 decision 7. Each address has one owner: `/admin/...` is the System Admin's pages, `/rdco/...` RDCO's, `/django-admin/` Django's admin site. Old addresses get no redirects.

**What changed:**

- `backend/config/urls.py` mounts the admin at `django-admin/`. Nothing of Django's resolves under `/admin/`.
- `frontend/nginx.conf` no longer has the open `location /admin/` proxy. `/admin/...` and `/rdco/...` fall through to `location /`, which serves `index.html`, so opening or refreshing one of those pages loads the app. `/django-admin/` stays behind [IR-668](IR-668.md)'s allowlist.
- **Beyond the card, agreed while building it:** `location /static/` became `location ^~ /static/`. Without `^~`, the `.css`/`.js` asset regex won, so the admin's own stylesheets and scripts were looked for in the SPA build and 404ed, and the moved admin loaded unstyled.

**Evidence:**

| Check | Where | Runs |
|---|---|---|
| `/django-admin/` and `/django-admin/login/` resolve to the admin site; `/admin/`, `/admin/login/`, `/admin/users` and `/admin/audit` resolve to nothing | `backend/apps/tests/test_django_admin_address.py` | backend suite |
| Against the real production nginx config, `/admin/`, `/admin/users`, `/admin/role-requests`, `/admin/audit`, `/rdco/`, `/rdco/users` and `/rdco/role-requests` answer 200 with the app's `index.html`. Before this change they answered 502, because nginx proxied them to a backend that isn't there | `scripts/check_django_admin_allowlist.sh` | CI, Docker Compose job |
| `/static/admin/css/base.css` and `/static/admin/js/core.js` are proxied to Django (502 with no backend), not served from the SPA build | `scripts/check_django_admin_allowlist.sh` | CI, Docker Compose job |
| The admin's CSP header and the password-reset session check use the new address | `apps/tests/test_security_headers.py`, `apps/accounts/test_credential_invalidation.py` | backend suite |

The nginx check uses a stand-in `index.html` and `curl`, so it shows nginx serves the app for these paths. It does not render the React routes in a browser.

Breaks any bookmark to the old `/admin/` Django address. Only developers use it today.
