# IR-781: System Admin is a role of its own, and it alone reads the Audit Log and system settings

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** ADR-051 decisions 1 to 6, with decisions 4 and 5 amended on 2026-11-03 (the ADR's IR-781 Amendment). `FR-M6-06` is a stable label only.

**The criteria changed while building this.** Hermoine Zozobrado decided two things, recorded in the ADR, which outranks the card:

- **Office accounts are the System Admin's.** It alone gives the office roles (RDCO, KTTO, ITSO, IERC) and the coordinator flag. RDCO gives Student or Adviser, only to someone outside the offices. That replaces "RDCO keeps ... office coordinators".
- **The first System Admin is given in Django's admin site,** by a superuser. The card's server command isn't built.

**The role:** `RoleName.SYSTEM_ADMIN` ("System Admin"), seeded by `accounts/0018`. It is in neither `STAFF_ROLES` nor `REVIEWER_ROLES`, staffs no office party, and `visible_to` shows it the public catalogue only.

**`core/permissions.py`:**

- **Classes:** `IsSystemAdmin` and `IsAccountAdmin` (RDCO or the System Admin). `is_superuser` still grants nothing in the API.
- **`role_change_refusal(actor, target, role)`** is the one rule for giving a role. Nobody gives, changes or removes System Admin through the API. The System Admin gives any other role. RDCO gives Student or Adviser to someone with no office role.
- **`ADMIN_ROLES` stays `{RDCO}`,** now documented as account administration and the request queues, not IRIS's administration.

**Who reaches what:**

| Route | Who |
|---|---|
| `GET /audit/`, `GET /audit/export/` | the System Admin |
| `GET`/`PATCH /settings/<key>/` | the System Admin |
| `PATCH /users/<id>/coordinator/` | the System Admin |
| `GET /users/`, `/users/<id>/`, `PATCH /users/<id>/role/` | RDCO or the System Admin, under `role_change_refusal` |
| lock, unlock, locked list, sessions, revoke, role requests | RDCO, as before |

**RDCO acts on no System Admin account.** Lock, unlock, revoke session, edit details, change role and approve a role request each answer 403 on one, through `_refuse_system_admin` in `apps/accounts/views.py`. It still sees the account in lists. Approving a role request now runs `role_change_refusal`, so RDCO can't give an office role that way either.

**Sign-up** accepts only `role_name` Student or Adviser. It took any existing role name before, including RDCO.

**Django's admin site** now registers `User` (`apps/accounts/admin.py`). It's email-based, has the role field, and its add and change forms refuse the System Admin role together with `is_superuser` or `is_staff` (decision 6). A role change made there goes through `User.assign_role`, so the coordinator grant goes with it. Since `accounts/0009`, no office account is `is_staff`, so only superusers reach this page.

**`seed_demo`:** `admin@cit.edu` is the System Admin and keeps its superuser flag, the one account ADR-051 §6 allows to hold both.

**Frontend:**

- `ROLES.SYSTEM_ADMIN` is added.
- The Audit Log route and nav entry are the System Admin's.
- Users is offered to RDCO and the System Admin, and every page open to everyone includes the System Admin.
- The router's admin group is split, so the Audit Log no longer gates RDCO's other pages.
- The Users page offers each viewer only what the server allows (`features/accounts/accountActions.ts`). RDCO sees Student or Adviser and Lock, the System Admin sees office roles and the coordinator flag, and nobody sees anything on a System Admin's row.
- IR-783 builds the System Admin's own section.

**Access matrix:** `world.ROLES` gains `sysadmin`, and every row in `apps/tests/access/table.py` declares it. It reads like the role-less superuser, because neither holds workflow access, except on the routes above, which use the new `SYSTEM_ADMIN_ONLY` and `ACCOUNT_ADMINS`. No route disagreed with its row.

**Tests changed deliberately,** because the Audit Log, settings and coordinator flag moved:

- These now read or act as a System Admin, with RDCO added to the refused cases: `test_session_invalidation.py`, `test_workflow_events.py`, `test_csv_export.py`, `test_immutability.py`, `test_system_settings.py` and `reviews/test_seats.py`'s coordinator tests.
- `test_authorization_matrix.py` adds "System Admin" to every role check. The Audit Log is now the System Admin's alone, and the Users list and role change are RDCO's and the System Admin's.
- `test_seed_demo.py`'s "no application role" assertion is now "the System Admin, and a superuser".
- `UserListPage.test.tsx` now opens the page as a System Admin, and `access.test.ts` moves the Audit Log off RDCO's list.

**New tests:**

- `apps/accounts/test_system_admin.py` covers the role, the Audit Log and settings, who gives which role, every RDCO refusal on a System Admin account, role-request approval and sign-up.
- `apps/accounts/test_django_admin_users.py` covers the admin site.
- `UserListPage.test.tsx` ("what each viewer is offered") and `access.test.ts`.

**Evidence, 2026-11-03:**

- **Failing first:**
  - The API tests failed on the missing role.
  - The admin tests failed because `User` wasn't registered.
  - The frontend access and Users page tests failed before the code.
  - The role-request test reproduced RDCO approving a KTTO request (200).
- **After:**
  - The accounts, audit, both matrix tests, `test_seats.py` and `test_seed_demo.py` pass 396, except three `test_workflow_events.py` document-request tests. Those fail on Windows only (PDF checking), and on `main` too.
  - The frontend access, landing, router, layout, accounts, audit and admin tests pass.
  - `tsc` and `flake8` are clean, and `makemigrations --check` finds nothing.
- **A copy of one developer's dev database:**
  - `accounts/0018` applied, and `seed_demo --accounts-only` made `admin@cit.edu` the System Admin while keeping its superuser flag.
  - No other account holds the role.
  - The copy was then dropped.
- **Full suites:** left to CI.
- **Review:** a standards review and a spec review ran on the diff. They found the role-request gap above and the Users page offering actions the server refuses, both fixed. They also led to one refusal helper, the admin form mixin and `assign_role` reuse, and correcting the remaining "RDCO is the administrator" text in ADR-053, `access.ts` and the Delete Requests page.
- **Not run:** no real server or browser look at the Users page or the Audit Log as the System Admin.
