## IR-720 — Prevent withheld or revoked evidence from reaching a provider

**Basis and scope.** IR-720 under IR-712; authority ADR-015 and ADR-052 (on `main`) and ADR-049. Uses IR-811's stored embargo answer (#435, IR-250's first subtask): the guard's default gate is `decision_for_record`, which reads `Record.embargo_state`, and every attempt re-reads the Record, so an embargo answered, consent withdrawn or an IP mark set after a read withholds that paper at the next send. The first acceptance criterion is partly met: the facts and their writer exist and an unanswered paper stays Unknown and refused (ADR-052 §15), but IR-250's remaining subtasks (release, reminders, removing IR-317's bypass) are not on `main`.

- **Guard** (`apps/ai/policy/outbound.py`). `OutboundGuard.authorize(dependencies, model=...)` rechecks, for each `Dependency` (a Record at the passage chunk set, abstract digest, or metadata it was read at): the principal's current research visibility (`research_records`; `None` is system work), the Paper Chat scope, the source revision, the disclosure gate (default: the real `decision_for_record`), and the recipient's provider policy (default: only a model a configured Inference Profile names under `DataPolicy.NO_TRAINING`, or the configured Voyage models; an unnamed model refuses everything). The `Authorization` result lists permitted and withheld dependencies, offers `retain()` to keep only derived artifacts whose every source is permitted, and exposes one neutral reader-facing code, `source_unavailable`, with no identity, title or count.
- **Per attempt.** `OutboundGuard.fence()` installs the check on admission's `before_send` hook, which every adapter reaches through `mark_sent` immediately before its transport: so each retry, fallback model and embedding window is rechecked. A refusal raises `Withheld` (an `AdmissionDenied`: never retried, never failed over, never counted against a circuit) before anything is sent. `before_send` now chains nested guards instead of letting an inner one shadow an outer one. Voyage now names its model to `mark_sent`.
- **Wired, but untested** (no test drives these paths through the fence). Controller PLAN (on a refusal: drop envelopes depending on withheld sources, drop the previous exchange and its native continuation, rebuild once, then stop as `source_unavailable`); the answer draft (rebuild once from still-permitted sources, or answer `unavailable` when a computed fact or every source is withheld); the repair (never resent once its draft's sources lose permission — the first draft is validated against live sources as before); reranking (on a refusal, recall order over what remains; a refused provider sends nothing and keeps every candidate; the rerank check covers access and disclosure, not passage revision); record and chunk-set embedding (refused outcome; no further window sent).

**Tests.** `apps/ai/policy/tests/test_outbound_guard.py` (17, real PostgreSQL): permitted source; one source withheld by disclosure while the other stays usable; lost visibility; reading permission without disclosure refuses; outside Paper Chat scope; re-chunked passage and changed abstract; an unknown recipient model (or none) receives nothing; the default gate refuses unknown embargo facts; the default provider policy; `retain()` drops a derived artifact using any withheld source; the limitation names nothing; and, on IR-811's real rows with the real gate, an embargo answered through `record_answer` after a read withholds only that paper, an unanswered paper the reader owns is readable but never sent, and withdrawn consent or an IP mark withholds a paper read earlier. Only this seam was agreed for tests.

**Not done here.** Nothing is rechecked at Turn commit beyond the composer's existing live-source validation. When a repair is refused, the first draft is still validated and delivered. A successful rebuild adds no reader-facing limitation. The planner's withheld counter spans the run, so a second, unrelated refusal also stops it, and a refused PLAN attempt still charges its prompt estimate to the run's budget. Handoffs and plan text other than the envelopes are not rechecked per attempt. `openrouter_decisions` names no model to `mark_sent`, so it would be refused if ever fenced. No test drives the fence through an adapter or the authenticated Ask boundary, so the ticket's independent demonstration (revoke immediately before a recorded outbound attempt and inspect the fake provider's payload) is **not yet shown**, and the existing scripted fakes never call `mark_sent`, so they do not exercise the fence. Compaction and native compaction are not built; the fence is the seam they must use. The legacy `/ask/` answer path (`answers/service.py`), the AI Overview, briefs and comparisons keep their own checks and are not moved onto the guard. The planner's recent history is rechecked when its payload is built, not per attempt. The AI runtime (`ai/`) sends nothing to a provider, so nothing there is fenced. Data already transmitted cannot be recalled, and a send cannot be revoked atomically: the guard narrows the window to the instant before transport, it does not close it.

**Status.** Partially implemented; awaiting review.
