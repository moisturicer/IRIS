# IR-972: the Notice moves onto Setup, and only RDCO reads and publishes it

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Story IR-969. [ADR-063](../../adr/063-rdco-sets-requirements-and-templates.md) decision 9, which amends [ADR-051](../../adr/051-system-admin-account-deletion-and-consent.md) decision 16.

## Already met before this card

IR-799 and IR-800 already did three things. The tests in `backend/apps/accounts/test_notice_publish.py` that prove them are not changed by this card, and they pass:
- only RDCO publishes, and the System Admin is refused (`test_no_other_role_can_publish`);
- each publication is audited as `NOTICE_PUBLISHED`, recording who, when, the version, its length and a sha256 of the text;
- a published version never changes, because there is no edit or delete route.

## What changed

The owner decided the three open points on 2026-11-14.

- **Setup has two sections**, Requirements & Templates and Notice. A tab switch at the top of the page selects one, the address keeps the choice (`?section=notice`), and the arrow keys move between them. Only the open section is read from the server. The Notices page is now `features/setup/NoticeSection.tsx`, moved with `git mv`. It shows the current version, the publish form with its impact count, and the history, with no page header of its own.
- **The System Admin's Notices page is gone.** Its sidebar entry (`adminNotices`) and RDCO's separate `notices` entry are both removed. **`GET auth/notice/versions/` is RDCO-only** (`IsAdmin`), where before it also allowed the System Admin (`IsAccountAdmin`). The System Admin reads each publication in the Audit Log, which records who, when and which version, but not the text. The current version stays public to everyone.
- **`/notices` redirects by role** (`router/redirects.tsx`, which gains an optional per-role target). RDCO, and anyone else, goes to `/rdco/setup?section=notice`, where Setup's own guard applies. The System Admin goes to `/admin/audit?event_type=NOTICE_PUBLISHED`.
- **The Audit Log reads `?event_type=` on arrival**, so it opens filtered, and it never reads the unfiltered log first. If the type isn't among those the server lists, or the list fails to load, the dropdown still offers it by name, so the filter it shows is always the one applied.

## The ADR, amended to match

ADR-063 decision 9 said Setup has **three** sections, counting each record type's description as its own. The build has two, with each description inside its record type's tab. On 2026-11-14 the owner chose to change the ADR's wording rather than the page: see [ADR-063 §Amendment 2026-11-14](../../adr/063-rdco-sets-requirements-and-templates.md#amendment--2026-11-14-ir-972-setup-has-two-sections-and-only-rdco-reads-the-notices-history). The amendment also records that only RDCO reads past Notice versions.
