## IR-1222

**Requirement:** A person stays signed in across tabs, typed addresses and, with "Keep me signed in", browser restarts. The refresh token is only in an HttpOnly cookie, never in a response body or the browser's own storage. Without the box, the 30-minute idle rule is the only limit. With it, the session lasts 30 days from sign-in, outside the idle rule. Refresh and logout accept only first-party requests, and tabs refresh one at a time

**Design:** [ADR-072](../../adr/072-stay-signed-in-with-a-secure-cookie.md), accepted 2026-11-18 by Lee Jasmin Adolfo (verbally, recorded by Ashlee Sean); Jira IR-1222

**Implementation:**

- **Backend:**
  - `apps/accounts/refresh_cookie.py`: the cookie (`iris_refresh`: `HttpOnly`, `Secure` unless `DEBUG`, `SameSite=Strict`, path `/api/v1/auth/`) and the first-party check (`X-IRIS-Auth: 1`, `Origin` in `CORS_ALLOWED_ORIGINS` or the site's own).
  - `LoginView` takes `remember` (a JSON `true` only), sets the cookie and answers `remembered`, with no `refresh` in the body.
  - `RefreshView` replaces simplejwt's view. It reads the cookie, answers `401 no_session` without one, and clears the cookie on any 401. It declares a `WWW-Authenticate` header so a refused session stays 401.
  - `LogoutView` reads the cookie and clears it.
  - `sessions.start_session(remember=)` stores `UserSession.remembered` and `expires_at` (migration `accounts/0024`). `touch` skips the idle rule for a remembered session and ends it at `expires_at` with the new `SessionEndReason.EXPIRED` (`session_expired`).
  - `expire_with_session` gives every rotated token of a remembered session the session's own end.
  - Settings: `REMEMBERED_SESSION_DAYS` (30) and `REFRESH_COOKIE_SECURE`; `x-iris-auth` is added to `CORS_ALLOW_HEADERS`. The allowed origins are unchanged.
- **Frontend:**
  - `lib/authStorage.ts` only clears keys earlier versions stored.
  - The auth store has no `refreshToken`. It has a `remembered` flag, and `hydrateAuth` always asks the server, treating `no_session` as signed out rather than a lost session.
  - `api/client.ts` refreshes with an empty body, `X-IRIS-Auth` and `withCredentials`, inside `withRefreshLock` (`navigator.locks` "iris-refresh").
  - The sign-in form has "Keep me signed in for 30 days", unticked.
  - `AuthBootstrap` skips the idle watch for a remembered session.
  - Logout sends no token.
- **Docs:** `SECURITY.md` §2 and `DATA_INVENTORY.md`.

**Test:**

- `backend/apps/accounts/test_refresh_cookie.py` (19):
  - cookie attributes;
  - no token in any body;
  - rotation and a body token ignored;
  - `no_session`;
  - a refused refresh clears the cookie;
  - header and `Origin` refusals for refresh and logout;
  - logout ends, blacklists and clears;
  - without the box: a browser-session cookie, the idle rule still applies, and only a JSON `true` ticks it;
  - with the box: 30 days from sign-in, idle ignored, ends on day 30 despite daily use with `session_expired` recorded, and rotated tokens and the cookie keep the session's end.
- Existing account tests now present the token as the browser does, through `apps/accounts/testing_auth.py`. These were changed on purpose: they read `refresh` from the body, which ADR-072 removes.
- `contracts/auth-login.json`: `refresh` is replaced by `remembered`. Only that line changed; the other recordings were left as they were.
- **Frontend:**
  - `store/hydrateAuth.test.ts` (fake cookie jar that rotates and blacklists) and `lib/authStorage.test.ts`. Both were rewritten on purpose, because they pinned `sessionStorage`.
  - `lib/tokenRefresh.test.ts`: the lock makes refreshes take turns, and works without Web Locks.
  - `api/client.test.ts`: no body, the header, `no_session`.
  - `api/auth.test.ts`.
  - `features/auth/LoginPage.test.tsx`: the box is off by default and `remember` is sent when ticked.
  - The logout tests in `PendingApprovalPage` and `NoticeAnswerScreen` now expect no token.
