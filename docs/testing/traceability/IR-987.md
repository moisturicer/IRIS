# IR-987 — Figures for Unstructured reads: stored crops through the existing figure path

**Affected requirement labels:** none by FR- id. This builds [ADR-067](../../adr/067-unstructured-replaces-llamaparse.md) decision 10 under the IR-980 spec. No other matrix row changes status.

## Scope, corrected to the ADR

The card offered two paths. ADR-067's 2026-11-14 amendment §4 records that Platform `hi_res` returns `image_base64` for `Image` elements, so this takes the first path: decode the bytes in the client. No `figure_crops.py`, no pypdfium2.

Two acceptance criteria are met differently from how the card words them:

- **"Crops are valid PNGs":** `hi_res` returns JPEG, as in the `ruled_table` recording. The vendor's media type is kept and must match the bytes. The existing magic-byte check in `documents/figures.py` accepts PNG, JPEG, GIF and WebP.
- **"The `figures.pdf` fixture … stores one `ExtractionFigure` per image":** the Platform recording of `figures.pdf` has no `Image` element, because its shapes are vector drawings. The tests add Image elements to that recording in memory. The recording itself is not edited.

## What changed

- `unstructured_client.py`: each shaped `Image` with `image_base64` becomes a `FigureImage`:
  - `name` is its `element_id`, the same name shaping gives `DocumentElement.figure`, so the stored Figure joins its element.
  - Page and bound caption come from shaping.
  - `bbox` is the element's box in `x/y/w/h` page points, the shape LlamaParse Figures use.
  - Table images are not Figures.
  - Undecodable or non-image bytes are dropped. So are images over `UNSTRUCTURED_MAX_FIGURE_PIXELS` (default 16,000,000, read from the header only) and Figures past `UNSTRUCTURED_MAX_FIGURES` per read (default 200). Each drop is logged.
- `shaping_unstructured.element_boxes()`: one raw element's boxes, public for the client.
- `selection.unstructured_extractor()` passes both bounds. The settings are in `config/settings/base.py` and `backend/.env.example`.
- `figures.replace_figures`, the Figure endpoint, `describe_extraction_figures` and the LlamaParse client are unchanged.
- `raw` still holds `image_base64`: ADR-067 decision 4 stores the vendor's output whole.

## Evidence

Run 2026-11-14, new tests only. The full suite is left to CI.

- `apps/ai/extraction/tests/test_unstructured_figures.py`: 8 passed. Covers decoding, page, box, caption, name, JPEG, both bounds, non-image bytes, Table images and the builder's settings.
- `apps/documents/tests/test_unstructured_figure_storage.py`: 1 passed, against Postgres. `figures.pdf` is read through the adapter by `extract_manuscript_text`; one `ExtractionFigure` is stored with page, box and caption, served to the owner, and the 404 of a missing record to a stranger.
- `flake8` clean on the changed files.
