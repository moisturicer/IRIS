**Office console: why it was not visible live, and the redesign.** Written 2026-11-15.

## Why the console was not visible on the live site

Found by reading the code; the live site and its accounts were **not** inspected.

- The sidebar link and My Reviews' header link show only when `GET /users/me/` returns `review_access.is_coordinator: true` (`reviews/seats.py`). That needs an office role **and** `User.is_office_coordinator`.
- The flag was added by `accounts/0010` with `default=False` and **no backfill**. Only `seed_demo` sets it. On a live database it is set only by the System Admin's "Make coordinator" action (`PATCH /users/<id>/coordinator/`, ADR-032 §4). RDCO cannot grant it. An unflagged coordinator gets no link and a 403 on `/review/office`.
- `rolesFor("reviewOffice")` and the server's `OFFICE_PARTY_BY_ROLE` both include RDCO, so RDCO has a console like the other three offices.
- The sidebar entry itself shipped with IR-1085 (merged 2026-11-14); a live build older than that has no link either.

**Fix on the live site is data, not code:** the System Admin flags each office coordinator. This is for Jive / the System Admin to do; nothing here grants the flag automatically.

## What changed

- `GET /reviews/office/` rows now carry `authors_line`, a server-worded `status` (`kept`, `overdue`, `unassigned`, `due`, `paused`, `no_date`) and the `actions` the viewer may take. The browser computes no overdue wording.
- The page is one table (caption, Paper / Reviewer / Due / Status / actions), "Nobody yet" for an unassigned row, Assign as a button on an unassigned row and a "More actions" menu (Reassign…, Extend due date…) otherwise; each row stacks into labelled lines below 640 px.
- No behaviour change to assign, reassign or extend.
