## IR-741 — Produce an honest release-evidence report with explicit missing gates

**Basis and scope.** IR-741 under IR-716; authority ADR-049 §25-§26. The acceptance criteria below are tracked in Jira (read 2026-11-05) and in the local copy `docs/superpowers/specs/2026-10-31-ai-runtime/tickets/26-ir-741.md`; Jira plans the work, it does not define it. Blocker IR-740 is Done. It extends IR-605's `eval_campaign` report; it adds no scorer, no run-file format and no collection. Live campaign collection, human review and paid capacity measurement are IR-755.

**What changed.**
- `evaluation/readiness.py` (new, pure): `build_readiness` produces a `release-readiness-1` manifest of eleven gates (`comparison`, `quality`, `safety`, `human_review`, `baseline`, `access_disclosure`, `postgres_workers`, `browser_accessibility`, `authorization`, `workload`, `cost`). Only `met` clears a gate; `not_met`, `inconclusive`, `not_measured`, `incomparable`, `contract_only` and `breached` all block. `collection_preflight` names every missing declaration, cap and approval. `verify_manifest` and `assert_ready` are what IR-742's cutover preflight reads.
- `evaluation/campaign_report.py`: a measured arm now records its conditions and the distinct cases each family ran, and the report lists the set's families, so a saved report can be matched against a frozen baseline later. Existing fields are unchanged.
- `management/commands/eval_readiness.py` (new): `--build`, `--preflight`, `--validate-measurement`, `--verify [--check-files] [--assert-ready --expect-commit]`. Records each input by path and file SHA-256, and the build arguments, so `--assert-ready` can rebuild the manifest.
- `evaluation/scenarios.py`: the browser producer records `evidence_recorded` per check (the private reference is still never copied).
- `docs/evaluation/general-tools/workload-measurement.example.json` (new): a fake example of the measurement contract.
- Docs: `docs/evaluation/general-tools/readiness.md`.

**Acceptance criteria.**
1. *90% / 95% objectives per repetition and family, three repetitions, ten distinct cases.* `test_every_repetition_and_family_is_scored_against_the_selected_objectives`, `test_a_family_below_the_objective_fails_even_when_the_average_clears_it`, `test_claim_citation_and_page_support_use_the_higher_objective`, `test_fewer_than_three_repetitions_is_inconclusive_not_a_pass`, `test_a_family_with_fewer_than_ten_distinct_cases_is_insufficient`.
2. *Matched baseline comparison; separate capability/model; explicit gaps.* `test_equal_matched_aggregates_are_not_a_regression`, `test_a_matched_aggregate_regression_blocks_even_when_every_objective_is_met`, `test_a_baseline_taken_under_other_conditions_is_incomparable_not_compared`, `test_capability_and_model_results_are_reported_apart_and_never_gate`, `test_unreviewed_and_single_reviewed_cases_are_explicit_human_review_gaps`.
3. *Access/disclosure, PostgreSQL/worker, browser/accessibility, workload evidence; breach blocks.* `test_an_access_breach_blocks_readiness_whatever_the_quality`, the scenario tests (`test_an_omitted_worker_result_is_not_measured_and_blocks`, `test_a_contract_suite_cannot_stand_in_for_real_postgres_and_independent_workers`, `test_browser_evidence_needs_the_accessibility_checks_measured_and_passed`).
4. *Workload and profile preflight; p95, tool/model time, resources, cost per successful task, unknown usage.* `test_queue_inclusive_p95_tool_model_time_and_resources_are_reported_per_class`, `test_total_cost_per_successful_task_includes_the_failed_requests`, `test_unknown_usage_is_counted_at_its_reservation_and_blocks_the_cost_gate`, `test_usage_with_no_figure_at_all_cannot_be_bounded`. Hand-worked figures are in `readiness_fixtures.measurements`.
5. *Passing, failed, breached, mismatched and not-measured fixtures; fake never measured; missing caps/approvals block live collection.* `test_a_complete_synthetic_fixture_is_the_only_way_to_evidence_met_and_authorizes_nothing`, `test_fake_providers_are_a_contract_check_never_measured_quality`, `test_a_missing_operational_cap_blocks_live_collection_and_is_named`, `test_missing_paid_provider_or_data_approvals_block_live_collection`, and through the command `test_preflight_names_every_missing_declaration_cap_and_approval`.
6. *Versioned machine-checkable manifest with evidence references and human-review gaps, usable by cutover preflight.* `test_the_manifest_is_versioned_self_digested_and_byte_for_byte_reproducible`, `test_a_ready_manifest_passes_the_cutover_check_and_a_blocked_one_is_refused_with_why`, `test_a_manifest_edited_to_say_ready_is_caught_even_when_resealed`, `test_every_gate_names_the_evidence_it_rests_on`, and `test_readiness_command.py` (build, verify, assert-ready).

**Independent demonstration.** `test_a_missing_worker_and_browser_result_a_breach_and_unknown_usage_yield_blocked_readiness` and `test_build_blocks_and_says_why_when_a_worker_and_browser_result_is_omitted` generate a manifest from synthetic fixtures with a worker/browser result omitted, a breach and unknown usage injected, and observe `blocked` with each reason named. The "preserved baseline" is a synthetic copy of a fixture report, not a recorded one.

**Evidence.**
- Local (Windows, Python 3.14, backend requirements in a scratch virtualenv, **no PostgreSQL**): `test_release_readiness` (97), `test_readiness_command` (19) and the neighbouring `test_scenarios`, `test_campaign_report`, `test_campaign_command`, `test_conversation_scoring`, `test_review_campaign`, `test_conversations`, `test_conversations_command`, `test_runtime_engine`, `test_runtime_campaign` and `test_runtime_smoke` all pass (247 tests in one run). flake8 is clean on the changed files. All of these are pure and need no database. As a check that the new tests are not vacuous, removing the provenance check and the measurement-shape check made six of them fail; both were restored.
- Not run locally: the rest of the backend suite, including every PostgreSQL-backed suite. No new test needs a database.
- CI: recorded in the PR.

**Not verified / not done.**
- **Review found and this change fixed** (two-axis code review of the first commit): a report without `set_families` could clear `quality` with no family check; a family needed ten distinct cases only across all repetitions, not in each; a family metric with no denominator was skipped; `cost` accepted a measurement of another workload or an in-process one; a naive timestamp crashed the workload gate; concurrency was declared but never compared with what ran; a baseline with fake providers, fewer than three repetitions or unrecorded conditions could be matched; browser checks needed no `evidence_ref`; a negative cost lowered the total; `verify_manifest` rejected a file as `write_run` wrote it and crashed on malformed JSON; `--capability`/`--model` inputs were not referenced; and a hand-made manifest with invented digests passed `assert_ready` (it now re-hashes every named input).
- **The four documented observations, as resolved in the follow-up commit.** (1) *Point estimate vs Wilson interval:* point-estimate gating is preserved and the interval is reported beside it; the interpretation is written into every manifest as `policy_decisions[objectives_on_point_estimate]`, status `awaiting_confirmation`, and printed by `--build` as `CONFIRM`. A 10-case family cannot have a lower bound at 0.90 (10/10 gives 0.72), so gating on it would make the profile unreachable; **Jive must confirm**. (2) *IR-608 provenance:* `eval_scenarios` records the commit once on the run file and `eval_campaign` read only the rows, so the recorded provenance never reached a gate. `scenario_rows` now copies the run-level commit onto a row that has none, marked `git_commit_source: run_file`; a run that records none, or `unknown`, gives its rows none and the gate is `not_measured` / `unverified`; another commit or a dirty tree is `incomparable` / `mismatch`. Nothing is inferred. The browser producer now records `evidence_recorded` (a private reference is still never copied). The first commit required `evidence_ref` on the browser row, which the real producer strips, so a real run could never have passed: fixed here. (3) *Success rate:* no threshold is invented. The workload gate reports successes, failures and observed rate per class, keeps the all-samples-failed block, and states the limitation in `success_rate_policy` and `policy_decisions[no_success_rate_threshold]` (awaiting confirmation). (4) *`workload-measurement-1`:* unchanged in shape; now documented field by field in `readiness.md`, checked by `validate_measurement` and `eval_readiness --validate-measurement`, with a committed fake example. A malformed file makes the `workload` and `cost` gates `not_measured` instead of crashing them. IR-755 can write its producer to that contract alone; no paid measurement is needed for IR-741.
- **Other judgement calls left as written.** `access_disclosure` is `met` from the IR-608 deterministic-provider access suite, a contract check by that suite's own definition. The `verify` / `assert-ready` / `--preflight` modes and the CLAUDE.md and docs additions go slightly beyond "usable by cutover preflight"; they are small and are what IR-742 would otherwise have to write.
- Every passing fixture is synthetic and declares itself `real` to exercise the logic. **No real campaign, load measurement, browser exercise or human review exists**, so no actual manifest can be `evidence_met` today; that is IR-755's collection.
- Nothing yet produces a `workload-measurement-1` file; its shape is defined by this change and documented for IR-755, which must emit it or amend it with a version bump.
- No operational cap value is approved; the command only reports which are missing.
- No reader or HTTP surface: the operator surface is the management command, as for IR-609.
- The manifest is not yet consumed by IR-742's cutover rehearsal; `assert_ready` is its intended entry point.
- Independent human approval of the PR is required.

- **Second review (2026-11-05), fixed in the follow-up commit.** Each gate that cleared wrongly now blocks, with a test per case in `test_release_readiness.py` under "second review": campaign rows with no cache state and no cold/warm spend; a workload declared under another corpus, models, data policy or cache state; a measurement at another commit or none (`git_commit` is now a required field); a resealed verdict or emptied `inputs` (`assert_ready` now rebuilds the manifest and needs `--expect-commit`); infinite caps and samples; a dirty tree verifying against itself; NaN or inconsistent fractions, repeated cases and repetitions, `set_families` that omit families that ran, and the report's own `enablement_blocked` and `excluded_runs`; a baseline that is the candidate; missing tool/model time, an unnamed browser operator, a non-numeric test count, and ingestion that all failed or has no cost. The preflight key is now `unrecorded` rather than an allowlisted `missing`.
- **Existing tests changed deliberately:** `test_a_missing_worker_and_browser_result_a_breach_and_unknown_usage_yield_blocked_readiness` now also expects `comparison: not_met`, because the comparison gate reads the campaign report's own `enablement_blocked`, which the injected breach sets. Two command tests now pass `--expect-commit`, which `--assert-ready` requires, and one matches the rebuild's "cannot be read" message instead of "not on disk". Preflight assertions read `unrecorded`.
- **Access evidence:** `access_disclosure` stays `met` from the deterministic access suite. The module docstring now says why: access and disclosure rules are deterministic code, so a deterministic suite is the evidence kind that claim needs; deterministic or fake runs remain `contract_only` for quality, latency and cost.
- **IR-755 cannot clear `quality` with the current set** (seven cases per family; A04, A07, A09-A13 unsupported); stated in `readiness.md`.
- **Still awaiting Jive:** the three questions in the PR (point estimate vs Wilson bound; a minimum success rate; run-level commit on suite rows, which now refuses `-dirty`).

**Status.** Implemented; second-review fixes pushed, awaiting CI and re-review.
