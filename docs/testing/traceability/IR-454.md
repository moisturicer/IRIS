## IR-454 — The retrieval harness can measure a refusal

**Requirements:** ADR-023 (retrieval quality is measured; see its row). No FR- id.

**Design:** [ADR-023 §A third measure, correct refusal](../../adr/023-retrieval-quality-evaluation.md) · [ADR-033 §Divergence — IR-453](../../adr/033-hybrid-retrieval-and-passage-selection.md), item 3, now marked closed · ADR-027 §2 (two signals are never combined into one score).

**What changed.** Both harness measures are recall measures, so a precision technique such as the relevance cut-off (ADR-033 §3) could only ever score at or below baseline. The harness now:

- runs every **unanswerable** question (`evidence_required` `corpus`/`corpus_multi` with `expected_outcome` `decline-no-evidence`) through the same retriever and selection as the answerable ones (`harness.py`);
- keeps those outcomes in a separate `refusals` list on the report, so neither recall average can include them (`report.py`);
- reports **correct refusal**, the share of unanswerable questions whose final set is empty. It is `None`/`n/a` when the set holds none, rather than a 0 that would read as "refused nothing";
- names every **false refusal**, an answerable question whose final set is empty, by id in the results file, the printed report and the comparison table's `false-ref` column;
- names unanswerable questions that were still given passages;
- has `--dry-run` count the unanswerable questions it validated.

General-knowledge (`none`) and `decline-restricted` questions are still not run, as IR-463 left them.

**Question data.** `docs/evaluation/proxy_starter.json` already holds ten unanswerable questions, added under IR-463 (q55, q56, q66–q68, q83–q87, kind `off-corpus-research`). That file is not changed here: it is pinned by SHA-256 in `docs/evaluation/fixed-workflow-pilot/proxy_audit.json` (IR-542), and adding questions would need that audit and its development/held-out split redone deliberately.

**Tests:**
- `apps/ai/evaluation/tests/test_refusal_measure.py` has 13 tests with no database. They cover which questions count as unanswerable, the measure and its `None` case, recall unchanged by refusals, the results-file shape, false refusals named by id, a miss not counted as a false refusal, rendering, and the side-by-side comparison.
- `apps/ai/tests/test_eval_harness.py` gains 5 database tests:
  - With no floor, an unanswerable question is retrieved for, kept out of recall, scores 0 and is named.
  - A gate that empties every final set scores refusal 1.0 and names both answerable questions as false refusals.
  - The committed synthetic set reports refusal as unmeasured.
  - `--dry-run` counts unanswerable questions.
  - The results file carries the measures.

**Status:** **IMPLEMENTED.** The measure exists and is tested, but no run on the proxy set has produced a number yet. The relevance cut-off it is meant to judge is not built yet (IR-396), so on a healthy stack correct refusal will read 0 until it is. Moving any default stays with IR-402.
