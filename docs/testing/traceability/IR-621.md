## IR-621 — overdue assignment escalation

**Authority.** [ADR-043 §1, §7–§8](../../adr/043-review-turnaround-reminders-and-escalation.md). The original ticket said per Seat and once only; its description was corrected to assignment deadlines and repeats every five working days. Adviser assignments never escalate.

**Implemented.** The existing hourly deadline job sends the latest overdue moment to all active office coordinators, with unfinished reviewer names or an unclaimed Pool, and falls back to RDCO coordinators with a warning when the office has none. Each recipient passes `Record.objects.visible_to`. The existing ledger's assignment/due-date/kind/step key deduplicates concurrent ticks; an Extension or document pause changing the date re-arms it. `ASSIGNMENT_ESCALATED` (audit/0007) commits with the ledger, with metadata documented in [AUDIT_EXPORT.md](../../evaluation/AUDIT_EXPORT.md). Notification delivery remains best effort. No workflow, clearance or Seat is changed.

**Evidence (2026-10-30).** `apps/reviews/test_reminders.py`: **28 passed** against PostgreSQL, including simultaneous escalation, repeat/catch-up, weekend/holiday, extension/pause, Adviser exclusion, RDCO fallback, visibility, unchanged workflow data and audit rollback/retry. The repeat regression failed on the original scheduler and passed with escalation implemented. Scoped flake8 and Django migration consistency passed; Django check reports only the existing Axes deprecation warning. Audit migrations through `0007` applied successfully to a disposable `pg_dump`/restore copy of the development database; `sqlmigrate audit 0007` confirms a SQL no-op (choices only), and the copy was removed afterwards. Full-suite and CI evidence are recorded on the PR. No human approval is claimed.
