## IR-312

**Requirement:** **A proposer sees when their idea was already done here** — the Novelty check; FR-M4 (stable label only)

**Design:** [ADR-029](../../adr/029-proposal-similarity-and-collaboration.md) §1, §2, §6 and its 2026-09-26 amendment, items 7 and 9

**Implementation:** `apps/ai/similarity.py::related_published_research` compares a **Proposal's** record vector against published, non-Proposal records within `visible_to(user)`, same embedding model only, nothing below `AI_NOVELTY_MIN_SIMILARITY` (default 0.70, **untuned** — amendment item 7; `AiConfig.ready` refuses to start outside (0, 1], so "70" fails loudly), top 3. It shares one query, `_nearest`, with `similar_records`, run inside `scan_depth()` so pgvector's 40-row HNSW cap cannot hide published matches behind filtered-out neighbours (IR-440) — which also moves the existing `similar/` path onto the configured depth. `GET /records/<id>/related-research/` serves it **owner-only**: `RecordViewSet.get_queryset` narrows that action to owners, so anyone else, the Adviser included, gets the 404 of a missing record (IR-153). The response carries `checked`: false when no comparison ran (not a Proposal, or no vector yet), so an unindexed Proposal says "not compared yet" rather than "nothing close". `RelatedPublishedResearch` shows it on the owner's Proposal Overview with each match's similarity as a percentage, recomputed on every view. **Delivered as the owner-only list amendment item 9 specifies, not the at-submission notification the card's original wording described** — the card predates the amendment, and a Proposal has no vector at submission anyway (Jira comment on IR-312, 2026-10-11)

**Test:** `apps/ai/tests/test_related_research.py` (24, through the HTTP API with the deterministic fake embedder: a close published record listed with its figure and the threshold; matches need no consent (published record with no DPA stamp); draft, in-review, approved, completed-unlisted and rejected records never surfaced even when the proposer owns them; a published Proposal is not completed work; an empty list rather than a weak match; never matches itself; no vector yet → `checked: false`; the query runs under `scan_depth()`; Thesis/Research and Project subjects return nothing and `checked: false`; impossible thresholds (70, 1.5, 0, −0.2) refused at startup; a stranger, an RDCO officer and the Proposal's own Adviser all get 404). `frontend/src/features/records/paper-view/RelatedPublishedResearch.test.tsx` (4: links with the percentage and axe, an empty state naming the threshold, an unchecked state, a failed request says the check could not run rather than claiming nothing is close) and `PaperViewPage.test.tsx` `related published research (IR-312)` (3: shown to a Proposal's owner, neither shown nor requested for a non-owner or a non-Proposal)

**Evidence:** 2026-10-11, local against a pgvector Postgres: `test_related_research.py` + `test_similarity.py` **32 passed**; full backend suite **3215 passed, 5 failed** — all also fail on `main` without this change (the `ktto_review` and policy source scans read a `backend/venv/` inside the tree; `test_complete_authority::…old_url…` raises `Resolver404` for two actors; `test_chunker_core[fixed-window]` is IR-202's flake). Frontend `npm test` **758 passed**, `tsc` clean, `npm run lint` 0 errors. **Nothing real is indexed yet** (IR-250), so on a live deployment the list is empty until the disclosure gate admits records
