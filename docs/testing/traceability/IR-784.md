## IR-784 — RDCO is notified of a role request once the person has verified their email

**Basis and scope.** IR-784 under IR-779; authority ADR-051 decision 20 (RDCO gets the existing in-app notification once the person has verified their email, so a mistyped address alerts nobody; both empty email tasks are deleted; verification emails keep working). Related to IR-705 (only verified accounts reach RDCO). No FR- id.

**What exists now.**
- `apps/accounts/services.py::activate_user` flips `is_verified` with one conditional `UPDATE ... WHERE is_verified = false`. Only the request that changed the row calls `notifications.services.notify_role_request`, with the person's newest pending `RoleRequest`. The activation token stays valid after use (Django's generator hashes the password and last login, not `is_verified`), so a repeated or concurrent click verifies nothing new and notifies nobody.
- The notification is the existing in-app broadcast to RDCO (`Role Request - Student` or `Role Request - Adviser`); no email is added.
- `send_verification_email_task` and `send_role_request_email_task` are deleted from `apps/accounts/tasks.py`; nothing referenced them. `send_email_task` and `send_verification_email()` (the direct send used at registration) are untouched.

**Tests** (`backend/apps/accounts/test_role_request_notification.py`, through `GET /auth/activate/<uid>/<token>/`):
- verified: one broadcast to RDCO, sender the registrant, no direct recipient, Student and Adviser types, message names the person and role;
- unverified: signing up without following the link, and following a bad token, alert nobody and verify nobody;
- repeated: the link followed three times returns 200 each time and leaves exactly one broadcast;
- an account with no pending request, and one whose request is already decided, verifies without a notice;
- the two empty tasks are gone and `send_email_task` remains.

**Verification.** The suite was not run locally (no backend dependencies in the author's environment); the file compiles. The run is CI's, recorded on the PR.

**Not done here.** Deleting abandoned unverified signups and keeping them from RDCO's lists is IR-705. Registering over HTTP and then verifying end to end is not covered: registration and activation are tested separately.
