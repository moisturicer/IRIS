## IR-1335

**Requirement:** **A page keeps its width whether or not it scrolls, so My Library and My Reviews do not move sideways as their tabs switch.** No FR- id; reported by Hermoine Zozobrado, 2026-11-25.

**Cause:** in a browser with visible scrollbars, such as Chrome on Windows, a page taller than the window gets a scrollbar about 15px wide, and a short page gets none.
- On My Library, Overview and Saved Papers are tall, while My Submissions, Saved Calls and Download Requests can be short.
- The page's width therefore switched between 1905px and 1920px on a 1920px screen.
- The page is centred (`max-w-page mx-auto`), so its content jumped 7.5px at each switch: the heading moved from x = 360.5 to x = 368.
- Measured 2026-11-25 on the smoke build, with Chromium's scrollbars shown.

**My Reviews (reported 2026-11-25, same day):** Done gathers every decision and grows taller than the window, while To review and In review stay short. On `main` at 1920px, the heading sat at x = 368 on the short tabs and 360.5 on Done. Advisers and office staff share this page. The same rule fixes it: on this branch it sits at 360.5 on every tab. The Office console has no tabs.

**Implementation:** `index.css` gives `html` `scrollbar-gutter: stable`, which keeps the scrollbar's room whether or not the page scrolls. It applies on every page, so any page whose height crosses the window's stops moving too. Overlay scrollbars (macOS, phones) take no room, so nothing changes there.

**Test:** new `e2e/smoke/no-sideways-shift.spec.ts`. It shows scrollbars in the smoke browser, which hides them by default. At 1920 by 900 it switches through all five tabs and checks that the My Library heading keeps one x position. It first checks that some tabs scroll and some do not, so that the test means something. A second test does the same for My Reviews, as RDCO staff: To review, In review, Done (twelve decided rows), then To review again.

**Changed deliberately:** `e2e/support/viewport.ts`'s `measureOverflow` now reports how far the page sticks out as never less than 0. The smoke browser hides its scrollbars but still reserves the gutter, so the page came out 15px narrower than the window. That gave an "overflow" of -15, and the viewport matrix and Discover toolbar tests, which expect exactly 0, failed 188 times. A page narrower than the window does not scroll sideways. In a browser with visible scrollbars the measure is 0, as before.

**Evidence:** 2026-11-25, local.
- Built from `main`, both new tests failed: each found two positions.
- With the change, both pass. The full smoke tier passes, 563 of 563, once `measureOverflow` is fixed.

**Status:** **IMPLEMENTED**; awaiting CI and review.
