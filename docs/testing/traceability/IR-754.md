## IR-754 — Compact a Conversation from the reader screen

**Basis and scope.** IR-754 under IR-715; authority ADR-049 §19 and the ticket's acceptance criteria. IR-734 compacts a long Conversation automatically inside a run that is already answering, and IR-735 lets the agent recover the originals. Nothing let a reader ask for it. This adds the reader's *Compact conversation* action in Ask IRIS and Paper Chat, as the same mechanism asked for now. It builds no second summarizer, and native-compatibility integration (IR-736) stays separate.

**Decision: a compaction is a run of its own.** The two ways the ticket allows are a bounded run of its own, or the active run where its revision contract permits. A run that is already investigating has spent part of its allowance on a question the reader asked, and compacting inside it would either spend that or extend it. So the request is admitted as its own `ask_run` with its own identity (idempotency key), deadline, allowance and fence, under the rules an Ask is admitted by. It carries no question and writes no Turn and no revision. It is distinguished only by its stored pin (`pinned.kind = "compact"`, `ai/runs/config.py KIND_COMPACT`), so there is no migration. **Gain:** the investigation's budget cannot be shared, extended or interrupted, and Stop, reconnect, lease takeover, spending admission and deletion all work as they do for any run. **Cost:** the reader waits for an Ask to finish before compacting, and a compaction counts against `RUNS_MAX_ACTIVE_PER_READER` and the queue like any run.

**Code.**
- **Entry point** (`ai/api/runs.py`). `POST /api/v1/ai/conversations/{id}/compact` with `{base_revision}` and an `Idempotency-Key`, reader protocol only. 201 with the run when admitted, 200 for the same request again, 409 when another run is active in the Conversation or the revision moved, 404 for a Conversation that is not the reader's, 503 `unavailable` where the service cannot compact. It is reached through the same-origin edge: `frontend/nginx.conf` allows `conversations/<id>/compact` beside the existing run routes, and Django's edge grant is unchanged.
- **Admission** (`RunStore.admit(..., compaction=True)`, `RunService.submit_compaction`). The Conversation must exist, belong to the reader and have the Paper Chat scope of the grant, so a compaction never widens or narrows a scope. Its request hash is distinct from an Ask's, so one key can never replay as the other. It is pinned to the ordinary profile and takes the same `allowance()` as any run, persisted at admission.
- **Capability** (`RunService.can_compact`, `public.run(..., manual_compaction=)`). True only for an AGENT that new runs are pinned to and that has a configured compaction rule (`RUNS_AGENT_COMPACTION`). The projection's `capabilities.manual_compaction` reports it, which is the first time it is not a constant `false`. A deployment without the rule offers no control.
- **Mechanism** (`AgentExecutor.compact`, `_Run.compact`). It runs IR-734's `_compacted` unchanged except for a `forced` flag: no threshold applies, and only the summary must be affordable, since no answer follows it. The same pin and provider checks as `answer`, so the same admission, ledger reservation and disclosure guard apply (IR-725); the summary is still one admitted AGENT turn with research closed. The task it serves is a fixed neutral request (`COMPACT_REQUEST`), never a question the reader did not ask. The handoff is built and committed by the same `compacting.build` and `RunStore.commit_handoff`.
- **One bounded attempt.** A worker that takes the run over after a summary was sent but nothing committed ends it `unavailable` (`attempts_exhausted`) instead of summarizing again. One that finds a revision its run committed finishes the run without summarizing or spending again. Spending already charged to the run is restored from the ledger, as for any run.
- **Completion** (`RunStore.commit_compaction`, the gating prelude `_finishing` it shares with `commit_final`). The run ends `completed` with end reason `compacted` or `nothing_to_compact`, without a Turn. A Stop, deletion, departed reader, deadline or moved revision ends it as that, and a handoff of a run that did not complete is never opened by a later one (IR-734's `hr.state = 'completed'`).
- **Projection** (`ai/runs/public.py`). Each run gains `kind` (`ask` or `compact`, nothing else is published); a compaction's `question` is `""`. The `compaction` block is IR-735's, and a revision committed and journalled twice by a takeover is counted once. Nothing about the pin, bounds, reasons, summary text or revisions is published.
- **Reader** (`RuntimeReader.tsx`, `api/runtimeReader.ts`). The button shows only when the latest run reports the capability, the Conversation has a Turn, nothing is active and there is no error to reconnect from. It has an accessible description ("Original answers are kept"), one idempotency key per click, a synchronous re-entry guard and a disabled state while a request is in flight. `CompactionStatus` says *Compacting conversation*, *Conversation compacted*, *Nothing older to condense yet*, *Compaction stopped*, *Compaction unavailable* or *Conversation changed*, always with "your conversation is unchanged" where that is true and the same estimated-context line the other runs show. A compaction run is never drawn as a question. Stop reads *Stop compaction*. A 409 reopens the Conversation and shows the active run if there is one, and asks the reader to reconnect only if there is not. A retryable failure keeps the same request for *Reconnect*.

**Tests.**
- `apps/ai/tests/test_ai_runtime_manual_compaction_contract.py` (no database; recording provider, IR-728's in-memory stand-in): a compaction below any threshold writes the same handoff as IR-734's, from one admitted summary with research closed and no answer asked; it keeps the newest exchange; a handoff from an earlier compaction is carried; nothing older than the kept exchange sends nothing; malformed, empty and truncated summaries, a stale commit and a fenced worker each commit nothing; a stopped run sends no summary; a replacement does not summarize again after a failed attempt and finishes a committed one; the run pays for its summary alone from its own allowance, and one it cannot pay for is not sent; already-charged spending is not renewed; no rule, no way to commit, or a paid provider that is not admitted all refuse before sending.
- `apps/ai/tests/test_ai_runtime_manual_compaction_public.py` (no database): `kind`, the empty question, the capability on every run, the pin not published, a takeover's second journal counted once, and *nothing to compact* as a `kept` outcome with no counts.
- `apps/ai/tests/test_ai_runtime_manual_compaction_db.py` (real PostgreSQL, restricted runtime login, Django-issued grants): a compaction condenses older Turns, writes no Turn or revision, leaves all originals on reopen and opens the next run with only the later Turns; a second click is the same run and one summary, the same key with another revision is a mismatch, and a request with nothing newer is harmless; one active run per Conversation both ways, including a second click with another key; a stale revision admits nothing; a Turn landing after the request ends the run `failed` with no handoff; a failed summary changes nothing and can be retried; Stop on a queued compaction sends nothing; a lapsed grant waits and a reconnect resumes the same run once; only the owner can compact, and a deleted or missing Conversation is a 404; a Paper Chat grant cannot compact a general Conversation or the reverse; the capability follows the deployment.
- `RuntimeReader.compact.test.tsx` (accessible tree; 16 tests): the request, revision, Paper Chat header and key; no control without the capability or before a Turn; a double click is one request; compacting, compacted, nothing-to-condense, stopped, unavailable and conflict states; a lapsed session; Stop by keyboard; another active run shows that run, not an error; a moved conversation asks to reconnect; a busy answer keeps the same request; originals are never described as removed; no internals; axe-core at serious/critical on the compacting and compacted states.
- Changed deliberately: `test_runtime_reader_e2e.py` pins the reader projection's exact key set, so `kind` was added to it, and `runtimeReader.recorded.json` gained `"kind": "ask"` on its two runs by hand (the recorder was not run here). `backend/testing/parallel.py` registers the new DB suite with the Postgres role scope. No assertion was weakened.

**Evidence (2026-11-05).** Run locally with the AI runtime's own dependencies (no Django, no PostgreSQL): the new contract and projection files (25 tests), with the compaction, recovery, checkpoint, agent-loop, context, manuscript, metadata, partial-outage and profile suites (all dependency-free AI runtime tests) pass. Frontend: `tsc` clean, eslint clean on the changed files, and the whole Vitest suite passes (137 files, 1,855 tests, including the 16 new ones). The new DB suite and the changed e2e test were **not** run here (no PostgreSQL with pgvector, no backend environment); neither was the nginx change. CI is the gate and its result is recorded on the PR.

**Not done here.**
- **No live effect against a paid provider for a Conversation whose Turns drew on Records.** IR-725's guard withholds Record evidence from a paid provider until the disclosure decision (ADR-049 amendment §4, Jive Tyler I. Revalde's). A summary of earlier Turns alone is not withheld, as for automatic compaction; whether that is enough to compact real answers is that decision.
- **The manual action keeps `RUNS_AGENT_COMPACTION.keep_exchanges`.** The newest `keep_exchanges` Turns are never condensed, so a short Conversation answers *Nothing older to condense yet*. A second, smaller rule for manual use would be a second mechanism; it is left to a person to decide.
- **A manual compaction takes the ordinary deadline and the Ask allowance.** No separate allowance for it exists or is approved; the limits are IR-861's.
- **The reader polls status once a second**, as IR-730 does; the compaction state is not pushed.
- The migration-free choice means `kind` lives in the stored pin; querying compaction runs by kind in SQL would need a column.
- The ticket's independent demonstration (reconnect during compaction, double click, injected failure, then an older exact detail) was not run against a browser. Its parts are shown separately: reconnect and double click in the reader tests, failure and Stop on PostgreSQL, and the exact detail by IR-735's recovery.
- The nginx edge route is checked by reading the configuration, not by a request through `auth_request`.
- Native compatibility and repeated compactions across incompatible state are IR-736's.

**Status.** Partial: implemented, with contract and reader evidence recorded; the PostgreSQL, e2e and edge evidence is left to CI. Awaiting review.
