## IR-1314

**Requirement:** A page whose answer is empty, or that answers quickly, does not first show a placeholder in the shape of content it doesn't have. Calls & Conferences and My Library drew call rows and research cards from their first frame, then swapped them for their empty state; Calls also showed its search box, Area select and type chips while loading and removed them when the board turned out empty. No FR- id.

**Design:** `docs/ui-ux/01-design-system.md` §Loading placeholders, one sentence added: `Skeleton` and `LoadingRegion` draw their shapes only once a load has taken 400 ms, announcing the label from the start.

**Implementation (frontend only):**

- `components/ui/slowLoad.tsx`: `SHOW_PLACEHOLDER_AFTER_MS = 400` beside `SLOW_AFTER_MS`, and `usePlaceholderDelay()`, a separate timer from mount. `useLoadStage`'s 2 s and 10 s are unchanged and still count from mount.
- `components/ui/LoadingRegion.tsx` and `components/ui/Skeleton.tsx`: until 400 ms, the `role="status"` region holds its label and an empty `aria-hidden` div, with none of the caller's `className` (so no min-height) and, for `Skeleton`, no padding.
- `features/opportunities/CallsAndConferencesPage.tsx`: the controls row renders only when `ready && items.length > 0`. They are no longer shown while loading or after a failure, so their `disabled={loadFailed}` and `ready &&` count guards, which could no longer apply, are removed.

**Test:**

- `components/ui/LoadingRegion.test.tsx` (new), for both `LoadingRegion` and `Skeleton`, fake timers: the label is in the status region from the first frame; no shapes and no `min-h`/`p-8` at 399 ms; shapes at 400 ms; "Still working…" at 2 s, not at 1,999 ms.
- `features/opportunities/CallsAndConferencesPage.test.tsx`: no search box or type filters while loading, then both arrive with the calls; an empty board never shows them, before or after it answers. **Changed deliberately:** "shows no counts until there is a board to count" asserted the controls were on screen, without counts, while loading; it is now "shows no search or filters while loading, and brings them with the calls". "says the board failed to load" asserted the search box and All chip were disabled after a failure; it now asserts they are absent.
- `features/library/MyLibraryPage.test.tsx`: an empty library that answers at once never draws a placeholder, on the Overview and on Saved. A MutationObserver records anything put inside a status region's `aria-hidden` wrapper, so a shape shown for one frame still counts. Against the old `LoadingRegion` both cases fail; against the new one both pass.

**Evidence:**

- **2026-11-24, locally:** `npm run lint` 0 errors (2 warnings, in `UserListPage.tsx` and `ConversationSidebar.tsx`, neither touched here). `npm run build` passed. `npm run test:changed` ran 111 files: 2153 passed, 1 failed, 3 skipped. The failure was `MyTemplatesPage.test.tsx` "sends the title, description and file, then shows the new list", which uses `Spinner` and none of the changed modules; on its own it passed 12 of 12 in each of 4 runs. It is a known flake: IR-1291 recorded the same test failing under load.
- **2026-11-24, `npm run preview:local` against the local stack**, Chromium (Playwright), signed in through the form, 10 runs a case. Times are from navigation start (full load) or from the in-app route change, to the last of the page's own API answers; the empty state appeared within a few ms of that answer in every run. The demo board has no calls, so Calls was measured empty for both accounts.

But an empty load still takes over 400 ms in one case, so the flash is shorter, not gone, for an adviser opening My Library from the app. Per the ticket's acceptance criterion 4, this is reported to Ashlee before going further.
