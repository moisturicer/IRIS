## IR-925 — Production renders the API in JSON only; DRF's browsable API stays in development

**Basis and scope.** A defect found by IR-829's manual ASVS run (14.2.2, unneeded features removed) on 2026-11-05. It changes how production renders API responses, not what they contain. No FR- id.

**What was wrong.**
- `REST_FRAMEWORK` in `config/settings/base.py` set no `DEFAULT_RENDERER_CLASSES`, so DRF's default, `JSONRenderer` plus `BrowsableAPIRenderer`, applied in production too.
- Any browser that opened an API address got DRF's HTML page: every endpoint's methods and fields, with forms to call it. IR-829 saw it on `GET /api/v1/courses/` with `Accept: text/html`, under production settings through nginx.
- The app itself never uses that page. It is a developer tool, and a second rendering path, with its own templates and form handling, exposed for no use.

**What exists now.**
- `config/settings/production.py` sets `DEFAULT_RENDERER_CLASSES` to `JSONRenderer` alone, on top of base's `REST_FRAMEWORK`.
- Development is unchanged and keeps the browsable API, decided with Hermoine on 2026-11-11: only the developer can reach it there.
- No view sets its own `renderer_classes`, so the setting covers every DRF route.

**Tests** (`apps/tests/test_production_renderers.py`).
- Seam: the real production settings module in its own process, through the full middleware stack, as `test_transport_security.py` does. The route is `/api/v1/records/`, asked signed out, so it answers 401 before reading the database or cache. DRF renders that 401 with the same renderers as any other reply.
- A browser's `Accept` header gets `application/json` and no HTML page. `Accept: text/html` alone gets no HTML page. `application/json` is answered as before.
- Before the fix, the first two failed with the ticket's symptom: 401 `text/html; charset=utf-8`, the browsable page.

**Verification.**
- Run locally on 2026-11-11 against PostgreSQL in Docker: `apps/tests/test_production_renderers.py`, `test_settings_validation.py`, `test_transport_security.py` and `apps/accounts/test_client_address.py`, 76 passed. flake8 is clean.
- Not re-checked through nginx on the Core journeys stack, where IR-829 found it. nginx passes the `Accept` header through unchanged.
