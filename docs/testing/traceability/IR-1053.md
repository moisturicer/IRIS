## IR-1053 · PDF evidence: IRIS's own reading of the uploaded PDF (ADR-067 decision 4)

Unstructured gives element boxes, but no printed page numbers and no heading
levels. The uploaded PDF carries most of what is missing. So the Manuscript
extraction task now reads it once, after the vendor read, and stores the result
in `PdfExtraction.pdf_evidence` (migration `documents/0023`), beside
`raw_result`. Shaping (IR-1057) can then re-run on stored data without opening
the PDF again.

| Evidence | Source | Stored as |
|---|---|---|
| Words | `pdfplumber` | per page, per line: `[text, x0, top, x1, bottom]` in page points, top-left origin, 0.1 pt |
| Fonts | `pdfplumber` | per line: `size` (by character count) and `bold` (most characters in a bold face) |
| Bookmarks | `pypdf` outline | `{title, level, page}` |
| Page labels | `pypdf` | one label per page, or `null` when the PDF defines none |
| Contents entries | the table-of-contents page(s) | `{page, number, title, indent, page_label}` |
| Text layer | `pdfplumber` | `has_text_layer` per page; a page without one stores nothing else |

**Bounded.** The reader (`apps/documents/pdf_evidence/reader.py`) parses an
untrusted PDF, so it runs in the IR-830 sandbox like the review text reader:
isolated interpreter, no network, address-space and wall limits, confined before
parsing (PDF_INTAKE.md). Pages and size follow the upload's limits
(`PDF_VALIDATION_MAX_PAGES`, 50 MB). Wall time and memory are its own
(`PDF_EVIDENCE_WALL_SECONDS`, `PDF_EVIDENCE_MEMORY_MIB`), required, and added to
the extraction task's time limit.

**Never fails extraction.** An unreadable, encrypted or over-limit PDF, unset
limits or a non-Linux host stores the empty document with its reason in
`error`, and the extraction still finishes `done`. Supplementary uploads are
not read.

**Tests:**
- `apps/documents/pdf_evidence/tests/test_reader.py`: the four extraction
  fixtures, plus a thesis-shaped PDF with bookmarks, roman page labels, a
  contents page and a scanned page.
- `apps/documents/pdf_evidence/tests/test_sandbox.py`: limits, refused output,
  a malformed PDF, the page cap and confinement, the last four on Linux only.
- `apps/documents/tests/test_pdf_evidence_is_stored.py`: storage, a malformed
  PDF completing with its error, and supplementary uploads skipped.

**Migration tested 2026-11-13** on a copy of the dev database (44
extraction rows, at `documents/0022`): `0023` applied, every row read `{}`,
then it reversed to `0022` and re-applied cleanly. The copy was dropped.

**Measured 2026-11-13** on the six-paper proxy subset (`proxy_ir851_six`;
ADR-023 proxy tier, never a finding about CIT-U research). Read in-process in
the `iris-backend` Linux image, outside the sandbox:

| Paper | Pages | Read (s) | Stored (KB) | Bookmarks | Page labels | Contents entries |
|---|---|---|---|---|---|---|
| active learning | 20 | 17.5 | 612 | 29 | no | 0 |
| astrophysics of galaxies | 23 | 11.0 | 1,127 | 20 | no | 0 |
| audio and speech | 5 | 1.0 | 290 | 16 | no | 0 |
| cosmology | 17 | 3.7 | 870 | 12 | no | 0 |
| econometrics | 8 | 1.0 | 219 | 5 | no | 0 |
| hardware architecture | 5 | 1.0 | 244 | 0 | no | 0 |

About 50 KB a page. The time is not the text but vector figures: pdfminer
builds every path, and one page of the active learning paper (8,140 curves)
takes 16 s on its own. A 300-page thesis full of plots could pass the 120 s
example wall time and store `over_limits`. No arXiv paper here has page labels
or a contents page, so those are proven only on the fixture.
