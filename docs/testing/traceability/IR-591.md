## IR-591 — generalized resolution, search, reading, aggregation and evidence extraction

**Requirement.** [General-tools spec](../../architecture-review/2026-10-15-askiris-general-tools-spec.md) §3.2 under [ADR-042](../../adr/042-general-tools-conversation-contract.md), acceptance scenarios A04–A07: five composable, read-only tools on IR-590's envelope, with no answer prose and no fixed task sequence.

**Built.** `general_tools()` registers `resolve_papers`, `search_research`, `read_papers`, `aggregate_records` and `extract_evidence` (`apps/ai/research/tools/{resolve,search,read,aggregate,extract}.py`) beside the legacy six, which are unchanged. A tool may return `Shaped`, an envelope-native status/items/facts/coverage/continuation that `envelope_of` passes through. **Resolve:** exact titles first (`research/titles.py`, now shared with the comparison lane's `_named_records`), then short title, then whole-phrase; several matches, duplicate titles included, are an `ambiguous` group of at most five candidates ordered by an optional topic hint; unknown, hidden and vendor-withheld references are all `match: none`. Ordinals resolve only against an application-supplied `ToolRun.presented` (`Presentation(revision, record_ids)`); with none, `no_presented_list`. **Search:** papers (record fusion) or passages (the one retriever), real metadata filters (completion year, not publication year), issued-handle scope inside Paper Chat scope, exact named-paper matches ranked first and labelled apart from related ones, each paper's best passage before any second, always `non_exhaustive`, a cursor bound to query, caller and the reader's visible set, and handles issued only for the page shown. **Read:** `outline` returns section identifiers (`S` + a digest of the whole heading path, so a repeated heading under another parent stays distinct) and page spans; `sections` accepts only those identifiers, `pages` only existing pages; each paper reads within its own share of the read cap, always advances at least one chunk, and returns its own continuation, so a late section is read directly and a long paper resumes without replaying its prefix. `brief` returns a cached IR-556 brief through `briefs.cached_brief`, which never queues or generates one. **Aggregate:** `count_records`/`corpus_facets` with the metadata predicate and snapshot, no topic argument, and a separate `ai_readable` fact. **Extract:** brief fields come from a ready cached brief via the comparison lane's `table_fields` (renamed from `_table_fields`); other fields (at most eight, five papers) are read under `InferenceTask.BRIEF` with the IR-556 reader, now parameterized by field set and able to verify a typed `metric` whose number is printed in its own cited quote. Each field stays `reported`/`not_reported`/`unsupported`; a paper read only in part turns `not_reported` into `unsupported`; a model failure is `unavailable`, never absence; a paper withheld or re-chunked during extraction contributes nothing. `purpose=screen` screens only the issued records under the existing twenty-candidate limit and reports a `subset_classification`. `run_research_tool --general` runs them as a user.

**Not built here.** No controller calls these tools yet (IR-593), so no HTTP path carries them; the authenticated boundary exercised is the user-scoped management command. Conversation presentation state does not exist (IR-592); the `Presentation` seam is what it will fill. Extraction batches are capped at six per paper per call. Retrieval weights remain application settings.

**Evidence (2026-10-15).** `apps/ai/research/tests/test_general_tools.py` (resolution, search, aggregation, contract, command) and `test_general_reading.py` (outline, late sections, continuation, stale cursor, revocation, cached brief and its invalidation, sourced fields, typed metrics, unsupported fields, screening scope), all with fake providers. `pytest apps/ai/research` plus the comparison, brief and IR-590 contract HTTP suites pass except `test_plan_profile.py` and `test_screen_profile.py`, which fail identically on `main` because this machine's `backend/.env` holds real model keys. The full backend suite on this branch has 47 failures, the same 47 as clean `main` (dc585f7) run with the same `.env`; none is in a module this change touches.
