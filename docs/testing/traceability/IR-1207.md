## IR-1207

**Requirement:** After sign-in, the login screen returns a person to the saved page only if their role may open it; otherwise it sends them to their own landing page. The "this page is not for you" screen still shows for an address typed or edited while signed in

**Design:** Jira IR-1207 (reported by Hermoine Zozobrado in team testing, 2026-11-17). Extends IR-236 (safe redirect) and IR-534 (landing page)

**Implementation:** `frontend/src/lib/access.ts` `canOpenPath(role, address)` reads the same screen table the route guards read (`SCREEN_ACCESS`), matched with react-router's `matchPath`; a screen with no `:param` outranks one that matches only through a parameter, and an address no screen names is left to the router. `frontend/src/features/auth/LoginPage.tsx` follows the saved destination only when `mayReturnTo(user, path)` allows it (`canOpenPath`, or Django staff with no IRIS role, whom `ProtectedRoute` lets through every guard), else `landingPathFor(user)`. `ProtectedRoute` is unchanged

**Test:**

- `frontend/src/lib/access.test.ts`, "canOpenPath": allowed and refused screens, query and fragment ignored, `/records/import` is the import screen and not a paper, a page two screens share, an unnamed address, no role.
- `frontend/src/features/auth/LoginPage.test.tsx`, "where the login screen sends you": a KTTO account given RDCO's `/rdco/users` in router state, or `/admin/audit` in `?next=`, lands on its own landing page; a saved `/review?status=pending` it may open is still followed after a real sign-in; Django staff with no IRIS role still return to `/rdco/users`; the existing destination tests still pass.
- `frontend/src/components/auth/ProtectedRoute.test.tsx`, unchanged: "refuses a signed-in user who lacks the role" still shows the refusal screen for a typed address.
