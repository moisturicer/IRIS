## IR-995 — Stop guardrail crashes and name mismatches from failing runtime agent answers

**Basis and scope.** IR-995 under IR-955; authority ADR-049 and its 2026-11-09 amendment. IR-956's paid agent-only rerun on IR-994 code (`docs/evaluation/runs/20261109-022740-IR-956-answer-quality-19c2515d`) lost about 40 of 108 questions to mechanical causes. Builds on IR-994.

**What the run showed (from the run journal of the eval copy).**
- Four runs (F06-04, F06-06, F07-03, F07-04) ended `unavailable` right after `resolve` returned `no_match`: the result carried a `matches` key, which is not a control key, so the guard refused it.
- Four F12 runs ended right after a search whose only paper was outside the IR-889 approval: `_screened` turned it into `no_match`/`withheld`, and `withheld` was not a control value.
- Category names are stored as slugs (`hardware-architecture`) and titles with hyphens (`TTM-Bench …`, `Tide-and-Seek …`); exact or case-only matching missed them.
- Eleven answers were trimmed to their supported sentences after one repair. Which check failed is in the worker log only (`agent draft refused: <codes>`); the run 8 worker log was not kept.
- F11-08 asked "which paper?" in a Paper Chat: the model was never told its paper.

**What exists now.**
- `ai/admission/guard.py`: `withheld` is a control value. `ai/agent/tools.py`: a result with no papers sends no `matches`; a partly withheld result carries reason `withheld`.
- `ai/research/metadata.py`: `fold`, the `title_phrase` tier on folded text, and a `close_title` tier (at least 0.75 of the reference's distinctive words present). `ai/research/tools.py`: `resolve` returns close titles as match `close`; taxonomy filters compare folded names. `ai/agent/assurance.py` compares quoted titles folded.
- `ai/agent/executor.py`: `research-7` (`CHAT_INSTRUCTIONS`, `PAPER_CHAT_PREFIX`) and two repairs under it. `ai/runs/agent_profile.py` pins new runs to `research-7`.

**Tests.**
- `ai/tests/test_send_guard.py`: an all-withheld search and a resolve miss reach the model; a partly withheld result says so and keeps its source; text dressed as a withheld status is still refused.
- `ai/tests/test_name_matching.py`: slug and spoken names fold alike; hyphenated titles are found by phrase; exact and short titles still win; a described paper comes back as a close choice; unrelated or one-word references match nothing.
- `backend/apps/ai/tests/test_ai_runtime_ir995_contract.py` (executor, recording model, the guard's provenance check on every request): a withheld search and a resolve miss do not end the run; `research-7` names a Paper Chat's paper, earlier pins and unscoped chats do not, and an unsendable paper is not named; `research-7` repairs twice and writes no validation code to the run journal; `research-6` still repairs once.
- `backend/apps/ai/tests/test_ai_runtime_metadata_db.py` (real PostgreSQL, restricted runtime login): a slug category counted and listed by its spoken name; a hyphenated title resolved by phrase and a described one returned as a close choice.
- Updated deliberately: `ai/tests/test_agent_profile.py` and `test_ai_runtime_executor_selection_db.py` expected the default pin `agent-research-6`; it is now `agent-research-7`. `test_ai_runtime_agent_loop_db.py::test_every_admitted_attempt_records_the_agent_purpose_and_no_other_writer` expected an unapproved search to end the run `unavailable`; it now completes, the second request carries no Record text and says `withheld`, and both reservations are sent.

**Runs.** `ai/tests` (all) and every `backend/apps/ai/tests` contract test pass. DB suites run serially (no xdist): `test_ai_runtime_metadata_db.py` 15 passed; `test_ai_runtime_agent_loop_db.py` passed; `test_ai_runtime_research_db.py`, `test_ai_runtime_turn_sources_db.py` and `test_ir886_hybrid_search_db.py` passed. `test_ai_runtime_executor_selection_db.py` has 3 failures (`test_the_deadline_ends_a_hung_attempt_with_no_turn`, `test_a_killed_workers_agent_run_is_resumed_by_another_under_the_same_pin_and_allowance`, `test_two_workers_settle_agent_runs_within_the_deep_and_per_reader_caps`); the same three fail on the IR-994 base commit `e9409835` on this Windows machine, so they predate IR-995.

The worker log names the failing checks: `unknown_title` on 36 drafts and 13 repairs, `unsupported_number` on 23 drafts and 7 repairs. The three failed questions (F08-07, F10-09, F12-04) are `invalid_draft`: every repair failed and no sentence stood on its own.

**Not done here.**
- An unknown filter value still returns only `unknown_filter_value`. The model is told to group a count to learn the valid names; having the tool list them would need a new guard shape.
- `unknown_title` is the check that most often rejects drafts; finding why is the next step.
- The three reader-a F12 questions need their private paper in the IR-889 approval, an owner decision. Whether the model may answer from general knowledge when the reader asked about the repository is also the owner's call.
