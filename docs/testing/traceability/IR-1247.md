## IR-1247

**Requirement:** pdf.js and the paper reader are not in the main bundle every page downloads; they load only when a paper or a Publish preview is shown

**Design:** Jira IR-1247, from a local performance investigation (Ashlee Sean, 2026-11-20). `PublishDetailsPreview.tsx` imported `PaperPdfReader` statically. Publish is reachable from every page, so pdf.js sat in `index-*.js`. `paper-view/lazyReader.ts` (IR-1203) already loads the reader on demand; Publish now uses it

**Implementation:**

- `frontend/src/features/publish/PublishDetailsPreview.tsx` imports `PaperPdfReader` from `paper-view/lazyReader`, inside `<Suspense fallback={<Skeleton rows={8} label="Loading the reader…" />}>`, the same fallback Paper View uses.
- Guard `frontend/src/features/records/paper-view/lazyReader.test.ts`: no source file may import `PaperPdfReader` statically (type-only imports allowed), so the bundle can't regress unnoticed.

**Test:**

- `lazyReader.test.ts`, "is never imported statically, so pdf.js stays out of the main bundle (IR-1247)": failed first, naming `features/publish/PublishDetailsPreview.tsx`.
- `PublishDetailsPreview.test.tsx`, "says the reader is loading, then shows it": the preview holds a busy status region until the reader arrives. It failed first, since there was no loading state.

**Evidence:**

- 2026-11-20, locally: both tests failed first, then `vitest run src/features/publish src/features/records/paper-view` and the guard passed (62 files, 1,190 tests). `tsc --noEmit` and `eslint` clean.
- Production build, checked from the source maps:

  After the change, `pdfjs-dist` is only in `PaperPdfReader-*.js`.

  - `/?publish=new` opens the Publish dialog with no page errors.
- Publish's preview after an actual upload was not hand-checked; it is covered by the unit test and uses the same lazy reader and fallback as Paper View.
