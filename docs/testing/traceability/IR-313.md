## IR-313

**Requirement:** Bulk-load a corpus of PDFs from a directory

**Design:** Jira IR-313 (no ADR — a dev-tooling command, not a requirement)

**Implementation:** `apps/records/management/commands/load_corpus.py`: one `Classification` per subfolder, one `Record` per PDF titled from its filename, `abstract_file` attached, idempotent on `(title, classification)`. Reuses `lifecycle.LEGACY_IMPORT_STATUS` — the same declared bulk-import bypass `RecordViewSet.import_excel` already uses — rather than inventing a second one. Creates the `PdfExtraction` row and queues `extract_manuscript_text` itself, in the same one atomic block, exactly as `RecordViewSet._queue_manuscript_extraction_if_present` does for a web upload — a management command writing through the ORM reaches neither hook

**Test:** `apps/records/test_load_corpus.py`

**Evidence:** `pytest apps/records` green (157 passed). Run for real against a 20-paper, 4-category corpus on the dev database 2026-09-25: 12 new records created, 8 already present from an earlier partial load correctly skipped as already-existing rather than duplicated, all 12 extracted and chunked with zero failures (354 chunks; see IR-116 above)

**Status:** **IMPLEMENTED** — **a real finding surfaced by this run, not a defect in this command**: none of the 354 chunks carry a `formula` element, even on an equation-dense paper ("State-Space-Based FIR Filtering on a Quantum Computer"). `do_formula_enrichment` is confirmed sent and accepted (it is a real boolean field on docling-serve's own OpenAPI schema, and `do_ocr`/`do_table_structure` sent the identical way both visibly work), but the running `docling-serve` container (`quay.io/docling-project/docling-serve:latest`, unmodified) has no CodeFormula model downloaded in its model cache — only layout, TableFormer, OCR and the figure classifier are present. IR-290's formula path is therefore unverified for a different reason than its PR recorded: not "no live docling-serve," but "this docling-serve has no formula model." Provisioning that model is deployment work, out of this command's scope
