## IR-819 — Passwords meet ASVS Level 1 (2.1.1, 2.1.2, 2.1.7, 2.1.8)

Found by IR-617. `AUTH_PASSWORD_VALIDATORS` set a minimum of 8, no maximum outside a reset, and only Django's common-password list, and no form showed a strength meter.

**Server** (`config/settings/base.py`, `apps/accounts/password_validation.py`). Registration, a signed-in change and a reset all run `validate_password`, so one list holds on all three:

| Rule | Validator | Message |
|---|---|---|
| 12 characters or more | Django `MinimumLengthValidator` | This password is too short. It must contain at least 12 characters. |
| 128 characters or fewer | `MaximumLengthValidator` | This password is too long. It must contain at most 128 characters. |
| not a common password | Django `CommonPasswordValidator` | This password is too common. |
| not a breached password | `BreachedPasswordValidator` | This password has appeared in a data breach. Choose a different one. |
| not all digits | Django `NumericPasswordValidator` | This password is entirely numeric. |

**The breached list is local.** 30,402 passwords of 12 to 128 characters from SecLists (MIT): the NCSC 100k list (from Have I Been Pwned data) and Pwdb's top million. Shorter ones are left out because the length rule refuses them anyway. Provenance, licence and the rebuild script are in `backend/apps/accounts/passwords/`. The ticket asks for an ADR before using an outside service; none is used, so none was needed. ADR-045 §4 described the validators of the time ("minimum 8"), so it gets a dated amendment, proposed for a named person to accept.

**Existing passwords keep working.** Validators run only when a password is set. The demo password `IrisDemo123!` is 12 characters and isn't on the list, and the e2e journeys' passwords pass too.

**Forms** (`frontend/src/lib/passwordPolicy.ts`, `components/ui/PasswordStrengthMeter.tsx`):
- Sign up, Reset password and Settings check the 12-to-128 length before submitting, counting characters as the server does (an emoji is one).
- Each shows a strength meter: four segments, which are decoration, plus "Password strength: …" in a polite live region.
- The meter weighs length and the mix of characters, and calls a repeated character or a single run weak. It is a guide. A breached password can look strong to it, and the server's refusal, shown verbatim, wins.

**Tests changed deliberately:**
- `test_password_policy.py` and `test_password_recovery.py` pinned the 8-character minimum; they now pin 12 (eleven refused, twelve accepted).
- The frontend Sign up and Reset tests pinned "8 characters".
- The Settings and Reset tests that check the server's reasons typed 8-character passwords the form now stops first, so they type 12.
- `test_password_recovery.py`'s numeric check used 8 digits, which the length rule would also refuse, so it uses 12 to keep testing the numeric rule alone.
