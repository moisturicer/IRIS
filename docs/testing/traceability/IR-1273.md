# IR-1273: a Record revoked after Submit new version or Open review lands on not-found

[Back to the matrix](../TRACEABILITY.md)

**Requirement:** a Record the viewer can no longer read must fall to the same not-available screen as one that never existed, whenever Paper View re-reads it (IR-906). Found during the IR-1266 Paper View refactor: two re-reads still went around `reload` from `useRecordLoader` (IR-1268), so a Record revoked mid-review stayed on screen after them. No FR- id.

## What changed

- **Submit new version** (`PaperViewPage.tsx`, `NewVersionDialog`'s `onDone`): re-reads through `reloadRecord` instead of `recordsApi.detail(...).then(replaceRecord).catch(() => {})`, which swallowed every failure, a refusal included.
- **Open review** (`openReview`): once `seatsApi.open` succeeds, re-reads through `reloadRecord`. A seat that fails to record still opens the Review section and skips the re-read, as before (IR-1206).

Any other failed re-read still leaves the page as it was; only a refusal changes it.

## Tests

**IMPLEMENTED.** Run locally on 2026-11-21: the three new cases failed on the old page code (the two re-read cases) and pass on the new one. CI is the gate.

| Test | Shows |
|---|---|
| `PaperViewPage.test.tsx` › *falls to the not-available state when Open review's re-read finds access gone* | The seat is recorded, the re-read is refused, and the page shows *Record not available* with no tabs |
| `PaperViewPage.test.tsx` › *still opens the review when recording the seat fails* | IR-1206 still holds: a failed seat call still opens the Review tab |
| `PaperViewPage.test.tsx` › *falls to the not-available state when Submit new version's re-read finds access gone* | v3 is submitted, the re-read is refused, and the page shows *Record not available* with no tabs |

The records API mock gains `submitNewVersion`, which the page test did not reach before. No existing test was changed.
