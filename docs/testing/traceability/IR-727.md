## IR-727 — Answer a direct question through the pinned AGENT provider contract

**Basis and scope.** IR-727 under IR-714; authority ADR-049 §13, §14, §20. The provider-contract prefactor and the first direct-answer slice: one model turn, no tools. The tool loop is IR-728, real transport waits on IR-725 and IR-732. No schema change.

- **Provider port, additively.** `ai/domain/ports.py` gives `LLMProvider` a concrete `converse(request)` that raises `UnsupportedCapability`, plus empty `endpoint`/`models`/`capabilities`/`dialect`. `OpenAILLMProvider` and `chat_service` are unchanged and refuse agent turns.
- **Typed exchange** (`ai/agent/protocol.py`). A `ModelTurn` is an ordered tuple of `Text`, `ToolGroup` (parallel `ToolCall`s with their ids, in model order) and `Opaque` items, plus a `StopReason`. `Opaque` hides its payload from `repr` and is bound to the `Pin.binding()` that produced it: endpoint, model, dialect, prompt version and tool version (ADR-049 §20). `check_history` refuses, before anything is sent, a tool group not answered completely and in order, and an artifact under any other binding. `final_answer` refuses length, filtered, malformed, tool-only, reasoning-only and empty turns.
- **Dialect** (`ai/agent/dialect.py`, `chat-completions-1`). It encodes requests and decodes responses. Anything it cannot read completely (unknown finish reason, missing or duplicate call ids, non-string arguments, tool calls that disagree with the finish reason) becomes a `MALFORMED` turn with no items. Reasoning text is never kept, only whether some was reported.
- **Pin.** `ai/agent/protocol.Pin` holds model, endpoint, adapter, dialect, prompt/tool/public/state versions, data policy and required capabilities. All are required. `RunService.pinned()` persists it under `pinned.agent` at admission. A claim returns the persisted pin. A run whose AGENT pin differs from the claiming worker's ends `failed`/`unavailable` without calling the provider; this includes a worker with no pin. Runs without an AGENT pin are unaffected, so IR-723's workers can still use their own executors. Reopen shows each Turn's pin.
- **AGENT executor** (`ai/agent/executor.py`). It sends the original question unchanged, with no tools. The provider's `accepts(pin)` checks adapter, endpoint, model, dialect, data policy and required capabilities; the executor also checks the versions it implements. Anything unsupported is `Unavailable("unsupported_pin")` and nothing is sent. A non-final turn is `Unavailable(<code>)`. The service ends both as `unavailable`. The code is logged for operators and kept out of the projection and journal.
- **Recording provider** (`ai/infrastructure/recording_adapter.py`). It replays scripted wire responses through the dialect and records every outgoing payload, with no network. `get_run_service` still builds the deterministic executor, and no route reaches a live provider.

**Tests.** `apps/ai/tests/test_ai_runtime_agent_contract.py` (26, no database): a parallel group keeps every call in order with its id; a history round-trips parallel results and a compatible artifact unchanged; an artifact is never forwarded to another model, prompt version, tool version or dialect; an unanswered or reordered group is refused before sending; the original question reaches the model unchanged; six non-final outputs are unavailable, and an artifact without answer text is `reasoning_only`; ten unsupported pins (including adapter and data policy) are unavailable and send nothing; the existing OpenAI adapter refuses agent turns. `apps/ai/tests/test_ai_runtime_agent_db.py` (5, real PostgreSQL, restricted runtime login, Django-issued grants): a direct question completes and reopens with its pin; an unsupported pin ends `unavailable` with no Turn; a queued run is never continued under another pin, nor by a worker without one; no opaque payload or reasoning text reaches the projection, status, reopened transcript or logs. IR-722's 20 run tests still pass unchanged.

**Not done here.** There is no tool loop, no real transport and no provider admission. Nothing configures `AgentExecutor` from settings: the routes still build the deterministic executor, so the AGENT path is reached only by tests until real transport is gated. Reopen and run status expose the pin (model, endpoint, adapter, data policy) to the run's owner, as IR-722 already did for `pinned`; whether that belongs in the public allowlist is open. Opaque artifacts are not persisted between runs: durable exchange checkpoints are IR-724. ADR-049 itself is not yet on `main`.

**Status.** Implemented; awaiting review.
