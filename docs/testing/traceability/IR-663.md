## IR-663 responses carry the browser security headers (NFR-S3; ASVS 14.4.3, 14.4.4, 14.4.6, 14.4.7)

Two servers answer a browser, and each now sends `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` (stricter than `strict-origin-when-cross-origin`), `X-Frame-Options: DENY` and a CSP with no inline script, `object-src 'none'` and `frame-ancestors 'none'`. **Django** (API, admin, WhiteNoise static): `SecurityMiddleware` and `XFrameOptionsMiddleware` settings pinned in `config/settings/base.py`, plus `core.middleware.ContentSecurityPolicyMiddleware`, because Django 5.2 has no CSP of its own. **nginx** (the SPA): `frontend/security-headers.conf`, included in each location nginx answers itself and copied into the image by `frontend/Dockerfile`; proxied locations leave the headers to Django. The SPA policy allows only this origin plus Font Awesome on cdnjs (styles and fonts), `data:` fonts (Vite inlines KaTeX_Size3 into the CSS), `blob:` images (profile photos) and the same-origin pdf.js worker; `style-src-attr 'unsafe-inline'` is allowed for KaTeX's `style` attributes, never a `<style>` element or script.

**The CSP ships as `Content-Security-Policy-Report-Only` on both servers.** It is enforced only after a manual walk-through (sign in, Discover, a Record with the PDF reader, Ask IRIS streaming, Submit, the review screens, the Django admin and DRF's browsable API) shows no violation in the browser console, where report-only violations appear (no report endpoint is configured); that walk-through has **not** been done. Expected findings before enforcing: the browsable API's inline `<script>` and the admin's inline `style=` attributes, both refused by Django's `script-src`/`style-src 'self'`. Enforcing is two reviewed edits: `CONTENT_SECURITY_POLICY_REPORT_ONLY` in `config/settings/base.py` and the header name in `frontend/security-headers.conf`. Browsers ignore `frame-ancestors` in report-only, so `X-Frame-Options: DENY` is what denies framing meanwhile.

**Tests:** `backend/apps/tests/test_security_headers.py` -- Django's headers on an API 404 and the admin login, the report-only/enforced switch, no header for an empty policy; the CSP's required properties; and, as text, that the snippet sends every header `always`, that every non-proxied nginx location includes it and no proxied one does, and that the image installs it at the included path. **CI** (Docker Compose job, "nginx sends the browser security headers") runs `nginx -t` and asks a real nginx for `/`, an SPA route, an asset, a missing asset and `/activate/`.

**Evidence:** run locally 2026-11-01 with Django stubbed out (no Django in this environment): the three nginx pins pass, and dropping the include from the asset location makes the location pin fail. The Django tests and the real-nginx step are left to CI.
