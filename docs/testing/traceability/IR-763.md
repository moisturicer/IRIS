# IR-763

[Back to the matrix](../TRACEABILITY.md)

**Posting, editing, deleting, confirming, rejecting and removing a Call are audited.** Built to [ADR-050](../../adr/050-calls-for-papers-and-rdco-confirmation.md) decision 15, as ADR-051 decision 15 changes who reads it, and ADR-050's IR-763 amendment of 2026-11-15 (accepted when #812 merged), which records the owner's decisions. Written 2026-11-15.

## What changed

- **Seven event types** (`audit/0030`):
  - `CALL_DELETED` already existed (IR-760). It now also covers a person's delete.
  - Five new types for the other acts: `CALL_POSTED`, `CALL_EDITED`, `CALL_CONFIRMED`, `CALL_REJECTED` and `CALL_REMOVED`.
  - **`CALL_LAPSED`** is a seventh type, for the daily job's deletion of a lapsed request (IR-762). The owner chose it over reusing `CALL_DELETED`, so the job's deletions are told apart from a person's (ADR-050 amendment, IR-763).
- **Where they are written:** `apps/opportunities/audit.py`, called inside each act's own transaction:
  - post and edit, in the view's `create` and `update`;
  - delete, in `destroy`;
  - confirm, reject and remove, in `review.py`;
  - the lapse, in `tasks.remove_lapsed_requests`.
  - A refused or rolled-back act writes nothing.
  - A failed audit insert can't break the act: `create_audit_event` logs it at ERROR, and the act commits without its event (IR-144).
  - A delete now holds the Call's row lock for its transaction, as an edit already did.
- **What each carries** (`docs/evaluation/AUDIT_EXPORT.md`):
  - **A snapshot of the Call:** posted, deleted, removed and lapsed. A snapshot holds every field, with Areas as ids and names and the poster as an id.
  - **Edits:** only the changed fields, each with its old and new value. Featured and Areas are included; `updated_at` never is. An Adviser's edit that sends a Call back to RDCO is one event, with `status` among the changes.
  - **Reasons:** a rejection and a removal keep RDCO's reason. A person's delete has `reason: null`.
- **Nothing written:** a reader saving a Call to their list isn't audited (ADR-050 decision 13), and an edit that changes nothing writes nothing.
- **Audit Log:** the System Admin reads these events (ADR-051), as with every other type.
  - The event-type list and the filter come from the server, so the types appeared there with no other change (IR-913).
  - `frontend/src/types/audit.ts` adds a "Calls" group, so they're filed there rather than under "Other".
- **ADR index:** the row for ADR-050 lists the audit events and the IR-763 amendment.

## Tests

- **`backend/apps/opportunities/test_call_audit.py`**, through the HTTP API, with each event read back from `AuditEvent`:
  - **Posted:** the actor and a full copy, including Areas as ids and names. RDCO's is posted `confirmed`. A refused post (a past deadline) writes nothing.
  - **Edited:**
    - Only the changed fields, Featured included, with old and new values. Areas are recorded as ids and names.
    - An Adviser's edit of a confirmed Call records `status` confirmed → pending. A resubmitted rejected Call records the cleared reason.
    - An edit that changes nothing writes nothing, and neither does a refused edit.
  - **Deleted:** the deleter, `reason: null` and a copy. RDCO's delete of a colleague's Call names RDCO. A refused delete (RDCO's plain DELETE of an Adviser's Call) writes nothing.
  - **Confirmed and rejected:** RDCO, the Call's id and title, and the rejection's reason. A stale decision (409) writes nothing.
  - **Removed:** RDCO, the reason and a copy, and no `CALL_DELETED` alongside it. A refused removal writes nothing.
  - **Lapsed:** the job, called directly with the clock frozen at 00:30 Manila on 2026-11-16:
    - It writes one event per lapsed pending or rejected Call, with no actor and a copy.
    - Nothing is written for a confirmed Call, and a second run writes nothing more.
  - **Same transaction:** a confirm that fails after writing its event leaves neither the event nor the confirmation.
  - **Snapshot coverage:** the snapshot's field list equals the model's fields, so a field added later fails a test instead of silently dropping out.
- **`frontend/src/lib/auditEventGroups.test.ts`:** every Call type is filed under "Calls", not "Other".
- **Guards:**
  - `audit/tests/test_event_types.py` lists the seven types and accepts each in the log's own filter.
  - `makemigrations --check` finds nothing.
