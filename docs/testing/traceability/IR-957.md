## IR-957 — Switch Ask IRIS to the runtime agent and retire Django's answer path

**Basis and scope.** IR-957 under IR-955. The authority is ADR-049's amendment of 2026-11-09, which amends §27. The change is stacked on IR-995 (PR 639), itself on IR-994 (PR 638).

**The gate was not met.** IR-955's bar requires IR-956's report to pass. IR-995's agent-only rerun (`docs/evaluation/runs/20261109-041415-IR-956-answer-quality-858559d8`) still fails F12, two readers with different access: 43.8% correct against Django's 62.5%. The owner directed the switch anyway on 2026-11-09 ("do it anyway"), and the ADR amendment records that.

**What exists now.**
- **The switch.**
  - `AI_RUNTIME_READER` is removed: no setting, no Compose variable and no nginx entrypoint case.
  - `RuntimeEdgeGrantView` no longer refuses on a switch.
  - `ReaderPathView` always answers `runtime`, so a page loaded before the deploy opens the runtime reader.
  - `ai/.env.example` sets `RUNS_EXECUTOR=agent`.
  - `ai/.env.example` is a complete production-style profile: the AGENT model, routing, capacity, price, `RUNS_*` and `AI_ADMISSION_*` values are filled in. Changing the model means editing the lines marked `[model]`. Only `AGENT_LLM_API_KEY` is the deployer's own. Spending is limited on the OpenRouter key, not in code or docs.
  - Dev matches prod: `docker compose up` adds an `edge` service on `http://localhost:8080` (`frontend/nginx.dev.conf`) in front of Vite. It includes the same `frontend/runtime-edge.conf` as the production `nginx.conf`, so Ask IRIS gets the grant check and gateway secret in both. `nginx -t` passes for both configs.
  - `scripts/setup_env.py` generates one `AI_GATEWAY_SERVICE_SECRET` and writes it to the repo-root `.env`, `backend/.env` and `ai/.env` (`SERVICE_SECRET`); an existing real value is reused. `docker-compose.prod.yml` now requires it instead of defaulting to blank.
  - `ai-runs-worker` is a default service in `docker-compose.yml`, and is added to `docker-compose.prod.yml`, which had none.
  - nginx's entrypoint now warns, rather than refusing to start, when `AI_GATEWAY_SERVICE_SECRET` is unset. Ask IRIS then answers unavailable while the rest of the site still serves.
- **The frontend.**
  - `RAGChatPage` and `PaperChatPanel` mount only `RuntimeReader`.
  - A numeric conversation address opens a read-only earlier conversation (`EarlierConversations.tsx`), and `/ai` lists earlier conversations under a disclosure.
  - Paper Chat keeps the page's contract: Close Ask IRIS, Back to paper, the minimized bar, the version notice and a draft held by the page.
  - `aiApi` keeps only `status`, `overview` and read-only `conversations`.
- **Django's answer path is retired.**
  - `/ai/ask/`, `/ai/ask/stream/`, `/ai/ask/runs/<uuid>/retry/` and `/ai/search/` answer 410 (`RetiredAnswerView`).
  - `POST /ai/conversations/` is 405.
  - Removed:
    - `apps/ai/controller/`, `orchestrator.py`, `routing/` and `research/`;
    - `conversation_state.py`, `comparison/service.py` and `comparison_configuration.py`;
    - `memory.py`, `turn_backfill.py`, `submissions.py` and `resilience/query_cache.py`;
    - `answers/assurance.py`, `GroundedAnswerService`, question resolution and `evidence/shadow.py` with its task;
    - the `shadow` queue route, the `celery-shadow` services and the shadow rate-limit lane;
    - `views/research.py` and the commands `ask_agent`, `route_question`, `run_research_tool`, `report_evidence_pilot` and `backfill_turn_vectors`;
    - every setting only these read.
  - `durable.py` keeps replay, cancel and `retire`.
- **In flight at the switch.**
  - Migration `ai/0044_retire_django_ask_runs` ends every queued or running `AskRun` as `failed` with reason `retired`, adding one `run_failed` event.
  - `answer_queued_question` stays registered and retires a run instead of answering it.
- **Earlier Conversations.** Stored Turns render through `conversations.py`, `stored_listing.py` (listing reader, moved out of the research lane) and `comparison/storage.py` (comparison reader).
- **Evaluation.**
  - `eval_answer_quality --run` requires `--reuse-django`.
  - `eval_replay_conversations` collects the runtime arm only.
  - Engine names for stored runs live in `evaluation/legacy_engines.py`.
  - `eval_pilot_milestone` and `eval_pilot_capacity` still exist, but their collectors hit 410.

**Tests.**
- `backend/apps/ai/tests/test_django_answer_path_retired.py` (new) covers:
  - every former answer route answers 410 and writes no Turn or AskRun, and still requires a session;
  - a retry starts nothing, and no Conversation can be created;
  - an earlier Conversation reads to its owner and is a 404 to anyone else;
  - the migration retires queued and running runs and leaves finished ones alone;
  - the tombstone task retires a late message;
  - a follower replays a retired run to `run_failed`.
- `backend/apps/ai/tests/test_runtime_reader_edge.py`: the reader path is always `runtime` whatever the browser sends; the switch-off test is removed with the switch.
- `backend/apps/ai/tests/test_embargo_every_way_out.py`: the chat-path cases now assert the shipped vendor gate directly. The recall, backfill and record-turn cases went with those features. The earlier-answer scene is built from stored rows.
- `frontend/src/features/ai/RAGChatPage.runtime.test.tsx` adds three cases:
  - an earlier conversation opens read-only and sends only GETs;
  - a missing one reads as unavailable;
  - earlier conversations are listed and linked.
- `frontend/src/features/records/paper-view/PaperChatDock.test.tsx` (rewritten): Paper Chat posts only to `/ai/runtime/runs`, with `X-IRIS-Record`.
- `frontend/src/api/ai.test.ts` (rewritten): the client offers no way to ask Django.
- **Deliberately deleted**, as tests of retired code:
  - backend: the controller, routing, research-lane, durable-ask, memory, resolution, shadow, pilot-report, comparison and public-protocol HTTP suites, and the Django-arm replay and outage tests;
  - frontend: `RAGChatPage.test.tsx`, `RAGChatPage.switchOff.test.tsx` and its snapshot, `SourceContextPanel.test.tsx`, `PaperChatDock.recent.test.tsx` and `answerStream.test.tsx`;
  - `PaperViewPage.test.tsx` lost its two Django-only Paper Chat blocks (IR-354 and IR-355 pinning and follow-ups).

**Rollback, exercised 2026-11-09** on `iris_ir957_rollback_copy`, a `pg_dump` copy of the development database with 27 Conversations and 47 Turns:
1. `migrate ai 0043` brought the copy level with this branch's base.
2. One queued `AskRun` was seeded.
3. `migrate` applied `0044`, and the seeded run became `failed`/`retired` with one `run_failed` event.
4. `migrate ai 0043` unapplied it cleanly.
5. The base commit `efe61ce3`, which is what a revert restores, ran against the copy:
   - `check` passed and `migrate --check` exited 0;
   - `/ai/ask/` resolved to `ChatQueryView` and `AI_RUNTIME_READER` was `False`, so Django's path was back;
   - the retired run stayed ended, and all 27 Conversations and 47 Turns were intact.
6. The copy was dropped afterwards.

**Runs.** See the PR for the suite results at the commit.

**Not done here.**
- **The bar.** F12 still fails, and the switch shipped anyway on the owner's direction.
- **The demonstration** of a question answered end to end through the runtime on a running stack was not done in this change. It needs the stack on this code with the AGENT profile and a paid model, which needs the owner's go-ahead. The recorded-provider end-to-end test (`test_runtime_reader_e2e.py`, IR-863) is the automated stand-in.
- **The development stack** serves the frontend from Vite, which has no runtime edge. Ask IRIS under `docker compose up` therefore cannot reach the runtime; only the production stack's nginx can. This predates IR-957 (IR-863's note), but it now affects every question.
- **ADR-014's preconditions** for the gateway (auth, CORS, public port) are still recorded as undone in CLAUDE.md.
- **Lost features:** readers lose Django's history sidebar, comparison picker and "All papers" widen.
- **Tables kept:** the tables for removed models' data (`ShadowEvidenceDecision`, `ResearchRun`, `ConversationState`, `ScreeningJudgment`) are kept, so nothing is dropped and a revert needs no data restore.

**Tests retired with Django's answer path (2026-11-09).** These drove `/ai/ask/`, `/ai/ask/stream/` or `/ai/search/`, which now answer 410, so they could only fail. The notes that cite them (IR-326, IR-334, IR-383, IR-504, IR-561, IR-578, IR-839, IR-907, ADR-034, ADR-035, ADR-038, NFR-S4, FR-M3-02) describe behaviour Django no longer serves.
- Removed files: `test_ask_stream_http.py`, `test_asgi_streaming.py`, `test_chat_identity_http.py`, `test_citation_regions_http.py`, `test_outcome_indistinguishable_http.py`, `test_resolver_wiring.py`, `test_retrieval_diagnostics.py`, `test_shadow_off_snapshot.py`, `test_eval_evidence_model_command.py`, `test_eval_evidence_route_label_command.py`, `evidence/tests/test_configuration.py`, and `e2e/smoke/ask-iris-stream.spec.ts`.
- Removed tests: the answer and search cases in `test_ask_http.py` (status and composition tests kept), the answer cases in `test_inference_tasks_http.py`, two in `test_figure_description_never_reaches_a_reader.py` and one in `test_overview_page_citations.py`.
- Rewritten: `test_conversations_http.py` stores Turns directly rather than through the retired endpoints.
- The runtime's own tests now carry what these asserted for Ask IRIS: `test_runtime_reader_e2e.py`, `test_ai_runtime_*_db.py` and the `test_ai_runtime_*_contract.py` set.

**The smoke tier on the runtime.** `e2e/smoke` mocks the runtime's `/ai/runtime/conversations` routes. Opening a conversation by its address now shows the shared read states in the runtime reader: "Loading this conversation…", a failure with Try again, a timeout with Retry, and the same not-available screen for 403 and 404. These states are forced in `forced-states.spec.ts`.
