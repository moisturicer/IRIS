# IR-806: Deploy IRIS to a temporary server and seed the validation environment

**Requirements:** no FR- id. Epic IR-805 (S2 Epic: Deployment). Covers ASVS 14.4.5 and, on the deployed domain, 9.1.1 to 9.1.3 (`SECURITY_CHECKLIST.md`).

## What exists

- **The server:** `iris-demo` in AWS `ap-southeast-1`, at `https://iris-citu.duckdns.org`, first deployed by hand on 2026-11-10. IR-1013 to IR-1018 record its template, guards, logs and one-command update.
- **Seeding, as changed on 2026-11-11 by Hermoine Zozobrado:** demo accounts only, one per role (`seed_demo --accounts-only`). No papers are seeded; a paper reaches the server through the real Publish and review process. The ticket asked for seeded papers at every workflow stage before this change.
- **HSTS on every response:** `deploy/caddy/Caddyfile` adds `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` to every HTTPS response. Before this, only Django's responses carried it (`production.py`), so the pages and files nginx serves went without. `defer` sets it after the upstream answers, so a Django response carries one header, not two. The value is `production.py`'s (ADR-057).

## Evidence

- **Checked on iris-demo, 2026-11-11, by Hermoine Zozobrado from a laptop (Git Bash):**
  - `curl -sSI https://iris-citu.duckdns.org/`: `HTTP/1.1 200 OK`.
  - Certificate: `subject=CN=iris-citu.duckdns.org`, `issuer=C=US, O=Let's Encrypt, CN=YE2`, `notAfter=Feb  8 12:30:22 2027 GMT`.
  - `/media/test.pdf`: `200` with `Content-Type: text/html`. That is the app's page from nginx's fallback, not a file: nginx has no `/media/` location (IR-152).
  - HSTS: **none** on the home page. That is the gap the Caddyfile change closes.
- **After the change, 2026-11-11, by Hermoine Zozobrado:** `deploy.sh` updated iris-demo from `11bdcc36` to `fccc2b16` (PR #689) with every step passing, and `docker compose -f docker-compose.prod.yml up -d --force-recreate caddy` restarted Caddy, which reads its config only at start. From a laptop:
  - `curl -sI https://iris-citu.duckdns.org/ | grep -i strict-transport-security`: `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`.
  - `curl -sI https://iris-citu.duckdns.org/api/v1/colleges/ | grep -ci strict-transport-security`: `1`, so Django's responses carry one header, not two.
- **TLS on iris-demo, 2026-11-11, by Hermoine Zozobrado from a laptop (OpenSSL 3.2.3):**
  - Plain HTTP: `308` to `https://iris-citu.duckdns.org/`.
  - `-tls1_2`: `New, TLSv1.2, Cipher is ECDHE-ECDSA-AES128-GCM-SHA256`.
  - `-tls1_3`: `New, TLSv1.3, Cipher is TLS_AES_128_GCM_SHA256`.
  - `-tls1_1 -cipher 'ALL:@SECLEVEL=0'`: refused by the server, `tlsv1 alert protocol version ... SSL alert number 70`, `Cipher is (NONE)`. Without `SECLEVEL=0` the laptop's OpenSSL wouldn't offer TLS 1.1 at all ("no protocols available"), which tested nothing.
  - TLS 1.0 and the weak ciphers are covered by CI's probe of the same Caddyfile, not checked on the server. A full scan of the deployed domain (ASVS 9.1.2) is still owed.
- **Re-checked on iris-demo, 2026-11-11, by Ashlee Sean (QA & Security) from a second machine (Git Bash, OpenSSL 3.5.5),** reviewing PR #691. Every result above reproduced. Also:
  - TLS 1.0 (`-tls1 -cipher 'ALL:@SECLEVEL=0'`): refused with `alert protocol version`, alert 70, so TLS 1.0 is now confirmed on the server too, not only in CI.
  - A connection with no version flag negotiates `TLSv1.3`.
  - Over TLS 1.2, `AES128-SHA`, `AES256-SHA256` and `ECDHE-RSA-AES128-SHA` are refused with `handshake failure`, alert 40. 3DES and RC4 weren't tested, because this OpenSSL doesn't include them. This isn't a full scan, so 9.1.2 stays Partial.
  - Plain HTTP to `/api/v1/colleges/?x=1` answers `308` to the HTTPS URL with the path and query kept.
- **Risk 4 closed, 2026-11-11, by Ashlee Sean as QA & Security owner:** "TLS is configured but hasn't run on a deployed domain, and HSTS isn't confirmed for one" moves from `SECURITY.md` §11 to §12, closed by IR-847 and IR-806. The full cipher scan stays tracked as ASVS 9.1.2 Partial. `SECURITY.md`'s TLS paragraph now names Caddy instead of saying the repository doesn't configure the proxy.
- **Demo passwords:** Hermoine Zozobrado reports the demo accounts on iris-demo no longer use `seed_demo`'s published password. Not checked here.
- **CI:** the "Caddy serves HTTPS only, with strong TLS and HSTS" step runs the real Caddy and Caddyfile and requires exactly one HSTS header with that value, both where the upstream sends none (as nginx) and where it sends its own (as Django, under `/api/`). It passed on PR #689: `HSTS on /` and `HSTS on /api/x` each printed `strict-transport-security: max-age=31536000; includeSubDomains; preload`. Not run locally: this session has no Docker daemon and couldn't fetch Caddy.

## Still open

- The post-deploy smoke test: signing in, submitting a record, and a non-owner getting a 403 on a document.
- `ai-gateway` runs on iris-demo (`iris-ai-gateway-1` was up after the deploy). Whether ADR-014's preconditions hold there is not decided.
- `deploy.sh` doesn't restart Caddy, so a Caddyfile change needs the `--force-recreate caddy` step above by hand.
- The steps and environment variables recorded as the deployment runbook.
- ADR-057 asks a person to confirm the HSTS values for the chosen domain. `preload` has no effect on a `duckdns.org` subdomain, which the preload list doesn't accept, and `includeSubDomains` covers only names under `iris-citu.duckdns.org`.
