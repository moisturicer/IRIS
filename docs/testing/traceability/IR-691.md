## IR-691

**Requirement:** Readers report Comments, and RDCO or the System Admin remove them with a reason or dismiss the reports. ADR-032 §7, amendment 2026-10-31, and its build decisions of 2026-11-15; spec IR-420. No FR- id.

**Design:** ADR-032 (the amendment's "Reports" and "Removal" points, and the 2026-11-15 build decisions: a shared queue, Remove from the paper too, a writer's delete closes open reports while an edit changes nothing, reports share the posting budget, the sidebar counts the queue).

**Implementation:**

- `records.CommentReport` (migration `records/0042`): the comment, the reporter, a reason (`CommentReportReason`), a note for *Other*, the text as reported, a state (`CommentReportState`: open, dismissed, removed, writer deleted) and who resolved it when. One per reader per comment.
- `apps/records/public_comments.py`: `report()` behind `POST /records/<id>/comments/<comment_id>/reports/`, which spends the posting budget. `can_report` is offered on someone else's standing comment the reader has not reported yet, and `can_remove` to RDCO and the System Admin. A writer's `delete()` closes the comment's open reports.
- `apps/records/comment_moderation.py` behind `/api/v1/moderation/comments/` (`views_moderation.py`, `IsCommentModerator`): the queue, `remove/` with a required reason and `dismiss/`. Whoever acts second is told 409 "already". The queue, the count and both acts cover only comments on a paper the moderator can read (`Record.objects.visible_to`) that is public now: "a paper that stops being public takes its comments with it", and they come back with it.
- Notifications: RDCO on a comment's first open report (so a comment reported again after a dismissal is announced again, since it is back in the queue), with no sender, because a notice shows its sender to everyone it reaches, bound to the comment as `TaskKind.COMMENT_REPORT`, which settles when no report is open (`notifications/0013`); the writer on a removal, with the reason.
- Audit: `COMMENT_REMOVED` and `COMMENT_REPORTS_DISMISSED` (`audit/0029`), with the comment's id and the counts, never its text.
- `GET /dashboard/queue-counts/` adds `reported_comments` and admits the System Admin, who is told that count alone.
- Account deletion keeps a report and who resolved it (`deletion/registry.py`); the personal-data export lists the reports a person made, without the reported words (`comment_reports` section).

**Tests:**

- `backend/apps/records/test_comment_reports.py` (31): reporting (offered, own refused, one per reader, *Other*'s note, deleted and unpublished, RDCO told once and nobody else, never visible in the thread, the posting budget); the queue (who reads it, what a row says without naming reporters, order, only open); removal (with a reason, the writer told why, an unreported comment, the offer, who may, already handled, 404, audit); dismissal; a writer's delete and edit; the notice settling; the queue count; a comment addressed through another paper.
- Changed deliberately: `test_public_comments.py` (the payload gains `can_remove`; Report is now offered, where it was pinned as not offered "until reports exist") and `test_queue_counts.py` (the count gains `reported_comments`).
- `apps/accounts/test_personal_data_export.py`: the reports a person made, without the reported words.
- Access matrix: the four new routes and the wider queue count.
- After code review (2026-11-15): the report notice names no sender; Report is no longer offered once you reported; a paper that leaves the public catalogue takes its reported comments out of the queue and the count, and acting on one is a 404 (`PaperLeavesPublicTests`).

**Evidence:** run locally on 2026-11-15, Linux, PostgreSQL 16:

- The new tests failed first: no routes, then two test mistakes fixed (a standalone removed comment leaves the thread, as the ADR says; notifications run after commit) and one code fault (the notification types were read as seeded rows).
- The access matrix found that account deletion did not know the new report's links to a user; both are declared now.
- `pytest -n 4 apps/records apps/notifications apps/audit apps/accounts apps/tests`: 2,175 passed. flake8 clean.
- Code review found three faults, each pinned by a test that failed first: the RDCO notice named the reporter as its sender; Report stayed offered after reporting; the queue, the count and both acts reached comments on papers no longer public (and, for the System Admin, papers it cannot read).
- After the review fixes: `pytest -n 4 apps/records apps/notifications apps/audit apps/accounts apps/tests`: 2,178 passed, 1 failed (`accounts/test_recovery_delivery.py::RedactionTests::test_the_broker_carries_only_the_intent_id`, untouched here; passes alone).
- Migrations `records/0042`, `audit/0029`, `notifications/0013` on a database seeded by `seed_demo` at main's schema (20 records): forward, back with a report stored (records and comments kept), forward again; `makemigrations --check` clean.
