## IR-1305

**Requirement:** A citation points readers at published work they can find, so Cite is offered only on a published paper. A Proposal (which is never published), a draft, a paper in review and a paper kept unlisted offer no Cite. Save and Share stay on every record.

**Design:** ADR-032 §10: Paper View is driven by the server's `capabilities`, and `cite` is one of them. The server decides; the frontend renders what it is offered. Discover needs no change: it lists only published papers (ADR-021 §13), so a Proposal never appears there.

**Implementation:**

- `backend/core/permissions.py` (`record_capabilities`): `cite` is offered only when `pipeline_status` is `published`. It was offered on every record.
- `frontend/.../paper-view/SaveCiteShare.tsx` and `PaperViewPage.tsx`: Cite renders only with `can.has("cite")`.
- `frontend/.../library/LibraryRecordTable.tsx`: a list item carries no `capabilities`, so Library → Saved shows Cite only on a `published` row, the same rule as the server's.

**Test:**

- `backend/apps/records/test_capabilities.py`: the IR-418 role × state table now expects `cite` only in the `published` and `under_embargo` (published, held again) rows, for every viewer who can read them, and nowhere else, Proposals included.
- `PaperViewPage.test.tsx` ("Cite only where the server offers it"): Cite on a published paper; none on a Proposal, which keeps Save and Share; none on a Thesis in review; none on a published paper the server did not offer it on.
- `LibraryRecordTable.test.tsx`: in list and grid, Cite on the published row only; the saved Proposal can still be removed.

**Evidence:**

- **2026-11-23, locally:** Vitest over `LibraryRecordTable.test.tsx` and `PaperViewPage.test.tsx` passed: 2 files, 253 tests. The backend table was not run locally; CI runs it (it is marked `slow`).
