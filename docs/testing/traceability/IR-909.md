# IR-909: keyboard-only and zoom checks

**Requirements:** WCAG 2.1.1 Keyboard, 2.4.7 Focus Visible, 2.1.2 No Keyboard Trap, 1.4.10 Reflow

The PR smoke suite `e2e/smoke/keyboard-zoom.spec.ts` drives these core actions with physical Tab, Shift+Tab, Enter, Space, and arrow-key input:

- Create a new submission, choose its type, provide a manuscript through the keyboard-opened native file chooser, complete details, and submit.
- Submit an existing draft, have a reviewer request revisions, and resubmit a new version as the author.
- Open a paper from Discover and ask a question in Ask IRIS.
- Check the Publish, Request Revision, and Submit new version dialogs for focus trapping, Escape dismissal, and focus restoration.
- Check visible focus indicators on journey controls.

The same important screens and actions, including the Publish manuscript and Details steps, are loaded at 320 CSS pixels (the reflow equivalent of a 1280 CSS-pixel viewport at 400% zoom). The test checks document horizontal overflow and that the journey's primary control remains visible and reachable. The dialog also notes that browser desktop zoom and 200% text resizing are not automated by this viewport check.

The smoke browser serves the production frontend build and mocks every API request. These checks establish browser behavior for the frontend journeys; they do not verify backend behavior or actual browser zoom settings.
