## IR-592 — conversation state and bounded follow-up context

**Requirement.** [General-tools spec](../../architecture-review/2026-10-15-askiris-general-tools-spec.md) §4 under [ADR-042](../../adr/042-general-tools-conversation-contract.md); acceptance scenarios A01–A03, A08, A11, A12.

**Built.** `ConversationState` (migration 0030, additive; one row per Conversation, cascades with it) stores topic, filters, the ordered presented record ids, selections, exclusions, a pending clarification, the answer Turn, request and retrieval query separately, and the active ChunkSet hash of each shown paper. `Turn.context_revision` records which revision a Turn committed. `apps/ai/conversation_state.py` holds the value and its transitions (topic change, find-another, select by ordinal), `commit` (inside `record_turn`'s transaction, after the durable guard), `snapshot`, `reissue_handles` and `conversation_context`. Only a `generated` Turn advances the state; a listing fixes order from its shown records, never its screened-out candidates; a comparison selects its pair; an answer citing only already-shown papers keeps the order and one citing others clears it. A commit against a stale revision keeps the newer choices and clears the displayed order (`basis=conflict`). A snapshot rechecks `visible_to` on every read: a revoked paper keeps its slot and resolves to nothing, and a changed source version is reported stale. With no row, state is rebuilt from stored Turns without writing; topic is never guessed and passage-only history stays unresolved. The request path pins the revision before any model call (`ChatQuestion.context_revision`); a queued run stores it at submission, so a retry answers against the context it was asked in. Turns citing a now-unreadable Record are dropped from the verbatim window (chat views, override, evidence shadow parity), memory recall, the research planner history and therefore the resolver cache key. The planner receives the state's papers as this run's handles.

**Not built here.** The controller that would set topic, filters and clarifications (IR-593) does not exist, so today only legacy listing, comparison and passage Turns write state and topic stays blank; `conversation_context` has no caller yet. The older-turn summary is the questions and their cited ids, not a model-written summary. The migration was exercised on the test database only, not on a copy of a populated one.

**Evidence (2026-10-16).** `apps/ai/tests/test_conversation_state.py` (31 cases), including a two-thread real-transaction race (`ConcurrencyTests`) and two HTTP cases; `pytest apps/ai/research apps/ai/evidence` and the conversation, memory, history and durable suites pass with `AI_RESEARCH_LANE=off AI_JEV_ROUTING_ENABLED=False`, except `test_plan_profile.py` and `test_screen_profile.py`, which read this machine's `backend/.env` model settings.
