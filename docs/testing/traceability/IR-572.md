## IR-572

**Requirement:** **A reader's own folders live in their account** — no FR- id; subtask 2 of IR-553 (User Stories 2–4 and 7)

**Design:** [ADR-070](../../adr/070-reader-folders-follow-the-account.md) (**Accepted** 2026-11-16 by Lee Jasmin Adolfo, verbally, relayed and recorded by Hermoine Zozobrado; its three product choices — unique names make creation idempotent, at most 10 folders of at most 60 characters, old browser folders hidden until IR-579 — were made by Hermoine Zozobrado on 2026-11-16) · [ADR-044](../../adr/044-account-backed-research-library.md) §6–§7

**Implementation:** `apps/library`: `LibraryFolder` (owner, name unique per account ignoring case, `MAX_FOLDERS = 10`, `MAX_FOLDER_NAME = 60`) and `FolderMembership` (folder and **saved record**, unique together), migration `0005_libraryfolder_foldermembership`, `folders.py` (name rule and listing shape), and `FolderListView` (`GET`/`POST /api/v1/library/folders/`), `FolderDetailView` (`PATCH`/`DELETE /api/v1/library/folders/<id>/`) and `FolderRecordView` (`PUT`/`DELETE /api/v1/library/folders/<id>/records/<record_id>/`). Creating an existing name returns that folder (`200`); deleting a folder or a filing is a `204` whatever its owner; another reader's folder is a `404` identical to a missing one; filing rechecks `visible_to()` and saves an unsaved Record; unsaving cascades out of every folder; nothing here writes a `DiscoveryDismissal` or invalidates For you. Not in Django admin, no `AuditEvent`. Declared in `accounts/deletion/registry.py` (DELETE) and `accounts/personal_data/registry.py` and `export.py` (a new `folders` section: name and papers, a title only while readable). Access matrix rows `library-folders`, `library-folder` and `library-folder-record`, with a `folder` fixture in `access/world.py`. Frontend: `libraryApi` folder calls; folders join `store/library.store.ts` (read with the saves in one load; cleared and fenced on every session change; rename, delete, file and take out optimistic with a visible rollback; create waits for the server; unsave empties every folder; failures name the paper where there is one); `PaperSaveDropdown`, `MyLibraryPage`, `FolderPicker`, `SavedView` (a folder view now reads the account's saves in filing order, with unavailable ones counted) and `LibraryOverview` read the store. `lib/recordLibrary.ts` loses all folder code: `iris_record_collections` is no longer read or written, and is left byte-for-byte for IR-579. "Folders stay in this browser" is gone from the Save menu, My Library, Overview and Help, and from PRODUCT.md and DESIGN.md.

**Test:** backend `apps/library/test_folders.py`, 36 tests: create, list, idempotent create by name (any case, trimmed), name rules, the database's one-name-per-account rule, the limit (per account, listed, deleting makes room, an existing name still answered at the limit), oldest-first order; rename idempotent, recasing one's own, refusing another folder's name, a missing folder is a 404; delete idempotent; filing once and again, filing an unsaved Record saves it without a status, several folders newest-filing-first, the database's one-membership rule, taking out keeps the save and its status and writes no dismissal, taking out of one folder leaves the others, unsaving empties every folder, deleting a folder keeps saves, a missing folder saves nothing; an unreadable Record is the same 404 as a missing one and saves nothing, a filed Record that becomes unreadable is listed by id only and still removable, a deleted Record leaves every folder; ownership (list, the identical 404 on rename and filing, deletes that cannot reach another's rows, a body naming an owner, shared names across readers, account removal); one account on two devices; two accounts on one client; a guard that no app outside `apps/library` and the registries names the models; not in admin. `accounts/test_personal_data_export.py` adds the `folders` section test. `apps/tests/test_access_matrix.py` gains **`test_library_routes`**: the library's cells (IR-566, IR-577, IR-580, IR-583 and these) were declared but never fired, because the matrix had no `library` case; all passed when first fired, and a deliberately wrong folder cell then failed as it should. Frontend `store/library.store.test.ts` (16 folder tests: load with saves and clear on sign-out, a failed folder read is not "ready", create and its refusal message, an existing name stays one folder, rename and delete rollback with saves untouched, filing an unsaved paper and its rollback, the server's answer kept, taking out keeps the save, unsave empties and restores folders, a late filing answer neither puts back an unsaved paper nor overwrites a newer Reading status, a refused take-out or unsave puts the paper back at its own place in each folder, an answer after an account switch dropped, no `localStorage` write), `MyLibraryPage.test.tsx` (7 folder tests: server folders and a folder's saves in filing order with an unavailable one, axe; create on the server and a refusal shown; no new folder at the limit; take out without unsaving; a failed take-out rolled back visibly; rename on the server and a failed delete restored with the save kept; **two accounts on one browser** never see each other's folders) and `DiscoverPage.test.tsx` (4 Save-menu tests: filing an unsaved paper saves it, taking out never unsaves or counts as Not interested, creating from the menu files the paper, the limit disables creation and says why).

**Deliberate test changes:** `MyLibraryPage.test.tsx` "keeps search, sort, Folder and Reading status in one toolbar…" now expects "Saves and folders follow your account." and the folder to be created through `libraryApi.createFolder`; its IR-579 legacy test also puts one of the reader's own browser folders in `iris_record_collections` and checks it is neither shown nor rewritten. The `@/api/library` mocks in `MyLibraryPage.test.tsx`, `DiscoverPage.test.tsx`, `PaperViewPage.test.tsx` and `library.store.test.ts` gain the six folder calls, and Discover's `beforeEach` also resets `folders` and `folderLimit`, because the store now reads folders with the saves. The e2e smoke tier's screen mocks (`smoke/support/screens.ts`, `fixtures.ts`) answer `GET /library/folders/` beside `GET /library/saves/`, since that tier fails on any request it did not mock.

**Review:** a standards and a spec review of the branch found no hard violation and no missing acceptance criterion. Fixed from them: a filing answer that landed after a newer unsave or Reading status overwrote it in the store; a refused take-out or unsave put the paper first in its folders instead of at its own place; `PUT …/records/<id>/` now locks the save (`select_for_update`), so an unsave arriving mid-filing waits and cascades instead of failing the request; the name check now compares with the database's `LOWER()`, the function the unique rule uses, instead of `iexact`; names and comments tidied. Left as they are, with the reason: the name rule repeats saved feeds' shape with folder wording (merging them would couple the two modules); a folder id with no matching save in the store (possible only for an instant between the two reads) is left out of the folder view, not shown as unavailable, because it is not unavailable.
