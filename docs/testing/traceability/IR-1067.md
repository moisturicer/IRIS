# IR-1067: seed accounts move off real CIT-U mailboxes

**Requirements:** none. This is demo data, not a requirement, so the matrix has no row for it.

## Why

`seed_demo` made its logins as `<role>@cit.edu`. The office addresses among them (`itso@`, `ierc@`, `ktto@`, `rdco@cit.edu`) are CIT-U's real Outlook mailboxes, so iris-demo's notifications during testing could reach the real offices. The `first.last@cit.edu` catalogue owners could also belong to real people.

## What changed

- **`seed_demo`:** every account it makes is on `iris.test`: the six role logins, the four coordinators, `admin@iris.test` and the eight catalogue owners. `.test` is reserved (RFC 6761) and never delivered. The `<role>@` part and `IrisDemo123!` are unchanged.
- **`scripts/seed_demo_opportunities.py`:** posts as `rdco@iris.test`.
- **Docs:** `CLAUDE.md`, `docs/engineering/DEVELOPMENT.md` and `docs/evaluation/README.md` name the new logins.
- **Unchanged:** registration still accepts only `cit.edu` (`REGISTRATION_EMAIL_DOMAINS`). Seed accounts never register, and logging in doesn't check the domain. Test fixtures, mocked e2e data and recorded contracts keep `@cit.edu`, because they send no mail.

## Renaming an existing database

A database seeded before this change still holds the `@cit.edu` accounts. A later `seed_demo` run would not find them and would create `@iris.test` duplicates beside them. Rename them in place first. Their records, reviews and history stay with them, because only the email changes.

1. List what would be renamed. This changes nothing.

   ```
   docker compose -f docker-compose.prod.yml exec -T backend python manage.py shell -c 'from apps.records.management.commands import seed_demo as s; from apps.accounts.models import User; names = {e.split("@")[0] for e, *_ in s.ROLE_ACCOUNTS + s.COORDINATOR_ACCOUNTS} | {s.ADMIN_EMAIL.split("@")[0]} | {(n[-1][0].split()[0] + "." + n[-1][0].split()[-1]).lower() for n in s.CATALOGUE}; print("to rename:", sorted(User.objects.filter(email__in=[n + "@cit.edu" for n in names]).values_list("email", flat=True))); print("already on iris.test:", sorted(User.objects.filter(email__in=[n + "@iris.test" for n in names]).values_list("email", flat=True)))'
   ```

2. Rename them. If an `@iris.test` account already exists, it refuses and renames nothing. Running it again renames nothing more.

   ```
   docker compose -f docker-compose.prod.yml exec -T backend python manage.py shell -c 'from apps.records.management.commands import seed_demo as s; from apps.accounts.models import User; names = {e.split("@")[0] for e, *_ in s.ROLE_ACCOUNTS + s.COORDINATOR_ACCOUNTS} | {s.ADMIN_EMAIL.split("@")[0]} | {(n[-1][0].split()[0] + "." + n[-1][0].split()[-1]).lower() for n in s.CATALOGUE}; users = list(User.objects.filter(email__in=[n + "@cit.edu" for n in names])); assert not User.objects.filter(email__in=[u.email.replace("@cit.edu", "@iris.test") for u in users]).exists(), "an @iris.test account already exists, nothing renamed"; [(print(u.email, "->", u.email.replace("@cit.edu", "@iris.test")), setattr(u, "email", u.email.replace("@cit.edu", "@iris.test")), u.save(update_fields=["email"])) for u in users]; print(len(users), "renamed")'
   ```

The names come from whichever `seed_demo` is deployed, so this works before or after deploying this change. Saving a new address also revokes that account's open recovery links (`User.save`), so a reset link already sent to a real mailbox stops working.

  - Step 2 renamed all 19, and a second run renamed 0.
  - Running `seed_demo` again afterwards left 19 users, 0 on `cit.edu`: no duplicates.
