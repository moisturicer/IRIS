## IR-590 — typed evidence-only tool contracts and scoped handles

**Requirement.** [General-tools spec](../../architecture-review/2026-10-15-askiris-general-tools-spec.md) §3.1 and §3.3 under [ADR-042](../../adr/042-general-tools-conversation-contract.md): a versioned result envelope with no answer, wording or UI hints; closed, bounded schemas with application-injected context; run-scoped handles and bound cursors; coverage that names its subject; cached results reauthorized before reuse.

**Built.** `ToolRegistry.invoke` returns `results.Envelope` (`schema_version` 1; `status` one of ok/empty/partial/ambiguous/unavailable/denied; `items`, `evidence`, `facts`, `coverage`, `continuation`, `limitations`) with a private `Trace` that `public()` never emits. `envelope_of` adapts the legacy `ToolResult`; `call()` keeps its return type and the research lane its prompts. Each tool declares a `CoverageSubject`; an unknown total is `null`; a truncated read is `partial`; `denied` is reserved for references this run may not use and carries no content or counts, while budget, floor and stale-cursor refusals are `unavailable`; forbidden keys (`answer`, `wording`, `route`, raw ids, in any case or camelCase) are refused at construction. `invoke` logs the private trace (run id, tool, reason code, timing), never content. `check_schema` now refuses unbounded strings, integers and arrays and any parameter named for injected context or a raw id. `ToolRun.start(..., scoped_handles=True)` tags handles with the run, so another run's or user's handle is rejected as unissued; `reissue` turns canonical record ids back into handles only where still readable and disclosable; `issue_cursor`/`resume_cursor` bind a continuation to tool, arguments, caller and source version. A cached result is reused only while every source is still readable, disclosable and on its recorded version; otherwise it is recomputed. **This changes the legacy lane too:** a repeated call there is now reauthorized (extra queries per duplicate, and a stale cached `screen_records` result can spend another screening call), and a handle argument now admits 24 characters instead of 12.

**Not built here.** No tool issues a cursor yet, nothing produces `ambiguous`, there is no separate AI-eligibility coverage for metadata aggregates, and the legacy lane does not opt into scoped handles; these belong to the generalized operations (IR-591) and the controller. The envelope is not on an HTTP path until the controller consumes it, so the HTTP capture below exercises the legacy wrappers, not the envelope; stale cursors and source versions are covered at the registry seam only.

**Evidence (2026-10-15).** `apps/ai/research/tests/test_envelope.py`, `test_registry_contract.py`, and the IR-590 cases in `test_ledger.py` and `test_schema.py`; `apps/ai/tests/test_research_tool_contract_http.py` captures every planner request at the fake vendor over `/ask/stream/` and shows malformed and foreign-handle calls rejected and a hidden draft never sent. `pytest apps/ai/research` passes except `test_plan_profile.py` and `test_screen_profile.py`, which fail identically on `main` because this machine's `backend/.env` holds a real API key.
