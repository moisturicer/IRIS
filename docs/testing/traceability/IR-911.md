# IR-911: one form and schema approach, unused libraries removed

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes. Child of IR-898 (forms and client-side validation). The choice is [ADR-060](../../adr/060-forms-use-react-hook-form-and-zod.md), **Proposed**: the ticket says an architectural choice is the team's, not an agent's, so it is not settled until a named person accepts it.

**What was listed.** react-hook-form + zod: `PublishDialog`, `EditDetailsDialog`, `MetadataForm`, `metadataSchema`. formik + yup: `LoginForm` and `LoginPage`'s `FormikHelpers` type, nothing else.

**The change.** `LoginForm` now uses react-hook-form with a zod schema (same fields, names, order and messages; `mode: "onTouched"`). Its `onSubmit` takes the values only and resolves when the attempt is over; `LoginPage` no longer calls `setSubmitting`. `formik` and `yup` are removed from `package.json` and the lockfile.

**What proves it**

| Acceptance criterion | Evidence |
|---|---|
| One approach is recorded | ADR-060 (Proposed; **not yet accepted**) |
| `npm ls` shows no unused form library | `npm ls formik yup react-hook-form zod @hookform/resolvers` after the change lists only react-hook-form 7.76.0, zod 4.6.7 and @hookform/resolvers 5.9.2, each imported in `src/` |
| Each migrated form keeps its tests green | `LoginForm.test.tsx` and `LoginPage.test.tsx`, unchanged: 67 tests passed |

**Not covered.** No one has signed in by hand through the rewritten form; the tests cover validation, submission, the busy state, the lock states and axe. One behaviour differs and is noted in the ADR: `onSubmit` receives the trimmed email (zod trims on parse; Formik passed the raw string). `LoginPage` trimmed it already.
