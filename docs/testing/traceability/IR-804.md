## IR-804 — The wrong-email advice at registration becomes true

**Basis and scope.** IR-804, subtask of IR-705; authority ADR-051 decisions 22 to 26. Builds on IR-705's backend (PR #680). On 2026-11-11 the System Admin's "Unverified" mark on the Users page was added to this ticket's scope, a decision made while shaping IR-705. No FR- id.

**What exists now.**
- **The wrong-email line** on the registration confirmation (`SignupPage.tsx`) now reads "If that address is wrong, register again with the right one. An account that is never verified is deleted after 30 days." The old line said the first request stays pending until an administrator declines it. That stopped being true: RDCO no longer sees an unverified account, and it expires after `UNVERIFIED_REGISTRATION_DAYS` (IR-705). The 30 is written into the page, because the frontend doesn't read that setting.
- **Sign-in's advice:** the line "register again if it expired" no longer exists. IR-643 replaced it with "If it expired or never arrived, resend verification email", because ADR-045 §7 says an expired link never means registering again. Nothing to change. `LoginPage.test.tsx` already covers that link.
- **Registering again too soon** shows the server's wait. `errorDetail` now also reads `retry_after` from the response body, which ADR-045's answers send, and IR-705's registration refusal too. It reads the body first, then the `Retry-After` header, then DRF's "available in N seconds". The registration form keeps what was typed.
- **Users page:** a row whose `is_verified` is false shows an "Unverified" badge next to its status. `UserListItem` gains `is_verified`. Only the System Admin's list holds such rows, because RDCO's leaves them out (IR-705).

**Tests** (all queries by role and accessible name; axe checks where the screen changed):
- `SignupPage.test.tsx`: the confirmation shows the new wrong-address line and not the old one (a deliberate change to the IR-709 assertion); a 429 with `retry_after: 42` shows "try again in about 42 seconds" and keeps the form, with an axe check; a 429 with only DRF's wording reads the wait from it.
- `UserListPage.test.tsx`: an unverified row shows "Unverified" and a verified row doesn't, with an axe check.
- `errorDetail.test.ts`: the body's `retry_after` is read.
