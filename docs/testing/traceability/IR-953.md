## IR-953 — Cut repeated cost and wait in the agent's research loop; IR-1003 — concurrent tool calls

**Basis and scope.** IR-953 under IR-712, and IR-1003 split out of it. Authority: ADR-049, 2026-11-09 amendment (IR-953). The approver, Jive Tyler I. Revalde, approved item 4 (concurrent tool calls) in chat on 2026-11-09. Item 3 (query-vector cache) was approved the same day and is on. Item 2 ships off.

**What exists now.**
- **Cached-token recording:** `ai/agent/dialect.py` reads `usage.prompt_tokens_details.cached_tokens`. `ai/admission/transport.py` passes it on, and `ai/admission/ledger.py` stores it in `ai_providerreservation.cached_input_tokens` (migration `ai/0044`, nullable). The charge is never discounted. `python -m ai.admission.report <run_id>` prints the total, and `provision_research_roles` grants the runtime the column.
- **`AGENT_LLM_PROMPT_CACHE=run`** (off): `ai/infrastructure/openai_adapter.py` sends `prompt_cache_key = iris-run-<run id>`.
- **Query-vector cache** (on unless `RUNS_QUERY_VECTOR_CACHE=off`, approved 2026-11-09): `ai/research/tools.py::_query_vector` reuses a vector by (Embedding Space, exact query) within one run's tools.
- **`RUNS_AGENT_TOOL_CONCURRENCY`** (optional, 1 to 16, blank means 1): `ai/agent/executor.py::_Fetches` starts the read-only calls in a group (`ai/agent/tools.py::PREFETCHABLE`) that fall within the tool limit and before any clarification. `Investigation.execute` folds the results in call order. `ai/research/tools.py::EARLIER_COMMITTED` holds each journal entry until every earlier call has committed.

**Tests.**
- `backend/apps/ai/tests/test_ir953_prompt_cache.py` (no database): cached tokens are read, and a malformed count is unknown, not zero. The key is sent only when set to `run`, only inside a run, and scoped to that run. Both settings refuse bad values.
- `backend/apps/ai/tests/test_ir953_cached_tokens_db.py` (real PostgreSQL, restricted runtime login): a settled attempt stores the cached count at the full charge, and an unreported count stays null.
- `backend/apps/ai/tests/test_ir953_query_vector_cache_db.py`: the same query twice in one run makes one embedding and one reservation, and finds the same passages. Turned off, it embeds twice. The cache never crosses runs.
- `backend/apps/ai/tests/test_ir1003_concurrent_tools_contract.py` (recording provider, slowed research stand-in):
  - two searches take one search's wait, and 1 is unchanged;
  - the model's requests are identical to a sequential run's;
  - a later call that finishes first still journals second;
  - a call past the tool limit is answered and never fetched;
  - the setting is bounded.

**Evidence, 2026-11-09 (Windows dev machine, private test database).** The new contract and unit tests, plus `test_ai_runtime_agent_loop_contract.py`, passed (59 tests). `ai/tests` passed. The database run passed with no failures: both IR-953 database files, `test_ir886_hybrid_search_db.py`, `test_ai_runtime_admission_db.py`, `test_ai_runtime_agent_loop_db.py` and `test_ai_runtime_research_db.py`. Teardown warned that another session still held the test database. flake8 is clean.

**Not done here, and why.**
- **No before-and-after latency or cost measurement on a real vendor.** It is paid inference, and it needs the approver's spending approval.
- **Caching was checked by hand on the configured OpenRouter route** (about US$0.001 of probes): the repeat prompts came back 99.9% cached at about 1/11 the cost, with or without the key. The figures are recorded in the ADR amendment.
- **Concurrency is not proved on restricted PostgreSQL under the per-reader caps** (IR-1003's last acceptance criterion). The ordering gate is proved with the in-memory stand-in only.
- **Migration numbering:** PR 640 also adds an `ai/0044`. Whichever merges second needs a merge migration.
