## IR-406

**Requirement:** **The Publish dialog can offer the manuscript's own title and abstract** — no FR- id; B1 of the IR-374 frontend redesign spec (§4.5, Appendix D), the backend half of F3b's prefill and assistance toward NFR-U2

**Design:** [IR-374 spec](../../frontend_redesign_spec.md) §4.5 · ADR-016 (the structure it reads)

**Implementation:** `apps/records/metadata_suggestions.py` (new) reads the record's `PdfExtraction(kind=MANUSCRIPT)` and restates its status as a local `SuggestionState`: `pending` (queued/running) · `ready` (done) · `failed` (failed, or any status added later) · `unsupported` (no manuscript extraction to read). From a `ready` structure it suggests the Docling title, **unless it is only the file name** (Docling's fallback, compared against the stored name and its stem with case and `_`/`-`/space folded, since storage rewrites spaces), and the text under an *Abstract* heading (case and trailing `:`/`.` ignored) up to the next heading, **leaving out running page headers and footers**; `null` when absent. `GET /records/<id>/metadata-suggestions/` on `RecordViewSet` is **owner-only through `get_queryset()`**, so office staff, the assigned adviser and a reader of a published record get a 404 identical in status and body to a missing record (IR-153). No LLM, no vendor call, no model change, no migration; it imports `apps.ai`'s extraction serializer and document kinds read-only and adds nothing there. `apps/tests/test_enum_vocabulary.py` gains one `ALLOWED` entry, with its reason: `SuggestionState`'s `"pending"` is ingestion vocabulary that shares a spelling with `RequestStatus.PENDING`. **Not done, by choice:** the optional B1b (`manuscript_extraction` on Record detail). **Known gaps, for the spec's owner:** a retrying extraction reads `failed` between attempts, so the dialog stops polling before a later success; and an image-only scan is stored `failed` (`EmptyExtraction`), not the `ready`-with-nulls §4.5 describes

**Test:** `apps/records/test_metadata_suggestions.py` (16 tests, REST seam): each state; title and abstract read from a structure built with the extraction package's own serializer; file-name titles suppressed including a storage collision suffix; page furniture excluded; a read structure with neither gives nulls; owner 200, stranger 404, office staff / adviser / public reader 404, **a refusal's body equal to a missing record's**, anonymous 401; the extractor is never called

**Evidence:** `pytest apps/records/test_metadata_suggestions.py` → **16 passed**. Full backend suite **1898 passed, 2 skipped, 1 xfailed, 0 failed** (2026-09-29, local Postgres 16 + pgvector). Re-run after rebasing onto `main` at `2264255`: **2191 passed, 2 skipped, 1 xfailed, 0 failed** (2026-10-03). **Red first:** every slice was seen failing before its code (no route; no `abstract` key; furniture included; file-name titles returned; `ready` for every status; 200 for non-owners). The identical-body test was added after the two-axis review found the first owner check answered `Not found.` where a missing record answers `No Record matches the given query.`

**Status:** **IMPLEMENTED** — the endpoint exists and is tested; the chips that consume it are F3b (IR-409), and nothing is VERIFIED until a person reviews it
