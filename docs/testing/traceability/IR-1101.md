# IR-1101 — Unstructured hi_res: realistic column and table fixtures, and join tables split across pages

**Affected requirement labels:** none by FR- id. Part of [ADR-067](../../adr/067-unstructured-replaces-llamaparse.md) under IR-980. It follows from IR-985's contract run.

## Why

The contract run in IR-985 failed on two synthetic fixtures. Neither showed what it was meant to:

- `two_columns` has three-line columns whose lines sit at the same heights. Every Extractor tested reads it row by row (ADR-067 amendment §3).
- `table_across_pages` is literal pipe text with no rules, so `hi_res` reads it as a one-column table with loose rows.

## What changed

- **Two fixtures** in `fixtures/layouts.py`, rendered by `build.py` and recorded through the Platform API on 2026-11-14. `Rule` draws lines.
  - `paper_columns` has two columns running the page, with paragraph breaks at different heights.
  - `ruled_table` has a gridded two-column table: the header once, 40 rows, rows 33–40 on page 2.
- **`shape_unstructured` joins a split table.** A table that is the first body element on a page is joined to a table that was the last body element on the page before, when their column counts match. Rows, boxes and HTML are concatenated. Without this, `hi_res` returns the continuation as a second table whose first row is marked as a header.
- **Contract.** Both new fixtures pass all four clauses for Unstructured. The two old fixtures' strict xfails now carry corrected reasons. LlamaParse's replay test skips fixtures it has no recording for, because LlamaParse is retired at IR-988.

## What was measured

- **Aligned paragraphs are read across rows.** In a first version of `paper_columns`, paragraphs started at the same height in both columns. `hi_res` read it left, right, left, right. With the text flowing like a paper's, it reads left then right. Pages whose paragraphs line up across columns remain a risk, and the real-page measure (`real_order/`) is the gate for it.
- **Cell values are OCR'd.** "401 g" was read as "4019", so the shaping test checks row labels, not values.

## Evidence

`python -m pytest apps/ai/extraction/tests`, run 2026-11-14: 291 passed, 24 skipped, 5 xfailed. The 5 xfails are `two_columns` reading order, `figures` reading order and boxes (formula OCR is withheld until transcription), and `table_across_pages` reading order and boxes.
