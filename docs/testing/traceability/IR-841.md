# IR-841 — LlamaParse Extractor

**Affected requirement labels:** FR-M3-01 (PDF text extraction). Its matrix status does not change: Docling stays the configured Extractor until IR-842.

[Back to the matrix](../TRACEABILITY.md)

**Implementation:** `apps/ai/extraction/llamaparse_client.py` is the LlamaParse v2 adapter (ADR-056). One `extract()` call uploads the PDF, starts a job with Cost Optimizer and every extra on, polls it, fetches `items`, `markdown` and `metadata`, downloads the word/line/cell boxes and `layout` figure crops, then deletes the uploaded file in a `finally`. A refused delete is logged and never masks the result or the error in flight. The request sets `disable_cache` and `processing_control.timeouts`. A job's budget is base + per page × its page count, sent to LlamaParse and enforced locally on the wall clock 60 s later. `timeout_seconds` covers the largest accepted PDF. Unreachable, timeout, 429, 5xx, a cancelled job and a first `TIMEOUT` raise `ExtractorUnavailable`, and so do 401, 402 and 403 and any failed download. **This narrows the ticket's "other 4xx raise `DocumentRejected`"**: a bad key, exhausted credits or an expired download link is the deployment's fault, not the paper's. A second `TIMEOUT` for the same PDF, `DOCUMENT_TOO_LARGE`, `PROCESSING_SIZE_LIMIT_EXCEEDED`, `CONTENT_POLICY_REFUSAL` and every other 4xx raise `DocumentRejected`. `FILE_IS_EMPTY`/`NO_DATA_FOUND_IN_FILE` raise `EmptyExtraction`. The port gains `Usage`, `FigureImage`, `ExtractedDocument.usage/figures/raw` and `leaves_campus`. Presigned URLs are stripped from `raw`, and downloads never carry the key.

**Settings:** `LLAMAPARSE_API_KEY`, `_TIER`, `_VERSION`, `_BASE_URL` (NA or EU only) and the three timeout settings, documented in `backend/.env.example`. With `EXTRACTION_BACKEND=llamaparse` Django refuses to start without a key or a pinned version, on `latest` with `DEBUG` off, on another region, and until IR-840's shaping exists (`apps.ai.extraction.shaping.shape_llamaparse`).

**Stored:** `PdfExtraction.raw_result`, `pages_read` and `credits` (migration `documents/0018`, additive). The task writes them with the provenance. `apps/ai/extraction/pages.py` reads the vendor's page metadata so no caller outside extraction does. The read-only, superuser-only admin lists each page's confidence, least first, flags those under 0.5 as `LOW` (provisional until IR-851), and shows watermark text. The API serializer exposes none of it.

**Tests:** `apps/ai/extraction/tests/test_llamaparse_client.py` replays IR-849's four recordings over `httpx.MockTransport` (`llamaparse_vendor.py`); no vendor call. It also runs the contract suite's failure clauses against LlamaParse; the 16 document clauses skip until IR-840. `test_selection.py` covers the start-up refusals; `apps/documents/tests/test_raw_extraction_is_stored.py` the task; `apps/ai/extraction/tests/test_pages.py` the page report; `test_extraction_admin_pages.py` the admin field and the serializer.

**Not verified:** no recording contains a figure image, so the figure path is tested against LlamaParse's documented shape only. Job failure codes are read from `error_message` because the v2 job has no code field; no failed job was recorded. No real Celery worker ran the adapter, so the task's time limit has not fired. Figures are downloaded but not stored (IR-845); a `layout` image matching no `image` item is skipped, its metadata kept in `raw`. Only the uploaded file is deleted: the parse job and its result stay with LlamaParse under its retention terms (ADR-056 open condition 1). Reaching the local deadline does not cancel the vendor job.
