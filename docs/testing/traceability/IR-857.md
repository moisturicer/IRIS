# IR-857: registration names

**Requirements:** IR-857 / IR-855, FR-M6-01 (authentication); accessible registration validation. This change does not alter the overall authentication requirement's status.

Registration now asks for first and last names in two equal columns (stacked on narrow screens). It omits `middle_initial` from the new-account request and its TypeScript payload type. Existing stored middle initials, full-name formatting, and profile editing remain unchanged; no migration.

Both registration boundaries require a letter and allow Unicode letters/combining marks, ordinary spaces, straight/curly apostrophes and hyphens (including U+2010/U+2011). Only outer whitespace is trimmed; interior spacing and decomposed accents are preserved. Digits, symbol-only names, emoji and malformed JSON values are refused by the API on the relevant name field before writes. The existing 100-character model limit also applies. Client errors have field descriptions and invalid state, clear after correction, and focus moves to the first invalid field after submission.
