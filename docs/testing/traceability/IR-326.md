## IR-326

**Requirement:** **Streaming Ask IRIS endpoint** — no FR- id; part C of IR-323's "event-shaped answer path", under [ADR-028](../../adr/028-no-tool-calling-in-the-answer-path.md) (one deterministic retrieval call then one generation call, never framed as agentic search) and [ADR-030](../../adr/030-ask-iris-bypasses-gateway-streaming-architecture.md)

**Design:** `apps/ai/answers/events.py` — the `AnswerEvent` vocabulary (`RetrievalStarted`, `RetrievalFinished`, `GenerationStarted`, `TextDelta`, `CitationsResolved`, `Done`)

**Implementation:** `GroundedAnswerService.answer_stream` (`apps/ai/answers/service.py`) — the same retrieval, disclosure gate, memory recall (IR-297, folded silently into retrieval with no event of its own) and citation parsing `answer()` performs, narrated as it goes; only synthesis actually streams, via `LLMProvider.stream()` (IR-325) in place of `.generate()`. `parse_citations` still runs exactly once, over the fully accumulated text, never per delta — `TextDelta`'s docstring states why. `ChatStreamView` (`POST /api/v1/ai/ask/stream/`, `apps/ai/views/chatbot.py`) is a plain **synchronous** DRF view returning a `StreamingHttpResponse` of Server-Sent Events; under the ASGI deployment ADR-017 already requires, Django's own ASGI handler bridges it via `sync_to_async` with nothing hand-rolled. `ChatQueryView`/`/ask/` is untouched — a separate, alternative endpoint, not a replacement. `ScriptedLLM` (`apps/ai/providers/fakes.py`) gained `stream_deltas` for a scripted multi-chunk stream with no vendor account. **Recorded limitation**: `RetryingLLMProvider`/`CircuitBreakingLLMProvider`/`FallbackLLMProvider` (IR-321) implement only `generate()`, so against the real configured model this endpoint still narrates retrieval incrementally but synthesis arrives as one `text_delta` — `LLMProvider.stream()`'s own default wrap of `generate()` — until those decorators gain a genuine `stream()` override, deliberately left for follow-up work rather than retrofitted here

**Test:** `apps/ai/answers/tests/test_service.py::StreamingTests` (event order for a grounded answer, a gated-to-nothing answer skipping straight to `Done`, and a vendor failure mid-stream ending in the same `UNAVAILABLE_TEXT`/degraded/sources-preserved shape `answer()` produces), `apps/ai/providers/tests/test_llm_contracts.py::ScriptedStreamingTests` (the scripted-delta extension itself), `apps/ai/tests/test_ask_stream_http.py` (HTTP boundary, driven through `use_composition_root` with no vendor account: the full event vocabulary in order with streamed text; the `done` event matching `/ask/`'s JSON shape field-for-field; no-sources skipping generation with zero LLM calls; a vendor failure producing an honest `done`; a blank question rejected before any retrieval; an anonymous caller refused; an unreadable record's passage never appearing anywhere in the raw SSE bytes)

**Evidence:** Full backend suite (`python -m pytest -q`) exits 0, zero `F`/`FAILED`/`ERROR` in the output, ~1,564 passed, 1 xfailed, 2 skipped (2026-09-22); `apps/ai/answers/tests/test_service.py`, `apps/ai/providers/tests/test_llm_contracts.py`, `apps/ai/tests/test_ask_stream_http.py` and `apps/ai/tests/test_ask_http.py` together 74 passed in isolation; `manage.py check` and `manage.py makemigrations --check --dry-run` both clean (no model touched, no migration expected)

**Status:** **IMPLEMENTED** — tested at the HTTP boundary with deterministic fakes, but no human review recorded yet (CLAUDE.md §Definition of Done), and the resilience-decorator `stream()` gap above means real-vendor token-by-token streaming is not yet true end to end. **Post-review fixes (2026-09-22, same commit range):** an `/code-review` pass (Standards + Spec axes) flagged the ~30-line request-parsing block duplicated verbatim between `ChatQueryView.post` and `ChatStreamView.post`, and the retrieval/gate/answer-construction logic duplicated between `answer()` and `answer_stream()` in `apps/ai/answers/service.py`. Both extracted: `_prepare_ask_request()` (views) and `_retrieve_and_gate`/`_recall`/`_no_sources_answer`/`_unavailable_answer`/`_grounded_answer` (service), with `answer()` and `answer_stream()` now calling the same private helpers rather than repeating the three `GroundedAnswer` shapes. The review also asked whether a plain synchronous `ChatStreamView` actually satisfies the spec's "new async SSE endpoint" / "bridged via `sync_to_async` at the boundary" wording — checked against Django 5.1's own `core/handlers/asgi.py::ASGIHandler.send_response`, which consumes a `StreamingHttpResponse` via `aiter(response)`, mapping a synchronous generator through `sync_to_async` internally; the design streams genuinely, chunk by chunk, under the ASGI deployment ADR-017 requires, so this was kept as documented rather than rewritten to `async def`. `test_the_done_event_matches_the_synchronous_endpoints_shape` was strengthened from spot-checking four fields to a full field-for-field comparison against a live `/ask/` response.
