# IR-1084: My Library says what each paper waits on and offers Continue draft

**Requirements:** the audit findings WF-03 (a draft has no next step on My Library), US-06 (Delete has the same weight as Continue) and WF-04 (pre-filled titles carry the uploaded file name), in `docs/frontend_ui_audit_spec.md` §3 stories 8–10 (IR-1071). The matrix has no `FR-` row for them. Thesis-critical because it says, on the author's own list, who a paper is waiting on.

## What was wrong

- A draft row on My Library offered "Continue" and a Delete as heavy as it, and nothing said what the draft was waiting on.
- Only a paper with an open request said what it waited on; every other row had a status badge and nothing else. The Overview's *Recent submissions* rows had no action at all.
- A title pre-filled from the manuscript could end in ".pdf": the server declines a suggested title that equals the stored file name, but storage may rename a file, so the extractor's file-name fallback got through.

## What changed

**Client only; no server change.** `features/library/waitingOn.ts` words one sentence per row from fields the server already sends on `GET /records/mine/`: `waiting_on_you[].label` (the server's words), `holders` (who has it, in tracker order, with their labels) and the `version` of each office's `reviewing` entry in `clearance_strip`. It computes no stage and no kept or reset clearance (IR-374 invariant 15); it chooses only the words around them.

| Row | Sentence |
|---|---|
| a draft | Not submitted yet. It waits on you to finish and send it. |
| an open request | Waiting on you: Revision requested by IERC. |
| an approved Proposal the author may continue | Approved. It waits on you to continue it as a Thesis or a Project. |
| offices hold it | IERC and KTTO are reviewing your version 2. Nothing to do yet. (`your paper` when their versions differ or are unknown) |
| RDCO holds it | RDCO is making the final decision. Nothing to do yet. |
| the Adviser holds it | Your Adviser is reviewing this. Nothing to do yet. |
| nobody holds it | Nothing is waiting on this paper. |

**One action per row** (`SubmissionRow`): **Continue draft** (`/?publish=<id>`, the dialog reopens at the first incomplete step, `firstIncompleteStep`) on a draft; the act that answers an open request where there is one; otherwise **Open review** (`/records/<id>`). The Overview's short list shows exactly one and no Delete; *My submissions* also offers Delete draft on a draft.

**Delete draft is a ghost** (`DeleteDraft`): no fill or outline at rest, a hover tint only. It still opens the confirmation, which names the draft ("“<title>” and its files will be removed. It can't be restored.") and starts with Cancel focused.

**Titles** (`publish/draft.ts`, `publish/autofill.ts`): `withoutPdfExtension` strips any run of trailing ".pdf". `provisionalTitle` applies it (so "paper.pdf.pdf" gives "paper"), and `fieldsOf` applies it to a suggested title, which is dropped if nothing remains. A suggestion that becomes the placeholder is then skipped by `planAutofill`'s existing "same value" rule.

## Open for the reviewer

- **The sentences are worded by the client** from server facts. `submitter_status` is described as server-worded (`apps/reviews/submitter_status.py`), so the stricter alternative is a server field (`waiting_on`) built beside `line`, which needs a backend change this ticket's file list does not name. Cost of the client route: new wording lives in two places.
- **Rows for a finished paper** (published, rejected) say "Nothing is waiting on this paper." and offer Open review, which opens the record.
- A draft saved with a title that already ends in ".pdf" is not rewritten; only new pre-fills are.
