## IR-657

**Requirement:** An administrator revoking a session ends it at once: its access and refresh tokens are refused on their next use, with a code that says an administrator did it

**Design:** Jira IR-657 (spec IR-652); ASVS 4.0.3 item 3.3.1

**Implementation:** `sessions.revoke_token` ends the `UserSession` named by the stored token's `sid` (`SessionEndReason.REVOKED`, migration `accounts/0014`) and blacklists the token. The 401 is `session_ended_revoked`, shown by the sign-in screen. `SESSION_REVOKE` now names the affected user

**Test:** `apps/accounts/test_session_revoke.py` signs in for real and uses the returned tokens. Before the fix 3 tests failed on the old access token still working and 1 on the audit metadata. A stored token with no `sid` is still only blacklisted: no test covers that older shape

**Evidence:** 2026-10-31, local Docker: `apps/accounts apps/tests` 237 passed, 11 skipped; `LoginPage.test.tsx` and `client.test.ts` 48 passed

**Status:** **IMPLEMENTED**
