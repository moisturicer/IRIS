## IR-665

**Requirement:** An uploaded PDF must really be one: its bytes carry the signature and it opens with at least one page; `uploads/create/` no longer skips the check

**Design:** Jira IR-665 (spec IR-654); ASVS 4.0.3 item 12.2.1 (Level 2)

**Implementation:** `pdf_upload_problem` (`apps/documents/validators.py`) checks the bytes with pypdf after the name, type and size checks, and all three PDF routes use it: manuscript, `submit/` and `uploads/create/`. Office attachments (`RecordFile`) accept any type by design and are not checked

**Test:** `apps/documents/tests/test_pdf_content.py`, plus `test_neither_upload_route_stores_a_file_that_is_no_pdf` through the API. Existing tests that uploaded fake bytes now upload a real PDF, via `apps/documents/testing.py`

**Evidence:** 2026-10-31, local Docker: `apps/documents apps/records apps/reviews apps/audit apps/tests` 1170 passed, 14 skipped. One real PDF (9.9 MB) opened in 0.09 s; no real theses were available to measure false refusals

**Status:** **IMPLEMENTED**
