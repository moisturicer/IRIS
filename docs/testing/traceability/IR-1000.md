# IR-1000: Section navigation on the paper Overview

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no requirement row changes status. This is S2 (Frontend UI/UX Redesign, IR-920) work on Paper View's Overview.

**What changed**

| Place | Change |
|---|---|
| `paper-view/OverviewIndex.tsx` (new) | An "On this page" `<nav>` of anchors to Abstract, AI Overview, Related works and Comments (Comments only on a published paper, the only place the page has them). A click scrolls to and focuses the section and does not touch the URL; a modified click is left to the browser. The current section is the last whose top has passed a line under the sticky header, the first before any has, and the last at the end of the page; it carries `aria-current="location"` and a filled style, so it is not shown by colour alone. Links use the reading controls' size and a visible `focus-visible` outline. |
| `PaperViewPage.tsx` | The four sections carry ids (`overview-abstract`, `-ai`, `-related-works`, `-comments`), `tabIndex={-1}` and `scroll-mt-20`, so a jump lands under the 56px header. The index is mounted twice: first in the Record details column on wide screens (`hidden overview-wide:block`), and again as a wrapping row of chips above the Abstract on narrow screens (`overview-wide:hidden`, kept visible while Ask IRIS folds the column away). The abstract is `sm:text-justify` with `hyphens:auto` and `lang="en"`; its column and measure are unchanged. |

**Where "the existing Overview gutter" is.** At the page's 1440px cap the Overview column has almost no room to the left of its 60rem measure while the rail is showing: 1440 - 88 (page padding) - 352 (rail) - 32 (gap) = 968px, against a 960px column. A left-hand index would therefore never appear beside the rail on a laptop. The wide placement is the top of the sticky Record details column instead, which is the side column the Overview already has. If a left gutter was meant, it needs the column's measure or the page cap to change, which this ticket was told not to do.

**What this does not show.** The index was not seen in the running app, so the wide placement in the rail, its stickiness, the current-section marker while scrolling a real page, and the whole page's overflow at 360px (the Core journeys' `a11y.reflow360`) are untested here. Hyphenation depends on the browser having a dictionary for the language, so it varies by browser and platform. A phone keeps a ragged abstract on purpose.
