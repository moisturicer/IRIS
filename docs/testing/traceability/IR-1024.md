# IR-1024: published paper Comments shown as threads

**Requirements:** ADR-032 §7 (public Comments); builds on IR-692. Prototype approved by the requester on 2026-11-12: `docs/prototypes/comment-threading.html`.

`CommentsSection` now shows each top-level comment with its replies beneath it, joined by a thread line. The data model is unchanged: the thread is worked out from `reply_to` in `commentThreads.ts`, which follows a reply up to its top-level comment, orders replies oldest first, keeps a deleted comment only while a live comment sits under it, and shows a reply whose parent is missing (or a reply loop) as a top-level comment rather than losing it. A reply to a reply stays in the same thread and starts with an @name link to the comment it answers; it is still posted with `reply_to` set to that comment.

Other behaviour: a thread with more than two replies starts collapsed; Reply stays under each comment while Edit, Delete and Report move into a "..." menu (Escape and outside click close it, focus returns to its button); the reply composer opens under the comment being answered; edit happens in place; Ctrl or Cmd + Enter posts, Escape cancels, Enter adds a line; the character count shows only at 300 or fewer left; bodies over 300 characters are cut with "See more"; times are relative with the full date on hover and for screen readers; Sort offers Oldest (default) and Newest; five top-level comments show at a time.

**Not changed, by decision:** no API change. "Most relevant" sorting is not shipped, because the API only sorts by time and whether to compute it on the server is undecided. A deleted comment with no replies is hidden in the UI only; the API still returns it.

**Evidence:** `CommentsSection.test.tsx` (26 tests, rewritten for the thread layout; the old flat-list and "In reply to" assertions were replaced because that design was replaced) and the new `commentThreads.test.ts` (18 tests): **44 passed**, with `readingStandards.test.ts` and `palette.test.ts` (**61 passed** across the four files). `npm run test:changed`: **13 files, 311 passed**. `tsc --noEmit`: clean. `npm run lint`: **0 errors**, two existing warnings in files this change does not own. `npm run build`: succeeds, and the thread-line and hover-menu classes are present in the built CSS. The full frontend suite was not run locally; GitHub CI is the gate.

**Not verified:** the rebuilt component has not been looked at in a browser against a running backend. The layout was checked in the HTML prototype at desktop and 375px widths, which uses the same geometry. Reviewers should look at a paper with a long thread, at a phone width.
