## IR-926 — Free-text fields have a length limit (ASVS 5.2.2)

Found by IR-829: as the owner of a draft, `PATCH /api/v1/records/<id>/` stored abstracts of 10,000, 200,000 and 2,000,000 characters. Abstracts are drawn on Paper View, embedded and sent to AI vendors. Reasons, comments and messages had no limit either, only Django's 2.5 MB request body.

**The limit.** 10,000 characters, chosen by Ashlee Sean on 2026-11-15, the same as a review comment. It is `FREE_TEXT_MAX_LENGTH` in `backend/core/text_limits.py`, which every check imports, so there is one number to change. Fields that already had a tighter limit keep it: Ask IRIS questions 2,000, review comments 10,000, thread notes 2,000, public comments 2,000, download notes 500, RDCO's reasons 1,000.

| Field | Where it is checked | Refused with |
|---|---|---|
| `Record.abstract` | `RecordWriteSerializer` (`extra_kwargs`) | 400 `{"abstract": ["An abstract can be at most 10,000 characters."]}` |
| Routing reason (`accept-and-route/`, `route/`) | `reviews/routing.py` `_plan` | 400, the same sentence for "A reason for routing" |
| Revision reason (`request-revision/`) | `reviews/revisions.py` | 400 |
| Office comment (`office-review/`) | `reviews/office_review.py` | 400 |
| Decision comment (`decide/`) | `reviews/decisions.py` | 400 |
| Reassignment reason | `reviews/seats.py` `reassign` | 400 |
| Document-request message | `DocumentRequestCreateSerializer` | 400 |
| Document-request rejection reason | `ItemDecisionSerializer` | 400 |
| Account-deletion rejection reason | `accounts/deletion/service.py` | 400 |
| Opportunity description | `OpportunitySerializer` (`extra_kwargs`) | 400 `{"description": [...]}` |
| Upload-review comment (`documents/upload-reviews/`) | `UploadReviewCreateView` | 400 `{"comment": [...]}` |

Each check runs after the text is stripped and before anything is written, so a refused request changes nothing.

## Evidence, 2026-11-15

Run by Claude Code at Ashlee Sean's direction, on a throwaway local `pgvector/pgvector:pg16` container (local Postgres has no pgvector). Not on iris-demo.

- `apps/tests/test_free_text_limits.py`: 13 passed. One test per field sends 10,001 characters and checks the 400, the limit in the message and that nothing was written. The abstract test also checks that exactly 10,000 is accepted.
- The existing tests of every module touched (routing, revisions, office review, decisions, seats, document requests and decisions, account deletion, opportunities, `records/tests.py`): all pass except 47 that upload a PDF. Those fail with "PDF checking is temporarily unavailable", because the PDF checker's sandbox needs Linux. The same files fail identically on a clean `main` checkout (`test_document_requests.py`: 19 on both), so CI is their record.

**Not changed:** the model fields stay `TextField`s with no database limit, so no migration. The limit is the server's, at the API boundary.
