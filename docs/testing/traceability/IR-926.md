## IR-926 — Free-text fields have a length limit (ASVS 5.2.2)

Found by IR-829: as the owner of a draft, `PATCH /api/v1/records/<id>/` stored abstracts of 10,000, 200,000 and 2,000,000 characters. Abstracts are drawn on Paper View, embedded and sent to AI vendors. Reasons, comments and messages had no limit either, only Django's 2.5 MB request body.

**The limit.** 10,000 characters, chosen by Ashlee Sean on 2026-11-15, the same as a review comment. It is `FREE_TEXT_MAX_LENGTH` in `backend/core/text_limits.py`, which every check imports, so there is one number to change. Fields that already had their own limit keep it: Ask IRIS questions 2,000, review comments 10,000, thread notes 2,000, public comments 2,000, download notes 500, RDCO's reasons 1,000, reading notes 20,000, the notice 50,000, profile bio 500.

| Field | Where it is checked | Refused with |
|---|---|---|
| `Record.abstract` | `RecordWriteSerializer` (`extra_kwargs`) | 400 `{"abstract": ["An abstract can be at most 10,000 characters."]}` |
| Routing reason (`accept-and-route/`, `route/`) | `reviews/routing.py` `_plan` | 400, the same sentence for "A reason for routing" |
| Revision reason (`request-revision/`) | `reviews/revisions.py` | 400 |
| Office comment (`office-review/`) | `reviews/office_review.py` | 400 |
| Decision comment (`decide/`) | `reviews/decisions.py` | 400 |
| Reassignment reason | `reviews/seats.py` `reassign` | 400 |
| Document-request message | `DocumentRequestCreateSerializer` | 400 |
| Document-request rejection reason | `ItemDecisionSerializer` | 400 |
| Account-deletion rejection reason | `accounts/deletion/service.py` | 400 |
| Opportunity description | `OpportunitySerializer` (`extra_kwargs`) | 400 `{"description": [...]}` |
| Upload-review comment (`documents/upload-reviews/`) | `UploadReviewCreateView` (also refuses a comment that isn't text) | 400 `{"comment": [...]}` |
| Finish-review summary (`finish-review/`) | `reviews/finish_review.py`, before the verdict's own service | 400 "A summary can be at most..." |
| Deadline-extension reason (`assignments/<id>/extend/`) | `reviews/deadlines.py` `extend` | 400 |
| System setting value (`settings/<key>/`, System Admin) | `SystemSettingView.patch` | 400 `{"value": [...]}` |
| Abstract in a staff Excel import | `records/services.py` `check_import_row` | the row is skipped and named in the import log |

Each check runs before anything is written, so a refused request changes nothing, and after the caller is authorized, so the 400 says nothing about whether a target exists. Reasons and comments are measured after stripping; the upload-review comment and the setting value as sent. The limit is noted beside `Record.abstract` and `Opportunity.description` in their models; the number itself lives only in `core/text_limits.py`.

## Evidence, 2026-11-15

Run by Claude Code at Ashlee Sean's direction, on a throwaway local `pgvector/pgvector:pg16` container (local Postgres has no pgvector). Not on iris-demo.

- `apps/tests/test_free_text_limits.py`: 19 passed. One test per field sends 10,001 characters and checks the 400 (or the skipped import row), the limit in the message and that nothing was written. The abstract test also checks that exactly 10,000 is accepted, the opportunity description is tested on create and on PATCH, and a non-text upload-review comment is refused.
- A review pass found four fields the first version missed: the finish-review summary, the extension reason, the setting value and the import abstract. They are in the table above, with their tests. The existing tests of their modules (`test_review_threads.py`, `test_deadlines.py`, `test_system_settings.py`, `test_system_admin.py`, `test_excel_import.py`, `test_account_deletion.py`) pass.
- The existing tests of every module touched (routing, revisions, office review, decisions, seats, document requests and decisions, account deletion, opportunities, `records/tests.py`): all pass except 47 that upload a PDF. Those fail with "PDF checking is temporarily unavailable", because the PDF checker's sandbox needs Linux. The same files fail identically on a clean `main` checkout (`test_document_requests.py`: 19 on both), so CI is their record.

**Not changed:** the model fields stay `TextField`s with no database limit, so no migration. The limit is the server's, at the API boundary.

**Not covered:** null characters. Raw-service paths read `request.data.get(...)`, which skips DRF's null-character check, so a NUL could reach Postgres. That is the other half of 5.2.2 (allowed characters) and is not checked here.

**Rebased on 2026-11-16** onto `main` with ADR-050's new Call fields (IR-649, IR-762). The description limit now sits beside the description's `required` rule, and the two Call tests build a Call through `test_call_review.payload`. RDCO's Call rejection reason already has a 2,000-character limit, which is tighter, so it stays. Rerun locally on a throwaway `pgvector/pgvector:pg16`: `pytest apps/tests/test_free_text_limits.py apps/opportunities`, 174 passed.
