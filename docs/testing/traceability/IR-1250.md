## IR-1250

**Requirement:** One documented command runs the production frontend against the local stack, so a tester judges speed and look as users get them, not on the dev server

**Design:** Jira IR-1250, from the local performance investigation (Ashlee Sean, 2026-11-20), which measured the dev server at 2.5–4.5 s to a screen's heading against ~0.2 s for the production build on the same backend

**Implementation:**

- `frontend/scripts/preview-local.mjs` (new) uses Vite's `build` and `preview` functions, so it works the same on every OS. It:
  - builds into `dist-local/`, never `dist/`, which CI's bundle scan reads;
  - serves on 4173 with `strictPort`, or another port from `PREVIEW_PORT`;
  - proxies `/api` to `http://127.0.0.1:8000`, unless `VITE_PROXY_TARGET` is set.
- `npm run preview:local` in `frontend/package.json`, and `dist-local/` in `.gitignore`.
- Documented in `docs/engineering/DEVELOPMENT.md` §5 and the CLAUDE.md command list.
- The same section's stale "There is no `npm test`" line is corrected: vitest has been installed since IR-210.

**Test:** `frontend/scripts/preview-local.test.mjs` (`npm run test:security` runs it) checks the build folder, the port and strict port, the 127.0.0.1 proxy default, a caller's own target kept, and `PREVIEW_PORT`

**Evidence:**

- 2026-11-20, locally: the test failed first (no module), then passed 5 of 5.
- `npm run preview:local` built and served at `http://localhost:4173` with the API at `127.0.0.1:8000`, and `dist-local/` stayed out of `git status`.
- Timed through it (full page loads, headless Chromium, `student@iris.test` and `itso@iris.test`):

  | Screen | Heading shows | Settled |
  |---|---|---|
  | Discover | 147–182 ms | 438–456 ms |
  | Paper Overview | 243–280 ms | 332–348 ms |
  | My Library | 253–255 ms | 271–336 ms |
  | Calls & Conferences | 267–296 ms | 285–379 ms |
  | Settings | 160–249 ms | 176–269 ms |
  | Notifications | 251–252 ms | 272–273 ms |
  | My Reviews | 260–269 ms | 281–287 ms |
  | Paper Review | 243–253 ms | 258–278 ms |

  The same screens took 2.5–4.5 s to the heading and 5–12 s to settle on the dev server that morning.
