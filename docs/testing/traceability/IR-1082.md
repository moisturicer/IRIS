# IR-1082: Discover toolbar and result rows: one action, one height, labelled filters, list rows

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Audit findings VIS-01, VIS-05, LAY-01, LAY-02, US-01 to US-04, CMP-03, CMP-04 ([`frontend_ui_audit_spec.md`](../../frontend_ui_audit_spec.md) §4.6). Decisions D4 (column toggle stays; 96 px outline thumbnail in one column only) and D6 (highlight roles), recorded on the ticket 2026-11-14.

## What changed

- **One filled control.** The feed segments (For you, Latest, Trending) and Papers/People were filled maroon when chosen. They are now the Selected segment role (white, raised, Ink text). Publish is the only filled control in the toolbar.
- **One control height.** Every toolbar control is 44 px: the feed and Papers/People tracks (were 44 and 40), Areas, My feeds, the 1 / 2 / 3 column toggle, Filters, Publish, the Sort select, the filter-panel dropdowns and the People tab's selects (were 40).
- **Visible filter labels.** Each filter in the panel has its name above it, and its button shows the choice ("Any type", "Project", "2 selected"). The button's accessible name is the label then the choice ("Type Project"). The per-dropdown count badge is gone; the Filters button still counts what is active.
- **Sort and a live count in a results header** (`DiscoverResultsHeader.tsx`), above the list: "8 papers" in a polite status region, and a Sort select (Newest, Most viewed) on Latest. Sort left the Filters panel. For you and Trending have no Sort, as before, and keep the count.
- **People only on the People tab.** The five-person preview and "See all people" under a Papers search are removed (`DiscoverPeopleResults` is the directory only). A People failure shows "We couldn’t load people." with Try again.
- **Areas is hidden until there are Areas** to choose from (neither list has an entry and the reader has none saved), so it never opens an empty dialog.
- **One column is a list row** with a 96 px outline thumbnail (`PaperThumbnail.tsx`, drawn, not rendered from the PDF, hidden below `sm`). Its facts and actions sit under the text in one footer. The abstract-preview panel, "At a glance" text and `ManuscriptCover.tsx` (which fetched and rendered each manuscript's first page) are removed. Two and three columns are unchanged text-only tiles. `ResearchCard` loses `preview`, `previewLabel` and `splitFooter` (Discover was their only user) and gains `thumbnail`.
- `ResearchCard`'s `summaryClassName` now replaces the default clamp instead of being added to it (`cn` does not merge two `line-clamp-*`, so the second never won).
- `src/test/fontSizeAllowance.ts`: two entries removed and one lowered, as the guard asks.

## Tests

- `DiscoverPage.test.tsx`, "the toolbar and the result rows (IR-1082)": exactly one filled control and it is Publish; the chosen segment is white (`bg-surface`, no `text-white`) in both segmented controls; every control carries only the one height token; each filter has visible label text and its button is named "<label> <value>"; Sort is a combobox in the "Results" group beside a status reading "3 papers", and is absent from the Filters panel; "1 paper" singular, and the count stays on For you with no Sort; Areas absent when both lists are empty; one column has one footer (one Save, one Cite), no "From the abstract", and a decorative 96 px thumbnail (`aria-hidden`).
- Changed existing tests: People appear only after choosing the People tab (and none before, with no people request); a malformed people response shows the alert and Try again recovers; the column cycle asserts the thumbnail in one column and none in two; both Sort tests drive the header select; the People-words test switches to the People tab first.
- **Limits.** jsdom loads no Tailwind, so fill and height are asserted as class tokens. The thumbnail is found by its `w-24` class because it is decoration with no role or name to query.
