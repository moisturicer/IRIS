# IR-1080: Phone Discover: search, then one row of controls

[Back to the matrix](../TRACEABILITY.md)

> **Superseded in part by [IR-1190](IR-1190.md):** the row no longer scrolls sideways (it is one non-wrapping row at every width), and Papers / People now sit in the row, not the header.

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Audit findings RES-01 (High), RES-02 and A11Y-09 ([`frontend_ui_audit_spec.md`](../../frontend_ui_audit_spec.md) §4.6, "Phone").

## What changed

- **Search, then one row.** On a phone Discover's controls are one row directly under the page header: the feed segments (For you, Latest, Trending), Areas, My feeds, Filters and, for an author, Publish. The row scrolls sideways inside itself (`overflow-x-auto`, scrollbar hidden, bleeding to the screen edge) so the page never does. From `sm` (640 px) up it is the wrapping toolbar it was.
- **Every control has a visible name.** Areas, Filters and Publish were icons on a phone; they now show their text at every width. Filters shows its count beside the word ("Filters 2"), no longer as a badge over the corner; its accessible name is still "Filters, 2 active".
- **Every control is at least 44 px tall on a touch screen.** The feed segments and the Papers/People switch lose their 2 px inner padding below `sm` so their buttons are 44 px; the segments' 11 px label is now the normal 14 px.
- **Papers / People moved to the header,** beside the "Discover" title (at every width: one element, not a phone copy).
- **My feeds opens as a bottom sheet on a phone** (`fixed`, like the Filters panel), because an `overflow-x-auto` row would clip an absolutely positioned menu. From `sm` up it is the same dropdown.
- `DiscoverPage.tsx` no longer has the one sub-12 px label, so its entry in `src/test/fontSizeAllowance.ts` is removed (the guard asks for this).
- `DiscoverTabs.tsx` is unchanged: with one tab it draws no tab bar.

## Tests

- `frontend/src/features/discover/DiscoverPage.test.tsx`, "the phone toolbar (IR-1080)": the search box comes before the controls group; every control is found by role and accessible name inside it (the three feed buttons, Areas, My feeds, Filters, Publish: seven for an author, six for an office reviewer with no Publish); Papers and People are outside the row, after the title and before the row; Filters, Areas and Publish carry visible text that is not `hidden`, and the Filters count is inline text; every control and both Papers/People buttons carries the 44 px height token and the row carries `overflow-x-auto`.
- Existing Discover tests (126) pass unchanged.
- **Limits of the tests.** The tests set no viewport: nothing here reads the window width and jsdom loads no Tailwind, so the same assertions hold at any width. jsdom loads no Tailwind, so the 44 px and "no sideways page scroll" criteria are asserted as the class tokens that produce them, not as measured pixels. The measurement was done in a browser (below).

## Evidence

- Run locally 2026-11-14: `tsc --noEmit` clean; `eslint src/features/discover` no errors; `npm run test:changed` 15 files, 236 tests passed after the allowance entry was removed (it failed once before that, on the font-size guard, as described above). The full suite is left to CI.
- **Checked in a browser** (a throwaway page mounting the real `DiscoverPage` with a signed-in Student and no API, so the list shows its error state; not committed): at 360 and 390 px the page is no wider than the window, the row is 643 px wide inside it and scrolls, every control in it measured 44 px, Papers and People measured 44 px, and search sits above the row. My feeds opened as a sheet inside the viewport, not clipped. At 1280 px the row wraps as before, the menu is a dropdown and the controls are as they were.
- **Not checked:** a real catalogue and signed-in session against the API, a touch device, a screen reader, 360 px with the Filters panel open against real filter data.
- **Finding:** this project's Tailwind config defines a raw `narrow` screen, and with it **no `max-*:` variant is generated** (verified in the served stylesheet). The existing `max-xl:ml-auto` on the Discover filter bar was dead and is dropped here (the bar keeps `shrink-0` only); right-aligning Filters on a tablet is left to the Discover toolbar ticket (IR-1082). New classes in this ticket are written mobile-first with `sm:` overrides for that reason.
- **Decisions:** Areas stays in the row with a visible label though the ticket lists only feed, Filters and My feeds (dropping it would remove Choose Areas on a phone). Publish is last in the row, with its text label.
- **Shared files:** the same toolbar is changed by IR-1082 (Discover toolbar and result rows, `not-ready`) and the same page by IR-1095 (whole card opens the paper). This ticket does not touch `DiscoverResultCard.tsx`.
