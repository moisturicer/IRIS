## IR-735 — Recover original details after compaction and respect deletion

**Basis and scope.** IR-735 under IR-715; authority ADR-049 §8, §19, §21 and the ticket's acceptance criteria. After IR-734 a long Conversation can carry a derived handoff instead of its older Turns, but nothing let the agent check an exact earlier value against the original. This adds bounded recovery of original Turns, a recheck that keeps a revoked handoff from reaching the model or the reader, proof that deletion removes the derived state, and a safe compaction status for the reader. Manual compaction (IR-754) and native-compatibility integration stay separate.

**Code.**
- **Recovery tool** (`ai/agent/tools.py` `RECOVER_TURN`, `ai/research/tools.py` `ResearchTools.recover_turn`). `recover_turn(turn)` takes one integer and nothing else; any other key is refused. It returns the stored question and answer of one earlier Turn, each capped at `RECOVER_CHARS` and marked `truncated` when cut, and re-binds every citation the Turn made to the stored passage: it finds the chunk by Record, page, exact quote and Manuscript revision in the active chunk set, issues a fresh run-bound passage handle, and replaces the answer's `[n]` markers with those handles. A quote that cannot be found again is left out, never invented.
- **Who may recover what** (`_recoverable_turn`, one predicate shared with resume). The run's own reader, in a live Conversation of the grant's Paper Chat scope, for a Turn at or before the revision the run started from, only while `CURRENT_SOURCE_TURN` holds under that reader's row policy: every source it read and cited is still active, and every Record an exact count counted is still readable. A missing Turn, another reader's, a deleted Conversation, a replaced or revoked source and an out-of-scope Turn are one refusal, `unknown_turn`, with the same result shape.
- **Pin** (`ai/agent/executor.py`). New pin pair `agent-research-4`/`research-4` offers `recover_turn` beside every research-3 tool; earlier pins keep their exact tool sets, and the profile now pins `research-4` (`ai/runs/agent_profile.py`). Its instructions say a summary is never a source for an exact value and tell the model to recover the Turn or read the paper again.
- **Summary is never evidence.** A recovered answer's numbers count as supported because they were checked when delivered, but a quotation is citable only through the fresh passage handle. The reader's exclusions still apply: recovering a Turn does not make an excluded paper citable again.
- **Revoked material cannot reappear** (`ResearchTools.handoff_current`, `_Run._handoff_current`). Before every provider attempt and at the final source recheck, a run whose history carries a handoff asks, under its grant, whether the handoff's Turns and sources are still current (the same `CURRENT_HANDOFF` predicate a claim and a commit use). If not, the run ends `unavailable` (`source_changed`) before the summary is sent or the answer committed. A checkpoint keeps the Turns a run recovered (`recovered`; additive, `agent-checkpoint-2` unchanged), and a takeover reauthorizes each of them with the same predicate before restoring, else rebuilds.
- **Deletion.** No new table. Recovery writes only run-bound handles and the run journal, and both are removed with the Conversation by `RunStore._delete`, together with its handoffs, Turns and citations; account deletion goes through the same `_delete` in `purge_departed`. `iris_ai.attempt_accounting` is kept and carries no content. A second deletion is a `NotFound`, a second purge removes nothing.
- **Context status** (`ai/runs/public.py`). The reader projection gains `compaction`: `{compactions, turns_compacted, last}`, from the `compaction` journal events and nothing else. A `kept` reason, a revision, a summary, a handle, a source revision, raw reasoning and opaque state are never published; a malformed event is ignored, and a run whose sources are gone publishes none of it. The context estimate already published stays labelled estimated. The reader (`RuntimeReader.tsx`) says plainly that earlier conversation was condensed and that a summary is not a source for exact details.

**Tests.**
- `apps/ai/tests/test_ai_runtime_turn_recovery_contract.py` (no database; recording provider; in-memory research stand-in): only `research-4` offers the tool; an exact detail is recovered and cited from the stored passage; recovery does not make an excluded paper citable; a number nobody recovered or read is refused; an unrecoverable Turn is the same refusal as a missing one; arguments are strictly the Turn number; a recovered Turn survives a checkpoint; a handoff revoked before the first send or after the last is not sent or delivered; a run that ended stops; no handoff means no recheck; compaction status is outcomes and counts only, ignores malformed events, and sits beside the context estimate.
- `apps/ai/tests/test_ai_runtime_turn_recovery_db.py` (real PostgreSQL, restricted runtime login, Django-issued grants): the owner recovers a Turn and its passage by a fresh handle that reads the same passage; only Turns the run started from; another reader through this run; a widened Paper Chat scope; a replaced source makes recovery look like a missing Turn and a handoff stale; a deleted Conversation recovers nothing; Conversation deletion and account purge remove Turns, citations, handoffs, handles and journal while spend accounting survives, and a second pass changes nothing.
- `apps/ai/tests/test_ai_runtime_agent_loop_contract.py`: the shared in-memory `Corpus` gains `recover_turn` and `handoff_current`. `test_ai_runtime_checkpoint_contract.py`'s `Recovering.reauthorize` takes the new `turns` argument. `ai/tests/test_agent_profile.py` and `test_ai_runtime_executor_selection_db.py` now expect the `research-4` pin. `test_runtime_reader_e2e.py` pins the reader projection's exact key set, so `compaction` was added to it deliberately, and the recorded `runtimeReader.recorded.json` gained `"compaction": null` by hand (the recorder was not run here). No assertion was weakened.
- `RuntimeReader.test.tsx`: the condensed-conversation line appears only after a real compaction and shows no internals.

**Evidence (2026-11-05).** Run locally with the AI runtime's own dependencies and no Django or PostgreSQL: the new contract file (17 tests) and the compaction, checkpoint, agent-loop, manuscript, metadata, partial-outage and context contract suites with `ai/tests/test_agent_profile.py` pass (197 in all). The new DB suite and the changed `test_ai_runtime_executor_selection_db.py` were not run here (no PostgreSQL with pgvector, no backend environment); neither were the frontend tests or type check (no `node_modules`). CI is the gate and its result is recorded on the PR.

**Not done here.**
- **No live effect against a paid provider for a run that has read anything.** IR-725's guard still withholds any request carrying a tool result, so recovery followed by an admitted answer is proven only without admission. The disclosure decision belongs to Jive Tyler I. Revalde (ADR-049 amendment §4).
- A Turn carried whole in a later run (`prior`) is checked when the run claims and is not rechecked per send; only a handoff is. A source revoked in the middle of a run is caught for cited passages and handoffs, as before.
- Recovery returns one Turn at a time, so a long Conversation needs one call per Turn; the run's tool-call bound applies.
- Export is IR-740's; there is no export route to verify "across export" yet, so denial is shown for live and reopened state.
- Recovery quality, and whether the model asks for it when it should, is a human-reviewed measurement (IR-736), not shown by a scripted provider.
- Manual compaction (IR-754) is not built; `capabilities.manual_compaction` stays `false`.
