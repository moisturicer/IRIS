## ADR-038 (proposed)

**Requirement:** **Ask IRIS gains a bounded research lane** — no FR- id; [ADR-038](../../adr/038-bounded-research-lane-for-ask-iris.md) (**Proposed** 2026-10-11, IR-499; awaiting a named approver) is the requirement once accepted. Application-executed read-only tools over handles issued in the run, a planner that reads documents, two loops under hard limits, Jev with an LLM backup for routing and reader-question screening, counts computed in code with completeness labels, off by default and shipped before it is measured

**Design:** Supersedes [ADR-035](../../adr/035-ask-iris-decides-whether-it-needs-evidence.md) §4 and §11 for the research lane only · amends [ADR-026](../../adr/026-conversational-retrieval-and-memory.md) §13, [ADR-027](../../adr/027-corpus-level-questions.md) and [ADR-036](../../adr/036-openai-compatible-inference-provider.md) · notes [ADR-028](../../adr/028-no-tool-calling-in-the-answer-path.md)'s third revisit condition is unmet

**Implementation:** **IR-500 (tool layer) as IR-509 and IR-510, in one PR that may not merge until ADR-038 is accepted.** IR-509 (foundation): `apps/ai/research/` — `RunContext` built from the request, `Budget` from `AI_RESEARCH_*` settings, `Spend` stopping a run at each limit (rounds, calls per sub-task, total calls, wall clock, prompt tokens), the ledger with per-run `E`/`R` handles and the `(record_id, chunk_id, chunk_set_hash)` pointer (passages beyond 30 dropped weakest first), a closed `ToolRegistry` with a JSON Schema and validator per tool, a repeated call returned from cache flagged `duplicate` and still counted, a passage the ledger cap dropped never handed to the planner, `ToolResult` with a required completeness label, `search_passages`, and `manage.py run_research_tool`. `CompositionRoot.retriever(records=...)` narrows to a set of records inside `visible_to` on every path. IR-510 (paper tools): `find_records` (record vectors + `Record.search_vector` + passage hits fused by rank; passage hits honour `AI_RELEVANCE_MIN_SCORE` once IR-396 adds it), `read_record_sections` (sections or pages, capped, truncation reported), `count_records` (`COUNT(DISTINCT id)` over readable records, worded "of the records you can see"), `corpus_facets` (refuses below `AI_LANDSCAPE_MIN_RECORDS` and above `AI_LANDSCAPE_MAX_UNCLASSIFIED_SHARE`; both defaults, 20 and 0.5, are placeholders nobody has chosen). Every tool reaches `Record` only through `tools/common.readable_records` (`visible_to`, then Paper Chat scope); content passes the gate before it enters a result, and the trim to `k` happens after the gate

**Test:** `apps/ai/research/tests/test_search_passages.py` (IR-509: drafts hidden from a student and from another draft's owner, visible to their owner and office; a handle set narrows only; Paper Chat not widened; gate checked on the captured planner request; a withheld paper indistinguishable from an absent one at `k=1`; unissued, lowercase and raw-id handles rejected and logged; context fields refused; duplicate counted; call and wall-clock limits; the command) · `test_paper_tools.py` (IR-510: the same visibility and gate properties for every paper tool; counts relative to the asker; a paper with two owners, two versions and three chunks counts once; an aggregate identical with and without a hidden draft; both facet refusals; every metadata filter; the cut-off hook; reads by section, page and truncation, unknown sections and pages rejected; chained command over all four tools) · `test_budget.py` · `test_ledger.py` · `test_schema.py` · `retrieval/tests/test_visibility.py::RecordSetScopeTests` · `test_one_retrieval_stack.py::test_research_tools_reach_records_only_through_the_one_predicate`

**Evidence:** `pytest apps/ai/research` (84) and the extended retrieval tests pass, 2026-10-11. `run_research_tool` verified on the dev database with `count_records` and `corpus_facets`. Not asserted on a real planner request: no planner exists until IR-502, so the captured-request tests feed tool output into `ScriptedToolCallingLLM`. `test_outcome_indistinguishable_http.py` is not extended, because there is no HTTP tool path until IR-502. `Spend`'s round and prompt-token limits are tested on `Spend` alone; their caller is the planner (IR-502). Full backend suite 2026-10-11: green apart from four `test_profiles.py`/`test_llm_contracts.py` failures that also fail on `main` with this machine's `.env`. `test_index_health.py::test_it_reports_perfect_recall_on_a_small_table` now truncates its table first: rolled-back vectors from earlier tests stay in the HNSW graph, and this suite's additions pushed them past the scan depth (recall 0.14 in suite order, 1.0 alone)

**Status:** **PROPOSED; TOOL LAYER BUILT ON A BRANCH.** IR-500 to IR-504 may not merge until a person accepts it. Evaluation is deferred to IR-505, so no claim that the lane beats the pipeline, preserves page precision or says anything about CIT-U research is supported
