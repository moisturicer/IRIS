## IR-1220

**Requirement:** **An office's supplementary file is PDF, Word (.docx), PNG or JPG; any other type, or a file whose bytes are not what its name says, is refused and not stored.** [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §10, *Amendment, 2026-11-18*, with Ashlee Sean's security review named. Subtask 7 of IR-1199; no FR- id. Decided by Hermoine Zozobrado on 2026-11-17; `.doc` dropped by her on 2026-11-18, after the code review.

**Cause:** `RecordFileUploadView` (`POST /documents/files/upload/`, `attach_file`) was the one upload in IRIS that took any type. It ran the PDF safety check only on a file that claimed to be a PDF, so an SVG, which can carry script, or an executable was stored as uploaded.

**Implementation:**
- `documents/validators.py`: `supplementary_file_problem(file)` names why a file is refused, or returns `None`.
  - The extension picks the expected first bytes: the PDF header within the first kilobyte, the PNG and JPG signatures.
  - Word is `.docx` only. A Word 97-2003 `.doc` begins with the same OLE2 header as `.xls`, `.ppt` and a Windows installer (`.msi`), so its bytes cannot show it is a document. The code review found an installer renamed `.doc` was accepted.
  - A `.docx` must be a zip holding `word/document.xml` and no `word/vbaProject.bin` (`_is_safe_docx`). Only the zip's directory is read, nothing is decompressed. A plain ZIP, or a document with macros, under a `.docx` name is refused.
  - A PDF then gets `pdf_upload_problem`, the safety check every PDF upload has.
  - The refusal is *"Only PDF, Word, PNG or JPG files are accepted."*, and an empty file gets it too.
- `documents/views.py`: `RecordFileUploadView` calls it once, before anything is stored, and answers a refusal with a 400 carrying the message in `file` and `detail`.
- `is_pdf_upload` is removed. It was used only here, and its rule ("general attachments retain their formats") is the one this ticket reverses.
- `DocumentsTab.tsx`: the attach control's `accept` is `.pdf,.docx,.png,.jpg,.jpeg` with `validate`, so another type is refused before it is sent. Its hint reads "PDF, Word (.docx), PNG or JPG." in place of "Any file type." The server's check is the one that counts.
- Stored files are not touched: the rule applies at upload. The *Download all* ZIP is built by IRIS and is unaffected.

**Test:** `documents/tests/test_supplementary_file_types.py`, at the HTTP route, as an office taking part (RDCO):
- Accepted, 201: `.docx`, `.png`, `.jpg`, `.JPEG`, each with its own bytes, and a real PDF after its safety check.
- Refused, 400 with the message, and no `RecordFile` stored: `.svg`, `.exe`, `.zip`, `.txt`, a file with no extension, a `.doc`, an `.msi`, an OLE2 file named `.docx`, a PNG named `.pdf`, a PDF named `.png`, an SVG named `.png`, a ZIP named `.docx` and `.doc`, a PNG named `.jpg`, a `.docx` carrying macros, and an empty file.
- Written before the code: 14 failed, the 5 Word, PNG and JPG cases passed, since nothing was refused then. After the review, the `.doc` case moved to the refused list and failed until `.doc` was dropped.

Three existing tests changed deliberately, each with a comment saying why:
- `test_accepted_source.py`: `test_general_attachment_non_pdf_policy_is_unchanged` asserted a `.txt` file was accepted. It is now `..._is_word_png_or_jpg`: a PNG is accepted, and the `.txt` is refused.
- `test_record_document_authorization.py`: two `_attach` helpers posted `memo.txt`. They test who may attach, not the type, so they post a PNG memo.

`DocumentsTab.test.tsx`: "lets an office attach a file of any type" is renamed "...attach a Word file". A new test checks the control names the four types, refuses `diagram.svg` and `minutes.doc` before sending them, and sends a `.JPG`. It failed before the control changed, and again before `.doc` left `accept`.

**Runs (2026-11-18, Windows, throwaway pgvector container):**
- `test_supplementary_file_types.py`: 21 passed. The PDF case fails locally with "PDF checking is temporarily unavailable": the PDF check needs Linux, as it does on `main` (see the local test notes). CI runs it on Linux.
- `test_record_document_authorization.py`, the `test_accepted_source.py` test above and `records/test_capabilities.py`: all pass except 12 subtests on the PDF-only `submit/` and `uploads/create/` routes. The same 12 fail on an untouched `main` worktree, for the same Linux-only reason.
- `apps/tests/test_access_matrix.py` and `test_enum_vocabulary.py`: 40 passed.
- `DocumentsTab.test.tsx`: 23 passed.

**Review:** a standards and a spec review, on the first commit.
- **Fixed:** an installer renamed `.doc` was accepted, since the OLE2 header is shared; `.doc` is dropped (Hermoine's choice (a)). `_docx_problem`, a bool among functions returning messages, is now `_is_safe_docx`. The ADR's "for the whole of IRIS" now reads "for every file IRIS stores", naming RDCO's import spreadsheet, which is read and never stored.
- **Left:** non-PDF attachments have no size limit, as before this ticket. The PNG signature is written in three modules. The PDF test is not skipped off Linux, like the repo's other PDF upload tests.
