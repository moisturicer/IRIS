## IR-639

**Requirement:** **The import template, uploaded unchanged, imports nothing.** Found by Lee Jasmin Adolfo in IR-315's review (PR #318). The import publishes with no review, and the template's example row became a published paper, as did its notes row, a paper titled "Required". Labelled FR-M2-04 (bulk import from a template).

**Design:** Jira IR-639 (no ADR; decided 2026-10-29).

**Implementation:**
- **The template** (`download_template`, `apps/records/views.py`) has two sheets:
  - **"Records"** is first and holds only the header row. Staff type one paper per row under it.
  - **"How to fill this in"** has the same headers in the same columns. Under them are the example row, what each column takes, and every name the Record Type, Classification, PSCED Classification and Origin columns accept, one per row.
  - The names are read when the template is downloaded, through `ImportChoices`, the same lookup the importer uses; Origin comes from `Record.Origin`. So the names can't go stale or be misspelled.
  - The example row's Classification and PSCED are this database's first names, and its Record Type is `Thesis / Research` when it exists. Before, it hard-coded "Applied Sciences" and "Information and Communication Technologies", which `seed_demo` never creates, so a copied example was skipped (the limitation IR-638's record names).
  - The template no longer ends in `END OF RECORDS`.
- **The importer** (`parse_excel_import`, `apps/records/services.py`) reads only the first sheet, by asking for it (`sheet_by_index(0)`) rather than relying on pyexcel's default. It still stops at an `END OF RECORDS` row that staff add.
- **The Import Records page**'s "Fill it in" step says to type under the headers on the Records sheet, and that the instructions sheet is never imported. It no longer mentions "a merged cell containing END OF RECORDS". Each step card is now a section named by its heading.
- **Supersedes** IR-638's note that the template's notes row "is now skipped": it is no longer on the sheet that is imported. IR-638's record says so.

**Tests:**
- `apps/records/test_excel_import.py`:
  - **`test_the_template_uploaded_unchanged_imports_nothing`:** downloads the template through `GET /records/download_template/` and uploads it unchanged through `POST /records/import_excel/`. Zero records are created and zero rows skipped.
    - **Changed deliberately:** it replaces `test_the_template_imports_its_own_sample_row_and_not_its_notes_row`, which required the example row to import. That is the behaviour this ticket removes.
    - **Before:** it failed, `(1, 1) != (0, 0)`. **After:** passed.
  - **`test_the_records_sheet_comes_first_and_holds_only_the_headers`:** the sheets are "Records", then "How to fill this in", and Records has one row.
  - **`test_the_instructions_sheet_has_the_example_and_every_name_the_import_accepts`:** adds a new Record Type, Classification and PSCED name, downloads the template, and finds each under its column, beside the stored `Thesis / Research` and the Origin value `imported_reference`.
    - **Before:** it failed on all four names. **After:** passed.
  - **`test_the_example_row_copied_onto_the_records_sheet_imports`:** on a database holding only "Maritime Studies" and "Fisheries Science", the example copied onto Records imports as one record with those names.
    - **Before:** it failed, `(0, 1) != (1, 0)`: the copied example was skipped. **After:** passed.
  - **`test_only_the_first_sheet_is_imported`:** a workbook with a paper on its second sheet imports nothing.
  - **`test_rows_after_an_end_of_records_row_staff_add_are_not_imported`.**
  - **Mutation check:** with the importer briefly made to read the last sheet, the first-sheet test and the round-trip test both failed; restored, they pass.
- `frontend/src/features/records/ImportRecordsPage.test.tsx`, **"says where to type and that the instructions sheet is never imported":** the "Fill it in" region names the Records sheet and the "How to fill this in" sheet, says it is never imported, and no longer mentions a merged cell.
  - **Before:** it failed (no region named "Fill it in"). **After:** 7 of 7 passed.
