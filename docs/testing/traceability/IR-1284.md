## IR-1284

**Requirement:** A comment, reply, resolve, reopen, severity change, answer or edit in a record's review discussion appears on every open page of the people who may read that review, without a refresh. It never reaches anyone `may_read_review` refuses. A draft reaches only its writer's own tabs.

**Design:** [ADR-073](../../adr/073-live-updates-by-server-sent-hints.md) §Amendment 2026-11-23, **Proposed**, not yet accepted.

**Implementation:**

- **Backend:**
  - `apps/live/signals.py`: `post_save`/`post_delete` on `ReviewComment`. A sent comment calls `review_changed(record_id)`, which works out the readers on commit (`apps.reviews.mentions.candidates`, i.e. `may_read_review`) and publishes `record:<id>` to each one's `live:user:<id>`. A draft publishes only to its author.
  - `apps/reviews/finish_review.py` and `apps/reviews/threads.py` (`close_by_decision`): their `update()` calls send no signal, so they call `review_changed` themselves.
- **Frontend:** `features/records/paper-view/threads/useReviewThreads.ts` uses `useLiveRefresh([record:<id>])` to refetch quietly on a hint, a reconnect or focus. A failed quiet read keeps the list it shows.

**Test:**

- `backend/apps/live/test_review_hints.py` (9): Conversation comment, reply, office pool member, resolve/reopen, answer, a draft's save and delete told only to its writer, Finish review, a Decision closing threads, and a refused comment telling nobody. Every case checks that no outsider and no role channel is told.
- `frontend/src/features/records/paper-view/threads/useReviewThreads.test.ts` (4): refetch on its own record's hint and not another's, on focus, keeping the list when a quiet read fails, and doing nothing while disabled.

**Evidence:**

- **2026-11-23, locally:** the new frontend file passed (4 tests), and the existing `threads/` tests passed alongside it.
- **Not run locally:** the backend tests (they need Postgres; CI is the record).
- **Not tested by hand in a browser yet:** an Adviser and a student on two screens.
