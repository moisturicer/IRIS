# IR-1188: Discover: one filter panel holds filters and Areas

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Areas and reset behaviour are ADR-062's (IR-567, IR-576); this changes where they are reached, not what they do.

## What changed

- **One Filters control.** The toolbar's Areas button and its "Choose areas for your recommendations" modal are gone. The Filters panel (`DiscoverFilterBar.tsx`) now has two sections, each under a plain heading: **Filter the list** (type, college, classification, year range, IP) and **Your Areas** (`DiscoverAreas.tsx`).
- **Areas behave as before**: the same choices, Save Areas (which switches to Best and closes the panel, as saving closed the modal), Clear areas (clears the unsaved selection), and Reset my interests with its confirmation and wording. A save or reset failure keeps the panel open with the same message. Closing the panel abandons a half-made reset confirmation, as closing the modal did, and a reset still running when the panel is reopened shows "Resetting…" disabled rather than a second Reset.
- **The Areas section shows when Areas fail to load.** Before, a failed read left no Areas button at all, so its message ("Areas couldn't load…") could never be seen. Now the section is drawn with that message and Save disabled. With no Areas to choose and no failure, the section is still left out (IR-1082).
- **"Clear all" is now "Clear filters"**: with Areas in the same panel, "all" would suggest it clears them too. It clears only the catalogue filters; Areas are saved separately and are not counted on the Filters badge.
- **The panel is modal while open**: it uses the shared `useDialogFocus` (as `Modal` does), so focus moves to Close, Tab and Shift+Tab stay inside, Escape closes it, and focus returns to the Filters control. A click outside still closes it. The dropdowns inside already stop their own Escape in the capture phase, so Escape on an open list closes only that list.
- **Width.** Phones keep the sheet inset 16 px each side (`inset-x-4`, 328 px at 360 px wide) with `overflow-x-hidden`; Area choices are one column at every width and long names wrap. On `sm` and up the panel is 24 rem (was 22 rem) and its height cap rose to 40 rem, since it now holds more.

## Tests

`DiscoverPage.test.tsx`:

- Saving classification and PSCED Areas from the panel calls the same API and opens Best, then closes the panel.
- A save failure shows "Areas couldn't be saved" in the panel, which stays open.
- A load failure shows "Areas couldn't load" in the panel with Save disabled.
- The panel holds "Filter the list" and "Your Areas" headings, and no Areas button remains in the toolbar.
- Clear filters clears a type filter but leaves a saved Area checked and calls neither update nor reset.
- Tab (30 presses) and Shift+Tab stay in the panel, which opens with focus on Close (`pretendLaidOut`, as other dialog tests do, because jsdom has no layout).
- Escape closes the panel and focus returns to the Filters control.
- At phone width: the panel's inset and `overflow-x-hidden` classes (jsdom lays nothing out, so classes are what is checked).

**Existing tests changed deliberately**, because they opened the Areas button or modal: the save test; the three reset tests (now opened through the panel; after a reset the Area is unchecked instead of the button reading "Choose areas"); "hides Areas until there are Areas" (now checks the panel has no Areas section); the phone-toolbar counts (buttons 4→3, and 3→2 for an office reviewer, Areas removed from the named list and the visible-text check); and the two "Clear all" clicks, now "Clear filters".

`e2e/specs/07-discover.spec.ts` (Playwright, core journeys): its "Clear all" click is now "Clear filters", and the filters journey ends by opening the panel and running the 360 px reflow check on it (`discover-filters-panel`), which measures real layout. Not run locally: the e2e dependencies are not installed here, so this is CI's to run.
