# IR-975: My Templates, Advisers share proposal Templates

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Story IR-969. [ADR-063](../../adr/063-rdco-sets-requirements-and-templates.md) decision 8 (Advisers' Templates), with decisions 10 (plain-text descriptions) and 11 (every change audited, downloads not), and its Security Impact (My Templates is the Adviser's own; every route is in the access matrix). [ADR-074](../../adr/074-uploads-scanned-for-malware.md) for the scan.

## What changed

- **`AdviserTemplate`** (`apps/documents/models.py`, migration `documents/0028`): an owner, a title (at most 200 characters), a plain-text description (at most 2,000), one current file with its display name, and a position. A file is required.
- **The Adviser's own API**, `IsAdviser` before any lookup, in `adviser_templates.py` and `adviser_template_views.py`. Each change looks the Template up among the caller's own, so another Adviser's Template is a 404 identical to a missing one. RDCO is refused by the role gate. **RDCO cannot remove an Adviser's Template.**

  | Route | Does |
  |---|---|
  | `GET my-templates/` | the Adviser's own, in their order |
  | `POST my-templates/` | add (multipart `title`, `description`, `file`), at the end |
  | `PUT my-templates/order/` | reorder; must name each of theirs once |
  | `PATCH my-templates/<id>/` | edit the title or description, or replace the file (multipart `file`) |
  | `DELETE my-templates/<id>/` | remove it, and its file once that commits |

- **Shown to anyone signed in:** `GET adviser-templates/[?shared_by=<user id>]` and `GET adviser-templates/<id>/file/`. Both read one predicate, `shown_templates`: the owner is in `open_profiles()` (active, not locked, verified, not deleted) **and** holds the Adviser role. A suspended, locked or deleted Adviser, or one who is no longer an Adviser, shows none everywhere, and their download is the same 404. The rows are kept, so a lifted suspension shows them again. A download is always an attachment with `nosniff`, and only the newest file is offered.
- **File rules:** the same as Setup's Templates (`template_problem`: PDF, Word, spreadsheet or image up to 50 MB, with the extension and the first bytes agreeing). **Then the malware scan** (`upload_problem`, `where="my_template"`). A flagged or unscanned file is refused, stored nowhere and audited as `UPLOAD_REFUSED_UNSAFE`. A flagged replacement keeps the old file.
- **Setup's Templates are now scanned too** (IR-971's gap). RDCO's Setup Template uploads never called the scan: IR-666's guard only looked for modules calling the PDF check, and Templates have their own. `setup.py` now scans before the change's transaction (`where="setup_template"`). A second guard fails any module that calls `template_problem` without `upload_problem`. Setup's "delete the old file after commit" helper moved to `template_files.drop_file_after_commit`, shared by both.
- **Audit** (decision 11): `ADVISER_TEMPLATE_ADDED`, `ADVISER_TEMPLATE_CHANGED`, `ADVISER_TEMPLATES_REORDERED`, `ADVISER_TEMPLATE_REMOVED` (migration `audit/0034`). Descriptions are recorded as character counts, never their text. See `docs/evaluation/AUDIT_EXPORT.md` §My Templates.
- **Account deletion:** `documents.AdviserTemplate.owner` is declared KEEP in `accounts/deletion/registry.py`. A deleted Adviser's Templates stop showing through `shown_templates`; the rows and files stay.
- **Client:** `/my-templates` (`features/myTemplates/MyTemplatesPage.tsx`, `api/myTemplates.ts`), with a sidebar link "My Templates" in Main for Advisers only, after My Reviews. Each Template shows its title, its description (links clickable, `PlainTextWithLinks`) and a download. Each has Edit, Replace, Move up/down and Remove, which confirms first. Adding asks for the title, the description and the file.
- **Not in this card:** showing the Templates on Guidelines (IR-974) and pointing out the chosen Adviser's in Publish (IR-973).

## Tests

- `backend/apps/documents/tests/test_adviser_templates.py` covers:
  - adding (the title, description and file name come back; the order follows when each was added);
  - a missing title or file is refused, as is every kind of file Setup refuses (wrong type, wrong bytes, empty);
  - a flagged file is refused, stored nowhere and audited;
  - editing is audited without the description's text; replacing offers only the new file; a flagged replacement keeps the old one;
  - reordering, and an incomplete or repeated order refused;
  - removing (its download then 404s) is audited;
  - RDCO and another Adviser can neither change nor remove one, and another Adviser's list and order never include it;
  - anyone signed in sees and downloads an active Adviser's, as an attachment;
  - a suspended, locked, deleted or no-longer-Adviser owner shows none, in the list or the download, and shows them again once restored;
  - only an Adviser reaches My Templates.
- `backend/apps/documents/tests/test_upload_scanning.py`:
  - a flagged Setup Template is refused, stored nowhere and audited as `setup_template`;
  - a Setup Template is refused while the scanner is down, and a clean one is stored;
  - every caller of the Template check also scans.
- `backend/apps/tests/access/table.py`: the five new routes, every role (`ADVISER_ONLY` for `my-templates/`, signed-in for `adviser-templates/`).
- `frontend/src/features/myTemplates/MyTemplatesPage.test.tsx`, through the accessible tree, with axe:
  - the list in order, with clickable links and the download;
  - the empty state;
  - adding sends the title, description and file;
  - a missing title or file is asked for before anything is sent;
  - the server's refusal is shown;
  - editing, replacing, moving and removing (after confirming).
- `frontend/src/router/roleNavigation.test.tsx`: it opens for an Adviser, and is refused for RDCO and a Student.
- `frontend/src/lib/access.test.ts`: only the Adviser may open it or has the link.
- **Smoke tier:** a new `Adviser` smoke role; a `my-templates` screen in `e2e/smoke/support/screens.ts` with a long title and file name; a dialog case "remove one of my Templates".

## Evidence

All run locally on Windows on 2026-11-19, against a throwaway `pgvector` container.

- **Backend:** these pass:
  - `test_adviser_templates.py` (17);
  - `test_access_matrix.py` (every app), `test_enum_vocabulary.py`, `accounts/test_account_deletion.py`: 80 in all, with the 17;
  - `test_setup_requirements.py`;
  - the new Setup scan tests and both scan guards;
  - `test_record_versions.py`'s file-deletion guard.

  In `test_upload_scanning.py`, 3 PDF tests fail locally with "PDF checking is temporarily unavailable". That is the known Windows-only failure: `pdf_inspection.py` needs the Unix-only `resource` module. CI runs them on Linux.

  `manage.py check` passes, `makemigrations --check` finds no drift, and `flake8 apps/ config/ core/ testing/` is clean.
- **The new tests were checked against broken code.** Two deliberate breaks, then reverted, made 5 tests fail:
  - `shown_templates` filtering on the role alone, which would show a suspended or deleted Adviser's Templates;
  - `own_template` looking among everyone's Templates.
- **Migration on a realistic database:** a copy of one developer's dev database (18 Records, 42 slots, 19 accounts).
  - Every pending migration applied, including `audit/0034` and `documents/0028`.
  - `migrate documents 0027_starting_requirement_labels` and `migrate audit 0033_setup_requirements` reversed both cleanly, and the table was gone.
  - Forward again applied both. Records and slots were unchanged throughout.
  - `makemigrations --check` reports no changes. The copy was dropped.
- **Frontend:**
  - `tsc --noEmit` and eslint are clean on the changed files, and the e2e `tsc --noEmit` is clean.
  - `vitest run` passes on the page, access, role-navigation, viewport-matrix and layout tests (10 files, 195 tests).
  - The smoke tier, run against a production build, passes for the new screen (49 tests): the viewport matrix at 360, 768, 1280 and 1745 px, full text at three widths, the route, dialog and forced-state coverage guards, and the Remove dialog's axe scan.
- **Not done:**
  - no person has used the page in a browser;
  - no Adviser has shared a real Template;
  - Guidelines and Publish don't show the Templates yet (IR-974, IR-973).
