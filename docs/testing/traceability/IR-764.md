## What changed

- **The form** (`OpportunityFormDialog.tsx`, `opportunityUtils.ts`):
  - Choosing **Journal or Book Chapter** hides the start and end dates and fills an empty location with "Online", which the poster can change; a typed location is kept (`withType`). Such a Call is sent with no event dates (`inputFrom`); dates typed before the switch stay hidden in the draft, so switching back restores them.
  - An edit the server says will send a confirmed Call back to RDCO (`edit_returns_to_pending`) says so at the top of the sheet before saving.
  - **Feature this call** is offered only to someone who may feature: the Call's own `can_feature` on an edit, and the board's `can_feature` on a new Call. The board takes it from the list's `can_review_requests`, true for RDCO alone (IR-762). The server ignores Featured from anyone else either way.
  - The fields, the optional markers and the removed fields are IR-760's, unchanged.
- **Each row** (`OpportunityRow.tsx`) shows type, title, about, the event's dates ("Event: Jan 20, 2027 to Jan 22, 2027", one date for a one-day event), location, the fee when given, Areas, the link and Posted by, with the Featured star and label.
- **Two tags** in words, as the server wrote them: the papers tag ("Accepting papers", with the days left, or "Submissions closed") and "Happening now" only while the event runs. "Upcoming" and "Over" are never shown; an Over Call has left the board.
- **Filters:** All and one per type, a new **Area** filter (every Area named on the board), search and Saved. A row with no link shows no link and no "Ask the office" line.
- **Order:** Featured no longer breaks a tie between Calls due the same day. The board stays grouped by how soon papers close, with **Submissions closed** last (by `papers_state`, not the day count).
- **Wording:** the empty board, the summary line ("3 calls accepting papers, 1 with submissions closed") and the Help page describe calls for papers, not funding.
- **Feedback without layout shift:**
  - A calendar file that can't be built is an error **toast** naming the Call, with **Try again**, that stays until acted on. It was a line that grew inside the row.
  - A save that fails is a toast, not a box at the top of the sheet: a refusal no field owns, a 403/404, or a failure to reach the server, which offers **Try again** and resubmits the still-open form. Field errors stay under their fields.
  - A delete that fails closes the question and is a toast; Try again repeats the delete the reader confirmed.
  - A post or edit that waits for RDCO leaves the board, as a reload would show, with the toast "Call sent to RDCO. It appears on the board once RDCO confirms it."
  - The shared toast gains an optional `action` (`ui.store.ts`, `Toast.tsx`), and a toast that carries one never leaves on its own; no other screen's toasts change. DESIGN.md §Toasts records the rule.
- **Delete** is offered only where the server says plain delete is allowed (`can_delete`). It followed `can_edit`, so RDCO saw a Delete on an Adviser's Call that the server refuses: removing one takes a reason (`can_remove`), which IR-765 offers.
- **Area filter** goes by the Area's name, as the rows show it; Classification names are unique.
- **Not in this card:** saved Calls still live in the browser (`lib/opportunityLibrary.ts`) until IR-766 moves the Saved filter to the account. RDCO's Call Requests page and an Adviser's view of a waiting Call are IR-765.
