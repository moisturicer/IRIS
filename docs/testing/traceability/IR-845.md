# IR-845 — Figures from LlamaParse: stored, and served only to permitted readers

**Affected requirement labels:** FR-M3-01 (PDF text extraction). Its matrix status does not change: Docling, which returns no Figures, stays the configured Extractor until IR-842.

[Back to the matrix](../TRACEABILITY.md)

**Design:** [ADR-056](../../adr/056-manuscript-extraction-moves-to-llamaparse.md) decisions 9 and 12.

**Implementation:**

- **Storage.** `ExtractionFigure` (`apps/documents/models.py`, migration `documents/0020`, additive) holds one Figure per row: its Extraction, the Manuscript `source_revision` it was cropped from, page, the vendor's page-point box, the printed caption (blank when there is none, so uncaptioned Figures are kept), media type and the image. Images go to default storage under `figures/`, which nothing serves directly since IR-152.
- **Writing.** `apps/documents/figures.py::replace_figures` runs in the task's final locked transaction (`apps/documents/tasks.py`), so a stale or superseded attempt writes nothing. It replaces the Extraction's whole set, for Manuscripts only. A supplementary upload is never chunked, so its Figures have no use. The media type is the vendor's word: an image is kept only when its bytes are the PNG, JPEG, GIF or WebP it claims to be.
- **Clean-up.** `reset_manuscript` drops Figures from any other revision at the same point it deactivates their ChunkSets (`remove_superseded`). A revision awaiting submission is not read yet, and readers are still served the submitted Manuscript, so the submitted Figures stay, as its chunks do (IR-273). A `post_delete` receiver removes each image after commit, so a new read, a replaced Manuscript, a removed one and any cascade all take their files.
- **Serving.** `GET /records/<id>/figures/<figure_id>/` (`RecordViewSet.figure`). `get_object()` resolves through `visible_to`. The Figure must belong to that Record and to the revision this reader is served (`versions.served_manuscript_revision`). Every refusal is the 404 of a missing record, and the endpoint takes an id, never a path. Responses are `inline`, `private, no-store` and `nosniff`. ADR-025's crop-on-request is not built.
- **Answer images.** `strip_images(answer, handed=...)` keeps an inline image only when IRIS handed the model its address. This is ADR-056 §12's "no image the system did not hand you". No caller passes an address until IR-293, so answers and AI Overviews still lose every image, as before.

**Tests:**

- `apps/documents/tests/test_extraction_figures.py`, at the extraction task and `reset_manuscript`: storage with page, box, caption and revision; an uncaptioned Figure kept; non-image bytes and a mismatched type dropped; a new read replacing the set and its files; a new revision removing the old Figures and files; a revision awaiting submission keeping them; a removed Manuscript taking its images.
- `apps/records/test_figures.py`, over HTTP: the owner, the assigned Adviser and RDCO get the image; an unrelated Student gets a 404 identical to a missing record's; a Figure reached through another Record's URL and one from a replaced revision both 404; while a revision awaits submission, the Adviser sees the submitted Figures and the owner, reading the unread revision, does not.
- `apps/ai/answers/tests/test_citations.py::ImageStrippingTests::test_only_an_image_the_system_handed_over_survives`.

**Evidence:** run 2026-11-03 in a container built from this branch (`backend/Dockerfile`, `development.txt`) against a throwaway pgvector Postgres, with CI's dummy secrets. Each file above passes alone, as does `apps/ai/overview`. Migrations `documents/0017`–`0020` were applied to a copy of a developer's dev database (2 extraction rows, last at `documents/0016`): every migration applied and no row changed. The full suite runs in CI.

**Not verified:**

- **No recorded figure image.** IR-849's four PDFs draw vector shapes and LlamaParse returned no crop (`fixtures/llamaparse/OPEN_CONDITIONS.md`). The tests use real PNG bytes in IR-841's documented shape. Recording a PDF with a raster figure needs the project owner's development key and spends credits. **This acceptance criterion is open.**
- Image files are written inside the locked transaction. If that transaction rolls back after the write, the file is left behind without a row.
- No real worker or browser was used.
