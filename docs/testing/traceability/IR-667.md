## IR-667

**Requirement:** System settings are readable and writable by RDCO only; a PATCH cannot create a key; every change is audited

**Design:** Jira IR-667 (spec IR-655); ASVS 4.0.3 item 4.1.3

**Implementation:** `SystemSettingView` requires `IsAdmin` on both methods. PATCH on a missing key is 404, needs a text `value`, and writes `SYSTEM_SETTING_CHANGED` with key, old and new value in the same transaction. Migration `audit/0010` adds the choice

**Test:** `apps/accounts/test_system_settings.py` through the API, plus the authorization matrix's `system-setting` entry, deliberately changed from signed-in to RDCO-only. Before the fix 6 tests failed

**Evidence:** 2026-10-31, local Docker: `apps/accounts apps/audit apps/tests` 294 passed, 11 skipped

**Status:** **IMPLEMENTED**
