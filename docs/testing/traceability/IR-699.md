## IR-699 — Settings: profile fields and a circular photo crop

**Basis and scope.** IR-699 (spec IR-694). Settings & Profile's Profile tab gains an **About you** panel: a photo upload that opens a crop dialog previewing a circle (zoom slider, drag, arrow keys), Remove photo, a bio with a 500-character counter, up to 10 research interests with suggestions, an ORCID iD checked as you type (format and ISO 7064 checksum, `src/lib/orcid.ts`), and **View my profile**. The API calls live in one module, `src/api/profile.ts`, built to the draft contract posted on IR-695 (Jira comment 10912), which Hermoine Zozobrado has not yet accepted. The crop's arithmetic is `src/lib/photoCrop.ts`; the server cuts the photo from the original file and the framed square (`crop_x`, `crop_y`, `crop_size`).

**Not yet true end to end.** IR-695 has not shipped, so the backend ignores these fields today and the photo endpoints do not exist. **View my profile** links to `/people/<id>`, which IR-700 builds. This must not merge before IR-695, and the path is IR-700's to confirm.

**Tests.** `src/lib/orcid.test.ts` (ORCID's own published iDs, an `X` check digit, lowercase `x`, malformed forms, a checksum mismatch), `src/lib/photoCrop.test.ts` (worked examples on a 1000 × 500 photo: centred, zoomed, dragged to an edge, dragged past it, zooming about the centre) and `src/features/settings/SettingsProfileFields.test.tsx` (13 cases through the accessible tree with axe: counter, interests add/suggest/remove/limit/duplicate, live ORCID refusal, what Save sends, clearing ORCID to `null`, the server's field message, the profile link, crop-and-upload, arrow-key framing, the server's photo refusal, Remove photo).

**Review and executed evidence (2026-11-01).** A two-axis review (Standards, Spec) found the first version broke DESIGN.md's Named Size Rule, colour rule and shared-button/focus rule, showed only the first refused field, and left Save disabled with no reason while an ORCID iD was half-typed. Fixed: the new panel uses `FieldLabel`, `fieldClasses`, `FieldError`, `PILL_PRIMARY`/`PILL_SECONDARY` and `FOCUS_RING`; errors are maroon and `role="alert"`; `fieldError` joins every named field, including a list's per-item messages; the ORCID message shows as soon as the iD is invalid. Settings' shared `Panel` now titles each section in sentence case at `text-heading`, so the existing panels' titles change with it; their bodies are untouched. Then `npx vitest run settings orcid photoCrop errorDetail`: 5 files, 53 tests passed, including the existing Settings password and consent tests; `palette.test.ts` and `typeScale.test.ts`: 20 passed. `tsc --noEmit` passed; eslint on every touched file reported nothing. The full suite is left to CI. Two test expectations were corrected deliberately: the arrow-key case first assumed a 200 px crop square, but the dialog's is 256 px, so the expected `crop_x` is 270, not 275; and a refused save is now asserted as an `alert`, not a `status`, to match the photo errors.

**Recorded, not fixed here.** `docs/engineering/DEVELOPMENT.md` §5 still says there is no `npm test`, which contradicts CLAUDE.md (vitest, IR-210). For IR-695 to confirm: whether the server applies a JPEG's EXIF orientation before cutting the crop, since the browser shows it rotated.

**Status.** **PARTIAL** until IR-695 ships and the contract is accepted.
