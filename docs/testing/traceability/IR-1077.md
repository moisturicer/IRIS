# IR-1077: Users: row actions in a menu, Lock behind a confirm that names the person

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Audit finding CMP-01 ([`frontend_ui_audit_spec.md`](../../frontend_ui_audit_spec.md) §4.10, user story 16).

## What changed

- **One "⋯" menu per user row** (`features/accounts/RowMenu.tsx`) replaces the row of buttons. The trigger is named for the person (`Actions for Ada Viser`, or the email when there is no name) and carries `aria-haspopup="menu"` and `aria-expanded`; the list is `role="menu"` with `menuitem`s. It opens onto its first item; ArrowUp/ArrowDown, Home and End move; Escape, Tab, a click elsewhere, a scroll or a resize close it. Choosing an item puts focus back on the trigger before the item's dialog opens, so the dialog returns focus to a control that still exists. It is drawn in a portal at the trigger's edge because `DataTable` clips overflow.
- **No filled destructive button.** *Lock* is a menu item in maroon text; *Unlock*, *Change role* and *Make/Remove coordinator* are plain items. Which items a row carries is unchanged: `accountActions.ts` still mirrors the server's rules (ADR-051 §4-5, amended, IR-781).
- **Lock asks first and names the person.** Title `Lock Ada Viser's account?`, body `Ada Viser (adviser@cit.edu) will be prevented from logging in until the account is unlocked.` Unlock names them too. Cancelling calls nothing and returns focus to the row's menu. The confirm button shows the dialog's in-flight state while the request runs, so a second press cannot send a second request.
- **No actions on your own row.** `rowActions(viewer, viewerId, target)` returns nothing when `target.id` is the signed-in user's id, whatever the role rules would allow; the row then renders no menu at all, as for a System Admin's row.
- **Name first, email under it.** The Email and Name columns are one *User* column.

## Tests

- `features/accounts/UserListPage.test.tsx` (by role and accessible name): every row has a menu named for its person and no row has a loose *Lock*/*Unlock*/*Change role* button; Lock opens a dialog naming the person and calls nothing; cancel calls nothing and returns focus to the menu trigger; confirm calls `setLocked(id, true)` once and reloads the list; Unlock names the person; a person with no name falls back to the email; the viewer's own row has no button; the name sits first and the email under it; axe finds nothing serious with a menu open and on the Lock dialog. The earlier coordinator, change-role and per-viewer tests now open the menu first.
- `features/accounts/RowMenu.test.tsx`: closed by default, then named and listed; first-item focus and arrow/Home/End movement; Escape, outside click and Tab close; choosing runs the item once and returns focus to the trigger; a destructive item has no filled background; nothing renders for no items; axe open and closed.
- `features/accounts/accountActions.test.ts`: `rowActions` for RDCO, the System Admin, a System Admin's row, the viewer's own row and other viewers.
