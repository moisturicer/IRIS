# IR-1055 — Section-mate expansion

**Affected requirement labels:** none change status. Part of IR-980; ADR-033 §4, amended 2026-11-15.

[Back to the matrix](../TRACEABILITY.md)

**Implementation:**

- `ai/research/selection.py`: after IR-397 chooses the hits, each hit's neighbours up to two chunks away are added when they and every chunk between share the hit's `section_key`, nearest first and every hit in turn, while the budget holds. A chunk set with no section keys gets none.
- `ai/research/tools.py`: neighbour rows are read under the reader's grant through `research_chunks()`, which exposes `section_key` since IR-397's `iris_ai` migration `0019`. A mate is marked `section_context` for the agent and `continues` the passage before it; it keeps its own handle, page and regions.
- On by default by owner decision (ADR-033 amendment); `RUNS_SECTION_MATES=off` switches it off.

**Tests:** `ai/tests/test_passage_selection.py` (section boundary, budget, contiguity, fairness, switch), `backend/apps/ai/tests/test_ir1055_section_mates_db.py` (through the run routes as the runtime login).

**Evidence:** 2026-11-15, Windows 11 host: `ai/tests/test_passage_selection.py` 21 passed; `test_ir1055_section_mates_db.py` and `test_ir397_passage_selection_db.py` 6 passed. The full suite is left to CI on the PR.

**Not done:** the ticket's harness run with and without expansion (final-set recall and token cost) is not recorded: the eval harness measures Django's retrieval stack, not the runtime's search, where this was built by decision. Citation-overlay tests are not touched by this change; CI runs them.

**Status:** Partial; CI and human review pending.
