## IR-1330

**Requirement:** **On the review page's Documents tab, each version of a document is downloaded from its own row in the versions list, and from nowhere else.** No FR- id; requested by Hermoine Zozobrado, 2026-11-24.

**Before:** a document with a file, such as Patent Draft, showed a **Download** for its newest version under its name. The versions list ("4 versions") also had a Download on every row, so the newest version had two buttons for the same file.

**Implementation:** `DocumentsTab.tsx` drops the Download from the actions under a document's name.
- With the list closed, a document shows its newest version's line ("v4 · Sam Student · Nov 22, 2026") and the versions toggle. Downloading means opening the list first, which was accepted on 2026-11-24.
- Unchanged: Upload and the held-upload Remove under the name, each version's Download and Remove, the manuscript's row, and Supplementary attachments.

**Test:**
- `DocumentsTab.test.tsx`: new test "downloads each version from its row in the list, and nowhere else". With the list closed, the document has no Download. Opened, it has exactly one per version.
- Changed deliberately, because they clicked the removed button: "shows a file in a slot nobody asked for with no Upload", the two "downloading a document version" tests in `DocumentsTab.test.tsx`, and "is the reviewers' first tab" in `PaperViewPage.test.tsx`. Each now opens the versions list first, then checks the same Download.

**Evidence:** 2026-11-24, local.
- Before the change, all four tests failed. The opened list found two Download buttons with the same name.
- After it, `npm test` passed: 255 files, 3803 tests. `tsc` and `eslint` are clean.
- No e2e test refers to the removed button.
- Before-and-after screenshots from the smoke build show Patent Draft with 4 versions and Ethics clearance with 1, closed and opened.

**Status:** **IMPLEMENTED**; awaiting CI and review.
