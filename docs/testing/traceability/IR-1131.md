# IR-1131: The Review workspace looks like the prototype

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Follows IR-1094, which fixed the workspace's layout; this ticket is its visual layer, matched to `iris-uiux-audit/prototype` (the Review workspace screen). Thesis-critical: the workspace is where clearance-aware resubmission is read and decided. Frontend only: every string and count comes from data the API already sends (`RecordVersion.created_by_name`/`created_at`, `ReviewComment.party_label`/`is_draft`, `RecordTracker.clearance_strip`, `turnLine`).

## What changed

- **White panes** (`reviewWorkspace.css`): the workspace, pane and right column are white; only the pane head and the right column's head sit on stone-50.
- **Header** (`ReviewWorkspaceLayout.tsx`): one row with the heading, *Take a tour* and (as a drawer) *Back to paper*; a second row with the holder as a "With …" pill and who sent the current version and when ("Ana sent v2 · 3 Nov"; "submitted" for v1).
- **Tab counts**: Threads keeps its count in its name, as before. Conversation shows a count pill of posted comments (drafts excluded); the number is given to assistive technology as a description ("4 comments"), so the tab's accessible name stays "Conversation".
- **Conversation as a timeline** (`ReviewTimeline.tsx`): a vertical rail; the submission is the first box ("Ana submitted v1 · date" with the abstract, clamped to three lines), replacing the bare "v1" event; each comment is a box with an avatar, a head ("who commented date · Edited", version tag, party label), its body, its replies inside the box and a reply field in the foot; workflow events stay one line on the rail with their badge.
- **Status box** at the end of the rail: a circle (maroon where someone must act, outlined once settled), the server's turn line as its heading, the workflow state under it when it says something different, and the clearance strip behind *Show all clearances*.
- **Composer** with the viewer's avatar; its label, field and buttons are a box like a comment.
- **"Your part" footer** (`YourPartFooter.tsx`): the icon in the same 32px circle as the status box, toned from the part's own icon.
- **Threads** (`threads/ReviewThreads.tsx`): each thread is a box with the author, party, date and "Edited" in its head, page and version on the right, and its actions in a foot that shows only when there is one; a draft thread has a dashed border. "Your drafts" is sentence case.
- **Details** (`ReviewDetails.tsx`): section headings are small semibold labels, not display titles.
- At a pane narrower than 360px the avatars drop out (container query), so a box keeps its width.

## Not changed

- No new endpoint, field or wording from the browser: the header line, counts, status heading and clearance list are the server's.
- The Changes tab has no count yet: the number of changed files is known only once the diff loads, and a count that appears late would move the tab row.
- The author's Review pane (`AuthorReviewWorkspace`) is not restyled; the ticket is the reviewer's workspace.
- The body of a thread card was not re-indented after it moved into the box; whitespace only.

## Tests

No test was changed. The existing suites read the workspace through the accessible tree and still pass: comment and reply names ("Comment by X", "Replies to X", "Reply to X"), the timeline's list name, the act text first in an event, the tab names ("Conversation", "Threads N"), the footer's landmark and the thread actions group.

- `frontend/src/features/records/paper-view/PaperViewPage.test.tsx`, `ReviewTimeline` and `ReviewThreads` tests under `paper-view/`, `ThreadsWorkspace.test.tsx`, `ReviewTour.test.tsx`, `reflow360.test.tsx`.
