# IR-850 — Gate and admit every extraction that leaves campus

**Affected requirement labels:** FR-M3-01 (PDF text extraction), FR-M6-02 (DPA consent). Neither matrix status changes.

[Back to the matrix](../TRACEABILITY.md)

**Decision:** ADR-056 §5-6 — the disclosure gate decides every off-campus read, and every read is admitted under ADR-041.

**Port (shared with IR-841):** `StructuredExtractor.leaves_campus` (`DoclingExtractor` False; `InMemoryExtractor(leaves_campus=...)`, default False). `ExtractedDocument.usage: Usage(pages, credits) | None` — optional, unlike the ticket's sketch, so Docling and other non-billing Extractors need not invent one; `credits=None` or no `usage` means not reported. An off-campus Extractor also names `account` and `model` (`timeout_seconds` is IR-839's). An Extractor that does not declare `leaves_campus` is treated as leaving.

**Gate:** `apps/ai/extraction/gate.py` asks `apps/ai/policy.decision_for_record` (consent, embargo, IP mark), so a read follows the same gate as embedding and generation and picks up ADR-054's per-person consent when IR-791 changes that input. Asked at queue time by `documents/sources.reset_manuscript` and `queue_upload_read` (the upload view now calls it): a refused read gets phase `awaiting_disclosure` ("Not read: awaiting consent or release", migration `documents/0018`, choices only, `sqlmigrate` prints no SQL), nothing is queued, and Publish's prefill reports `unsupported` with that message (IR-839's `reader_message`) so the author types the details. The upload path takes the Record lock before gating, and a send-time refusal rechecks the gate under the lock, so a release committing mid-way cannot leave a read held. `apps.ai.tasks.send_to_ai_on_commit` — called after submit (consent) and embargo release — and the development-only `clear_for_ai` now run `read_awaiting`, which re-queues held manuscript and supplementary reads when the gate allows. Extractors that stay on campus are never asked: Docling's behaviour is unchanged until IR-842.

**Admission:** `apps/ai/admission/extraction.AdmittedExtractor`, applied by `selection.current_extractor` to every off-campus Extractor (installed test adapters included). Refuses `admission_off` unless `AI_PROVIDER_ADMISSION=enforce`; refuses `not_configured` unless `AI_ADMISSION_EXTRACTION_CREDIT_USD`, `_CREDITS_PER_PAGE` and `_ADDON_CREDITS_PER_PAGE` are all set (no defaults; malformed values stop startup). Reserves pages (pypdf count in the worker; the intake page ceiling if uncountable) × (tier + add-on credits) × credit price on the `extraction` lane, through a new caller-priced `ledger.Request.cost_micros`. The gate is asked again inside the attempt, after the reservation and immediately before sending; a refusal there releases the reservation and leaves the read `awaiting_disclosure` without a retry. Any other admission refusal (admission off, unpriced, lane busy, campaign spent) is transient under IR-839's policy: retried, then failed with "temporarily unavailable", never "can't be read". `AdmittedExtractor.timeout_seconds` passes the adapter's through to IR-839's task time limit. Leases are not renewed: `timeout_seconds` must bound the whole read. Settles to the reported credits; unreported credits keep the reservation, even if the model name also has a token price. Settlement now rounds a reported US$ cost to the micro-dollar before rounding up, so float noise cannot add one.

**Tests:** `apps/documents/tests/test_offcampus_extraction.py` (real Postgres, committed transactions, both databases): refused before consent, while embargoed and with no embargo answer; consent withdrawn while queued; a read naming no Record; a release landing between the send-time refusal and the task holding the row (fails if the recheck is removed); sent after release (`release_embargo`) and after a later Yes (`send_to_ai_on_commit`); an act that leaves the gate shut queues nothing; supplementary uploads held and re-queued; reservation at pages and settlement to credits; unreported usage (no credits, no usage); admission off; each unset price; an unconfigured lane; local Extractor neither gated nor admitted; Publish prefill. `test_offcampus_workers.py` runs the real task in independent interpreters (`extraction_probe.py`): two workers against a campaign with room for one read send exactly one; a released and an embargoed paper in parallel send one and hold one. `apps/ai/admission/tests/test_limits.py` adds the price-setting checks; `apps/ai/extraction/tests/test_selection.py` the wrapping rule.

**Evidence (2026-11-03):** Linux `iris-backend` image against a private pgvector 16 server, full suite after rebasing onto `origin/main` 025b6637: 5,626 passed, 24 failed, 1 xpassed, 7 collection errors. All 31 are in `apps/ai` runtime, agent-contract, chunker-core and fixed-workflow-fixture files that also fail on the untouched base in the same container (the 7 errors are `asyncpg` missing from the image); none is in documents, records, extraction or admission. Windows, private test DB: `test_offcampus_extraction.py`, `test_offcampus_workers.py`, `apps/ai/extraction`, `test_limits.py` and IR-839's extraction failure, worker, task-surface and manuscript-task tests all pass. The independent-worker tests spawn real interpreters against the shared test database. `sqlmigrate documents 0018` prints `(no-op)`.

**Not done here:** the LlamaParse adapter (IR-841) and the corpus cutover (IR-842). ADR-054's per-person answer is not built; consent is still `Record.dpa_accepted`, stamped at submit, so today an off-campus read of a draft waits until submission. The frontend does not yet name the held state beyond Publish's manual-entry path.
