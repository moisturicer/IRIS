## IR-584: Paper Chat can continue a recent Conversation or start a new one

**Requirement.** IR-552 user stories 12 to 14. In Paper view a reader can continue a recent owned Conversation about the Record or explicitly start another.

**Implementation.** `PaperChatDock.tsx` (Django path) and the new `RecentChats.tsx`. Frontend only: it uses the existing owned list route (`GET /ai/conversations/?record=`), which is already filtered by `owned_by`, so no endpoint was added.
- The panel header has **Recent chats** and **New chat**; with no messages the recent list also shows under the starters.
- Choosing a recent chat opens it through the client's `openFound`, so a late response for the old selection is dropped. Nothing is sent.
- **New chat** shows an empty chat; the first question creates a distinct Conversation (`create({record})`, no `reuse_default`). Opening the default workspace still uses IR-561's reuse.
- Each Conversation keeps its own unsent draft (the client's thread draft); the page's draft is still kept through a close.
- A list failure or refusal shows no chat metadata.
- The runtime path (`RuntimePaperChatPanel`) is untouched.

**Tests.** `PaperChatDock.recent.test.tsx`, 6 tests: list and starters send nothing; recent restore with separate drafts; New chat creates without reuse; late answer stays out after switching; refused list shows nothing; cross-Record pin keeps this paper's recents.

**Not verified.** 360 and 1280 px layout and the software-keyboard behaviour were not checked in a browser; jsdom cannot measure them.
