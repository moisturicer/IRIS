# IR-875: review threads, frontend

**Requirements:** no FR- id. The rule is [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §7: the 2026-11-04 amendment, the 2026-11-06 Correction, and the IR-875 Note (one Finish review, a Threads tab for owners, a keyboard path through find, and *Suggestion* preselected), plus §10's Readiness contract. Parent IR-870; the backend is IR-874.

What changed (`frontend/src/features/records/paper-view/`):

- `threads/threadModel.ts`, pure: grouping and pins (1, 2… for sent threads, D1… for drafts), the filters (Open, Yours, Resolved, All), the tab count ("N must fix · M suggestions"), state words, and the Finish dialog's verdicts from capabilities and the server's blocked flags.
- `threads/passage.ts`, pure: page-fraction regions from client rects, the text either side of the quote, and an anchor from a DOM range.
- `threads/readerAnnotations.tsx`: a context the review workspace provides around the reader. It carries the highlights, the numbered pins, Comment, and landing on a thread.
- `PaperPdfReader.tsx` reads that context and offers *Comment* (button and key C). The anchor comes from the selection, else from find's current match.
- `threads/ReviewThreads.tsx` is the Threads tab: the composer, *Your drafts*, the filters, and each thread with the controls its `can_*` flags allow.
- `threads/FinishReviewDialog.tsx` is the Finish dialog: the summary and verdicts, each held verdict with its reason, and what a Decision closes. A 409 brings back a fresh token. *Accept & send to RDCO* continues in `RouteDialog` through `finish-review/`.
- `threads/useThreadsWorkspace.tsx` holds the threads, the composer, pin focus and landing, and the dialogs. Both workspaces use it.
- `ReviewWorkspaceLayout.tsx`: the reviewer's pane gets a Threads tab, and the footer gets *Finish review…*. The verdict buttons are hidden wherever `finish_review` is granted.
- `ReviewWorkspace.tsx` gives the author's pane Conversation and Threads tabs.
- `ReadinessPanel.tsx` gains the `show_threads` action, which opens a party's open threads.
- `timelineEntries.ts` hides the viewer's drafts, names each thread's party and page, and adds an entry for each *Comment only* round.
- `api/records.ts` and `types/records.ts`: the thread acts, `finish-review/`, the thread fields, and the new flags.

**Known, accepted:**

- Two held-verdict reasons are written in the client, because no server field carries them. One is the reviewer's own *Must fix* draft, whose wording mirrors `finish_review.py`'s refusal word for word. The other is a revision request that is already open.
- A former reviewer gets no severity choice. The server stores *Suggestion*, and offering the choice would need a role check.
- Pins are drawn for open threads and drafts only. A resolved thread stays under the Resolved filter.
- jsdom has no layout, so real selection geometry and pin placement are unchecked by tests and need a manual check in a browser. A thread anchored without regions saves but draws no highlight.
