## IR-933 — Profile and Settings are separate pages

The account menu offers **Profile** (`/profile`) and **Settings** (`/settings`). Profile shows the signed-in person's name, role, affiliation, photo, bio, research interests and ORCID iD, leaves empty optional fields out and never prints the account email; **Edit profile** (`/profile/edit`) holds the photo, name and optional fields behind one Save that returns to Profile. Settings keeps Account & security (now showing the read-only sign-in email), Data privacy & consent and Role & access. "View my profile" is removed.

Evidence (Vitest, run 2026-11-06): `ProfilePage.test.tsx`, `EditProfilePage.test.tsx` (IR-699's cases moved over; Save is now one button for the page, a deliberate change), `SettingsPage.test.tsx`, `Sidebar.test.tsx`, `access.test.ts`.

Not covered: another person's profile (IR-700), because no endpoint lets one user read another's public fields (`users/<id>/` is admin-only). Not checked in a browser at 360, 768 and 1280 px.
