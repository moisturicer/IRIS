# IR-1147 — Structural merging short sections with a sibling

**Affected requirement labels:** none change status. Part of IR-980; follows IR-1054.

[Back to the matrix](../TRACEABILITY.md)

**Implementation:**

- **Option.** `ChunkingOptions.sibling_merge_floor` (0 is off; capped at the target, so a small target still chunks), `AI_CHUNK_SIBLING_MERGE_FLOOR` (default 450 since measured), trial option `sibling_merge_floor=N`, stored with each chunk set (older sets read as 0).
- **Merge.** `assembly.merge_sibling_sections`, run by structural after heading-only folding: a passage under the floor merges forward, then backward, with a neighbouring section that shares a parent heading, up to the target. The merged passage carries the parent's path as its trail and `section_key`, and the union of the boxes. Merged subsections (3.1.1 + 3.1.2) can merge on with 3.2.
- **Never.** Two chapters (the parent is the title, or with no title a heading every key starts with), a parent's own intro with its first child, or a Figure passage. A merge passes over a Figure, which then follows the merged passage.

**Tests:** `apps/ai/chunking/tests/test_sibling_section_merge.py` (new; off pinned to pre-change hashes; property tests for the contract, boxes and keys with the option on), `apps/ai/tests/test_sibling_merge_wiring.py` (new; setting, trial variant, storage).

**Evidence:** 2026-11-16, Windows 11 host. Both new test files pass, and flake8 is clean. The full suite is left to CI. `test_consolidation.py::test_property_every_chunk_holds_one_sections_content` still runs with the option off: with it on, one chunk holds several sibling sections by design, and the new property test states the rule that replaces it. `test_sibling_merge_wiring.py::test_the_setting_defaults_to_the_measured_floor` changed deliberately when the default moved from 0 to 450.
