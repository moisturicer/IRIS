## ADR-035 §1 · §3 · §4 · §6 · §10 · §11

**Requirement:** **Reader-invisible shadow decisions on real traffic** — no FR- id; [ADR-035](../../adr/035-ask-iris-decides-whether-it-needs-evidence.md) (**Accepted** 2026-10-06). IR-466 under [IR-456](https://citiris.atlassian.net/browse/IR-456)

**Design:** ADR-035 §1 (`off`/`shadow`, `on` rejected, sample rate 0 by default, registered in the technique registry) · §3 (union: either half requires evidence) · §4 (a tool call is recorded, never executed) · §6 (the AI Overview is excluded by construction) · §10 (shadow supplies operational figures only; no hypothetical answer kept) · §11 (vendor retention gates real reader questions) · §Deployment Impact (own breaker key, shadow-only token lane, dedicated low-concurrency queue)

**Implementation:** `apps/ai/orchestrator.py` — both chat views go through `ChatOrchestrator`, which answers as before, records the Turn and calls `evidence.shadow.shadow_turn`; the Overview keeps calling `answer_service` directly · `apps/ai/evidence/shadow.py` — in-request: detector verdict + manifest (window Turn ids with question/answer lengths, history budget and margin, eligibility states, rule-set digest, prompt digest, model and generation parameters), verified, pending row written, task enqueued **after commit** with publish retries off, so a down broker cannot stall the reader; on `/ask/stream/` all of this runs only **after** `done` is yielded; skipped in-request (counted) when the reader's `answer` breaker is open or failing, because breakers are per process. Worker: atomic claim (row count checked), token fencing on every write, one stale reclaim, release-and-retry or `retries_exhausted` on the final attempt, skips for no model / answer breaker / spent shadow budget, parity recorded not skipped, union route stored, fenced-out completions counted, `coverage()` for IR-467 · `apps/ai/models/shadow.py` + migration `0018` (`ShadowEvidenceDecision`, one per Turn, cascades from it; `ShadowEvidenceTally` for row-less events) · `apps.ai.tasks.decide_evidence_shadow` on queue `shadow` (`acks_late` + `reject_on_worker_lost`, 3 retries, only the exception type reaches Celery's retry log) · `resilience/rate_limit.py` `Lane.SHADOW` with its own budget; `spend` returns its window key and `adjust` reconciles into that window, refunding the reservation when the decision raises; `resilience/circuit.py` `failures`; `inference/providers.py` `build_profile_llm(breaker_key=)`; `CompositionRoot.shadow_decider()` · settings `AI_EVIDENCE_SHADOW_SAMPLE_RATE`/`_TOKENS_PER_MINUTE`/`_STALE_SECONDS` · `celery-shadow` worker (concurrency 1) in both Compose files · `evaluation/techniques.py` gains `evidence_decision` (`choice`: off/shadow)

**Test:** `apps/ai/tests/test_evidence_shadow.py` (31 — a raising decision refunds its reservation; a fenced final attempt reports fenced, not failed; flag off records and enqueues nothing; zero sample rate records nothing; `on` rejected by config and by the technique; **response bodies identical off vs shadow on `/ask/` and `/ask/stream/`**; manifest and verdict on the pending row; enqueue only after commit; a broken broker never reaches the reader; one-off question → no row; **the Overview never reaches the orchestrator**; a search route makes **no embedding, rerank or answer call**; the decision sees prior reader questions and no answer or Passage text; union rule; **two claims, one winner, loser makes no call**; **a reclaimed row's first worker writes nothing and is counted**; stale reclaim once; retry-exhausted → failed and missing; the real Celery task retries then fails the row; cascade on Conversation delete and a counted `turn_deleted`; **parity mismatch recorded, decision still made**; skips for open breaker (in-request and worker), recent failures and spent budget; spend reconciled to vendor usage; **the reader path touches no bucket**; hypothetical answer and reasoning absent from the row, the Turn and the logs; logs carry codes and Turn ids only) · `apps/ai/tests/test_shadow_off_snapshot.py` (2 — **the adapter request on both endpoints matches a snapshot captured before the orchestrator existed**) · `resilience/tests/test_shadow_lane.py` (7) · `inference/tests/test_shadow_breaker.py` (5 — shadow failures open the shadow breaker and leave the answer breaker closed)

**Evidence:** `pytest` (whole backend) 2026-10-06 against the compose Postgres/pgvector: 6 failures, of which 4 are the host-`.env` failures recorded under IR-464/IR-465 (`test_profiles.py`, `test_llm_contracts.py`), 1 was this change's (`test_enum_vocabulary.py`, fixed: event code renamed, `ai/models/shadow.py` allowlisted with its reason) and 1 is `retrieval/tests/test_two_stage.py::test_a_limit_above_forty_is_reached`, order-dependent by its own comment and untouched here. **After the code-review fixes, a second full run had exactly the 4 host-`.env` failures** and nothing else. `flake8 apps/ai config` clean; `docker compose config` valid for both files. Existing HTTP suites unmodified; `test_techniques.py`'s two registry-set assertions were changed deliberately because ADR-035 §1 adds a seventh switch. **No live vendor call and no real broker**: the task ran eagerly and by direct call

**Status:** **BUILT and executed offline, not Done, and not enabled anywhere.** Default `off`, rate 0. **ADR-035 §11's vendor request/response retention check is not recorded, so shadow must not run on real reader questions** — a process control nothing in the code enforces. Not built: production `on`, web search, any agent loop, a stale-row sweep (reclaim happens only on broker redelivery; a running row past its one reclaim stays running and reports missing), and IR-467's report. **Breakers are per process**: the `answer`-breaker skip is read in the web process that served the question, so it reflects that process only, and the worker's own re-check cannot see reader failures — the bound between enqueue and run is the shadow budget and concurrency 1. IR-468 owns reader-path rate limiting. Contention at the vendor stays unprioritised, bounded only by concurrency 1 and the shadow budget
