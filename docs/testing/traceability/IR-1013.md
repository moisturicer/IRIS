# IR-1013: CloudFormation stack for the IRIS demo server

**Requirements:** no FR- id. Epic IR-805 (S2 Epic: Deployment). It replaces the EC2 console steps of the first deployment, 2026-11-10 (IR-806). It builds on IR-1014's `deploy/bootstrap_server.sh`.

## Decisions (Hermoine Zozobrado, 2026-11-11)

1. **The first-boot script is downloaded, not copied in.** User data downloads `deploy/bootstrap_server.sh` from GitHub at the `IrisRef` parameter (default `main`) and runs it. That keeps one copy of the script. The cost: a server runs whatever that ref holds at launch.
2. **The template lives at `deploy/aws/iris-demo.yaml`,** beside the bootstrap script, not in `infra/` (the ticket's example).
3. **The real-account run is deferred to the next migration,** as for IR-1014. CI lints the template meanwhile.

## What changed

- `deploy/aws/iris-demo.yaml` creates four things:
  - an EC2 instance: Ubuntu 24.04 from Canonical's SSM image parameter, gp3 disk encrypted and deleted with the instance, IMDSv2 required;
  - its security group: 80 and 443 from anywhere, IPv4 and IPv6; 22 from one `/32` only when `SshSourceIp` is given;
  - an Elastic IP attached to the instance;
  - an IAM role with `AmazonSSMManagedInstanceCore` only.
- Parameters: `InstanceType` (default `m7i-flex.large`), `DiskSizeGiB` (default 64), `SshSourceIp` and `KeyPairName` (both optional), `IrisRef`, `ImageId` (the SSM parameter).
- The region is wherever the stack is created.
- Outputs: `PublicIp`, `InstanceId`.
- No parameter or resource holds a secret, and nothing writes a `.env` file or starts IRIS.
- The `server-bootstrap` CI job also runs `cfn-lint` 1.59.0 on the template for `ap-southeast-1` and `us-east-1`.
- `deploy/README.md` covers creating the stack in the console, connecting with Session Manager, deleting the stack, and the public IPv4 charge.

## Evidence

- Local, 2026-11-11:
  - `cfn-lint` 1.59.0 is clean for both regions.
  - A copy with a misspelt property and a dangling `!Ref` fails with E3002 and E6101, so the linter does check these.
  - The user data, with `IrisRef=main`, passes `shellcheck` v0.10.0, and its download URL answers 200.
- CI on PR [#674](https://github.com/moisturicer/IRIS/pull/674), 2026-11-11: `server-bootstrap` passed, including `cfn-lint` on the template ([job](https://github.com/moisturicer/IRIS/actions/runs/42866630750/job/130006594535)). All 11 checks passed.
- After review, `IrisRef` accepts path segments only (no `..`, no leading or doubled `/`) and `SshSourceIp` only a valid IPv4 address. Both patterns were checked locally against accepted and refused examples.

  - create the stack in a real account and region;
  - reach the server over Session Manager with no SSH address or key pair given;
  - check port 22 is closed and the bootstrap log ends in `finished`;
  - delete the stack and confirm the Elastic IP is released.
