## IR-393

**Requirement:** **Chunks carry a stored keyword index the database maintains** — no FR- id; part C of IR-390's spec, and the asset the hybrid retrieval in IR-395 is built on

**Design:** [ADR-033 §2](../../adr/033-hybrid-retrieval-and-passage-selection.md) (the chunk keyword index is a stored column the database maintains, **not** application code on save)

**Implementation:** `DocumentChunk.search_vector` (`SearchVectorField`, `editable=False`) with a `GinIndex`, added by `ai/0015_chunk_keyword_index` · `apps/ai/keyword_index.py` holds the trigger SQL (`BEFORE INSERT OR UPDATE OF content`, `to_tsvector('english', …)`) and one `backfill_chunk_keyword_index()` used by both the migration's `RunPython` and `manage.py backfill_chunk_keyword_index`; the backfill is idempotent and resumable by construction — what it fills is "chunks with no keyword index", recomputed per batch, never a checkpoint file — exactly as `backfill_embeddings` is · `apps/ai/retrieval/degraded.py::FullTextRetriever` reads the column instead of building a `SearchVector("content")` per chunk per query. **A trigger rather than a generated column**, both of which ADR-033 §2 permits: a stored generated column is added by an `ALTER TABLE` that rewrites the whole table under an ACCESS EXCLUSIVE lock, while a nullable column plus a trigger does not, which is what leaves the fill as a separate resumable step. The configuration is `english`, named explicitly rather than inherited from the server's `default_text_search_config`, so the trigger, the `SearchQuery` and `Record`'s index agree by construction. **A real finding, recorded rather than smoothed over:** the obvious rewrite — `@@` against the column, so the GIN index answers the fallback's own query — is **not** behaviour-preserving. `ts_rank` does not consult `@@`, so `rank > 0` matches a passage holding *some* of a multi-word question's terms while `@@` on Django's default `plainto_tsquery` demands all of them; on the development corpus "pond sampling" returned 20 passages under `rank > 0` and **none** under `@@`. The fallback therefore keeps `rank > 0`, and the index is left for the hybrid retrieval that follows, where the stricter predicate is the intended one

**Test:** `apps/ai/tests/test_chunk_keyword_index.py` (11, DB — an inserted chunk, an edited chunk and a `bulk_create`d chunk set each indexed with no application code doing it, `bulk_create` being the path `repositories.save` actually uses and the one a signal would be skipped on; the `english` configuration asserted through stemming rather than by reading the setting back; the backfill filling a row that predates the trigger, writing nothing on a second run, and resuming after being stopped one row in; the command's dry run and its empty-backlog report) · `apps/ai/retrieval/tests/test_degraded.py::FullTextFallbackTests::test_a_passage_holding_some_of_the_question_still_matches` (new — pins the `rank > 0` predicate against the `@@` rewrite) · the eleven pre-existing `test_degraded.py` cases and `test_degradation_crosses_the_seam.py` unchanged

**Evidence:** `apps/ai/tests/test_chunk_keyword_index.py apps/ai/retrieval/` → 62 passed. Full backend suite **1776 passed, 2 failed, 2 skipped, 1 xfailed** (2026-09-28); both failures are the pre-existing environmental ones recorded on IR-378 (`test_llm_contracts.py` reading the developer's own `backend/.env`). **Migration exercised against a copy of the development database, not only an empty one** (`CREATE DATABASE … TEMPLATE iris_db`, 4,926 chunks): `0015` applied cleanly, all 4,926 rows backfilled with 0 left null, the GIN index and the trigger both present, `EXPLAIN` confirming a Bitmap Index Scan on `ai_chunk_search_gin_idx` for an `@@` query, and an `UPDATE` to a row's `content` re-indexing it with no code involved. The fallback's results were compared old-query against new-query on that corpus for five questions ("quantum filtering", "contamination bias", "pond sampling", "neural network training", "semiparametric estimator") — **top-20 chunk ids identical on all five**. The backfill was then run over 500 real rows, stopped at 200, resumed to completion, and re-run to a no-op. The copy was dropped afterwards

**Status:** **IMPLEMENTED** — the column, its index, its trigger and the backfill exist and the fallback reads them, with reader-visible behaviour unchanged by measurement rather than by assertion. Fusing this keyword search with the vector path is IR-395; nothing consumes the GIN index on the normal path yet
