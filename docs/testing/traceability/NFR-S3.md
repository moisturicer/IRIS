## NFR-S3

**Requirement:** Secure configuration

**Implementation:** **IR-154.** `CORS_ALLOW_ALL_ORIGINS` is gone from every settings module — `development.py` now lists its dev origins explicitly, and `production.py` refuses to start if the setting reappears. `SECRET_KEY`, `DB_NAME`, `DB_USER` and `DB_PASSWORD` are read through `base.py`'s `required()` and have no defaults, so a missing one raises `ImproperlyConfigured` instead of falling back to the committed credential. `production.py` re-reads `ALLOWED_HOSTS` and `CORS_ALLOWED_ORIGINS` without base's `localhost` default and rejects empty, `*` and non-https values. Both Compose files and the gateway's `DATABASE_URL` take the credential from the repo-root `.env` via `${VAR:?}`.

**IR-379** extends the same posture to per-task Inference configuration: `apps/ai/inference/startup.py` refuses startup on a task name outside the closed set (a typo like `LLM_ANWSER_MODEL` configures nothing, so without this it reads as a feature never switched on) and on a task whose model is set while no key resolves, naming the task, the variable that turned it on and every variable that could supply a key. **Configured means an operator set a model in the environment**, not that a model resolved: `answer` inherits the flat `LLM_MODEL`, which ships *with* a default, so refusing on the shipped default would make a vendor account a precondition for running IRIS at all. Setting `LLM_MODEL` does count, inherited or not, so the long-standing flat configuration — a model set and the key forgotten, which is the reported failure — is checked like any other; `.env.example` ships `LLM_MODEL` empty to match. An **unconfigured** task is off rather than an error — which is what keeps IRIS, and the test suite, startable on a machine with no vendor account. The rules are pure functions and `AiConfig.ready()` raises, so `runserver`, gunicorn, a Celery worker and `manage.py check` all refuse alike

**Evidence:** `apps/tests/test_settings_validation.py` — **18 executed, 0 skipped**: 16 against the pure rules in `config/settings/validation.py` (blank-vs-absent, every production rule, accumulation) and 2 repository sweeps (no `CORS_ALLOW_ALL_ORIGINS` assignment; no retired credential literal). Plus the real modules booted end to end, six environments: good prod config boots; empty `ALLOWED_HOSTS`, `*`, an http origin, a blank `SECRET_KEY` and a blank `DB_PASSWORD` each raise `ImproperlyConfigured`; development boots unchanged. `docker compose config` validates both files with the vars set and fails by name without them. A CI step repeats the good/empty pair. `apps/ai/inference/tests/test_startup.py` — **20 executed, 0 skipped**: 16 against the pure rules (both mistakes, one typo across several variables reported once, every real task name and every legacy flat `LLM_*` variable accepted, blank-vs-absent key, accumulation) and 4 that run `manage.py check` in a subprocess — a per-task keyless model, the inherited flat `LLM_MODEL` with no key, and an unknown task name each exit non-zero naming the offender, while a run with nothing configured still exits 0. Three more in `test_profiles.py` pin what a refusal may name: a named vendor drops the inherited key from the list but not the inherited model. Verified red by disarming the `ready()` call

**Status:** **PARTIAL** — every code-side criterion is met and tested.
