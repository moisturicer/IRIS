## IR-1235

**Requirement:** **Ask IRIS uses the design system's type roles and one outline icon set** — subtask 3 of the Ask IRIS redesign (IR-1229); no FR- id. No API change.

**Implementation:** `frontend/src/features/ai/`.
- `components/AskIrisIcons.tsx`: a 30-glyph outline set drawn as inline SVG (`PlusIcon`, `CloseIcon`, `RetryIcon`, `SearchIcon`, `BookIcon`, …), stroked at 1.75 in `currentColor`, 20 px in a control and 16 px with `inline`, always `aria-hidden`. No new dependency. `OUTLINE_ICONS` lists them by name; `OutlineIcon` is their shared type.
- Every Font Awesome `<i>` under `features/ai` is replaced. The depth menu uses search for Standard and book for Thorough research (`RuntimeReader.tsx`). `EmptyState.icon` now also takes an icon element, so the "Could not load this conversation" state draws `UnplugIcon`; a Font Awesome class still works for its other callers.
- Type roles: `text-xs`, `text-sm`, `text-base`, `text-xl`, `text-2xl`, `text-display` and the sub-13 px `text-label` / `text-2xs` are gone from the feature. Answer text is `ANSWER_TEXT` (16 px / 1.75, `answerLayout.ts`); questions and starters are `text-body`; pills, action buttons and panel prose are `text-control`; meta, groups, the disclaimer and citation markers are `text-small`; the conversation title and the opening prompt are `font-display text-title`.
- Compact answers (Paper Chat) now read at 16 px like the rest; the old `text-sm` variant is gone.

**Contradiction recorded, not reconciled:** the ticket asks for an answer measure of about 72 characters; DESIGN.md's Flush Column Rule (and CODING_STANDARDS F2) forbids a `ch` cap on reading text, and the column, not the text, sets the measure. The higher source wins, so no 72ch cap was added. `askIrisDesign.test.ts` now fails on any `max-w-[<n>ch]` in the feature. If the measure is wanted, DESIGN.md has to change first.

**Left as is:** `answerLayout.ts` keeps `text-lg` for the AI Overview's 17 px heading ladder (IR-1089, covered by `answerTypography.test.ts`). The Stop button's 12 px square is not a Font Awesome icon and stays. The two hub-page hero icons are the page's own.

**Tests:** `askIrisDesign.test.ts` (reads the feature's sources and fails on any `fa-` class, `<i>` tag, removed size utility, arbitrary size under 13 px, or `ch` cap; checks the reading role is applied in the three answer renderers). `AskIrisIcons.test.tsx` (every glyph is a 20 px / `inline` 16 px stroked SVG at 1.75, `aria-hidden`; every other icon in the module is hidden unless given a name). `EmptyState.test.tsx` gains an icon-element case. `ModelPill.test.tsx`'s fixture passes `PlusIcon` instead of a Font Awesome class string, because `ModelPillOption.icon` is now an icon component.

**Evidence:** `npx tsc --noEmit` clean; eslint on `src/features/ai` and `src/components/shared` 0 errors (one pre-existing `exhaustive-deps` warning in `ConversationSidebar.tsx`); `npm run test:changed` 78 files, 1,498 tests; two `documentTitle.test.tsx` cases timed out once under the parallel run and passed alone (10 of 10). Visual size and contrast under jsdom are not checked and stay a manual check against the prototype. Done requires review and approval (DEFINITION_OF_DONE §4).
