## IR-1233

**Requirement:** **The conversations pane opens and closes in place, with one toggle and a collapsed strip** — subtask 1 of the Ask IRIS redesign (IR-1229); no FR- id. Supersedes IR-570's 900 px drawer rule for history.

**Implementation:** `frontend/src/features/ai/`.
- `ConversationSidebar.tsx`: beside the chat the pane pushes it over and is never an overlay. Open, its top bar holds the toggle and New chat over Search, Pinned and Recents. Closed, it narrows to a 60 px strip of the toggle, a New chat icon and a Search icon, each with a visible tooltip (the shared `Tooltip`) and an accessible name. The width eases (200 ms) only while it opens or closes, so a drag still follows the pointer, and not at all under `prefers-reduced-motion`. Animating width is what the ticket asks for; it departs from DESIGN.md's opacity-and-transform-only motion rule on purpose, and only for this one column. The list keeps its own width while the column moves, and is hidden (`aria-hidden`, `inert`, `invisible`) rather than unmounted when closed, so a typed search survives.
- `ConversationsToggle` (same file): the one toggle, a left-panel icon (`PanelLeftIcon`, a 1.75 px stroked inline SVG in `AskIrisIcons.tsx`, decorative) at the pane's top-left, at the same place open or closed. It is one element, so focus stays on it through the change. Name "Hide conversations" / "Show conversations", with `aria-expanded` and `aria-controls` naming the pane. It replaces the `fa-angles-left` / `fa-bars-staggered` pair.
- `ChatToolbar.tsx`: carries the toggle only on a phone, where it opens the pane as a dialog (`aria-haspopup="dialog"`, 44 px). On wider pages the chat header has no history toggle.
- `RAGChatPage.tsx`: the choice is kept per browser under `iris-ask-pane` (every read and write in try/catch; blocked storage means the pane starts open). A phone is a measured page width of 640 px or less (`ASK_PHONE_MAX_PX` in `answerLayout.ts`, which replaces `ASK_PANELS_INLINE_PX`), so tablets push. On a phone the existing `ChatDrawer` is the dialog: scrim, X, Escape and a tap outside close it, and focus returns to the opener.
- Search from a closed pane: the strip's Search and Ctrl+K both open the pane, then put focus in the pane's own search box (phone: open the dialog, then focus it). Ctrl+K was already the pane's search focus (IR-1161) and did nothing while the pane was hidden; there is no separate search UI, so nothing needed to be kept apart. While the pane is open, the list's own Ctrl+K handler is unchanged.
- `ConversationHistoryList` no longer draws New chat and the collapse button; the sidebar's top bar owns them. The phone dialog still has its own New chat button.

**Tests:** `RAGChatPage.pane.test.tsx` (14), through the page's routes with requests answered at the axios adapter and the page's width reported by a stubbed `ResizeObserver`: at 1280 px one toggle, `aria-expanded`/`aria-controls`, no dialog, no a11y violations; hide leaves the list off screen and focus on "Show conversations", show returns focus to "Hide conversations"; the same by keyboard; the strip's New chat starts a conversation; the strip's Search and Ctrl+K open the pane with focus in the search box; a closed pane stays closed after a reload; blocked storage starts open and still toggles; at 768 px the pane pushes (no dialog); at 360 px no pane and a "Show conversations" opener that opens a dialog, Escape and the X close it with focus back on the opener, Ctrl+K opens it with focus in search, and a stored "open" does not open it.

**Deliberate test change:** `ConversationSidebar.test.tsx` renders the sidebar with the new props (`id`, `onSearch`, `onToggle` replacing `onCollapse`); none of its assertions changed.

**Not checked:** colour contrast and the width animation (CSS, which jsdom does not apply), a real browser, a screen reader, and a tap on the scrim (`ChatDrawer`, unchanged, has no role to query).
