## IR-315

**Requirement:** Staff bulk-import legacy records from an `.xlsx`/`.xls` sheet (`POST /records/import_excel/`)

**Design:** Jira IR-315 (no ADR — a dependency defect in an existing endpoint)

**Implementation:** `requirements/base.txt` now declares `pyexcel>=0.7` itself; only its plugins (`pyexcel-xls`, `pyexcel-xlsx`) were declared, so every upload answered "pyexcel is not installed". `apps/records/services.py` imports `pyexcel` at module level instead of catching `ImportError` into a row error, so a missing dependency stops `manage.py check` and the suite rather than reading as a skipped row. The `skipUnless(find_spec("pyexcel"))` tests the ticket names were already deleted with `test_workflow_characterisation.py` (IR-260), leaving the endpoint with no success-path test

**Test:** `apps/records/test_excel_import.py` (no skip guard): a real `.xlsx` through the endpoint creates a published Record with its owner and authors; a row without a Title is reported by row number while the rest import; a non-spreadsheet file is reported and creates nothing. Non-staff refusal stays in `apps/records/tests.py`

**Evidence:** 2026-10-29, local Docker: production and development images built from this branch both import `pyexcel==0.7.6` (`pyexcel-io 0.6.8`, `pyexcel-xls 0.7.1`, `pyexcel-xlsx 0.6.1`). The old `iris-backend` image reproduced the defect (`0 != 1 : pyexcel is not installed`); in it the new module now **fails** — 3 failed, `ModuleNotFoundError`, and `manage.py check` exits 1 — instead of skipping. In the rebuilt image `test_excel_import.py` + `records/tests.py`: 50 passed

**Status:** **IMPLEMENTED** — `.xls` parsing is not exercised (no writer for the format is installed). Seen and not fixed here: the downloadable template's notes row sits above `END OF RECORDS`, so importing it unedited creates a record titled "Required", and its sample Record Type `Thesis/Research` does not match the stored `Thesis / Research`
