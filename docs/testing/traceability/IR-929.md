## IR-929 — LlamaParse result URLs are checked before they are fetched (ASVS 5.2.6)

Found by IR-829. `apps/ai/extraction/llamaparse_client.py` downloaded the `presigned_url`s in LlamaParse's parse result (grounded items and figure crops) with a plain `httpx.Client()` and no check. Every other outbound URL in the backend comes from settings. These come from the vendor's authenticated HTTPS response, so abusing them needs the vendor or its response to be compromised. IR-825's egress limit was the only backstop.

**Fix.** `_download` calls `allowed_download(url, extra_hosts)` first. A URL passes only when:

- it is `https`, on the default port, with no user or password in it;
- its host is Amazon S3, which is where LlamaParse's v2 guide shows presigned results (`https://s3.amazonaws.com/...`, [API v2 guide](https://developers.llamaindex.ai/python/cloud/llamaparse/api-v2-guide/)): path-style, virtual-hosted, regional, legacy dash-regional and dual-stack names, and no other AWS service; or
- its host is exactly one listed in `LLAMAPARSE_DOWNLOAD_HOSTS` (empty by default; `backend/.env.example`).

Anything else raises `ExtractorUnavailable` ("… is not an allowed result host"), naming only the host because the query string is a credential. No request is sent, and the uploaded file is still deleted. `ExtractorUnavailable` means the document isn't at fault, so the extraction is retried rather than marked as a bad file.

**Why a setting.** The vendor docs give only placeholder URLs, and the IR-849 recordings strip the real ones. If LlamaParse serves results from somewhere else, the refusal names the host, and adding it to `LLAMAPARSE_DOWNLOAD_HOSTS` fixes it without a code change. Nothing else has to move.

Not covered here: the Unstructured client (ADR-067), which is not selectable until its cutover.
