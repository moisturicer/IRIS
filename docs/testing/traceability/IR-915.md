## IR-915

**Requirement:** **A change to a covered response shape on the backend fails a test, and a covered response that no longer fits the frontend's type fails a test** — no FR- id; subtask of IR-899 (API integration, typed contracts and session handling). Touches NFR-M (maintainability). Slice 1 of 2: the non-AI endpoints.

**Design:** Jira IR-915 · IR-899 · IR-913 (the audit-types regex test this replaces the idea of; see "Why additions do not fail") · `docs/architecture-review/08-framework-evaluation.md` (the `drf-spectacular` recommendation this does not adopt)

**Decision (2026-11-06, no ADR).** The contract is **recorded response fixtures checked by a backend test**, not a generated OpenAPI schema. The ticket asks for an ADR only "if it changes how types are produced"; the types stay hand-written, so none is written. The decision and its costs are recorded here, and a Jira comment on IR-915 gives the team a window to object.

| Option | Gain | Cost |
|---|---|---|
| **Recorded fixtures (chosen)** | No runtime code, settings or dependency on the backend; runs in the existing 4 backend shards; no new CI job; a renamed field fails a test that names it | Covers only the endpoints someone recorded; fixtures need an explicit refresh after a deliberate change |
| `drf-spectacular` schema | Whole-API coverage; docs for the defence; types could be generated later | A backend dependency, settings and annotations on every `APIView` without a `serializer_class`; reaches into every app including the AI area |
| Zod response schemas | Runtime validation | Rewrites every API module's types as schemas |

**Implementation**

- `backend/apps/tests/contract/`: `contracts.py` lists the covered responses (route, role, request); `test_response_contracts.py` fires each against the access matrix's `build_world()` and compares its structure with `contracts/<name>.json`; `shape.py` is the pure comparer (no Django), with its own tests in `test_shape.py`.
- `contracts/` at the repository root: one recorded sample per response. Tokens are redacted; values come from the seeded test world only.
- `frontend/src/test/contract/`: `responses.ts` names the type each call declares, `contract.test.ts` generates a JSON Schema from each (`ts-json-schema-generator`, dev-only) and validates every fixture with `ajv` (dev-only). `ContractChecks` in `responses.ts` makes `tsc` fail if a restated type stops being identical to the type its API call declares.
- `.gitattributes`: `contracts/*.json` is LF, so a refresh diff shows only a real change.
- `frontend/src/types/records.ts`: `RecordListItem.classification_name` is optional (see "Found").

**Covered (slice 1, 12 fixtures, 11 endpoints):** `GET /records/` · `GET /records/<id>/` (an owner's paper in review, and a published paper) · `GET /records/<id>/tracker/` · `GET /records/facets/` · `GET /records/classifications/` · `GET /records/<id>/document-requests/` · `GET /records/mine/` · `GET /library/saves/` · `GET /reviews/mine/?tab=in_review` · `POST /auth/login/` · `GET /users/me/`. **Not covered:** every write endpoint, the other workflow POSTs, document slots, and all AI endpoints (slice 2).

**What a change means**

| Change to a response | Result |
|---|---|
| A field removed, or its kind changed (including a value that becomes `null`) | **Fails**, naming the path (`$.results[].title: removed`) |
| A field that is `null` in the sample | Only the key must exist |
| A field only some list items carry (a saved paper that is available or not) | Optional |
| A field added | **Reported as a warning, does not fail** |
| A field the frontend type requires and the backend does not send, or sends with another kind | The **frontend** test fails, naming the field |

**Why additions do not fail.** An older screen ignores a new field, so a failure would stop every backend field addition until someone refreshes a fixture. IR-913 removed exactly that coupling from the Audit Log after three backend branches failed the Frontend job on 2026-11-05. The warning says what to refresh, so the frontend's types get checked against the new field. This is one rule in `shape.py` if the team wants it stricter.

**Refreshing.** After a deliberate change: `UPDATE_CONTRACTS=1 python -m pytest apps/tests/contract -q` from `backend/`, then commit the fixture diff (a reviewer reads it as the change to the contract) and update the frontend's types. CI never sets the variable, so a fixture is never rewritten there. The dev container mounts only `backend/`, so outside a checkout the test skips unless `CONTRACTS_DIR` is set; with `CI` set it fails instead of skipping.

**Found.** The first run caught a real mismatch: `classification_name` is declared `source="classification.name"`, and DRF **omits** the key when a record has no classification, while the frontend type said `string | null`, always present. Screens guard it (`record.classification_name &&`), so nothing was broken; the type was wrong and is now optional. Nothing else in the 11 endpoints disagreed.

**Test**

| Check | Where |
|---|---|
| Scalars, objects, lists, null-filled items, mixed items; removed, renamed, retyped, nulled, added fields; empty lists; optional keys; long lists cut to 3 | `backend/apps/tests/contract/test_shape.py` (21 tests, no database) |
| Every covered response keeps its recorded structure; a missing fixture and a fixture with the wrong route, method or role fail with the refresh command; a fixture with no contract fails | `test_response_contracts.py` (needs PostgreSQL) |
| Every fixture fits its type; a sample with a required field missing, or a field of the wrong kind, is refused (so the check is not vacuous) | `frontend/src/test/contract/contract.test.ts` (14 tests) |
| A restated type drifting from its call's type | `tsc` over `responses.ts` |

**Evidence (2026-11-06).** Local, backend in `python:3.11` against the CI-pinned `pgvector` image, with the CI environment's throwaway settings: the 12 fixtures recorded with `UPDATE_CONTRACTS=1` (23 tests passed); compare mode with those fixtures, 23 passed; a fixture with `title` renamed to `titel` failed with `$.titel: removed`; a fixture deleted failed with `no fixture at contracts/user-me.json. Record it with: UPDATE_CONTRACTS=1 ...`. Frontend: `contract.test.ts` 14 of 14 after the type fix, and 9 of 14 before it, with the five failures all naming `classification_name`; `tsc --noEmit` clean, and failing (`error TS2344`) with `RecordFacetsResponse` deliberately changed to `string[]`. **Not yet seen on GitHub Actions**, which is the gate (the backend job needs `contracts/` in the checkout, and the Frontend job reads it from the repository root).

**Limits.**

- Structure only: a type change on a field that is `null` in the sample is not caught (a populated sample would be needed; see the per-fixture note below).
- A sample list cut to 3 items can hide a field that only later items carry; such a field shows as a warning once it appears.
- The recorded values include seed-account emails (`student@cit.edu`, `adviser@cit.edu`) and today's timestamps; values are never compared, so they churn only on a refresh.
- Empty or thin samples: `record-document-requests`, `reviews-mine` and `classifications` hold at most a row or two, so a field those rows leave `null` is unchecked.
- `ts-json-schema-generator` does not resolve `ReturnType<typeof fn>`, so `responses.ts` restates two types and relies on `ContractChecks` to keep them honest.
- No write endpoint is covered: a request body drifting from its serializer is not detected here.
