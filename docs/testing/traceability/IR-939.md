## IR-939

**Requirement:** **A loading placeholder is announced once to a screen reader** (`docs/ui-ux/17-ui-states-matrix.md`: Loading is "announced once"). Paper View's `LoadingSkeleton`, the review tracker panel and the review timeline panel did not announce; they now do. No FR- id; subtask of IR-896. Supports **NFR-U3**, which is unchanged

**Design:** Jira IR-939 · [`../../ui-ux/17-ui-states-matrix.md`](../../ui-ux/17-ui-states-matrix.md)

**Implementation:** `PaperViewPage.tsx` (`LoadingSkeleton`), `ReviewRoutingTracker.tsx` and `ReviewTimeline.tsx` each wrap their skeleton in `role="status"` with one visually hidden line ("Loading this record…", "Loading the review tracker…", "Loading the review timeline…"); the shapes stay `aria-hidden` and unchanged. These use the plain pattern, not `LoadingRegion`, because that component adds a visible slow-load notice after 2 s and the ticket allows no change for a sighted reader. `e2e/smoke/support/states.ts` finds the three loading cells by role and name instead of `.animate-pulse`.

**Test:** `PaperViewPage.test.tsx` ("loading the record (IR-939)"), `ReviewRoutingTracker.test.tsx` and `ReviewTimeline.test.tsx`, each: one status, by role, with the words; and gone once the content draws. Seen failing before the change. Three IR-578 tests in `PaperViewPage.test.tsx` that did `findByRole("status")` straight after render now wait for the reader line first, since the skeleton is a status; their assertions are unchanged.

**Evidence:** 2026-11-15, `frontend/`: `tsc --noEmit` clean; `eslint` on `paper-view/` 0 errors; `npm run test:changed`: 21 files, 428 tests passed. The smoke tier's `forced-states`/`axe-states` specs were not run locally; CI runs them.

**What this does not show:** Whether a screen reader reads it aloud (manual, IR-414). Paper View's skeleton unmounts when the record draws, so nothing is announced twice; the page has no focus target while the skeleton is up, so none is lost.
