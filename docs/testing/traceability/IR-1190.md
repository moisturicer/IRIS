# IR-1190: Discover toolbar is one row, with Publish, on desktop and phone

[Back to the matrix](../TRACEABILITY.md)

**Requirements:** no FR- id. Epic IR-920 (S2 Epic: Frontend UI/UX Redesign). Takes over IR-1182 (phone Discover shows four rows of controls). Builds on IR-1187 (one Sort), IR-1188 (one Filters panel) and IR-1189 (My feeds leaves Discover); no ADR changes.

## What changed

- **One row under search, at every width.** Papers / People, Sort, Filters, the 1 / 2 / 3 column toggle (from `xl`, as before) and, for an author, Publish are one `flex` row. It no longer wraps (`sm:flex-wrap` is gone) and no longer scrolls sideways (`overflow-x-auto` is gone), so the Filters panel is no longer clipped by a scroll container either.
- **Papers / People moved from the page header into the row**, as its first control. This supersedes IR-1080's header placement. The header is now only the title and its line, which also lifts the first result on a phone.
- **On a phone the row fits 360 px by dropping words, not controls.** Below `sm` (640 px) Papers, People, Filters and Publish are icons whose word stays as `sr-only` text, so each keeps its accessible name; Sort's visible "Sort" label is `sr-only` and its select shrinks (`min-w-0 flex-1`) to take whatever width is left. The Filters count badge stays drawn. Every icon control is at least 44 x 44 px (`h-11 min-w-11`); the Sort select is 44 px tall. From `sm` each control shows its word again.
- **Over People the row keeps Papers / People and Publish.** Sort, Filters and the column toggle only narrow or order papers, so they are not drawn there; the switch does not move.
- **Publish still follows the server's `can_author`** and is absent from the row for anyone else.

## Tests

- **Changed deliberately** in `DiscoverPage.test.tsx`: "moves Papers and People out of the row and into the header" (IR-1080) is replaced by "holds Papers and People in the row, first"; the visible-text and scrolling-row checks are replaced by "keeps a name on every control that loses its word on a phone" and "makes every control 44 px square or more, and the row neither wraps nor scrolls"; control counts become 4 (author) and 3 (office reviewer). Added: the row stays, with Publish, over People, without Sort and Filters.
- **Added** `e2e/smoke/discover-toolbar.spec.ts`, run in the Frontend smoke tier in a real browser at 360, 768, 1280 and 1745 px: every control sits on one line (tops within 3 px), none overlaps another or passes the screen edge, the row computes `flex-wrap: nowrap`, `overflow-x: visible` and does not overflow itself, the page does not scroll sideways, the column toggle appears only from 1280, a phone's controls are each at least 44 x 44 px, Publish is absent for a user who cannot author, the first result starts inside a 360 x 740 screen, and the row survives the People view; and at 640, 700 and 1024 px with three filters on (the Filters count drawn) it is still one line. The Sort select can shrink at every width (`min-w-0`, `flex-initial`) so a tight row gives way there first.
- jsdom loads no Tailwind, so the vitest tests assert the class tokens that give these properties; the browser spec measures them.
