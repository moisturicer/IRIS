# IR-1340: one *Finish review…* for RDCO, and *+ Add a colleague* under the viewer's own office

[Back to the matrix](../TRACEABILITY.md)

**Requirement:** Hermoine Zozobrado asked for this on 2026-11-25 and started it on 2026-11-27. There is no FR- id. [ADR-032](../../adr/032-adviser-first-review-and-office-reviewer-pools.md) §10's amendment of 2026-11-27 holds the decision. It was accepted by Lee Jasmin Adolfo with PR #1025's merge on 2026-11-27, as relayed by Hermoine Zozobrado.

- RDCO's Review footer has one **Finish review…**, like every other reviewer. *Accept & publish*, *Keep unlisted*, *Request changes* and *Reject* are chosen in the dialog only.
- An embargo that holds publishing is still said in the footer, with *Release embargo…* where the viewer may release it.
- *Add a colleague* left the footer's menu. In Details → Reviewers it is a **+ Add a colleague** link under the viewer's own office, only where `add_reviewer` is granted.

## Design

- `ReviewFooterActions`: one *Finish review…* wherever `finish_review` is granted; the secondary pill is gone. `heldReason` falls back to the publish hold, so the embargo line and its release stay.
- `REVIEWER_FOOTER_ACTIONS` no longer adds `ADD_COLLEAGUE`.
- `addReviewerSeat` (in `reviewActions.tsx`) names the viewer's open office seat; `addReviewerAssignment` reads it.
- New `AddColleagueLink.tsx`: the link, named *Add a colleague to {office}*, which opens the existing add-reviewer dialog through `useReviewActionRunner`.
- `ReviewDetails` takes `addColleague` as `{ party, control }` and draws it inside that party's row.
