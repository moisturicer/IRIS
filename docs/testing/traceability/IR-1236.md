## IR-1236 · While IRIS researches, the page shows what the run reports it is doing, with Stop

Subtask 4 of the Ask IRIS redesign (IR-1229). While a run is queued or running, one quiet
block sits under the question: a heading ("Researching…", or "Thorough research…" when the
run's depth is `deep`), then only what the run already returns. Those are its `activity`
(the phase label and latest step, with the titles it read) and its `plan.steps`, shown as
done, in progress, upcoming or blocked. The page adds no step of its own, so a run that has
reported nothing shows the heading alone. The block sits in one polite live region
(`aria-live="polite"`, never assertive); the elapsed clock is outside what is announced.

The composer's send button is the Stop button ("Stop research") while a run is active, and
it uses the existing cancel call. Once the run is stopped, its question goes back into the
question box, focused, so the reader can edit and send it again. Nothing is sent by the stop.

**Implementation:** `frontend/src/features/ai/components/ReasoningBar.tsx` (the progress
block) and `RuntimeReader.tsx` (passes `activity`, `plan` and `depth`; restores the question
on Stop). Paper Chat mounts the same reader and gets the same block.

**Deliberate changes to existing tests:** `RuntimeReader.test.tsx` and
`RuntimeReader.starters.test.tsx` asserted "Thinking", a label the page itself supplied when a
run reported no activity, and that the plan stays hidden. Both now assert the heading and the
plan the run reports. The first also clears the question Stop put back before typing a new one.

**What the runtime reports:** `ai/runs/public.py` `activity()` returns a live label ("Waiting to
start", "Thinking" and the model phases) and only the **latest** tool step (kind and label,
plus the last three paper titles read); `plan` is whatever the agent wrote with `update_plan`
and may be null. The recorded fixture (`runtimeReader.recorded.json`) is a finished run, so its
`activity` is null and its plan has one done step. The running shape in the tests is built over
that recording in the shape `public.py` publishes. No live run was observed.

**Evidence:** `RuntimeReader.progress.test.tsx` renders a running run with activity and plan
and checks the heading, the polite live region, no assertive or alert element, every step's
status, `aria-current` on the step in progress and no blocking axe violation. A deep run is
headed "Thorough research…", a run that reports nothing shows the heading alone, and Stop sends
the cancel call and returns the question to the focused box. Colour contrast and the
reduced-motion spinner (`motion-safe:`) are not checkable under jsdom.
