## IR-908

**Requirement:** **Axe runs in a real browser on every routed screen in CI, failing on serious and critical findings (WCAG 2.x A and AA, contrast included), and each finding is fixed or filed with its screen and rule, not waived** — no FR- id; subtask of IR-896. Supports **NFR-U3**, which stays **PARTIAL**. **This change is the routes half only**: dialogs and the states matrix are not scanned here

**Design:** Jira IR-908 · [`../../../e2e/README.md`](../../../e2e/README.md)

**Implementation:** `e2e/support/a11y.ts` (`axeScan`, extracted from `A11yLedger.scan` so the journeys and the smoke tier fail on the same bar); `e2e/smoke/axe-routes.spec.ts` (one test per entry in `e2e/smoke/support/screens.ts`, the catalogue `viewport-coverage.spec.ts` holds equal to the router in both directions, so a new route cannot ship unscanned); `.github/workflows/frontend-smoke.yml` (an edit to `e2e/support/a11y.ts` now counts as a smoke-tier change). Each screen's full axe result is attached to its test. **Fixed by it:** the Import Records log `<textarea>` had no accessible name (critical, rule `label`); it now has `aria-label="Import log"` (`ImportRecordsPage.tsx`)

**Test:** `e2e/smoke/axe-routes.spec.ts` (28 screens, desktop width, signed in as the role each screen needs). It was seen to fail on the real defect above before the fix

**Evidence:** 2026-11-06, local, headless Chromium, `npm run build` in `frontend/`, then `npx playwright test -c playwright.smoke.config.ts smoke/axe-routes.spec.ts smoke/viewport-coverage.spec.ts --workers=2` in `e2e/`: 30 passed. Before the fix, 1 failed (Import Records, critical `label`, the log textarea). One earlier 4-worker run failed `my-reviews` and the same test passed alone and in the 2-worker run; its message was not kept, so it is read as load on a busy machine, not a result. `tsc --noEmit` clean in `e2e/`; `eslint` clean on the changed frontend file; `npm run test:changed` in `frontend/`: 9 files, 100 tests passed. **Not yet seen on GitHub Actions**

**What this does not show:** Dialogs and the states matrix (the other half of the ticket, so the card is not done by this change). Each route is scanned once, in its mocked happy state at 1280 px, with a few hand-built rows: an empty, error or loading state, a longer table, or a different role's view of the same route can still hold a finding. Axe covers what it can detect; keyboard and screen-reader use stay in IR-414's manual pass, so NFR-U3 is unchanged

**Status:** **PARTIAL** until the dialogs and states are scanned too, the workflow has run on a pull request and a reviewer has approved
