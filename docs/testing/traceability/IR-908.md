## IR-908

**Requirement:** **Axe runs in a real browser on every routed screen, every dialog and every state in the UI states matrix, in CI, failing on serious and critical findings (WCAG 2.0/2.1 A and AA, contrast included); each finding is fixed or filed with its screen and rule, not waived** — no FR- id; subtask of IR-896. Supports **NFR-U3**, which stays **PARTIAL**

**Design:** Jira IR-908 · [`../../ui-ux/17-ui-states-matrix.md`](../../ui-ux/17-ui-states-matrix.md) · [`../../../e2e/README.md`](../../../e2e/README.md)

**Implementation:** `e2e/support/a11y.ts` (`axeScan`, extracted from `A11yLedger.scan` so the journeys and the smoke tier fail on the same bar). In the smoke tier (`e2e/smoke/`, which gates every frontend PR): `axe-routes.spec.ts` (one test per entry in `support/screens.ts`, the catalogue `viewport-coverage.spec.ts` holds equal to the router, so a new route cannot ship unscanned); `axe-states.spec.ts` with `support/states.ts` (the cells of the states matrix that this tier can reach (loading, error, interrupted and revoked throughout, and empty where a mock reaches it), over Discover, Paper View, My Library's four views, Ask IRIS, My Reviews, the Office console and the review tracker and timeline panels; interrupted is a real request timeout, `makeReadsTimeOut`); `axe-dialogs.spec.ts` with `support/dialogs.ts` (each dialog opened and scanned, including the review actions, Publish, Submit new version, the coordinator's reassign and extend dialogs, the admin dialogs and the account-lock modal); `dialog-coverage.spec.ts` (fails when a dialog source file is neither scanned nor named in `UNSCANNED` with its reason); `support/open-screen.ts` (shared opening and settling, so contrast is not read mid-transition). `.github/workflows/frontend-smoke.yml` counts `e2e/support/a11y.ts` as a smoke-tier file.

**Fixed by it:** the Import Records log `<textarea>` had no accessible name (critical, `label`); text on the Cite dialog and the Notifications panel was `text-stone-400` on white, 2.52:1 (serious, `color-contrast`); the Publish and Files upload zone's accessible name did not contain the words drawn on it (serious, `label-content-name-mismatch`, WCAG 2.5.3), so the zone now takes its name from its content with the label leading. That last change altered the zone's accessible name from `Upload manuscript` to `Upload manuscript Drag and drop here, or browse …`, so the tests that found it by exact name (`UploadDropzone`, `PublishDialog`, `FilesSection`) now match the start of the name; no assertion was weakened beyond that. Also corrected: the Calls & Conferences mock in `screens.ts` had the wrong response shape, so the page was drawing its load-failed state and both the IR-910 matrix and the route scan were measuring that; it now returns a call, and the matrix looks the `All` filter up with its count.

**Test:** the specs above. Each was seen to fail on a real defect before its fix (Import Records, the Cite and Notifications contrast, the upload zone name)

**Evidence:** 2026-11-06, local, headless Chromium, `CI=true` (2 workers), `npm run build` in `frontend/` then the whole smoke tier in `e2e/`: 234 passed after the fixes above (28 route scans, 47 state scans, 28 dialog scans, 3 coverage checks, the IR-910 matrix and the earlier smoke specs); the states, dialogs and coverage specs re-run alone after the review fixes: 78 passed. `tsc --noEmit` clean in `e2e/`; `eslint` clean on the changed frontend files; `npm run test:changed` in `frontend/`: 24 files, 601 tests passed (it caught the `FilesSection` tests that a narrower run had missed). The routes half ran green on GitHub Actions on the first PR; this change has not yet run there

**What this does not show:** Matrix cells that exist but are **not scanned**, each needing a fixture this tier lacks: Discover's filtered-empty state and its timed-out "Load more"; the Saved view's empty and "no longer available" cells; My Reviews' per-tab empty copy; Ask IRIS's conversation-list failure and its no-sources state; the review tracker and timeline panels' empty copy. Seven dialog sources are not opened and are named with their reason in `UNSCANNED` (Paper Chat's dock, the reviewer name card, the review drawer, the comparison picker, the embargo dialogs, the file dialogs, and one dialog nothing renders yet); each needs a fixture the smoke tier does not have. A dialog is checked per source file: a file that holds several dialogs (`UserListPage`, `DiscoverPage`, `PublishDialog` past its first step) counts as scanned once a case opens one of them, so a second dialog added to it is not caught by the guard. Each route, state and dialog is scanned once, with a few hand-built rows, at 1280 px (the narrow Ask IRIS and review dialogs at 640 and 820 px). `/password/reset` and `/activate` are scanned in their invalid-link state only, `/ai/conversations/:id` as an empty chat and `/records/:id` as a Student. The review tracker and timeline panels' loading skeletons are `aria-hidden` and announce nothing; axe does not flag it and it was not changed. WCAG 2.2 rules are not scanned. Axe covers what it can detect; keyboard and screen-reader use stay in IR-414's manual pass, so NFR-U3 is unchanged

**Status:** **PARTIAL** until the workflow has run on the pull request, the unscanned dialogs have fixtures, and a reviewer has approved
