# IR-872: each version names the documents it was submitted with

**Requirements:** FR-M5-01 (a stable label only). The rule is [ADR-058](../../adr/058-each-version-keeps-its-text-and-its-files.md) §2 and its IR-872 amendment.

A version used to name only its manuscript. Each upload slot counted its own versions ("Consent form v2"), so nothing said which documents a paper version was reviewed with.

What changed:

- **`RecordVersionDocument`** (`apps/records/models.py`, migration `records/0031`) has one row per upload slot that held a file when a version was written. `write_version` writes them in the same transaction. A slot with no file gets no row.
- **"Added during vN"** is read from upload times (`versions.documents_added_during`), never stored. `versions_payload` now carries each version's `documents`, `documents_added` and `documents_reconstructed`, still only to viewers `may_read_review` admits.
- **Refused deletion, for everyone through the API, staff included:** a file a version names, or one that answered a document request (`versions.deletion_refused_reason`, enforced in `documents.services.delete_upload`). `upload` is `RESTRICT` in the database. The upload serializer exposes the reason as `delete_refused`.
- **Paper View** offers no Remove on a kept file and shows the reason instead. Every other removal, of a document version or an office file, now goes through a confirmation (`FilesSection.tsx`).
- **Backfill:** every existing version is flagged `documents_reconstructed`, and names each slot's newest upload made at or before it was submitted. An upload deleted earlier can't be known, which is why the flag exists.

**Evidence**

- `apps/reviews/test_version_documents.py` (8 tests, REST seam):
  - v1 names each slot's newest upload and nothing for an empty slot
  - an upload between versions is "added during" v1 and named by v2
  - a non-reader gets no versions
  - deleting a named file is refused for the owner and for RDCO
  - a draft's file can still be deleted
  - an unnamed upload between versions can be deleted
  - a file that answered a document request can't be deleted
  - the database refuses a direct delete, while a record's own delete still cascades
- `apps/records/test_version_documents_migration.py`: an old version names the newest upload made before it, a later upload isn't named, and both versions are flagged.
- `FilesSection.test.tsx`:
  - 3 new tests: a kept version has no Remove and shows its reason; Remove asks first and Cancel removes nothing; a refused removal keeps the dialog open with the server's reason
  - 1 existing test was **changed deliberately**: removing an office file now confirms first
