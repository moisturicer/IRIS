## IR-729 — Correct an invalid draft once before delivering the answer

**Basis and scope.** IR-729 under IR-714; authority ADR-049 §15–16. Adds the one bounded repair IR-728 reserved room for. Built on IR-728's loop and checks; human semantic review stays with IR-605.

**Code.**
- **Findings and feedback** (`ai/agent/assurance.py`). `findings()` returns each failing rule with the draft's own items that broke it (handles, bracket labels, numbers, titles, completeness phrases); `check()` is its sorted codes. `feedback()` turns findings into model-facing instructions, at most 8 items of 80 characters per rule, naming what to fix and never the reason code.
- **One repair** (`ai/agent/executor.py`). A draft that fails is first rechecked against its cited sources: a replaced, revoked or unreadable source ends the run (`source_changed`, `run_ended`, `unauthorized`) and is never repaired around. Otherwise the draft and the feedback are appended to the same ordered Conversation and one more turn is sent with the same instructions, tools declared and `tool_choice: "none"`, journalled as `model` phase `repair`. It goes through the same fitting, admission, deadline and Stop checks as every attempt, and is sent only while it fits the AskRun allowance after the usage already reported (`Budget.fits`); with `repair_tokens = 0` none is sent. Its usage counts in `reported_units`. A passing repair is rechecked against its sources and delivered.
- **When the repair fails, or none can be sent** (`assurance.supported_units`). There is no second repair. The repair, or the first draft if the repair was truncated, tool-only or never sent (no repair reserve, or no room left in the allowance), is split into lines and sentences; citations placed after a full stop stay with the sentence they close, so a citation never stands alone. Only sentences that cite a passage and pass every check on their own citations are kept, unchanged and in order, followed by a fixed limitation line (`assurance.LIMITATION`). The result is checked again and its sources are rechecked before commit. If no sentence stands, the run ends `unavailable` (`invalid_draft`).
- **What the reader sees.** Only the delivered text and its citations become the Turn, so live delivery and the reopened Conversation are the same rows. The refused draft and the feedback are never stored, the codes go only to the operator log, and the public projection (IR-730) carries no `model` events.

**Tests.** `apps/ai/tests/test_ai_runtime_agent_loop_contract.py` (52, no database, recording provider) adds:
- a bad page and a wrong count corrected once, with the repair request carrying the earlier request unchanged, then the draft, then feedback naming `9` and `912` and no code;
- a second invalid draft keeping only its independently supported sentence (an uncited sentence dropped) with the limitation;
- a citation after the full stop kept with its sentence, never delivered as a bare `[1]`;
- a truncated repair falling back to what the first draft supports;
- a source replaced before the repair fencing delivery with no repair sent; one replaced during the repair, and access revoked during the repair (`unauthorized`), each ending the run without delivery;
- no repair without a repair reserve, the first draft then keeping its supported sentences; no repair when reported usage leaves no room in the allowance; the repair's usage counted;
- Stop before the repair admitting no repair.

Four IR-728 tests changed deliberately: an invalid draft now gets a repair turn, so they script a second invalid draft and still expect `invalid_draft` (and three requests where counted).

Two mutations each failed the suite: removing the recheck before repair, and keeping uncited sentences when salvaging. A two-axis review (standards, spec) found the bare-citation case, which is fixed and tested here.

`apps/ai/tests/test_ai_runtime_agent_loop_db.py` (real PostgreSQL, restricted runtime login) adds the ticket's demonstration through the routes: a bad page and wrong count corrected once, the reopened Turn equal to the delivered answer with the citation on the right Record and page, and neither the refused draft nor any reason code in the run, its status or the Conversation; and a source rewritten by Django during the repair ending the run with no Turn. The invalid-draft test now scripts an invalid repair too.

**Evidence (2026-11-04).** From `backend/` with a local venv: `python -m pytest -n 0 -q apps/ai/tests/test_ai_runtime_*contract*.py` — every AI-runtime contract suite passed, IR-729's 52 included; `flake8` on the changed files is clean. The DB suite was **not run locally**: this machine's port 5432 belongs to another project's Compose stack and the IRIS database publishes no port, so it is left to CI.

**Not done here.**
- A provider failure, timeout or deadline during the repair ends the run `unavailable`; it does not fall back to the supported sentences.
- A clarification failing the checks is not repaired; it ends `invalid_draft` as before.
- Under admission each attempt is admitted separately, so a paid run's AskRun `max_attempts` also bounds the repair; IR-725's guard still withholds Record evidence from a paid provider.
- Numbers are checked against everything the whole draft cites (IR-728's rule), not bound to the citation beside them: a wrong count or page that happens to equal a number in another cited passage, its page, a coverage figure or an earlier Turn passes the whole-draft check. Salvage is stricter, per sentence. Typed exact counts are IR-750.
- Salvage judges sentences mechanically: an uncited claim inside a cited sentence, or a kept sentence that leaned on a dropped one, is not detected. These checks catch literal mistakes and never prove a claim true; human review stays with IR-605.
- When the repair yields nothing usable, salvage may keep sentences from the first draft that the repair had revised away; each still passes on its own citations.
- The recheck and the Turn write are still separate transactions (as in IR-728): a revocation in between is hidden on reopen by the store's stale-citation filter but not fenced at write time.
- Sentence splitting is punctuation-based (abbreviations such as "e.g." split a sentence).
- No route or worker change: the agent executor is still built only where IR-862 builds it.
