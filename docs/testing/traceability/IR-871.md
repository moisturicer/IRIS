# IR-871: each Version keeps its review text, read on campus without AI

**Requirements:** FR-M5-01 (a stable label only). The rule is [ADR-058](../../adr/058-each-version-keeps-its-text-and-its-files.md) §1 as amended 2026-11-05, and its IR-871 build notes.

Since IR-882 every paper starts embargoed and LlamaParse waits for a release, so a paper under review had no text a reviewer's comment could be anchored to or compared against. Each Version that changes the manuscript now gets its own **review text**, read from its own PDF on this server with pdfplumber and plain rules. No model is called and nothing leaves campus.

What changed:

- **The reader** (`apps/records/review_text/reader.py`) is pure: it imports pdfplumber and the standard library only. Its rules come from the prototype (`prototype/pdf-version-comparison`): running heads and page numbers dropped, line-end hyphens rejoined (a compound keeps its hyphen when the whole word appears elsewhere), ruled tables read as rows, two columns split at the gutter, `x_tolerance` 1.5. Three rules are new:
  - headings found by numbering and capitals as well as bold
  - table-of-contents lines and captions never taken for headings
  - warnings when sections may not have been found

  Building it found and fixed one prototype bug: the abbreviation check looked one character past the full stop, so "Engr." and "J." ended sentences.
- **The sandbox** (`sandbox.py`) runs the reader as `python -I reader.py` under its own required limits, `REVIEW_TEXT_WALL_SECONDS`, `_MEMORY_MIB` and `_MAX_PAGES`, the way IR-830 runs upload checks. Its exit code is the protocol, and only a clean exit's JSON is read back, after a size cap and a shape check.
- **Storage** (migration `records/0033`):
  - `ReviewText` is one manuscript file's reading: its state, reason, reader version, page count and warnings.
  - `ReviewTextSection` is one row per section: key, heading, page and text hash, with its sentences as JSON (text, page, paragraph, kind, regions in ADR-031's page fractions).
  - `RecordVersion.review_text` (`RESTRICT`) points each Version at its text. A metadata-only Version points at the previous Version's.
- **When it's read:** `write_version` calls `review_text.store.attach`, which queues `records.tasks.read_review_text` after commit, on `default`. Nothing asks the extraction gate or AI consent. A text that's already stored is never read again (`store.read_text` reads only `pending` and `unavailable` texts, and rechecks under the row lock).
- **Serving:**
  - `GET /records/<id>/versions/<n>/text/` serves the sections under `may_read_review`, with the same 404 as a missing Version for anyone else, audited as the Version's manuscript is.
  - `versions_payload` carries each Version's `review_text` state and message, for example *"No text for v2, so it can't be compared."*
  - The access matrix has a `record-version-text` entry.
- **Earlier Versions:** `manage.py read_review_texts [--dry-run] [--record N]` reads each Version that has no text from its own manuscript file, shares a metadata-only Version's, marks a missing file *"text not kept"*, and retries `unavailable` texts.

**Evidence**

- `apps/records/test_review_text_reader.py` (23 tests, pure, run on Windows): every reading rule above on PDFs drawn with reportlab, no socket opened, no Django or AI import, and every reading in the stored shape.
- `apps/records/test_review_text.py` (26 tests, database), one class per acceptance criterion:
  - v1 and v2 each keep their own text
  - read with no network, and the gate is never asked even for an embargoed paper with no consent
  - a metadata-only Version shares v1's text
  - withdrawing the last request keeps every Version's text
  - kept for the Record's life, whatever its ending
  - a scan stores "No text for v1"
  - an earlier Version is read from its own file, or marked not kept
  - served only under `may_read_review`
- `apps/records/test_review_text_isolation.py`: no module under `apps/ai/` or the `ai/` runtime names review text, and the review text package never touches the Extraction, the gate, chunks or embeddings.
- `apps/records/test_review_text_sandbox.py`: the real subprocess (Linux, so CI), plus each limit's refusal.

**First real paper, 2026-11-06.** Hermoine Zozobrado supplied two Versions of a real paper by a CIT-U author: a published 25-page, two-column journal article (v1), and a copy with one abstract paragraph lightly reworded (v2, 26 pages). The PDFs were read on this laptop only and deleted afterwards, and no text from them is recorded here. It wasn't a thesis.

The first reading was wrong in five ways the prototype's single-column papers couldn't show. All five are fixed in the reader:

1. **The journal's footer** sat at 91.6% of the page height, inside the 8% band the reader checked, and ran across both columns. It was read as a capitals heading on every page, cutting real sections at each page break, so 13 sections read as changed for a one-paragraph edit. Running heads and footers are now found by repetition across the page's whole width, in a 12% band, before any column split. A line must repeat on at least three pages, and a "CHAPTER N" line is never treated as one.
2. **Two headings were joined** as one wrapped heading: "Materials and Methods", 12 pt bold, over "Review Design…", 11 pt bold italic. A heading now continues only in the same font and size.
3. **Headings kept line-end hyphens**, such as "Accom- modation". These are now rejoined as in body text.
4. **A few stray mid-line hyphens in v2's edited paragraph** (for example "ad-justment", which pasting from a PDF leaves) made every later "ad-" / "justment" break keep its hyphen, because the prototype's rule kept a hyphen whenever the hyphenated form appeared anywhere. It now counts both spellings: the more common one wins.
5. **Two-column pages:**
   - Every line of a right-hand column became its own paragraph, because indents were measured from the page's leftmost text. They're now measured from the column's own left edge, with a 10 pt indent.
   - Page 1's full-width title stopped the column split, and its narrow side column fell outside the 30–70% gutter search. The search now covers 20–80%, and lines spanning the page above or below the columns don't count against the gutter. A band of columns must be at least five lines tall, which the prototype's single-column papers needed.

**After the fixes:**
- Both Versions read 50 sections and 732 passages, with no warnings.
- The comparison marks exactly two sections changed:
  - **the abstract**, with the five reworded phrases and v2's stray hyphens
  - **the front matter**, where the longer abstract pushes two lines of page 1's "How to cite" box onto the right column in v2, a known limit of this journal's front page
- Every other section reads unchanged, including those pushed onto a later page.
- **Correction:** an earlier note here said the PDF's font had no character for its curly quotes and dashes, so they read as `�`. That was wrong. The reader keeps them as real Unicode (’ “ ” – —). The `�` was the Windows console failing to print them, and pypdf's output went through the same console.
- The prototype's four PDFs still read the same sentences as the prototype.

Each fix has a test in `test_review_text_reader.py`, drawn with reportlab (`testing.journal`, `testing.headings`), and the reader tests give **31 passed**. On Linux, the affected set gives **158 passed, 0 skipped**.

**Fail safe for any field's format, 2026-11-06** (ADR-058 build note 5 as amended): no rule set covers every college's layout, so the reader now refuses to guess.
- Sections in a shape no real paper's headings take make the paper one `document` section, with a `sections_unreliable` warning that names the shape. Every sentence keeps its page and regions.
- A heading wraps onto three lines at most.
- A font-size change starts a new paragraph, so footnotes, captions and block quotes stay apart from body sentences.
- Text that is mostly unmapped characters is stored as *No text for vN*.

Each rule has a test in `test_review_text_reader.py`, which gives **39 passed**. The real article still reads 50 sections, and only its abstract and front matter differ. The prototype's four PDFs still read the same sentences.

**Papers from other fields, 2026-11-06.** Hermoine Zozobrado supplied five more real papers by CIT-U authors, kept in an ignored `samples/` folder and never committed:
- a second pair: an engineering short paper and a reworded copy
- a banking statistics article
- a journal paper with numbered headings
- a conference paper with roman-numeral headings

They exposed four more patterns, each now a rule with a test:
- **Identifiers from references read as capitals headings**, such as `ICCOINS.2016.7783277`, a DOI, or `QUADCOPTER_CONTROL…`. A heading must now be words: at least four letters, no underscore or slash, and at least half its tokens words.
- **Years read as numbering.** Section numbers now run to two digits.
- **Small capitals split a heading**, as "I NTRODUCTION". The word is rejoined.
- **Roman and lettered numbering stayed in section keys.** "II." and "A." are now stripped like "2.1".

Results:
- References are one section again in both journal papers.
- The engineering pair differs only in its two edited sections.
- The first pair still differs only in its abstract and front matter.
- All five single papers read with no fallback needed.

Journal front pages still give a few minor sections (author names, numbered affiliations). That's front matter, left as it is. Reader tests: **54 passed**.

**Open (merging):** this was a journal article in two columns with a constructed edit, not two Versions of a CIT-U thesis. Whether it meets the card's acceptance criterion is the reviewer's call. A thesis in the single-column CIT-U format, revised by its authors, would still test the layout the reader was built for.

**Not changed:** the FR-M5-01 row's status.
