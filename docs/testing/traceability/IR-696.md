## IR-696 Any signed-in user opens a person's public profile: their papers, advised papers and collaborators (NFR-S4)

**Basis and scope.** IR-696, subtask 2 of IR-694 (public profiles and people search), built on IR-695's photo, bio and research interests. The backend half; the page that reads it is IR-700 (merged), and the Profile tab on your own account is IR-949. The contract is the one agreed with Hermoine Zozobrado on 2026-11-07 and written out in [IR-700](IR-700.md) §"IR-696 contract". It differs from the Jira description in one place: **there is no ORCID iD** (decided 2026-11-07; IR-695 dropped the field).

**Decisions.**

- **One predicate for "has a profile"** (`open_profiles`): active, verified, not locked, and a role of Student, Adviser, ITSO, IERC, KTTO or RDCO. A suspended, inactive, unverified or role-less (unapproved) account, a System Admin and a missing id all answer the same `404 {"detail": "Not found."}` on all four routes, byte for byte, so the API never confirms a hidden account exists. The two flags on a record, the collaborators list and the 404 all use it, so a name never links to a page that answers 404. The caller's own suspended account is hidden from them too.
- **Papers use Discover's predicate.** `Record.objects.visible_to(viewer)` narrowed to `PUBLICLY_VISIBLE_STATUSES` (the published catalogue), plus an explicit exclusion of Proposals; soft-deleted papers are already out of the default manager. A person does not see their own drafts on their own Profile.
- **Never returned.** Each payload is built field by field, not by serializing the account, so a field added to `User` later cannot leak into it. A test asserts that no response, for any role of subject, contains an email address, coordinator, lock, verification or credential text.
- **Collaborators** are accounts that were both among a published paper's owners or its Adviser, so co-owners and Adviser-with-advisee both count, once per paper. Byline authors are names, not accounts, and never count. Accounts without an open profile are left out.
- **No totals anywhere.** Lists return `{next, results}` with no `count`; one extra row is read to know whether a page follows. A page past the end is empty rather than an error, since a paper can leave the list between two reads. `page` and `page_size` must be whole numbers of 1 or more (else 400); a `page_size` over 50 is capped at 50.
- **`views` is `Record.access_count`.** Newest first is `created_at` descending, as Discover orders it: there is no separate publication timestamp.

**Needs a decision (reported, not settled here).** IR-700's `ProfilePaper.views` comment calls the figure "distinct accounts that opened it". `access_count` is not distinct: it rises by one on every `POST /records/<id>/increment_access/`. The API sends what the card asks for, "each paper carries its view count", and it is the frontend's comment, or the counter, that has to change.

**Tests.** `apps/accounts/test_public_profile.py`, all at the HTTP level: the profile's exact key set and values for a Student, an Adviser and each office; empty values; the photo path; that no security or contact text appears in any response; own profile; signed-out 401 on every route; every hidden account (suspended, inactive, unverified, unapproved, System Admin) answering the missing id's 404 byte for byte on every route, including from RDCO's and the person's own session; research and advised lists; drafts, in review, unlisted, rejected, approved, pending-delete, soft-deleted and Proposal papers never listed; a paper's exact fields and no totals; newest-first paging with a null `next` and no `count`; the `next` link; a page past the end; bad page and size refused; an oversized size capped; collaborators as co-owner, Adviser and advisee, with counts, never themselves, published only, no byline-only names, hidden accounts left out, ordering and paging; and the record-detail flags, including that each agrees with whether the profile opens. The matrix declares the four routes as `SIGNED_IN`, and `RouteDeclarationTests` fails on any left undeclared.
