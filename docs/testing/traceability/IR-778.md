## IR-778

**Requirement:** **The account menu's accessible name begins with the name and role it shows** — no FR- id; WCAG 2.1 2.5.3 Label in Name, found by IR-631's axe run (`label-content-name-mismatch`, serious). Touches NFR-A1

**Design:** Jira IR-778 · [`../ui-ux/12-accessibility.md`](../../ui-ux/12-accessibility.md)

**Implementation:** `components/layout/AccountMenu.tsx`: the trigger has no `aria-label`; its name is computed from the visible name and role, with a screen-reader-only comma between them and a screen-reader-only ", account menu" outside the wrapper that is itself screen-reader-only on the collapsed rail

**Test:** `components/layout/Sidebar.test.tsx` "is named by the name and role it shows", expanded and collapsed: the name is exactly `Ana Adviser, Student, account menu` and no `aria-label` stands beside it. jsdom's axe passed the old label too (no layout), so the rule itself is checked in a browser
