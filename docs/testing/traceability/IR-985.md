# IR-985 — Unstructured client: a StructuredExtractor over the Platform API

**Affected requirement labels:** none by FR- id. This builds part of [ADR-067](../../adr/067-unstructured-replaces-llamaparse.md) under the IR-980 spec. No other matrix row changes status.

## Scope, corrected to the ADR

The card asked for the Transform API (`/api/v2/parse`, 202 polling, a vendor registry). ADR-067's 2026-11-14 amendment replaced Transform with the **Platform partition API on `strategy=hi_res`**, and decision 1 rules out a second selectable Extractor and the registry. The ADR outranks the card, so this follows the ADR; the correction is recorded on the card.

## What changed

- `backend/apps/ai/extraction/unstructured_client.py`: `UnstructuredExtractor` posts the PDF to `/general/v0/general` with the amendment's options. Each attempt's timeout is base + per page × pages, and one timeout is retried; the request options record that (`call`).
  - 401, 402, 403, 408, 429, 5xx, network faults, a second timeout or a non-list answer → `ExtractorUnavailable`.
  - A 4xx listing field errors (our request was wrong) → a permanent `ExtractionError`; any other 4xx, such as the recorded 422 for a broken PDF → `DocumentRejected`. An answer with no text element (only `PageBreak`) → `EmptyExtraction`. An unreadable PDF is rejected before anything is sent.
  - `raw` is `{"elements": [...]}` with signed URLs removed. `Usage.pages` comes from `x-num-pages`. Provenance is `unstructured` / `general/v0:hi_res`, because the API returns no model identifier.
  - The endpoint returns no upload or job id, so there is nothing to delete; what it retains is ADR-067 open condition 1.
  - The request options record the call policy and the attempts actually made (`call`).
- `selection.unstructured_extractor()` builds it, refusing a missing `UNSTRUCTURED_PLATFORM_API_KEY` or a host other than `api.unstructuredapp.io`. `EXTRACTION_BACKEND` still accepts only `llamaparse`.
- Settings `UNSTRUCTURED_*` in `config/settings/base.py` and `backend/.env.example`. Compose needs no change: `celery-extraction` already joins `egress`, which cannot filter by host (SECURITY §7).
- `tests/fixtures/unstructured_platform/`: Platform `hi_res` recordings of the four synthetic fixtures, a blank PDF and a non-PDF (422), made with `record_unstructured_platform.py` on 2026-11-14.

## Evidence

Run 2026-11-14 after IR-986 merged: `test_unstructured_client.py`, `test_contract.py`, `test_llamaparse_client.py`, `test_selection.py` and `test_shaping_unstructured.py` together: 162 passed, 16 skipped (LlamaParse's document clauses, skipped as before), 5 xfailed.

The contract now runs IR-986's shaping over the Platform recordings. Eleven of the sixteen layout clauses pass. The five strict xfails are vendor or shaping gaps, each named in `KNOWN_GAPS`:

- `two_columns` reading order: `hi_res` misorders the synthetic fixture (ADR-067 amendment §3 judges order on real pages instead).
- `figures` reading order and boxes: Formula OCR is withheld until it is transcribed (ADR-067 formula amendment).
- `table_across_pages` reading order and boxes: `hi_res` reads the table as one-column rows and leaves page 2's rows as text. IR-986's shaping assumed Unstructured joins a split table, which holds for Transform but not for this Platform recording.

**Test change, deliberate:** `contract.py` now accepts the labeled-structure kinds (`header`, `footer`, `table`) that both real shapers emit, alongside the legacy ones. It also compares a column's left edges within its own `TOLERANCE` rather than exactly. Neither clause could pass for a real Extractor before, and the in-memory adapter still passes.
