## IR-1310

No FR- id. Supersedes IR-534's B2 dot (noted in [`IR-534`](IR-534.md)).

**Requirement:** My Library's sidebar item says how many of the user's records wait on them (a revision or a document was asked for), as Notifications and My Reviews already show their counts. It showed only a dot (IR-534, B2).

**Design:** The count is the `needs_action_mine` figure the sidebar already read from `/dashboard/stats/`. It goes through the same badge as the other counts: the number, "9+" from ten, the real count for a screen reader, and a dot in its place on the collapsed rail. A screen reader hears "My Library, N waiting on you"; the ticket's "need your action" reads wrongly for one record, so the wording is number-neutral.

**Implementation:**

- `frontend/src/components/layout/Sidebar.tsx`: `library` moves from the dot map to the badge map, with `badgeWord` "waiting on you". The number-less dot, which only My Library used, is removed from `NavItem`.

**Test:**

- `Sidebar.test.tsx` ("the My Library count"): the number shown and named; "9+" with the real count named; no badge when nothing waits or when the read fails; still named with the count on the collapsed rail. These replace IR-534's three dot tests, deliberately: the behaviour they asserted is what this ticket changes.

**Evidence:**

- **2026-11-23, locally:** Vitest over `Sidebar.test.tsx` passed: 86 tests. The three new count tests failed before the change. `tsc --noEmit` and ESLint on the changed files were clean.

**Status:** **PARTIAL** until CI passes and the PR is reviewed.
