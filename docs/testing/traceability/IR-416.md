## IR-416

**Requirement:** **Record versions: v1 at submission, the next at each resubmission, a review made against one, and the version picker** — ADR-032 §14's T2; touches FR-M5-01 (stable label only)

**Design:** [ADR-032 §5, §13](../../adr/032-adviser-first-review-and-office-reviewer-pools.md), each with its 2026-10-08 IR-416 Amendment · design settled with the project lead 2026-10-08 (grilling; 14 decisions in Jira) · [frontend_redesign_spec](../../frontend_redesign_spec.md) §4.6, §4.11 · Jira IR-416

**Implementation:** `RecordVersion` (`records/0014`): number, cause, and `manuscript`, a nullable file field naming the stored manuscript file, because the manuscript is `Record.abstract_file` and not a `RecordUpload`. `Review.version` (`reviews/0011`). `apps/records/versions.py`: `write_version` is the one writer, called by the legacy submit, `routing.enter_at_adviser`, the legacy `resubmit_record` and the seed; every path that writes a Review stamps the latest version. The manuscript lock: replacing or clearing `abstract_file` is refused unless the record is `draft` or legacy `declined`, staff included. The backfill (`records/0015`): one version per non-draft record, v1 or v(k + 1) after k resubmissions, nothing made up; every existing `Review.version` stays null. Read side, participants only (`may_read_review`): record detail's `versions`, the tracker's `versions` and each review's `version`, and `GET /records/<id>/versions/<n>/manuscript/` (404 otherwise; audited as a `DOWNLOAD` with the version). Frontend: the header's version picker with two or more versions, `?version=N` with a banner, no citation page or highlight on an earlier version, Paper Chat's note that answers are about the current version, and the timeline's version entries and per-review version tags

**Test:** `apps/records/test_record_versions.py` (REST seam, one class per criterion; includes a source sweep that no module deletes a manuscript file) · `apps/records/test_version_backfill_migration.py` · `paper-view/PaperViewPage.test.tsx` ("record versions (IR-416)") · `paper-view/timelineEntries.test.ts` · `paper-view/ReviewTimeline.test.tsx`

**Evidence:** CI on the IR-416 PR (flake8, `makemigrations --check`, pytest, lint, Vitest, build); per the team rule these were not run locally
