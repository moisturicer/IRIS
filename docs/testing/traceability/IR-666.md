# IR-666

[Back to the matrix](../TRACEABILITY.md)

**Uploads are scanned for malware before anyone can open them.** ASVS 4.0.3 12.4.2 (Level 1). Built to [ADR-072](../../adr/072-uploads-scanned-for-malware.md), accepted as written by Ashlee Sean on 2026-11-16 after she chose its four main options (ClamAV, during the upload, fail closed, ADR first). Written 2026-11-16.

## What changed

- **The scanner** (`backend/apps/documents/scanning.py`): ClamAV's `clamd`, reached over TCP with `INSTREAM` (`ClamdScanner`).
  - `scan_problem(file)` answers None (store it), "This file was flagged as unsafe and was not uploaded.", or, when the scanner can't answer, "File checking is temporarily unavailable. Please try again shortly." (fail closed).
  - `upload_problem(file, user=, where=, record=)` is what every intake path calls. It audits a refusal as `UPLOAD_REFUSED_UNSAFE`: who, where, the file's SHA-256, size and name, and the signature, never the bytes.
- **Every intake path scans**, after the existing PDF checks and before anything is written:
  - an owner's slot upload, new and as a new version, and a document a request asks for (`documents/views.py`);
  - an office's attachment, **of any type**;
  - the Manuscript at Publish and on edit (`RecordWriteSerializer.validate_abstract_file`);
  - each PDF in RDCO's bulk import (`check_import_pdf`);
  - a profile photo, though it is re-encoded;
  - `load_corpus`.
  - A test fails if a module checks uploads as PDFs without scanning them.
  - RDCO's import spreadsheet is parsed in memory and never stored or served, so it is not scanned (ADR-072: "before it is stored").
- **Fail closed, and never off in production.** With `DEBUG` off, Django refuses to start unless `MALWARE_SCAN=clamd` and `MALWARE_SCAN_HOST` is set (`documents/apps.py`). With `DEBUG` on, `MALWARE_SCAN` defaults to `off` (`development.py`), so teammates need no container; each upload is then logged as stored unscanned.
- **Files stored before scanning** are scanned once by `manage.py scan_stored_uploads` (`--dry-run` reports only). A file that fails:
  - its bytes move to `QUARANTINE_ROOT`, outside `MEDIA_ROOT`;
  - every row naming it keeps its history but loses the file. No row is deleted: a version's documents are `RESTRICT`ed;
  - `FILE_QUARANTINED` is audited;
  - its uploader and RDCO are told ("File Quarantined", `notifications/0014`).
  - The download paths answer "This file is no longer available." (404) for a slot upload or attachment with no file, and the ZIP of all files skips it; a Manuscript with no file already answers as having none.
  - If the scanner doesn't answer, the run stops and changes nothing more.
- **Audit types:** `UPLOAD_REFUSED_UNSAFE` and `FILE_QUARANTINED` (`audit/0032`), described in `docs/evaluation/AUDIT_EXPORT.md`, and grouped under Files in the Audit Log.
- **Compose:**
  - Production gains a `clamav` service (`clamav/clamav:stable`) on `private` and `egress`, with no published port.
  - Its settings are `StreamMaxLength` 60M (above the 50 MB upload cap; clamd's default is 25 MB) and `ConcurrentDatabaseReload no`.
  - It has a signature volume, a health check and a 1.5 GB limit, and every Django service gets `MALWARE_SCAN_HOST=clamav`.
  - The backend keeps a `quarantine` volume.
  - Development gains the same service under the opt-in `scan` profile.
  - The e2e overlay makes the backend wait for ClamAV to be healthy.
- **CI:**
  - a new `malware-scan` job starts the real ClamAV and runs `test_real_clamav.py` (EICAR refused, a clean PDF passed, a 49 MB file taken), failing if it was skipped;
  - the production-settings step proves production boots with a scanner and refuses without one or with `MALWARE_SCAN=off`.
- **Docs:**
  - the checklist's 12.4.2 is now Pass;
  - SECURITY.md's risk 2 is narrowed to unknown malware;
  - ADR-053's gap now names ADR-072;
  - `deploy/README.md` gains the one-time command and the memory figure.

## Tests

Run locally by Claude Code at Ashlee Sean's direction, 2026-11-16, on a throwaway `pgvector/pgvector:pg16`. The PDF checks need Linux, so the backend tests ran inside the project's `iris-backend` image, against a real ClamAV (`clamav/clamav:stable`) started locally.

- `apps/documents/tests/test_scanning.py` (13):
  - the clamd client against a stand-in speaking clamd's protocol on a real socket: clean, a named signature, an error and a closed connection as unavailable, nothing listening;
  - the test scanner;
  - fail closed;
  - production refusing to run with scanning off or no host.
- `apps/documents/tests/test_upload_scanning.py`:
  - the EICAR file sent as an office attachment is refused, never reaches storage, and is audited without its bytes;
  - a clean file is stored;
  - a scanner that is down refuses;
  - a slot upload, a profile photo and an import PDF the scan flags are refused and audited with their path;
  - every PDF-checking module also scans.
- `apps/documents/tests/test_real_clamav.py` (3, against the real ClamAV): EICAR flagged as `Eicar-Test-Signature`, a clean PDF passed, a 49 MB file taken.
- `apps/documents/tests/test_scan_stored_uploads.py` (5):
  - a dry run changes nothing;
  - a real run quarantines an infected attachment and an infected Manuscript named by a Record and its version, and leaves a clean file;
  - the rows stay and are emptied;
  - audit and notices;
  - a quarantined file answers 404 "no longer available";
  - idempotent;
  - a scanner that is down stops the run with nothing changed.
- **Measured against the real ClamAV:**
  - about 1.0 GiB with signatures loaded;
  - a 45 MB file scanned in 2.8 s.
  - **A valid PDF carrying the EICAR string in a comment is not flagged.** ClamAV flags EICAR only at the start of a file, as the EICAR standard defines it. So the test scanner flags EICAR only there, and tests that need a valid PDF or image use a marker it is told to flag.
- Compose: both files validate (`docker compose config`) and `check_compose_prod.py` passes.

Not checked: the scanner on iris-demo, which is off; its memory there and the one-time `scan_stored_uploads` run happen at the deployment that ships this.
