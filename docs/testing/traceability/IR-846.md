# IR-846 — Source Publish suggestions from LlamaExtract behind IR-833's suggestions contract

**Affected requirement labels:** none by FR- id. This implements [ADR-056](../../adr/056-manuscript-extraction-moves-to-llamaparse.md) decision 15 inside the Publish contract IR-830 owns (via IR-833 and IR-834). It changes where a LlamaParse Manuscript's suggestions come from, not the journey. No other matrix row changes status.

## What changed

**One read of the parse** (`backend/apps/ai/extraction/llamaextract_client.py`). `LlamaExtractReader.read(parse_job_id)` posts to `/api/v2/extract` with the completed LlamaParse job (`pjb-…`, from the stored `raw_result`) as `file_input`. Nothing is uploaded or parsed again. The request carries one fixed schema (title, authors, abstract, keywords, publication year), `cite_sources` and `confidence_scores`, a pinned version and tier, and `extraction_target: per_doc`. The reader polls, then fetches with `expand=extract_metadata` and `expand=usage`. A vendor or network fault is `ExtractorUnavailable`; a failed job is an `ExtractionError` whose text never carries the vendor's message.

**Gated and admitted** (`apps/ai/admission/extraction.py`, `apps/ai/admission/limits.py`). `AdmittedMetadataReader` follows IR-850's `AdmittedExtractor`:
- refused unless admission enforces;
- reserved at pages × `AI_ADMISSION_METADATA_CREDITS_PER_PAGE` × `AI_ADMISSION_EXTRACTION_CREDIT_USD`, on the `extraction` lane;
- the disclosure gate is read again just before sending;
- settled to the `extract_credits` reported.

The price is required and has no default. A set `LLAMAEXTRACT_VERSION` is checked at startup, as `_verify_llamaparse` is: key, tier, a known region, and no `latest` outside development.

**Bound and fenced by source revision** (`apps/documents/models.py` `ManuscriptMetadata`, migration `documents/0020`, `apps/documents/tasks.py`).
- When a LlamaParse Manuscript read completes, and `LLAMAEXTRACT_VERSION` is set, one `ManuscriptMetadata` row is created for that extraction and source revision, and `read_manuscript_metadata` is queued on `extraction`.
- The task claims the row under the Record lock and refuses once the Record's Manuscript has moved on. It writes back only under the same fence and its own attempt token, so a replaced Manuscript's late reading never lands.
- A gate refusal is stored as `refused`, anything else as `failed`. Neither is retried: Publish falls back at once.

**The suggestions** (`apps/records/metadata_suggestions.py`, `apps/records/extracted_metadata.py`). For a LlamaParse extraction:
- If the disclosure gate now refuses the paper, `unsupported`.
- While its reading is queued or running, `pending`. A reading is treated as dead `LLAMAEXTRACT_TIMEOUT_SECONDS` + 120 s after a worker claimed it (`started_at`), or after it was queued if no worker ever did.
- If the reading is `done`, each field fills IR-833's entry with `source: "llamaextract"`, `basis: "cited_text"`, `page`, `region`, `matching_text` and `confidence`.
  - `region` is the union of the parse's grounded line boxes holding the cited words, compared word for word on that page.
  - `confidence` is LlamaExtract's own number, or `null`; IRIS never computes one, and an array field's per-item scores are never combined.
  - The top-level `source` is `llamaextract`.
- A `done` reading from which no field could be read counts as a failure.
- Otherwise it falls back to the shaped document (IR-840) read by IR-833's title and abstract rules. LlamaParse papers are not read for labelled front matter.

The Docling path is unchanged until IR-843. The legacy `suggestions` projection stays. No vendor payload, job ID, credits or storage path is exposed.

**Auto-apply.** Only a title or abstract, and only when all four hold:
- `PUBLISH_AUTOFILL_MIN_CONFIDENCE` is set (0–1, no default; malformed refuses to start);
- the reported confidence reaches it;
- the cited text, and the value itself, are found on the cited page of the parse;
- the value is within its limit.

Unset, nothing is ever filled in unasked. Authors, keywords and year are always offered. IR-833's client rules still decide whether an `auto_apply` value may replace what is in the field.

**One additive field, `low_confidence`.** It is `true` only when a threshold is set and the reported confidence is below it. The frontend shows it as words and never compares or shows a number. *Divergence:* the ticket lists the per-value fields and says "nothing else changes". This flag was added so that no threshold has to live in the client.

**Publish** (`frontend/src/features/publish/`).
- Every suggestion and filled-in note says "Found on page N", or "Found in your PDF" when no page is known.
- It quotes the PDF's matching text where it differs from the value.
- A `low_confidence` value says "Check this against your PDF."
- *Show in PDF* (`PublishDetailsPreview`'s `useShowInPreview`) turns the IR-834 preview to the page and highlights the region. On a narrow screen it opens the preview pane and moves focus there; side by side, focus stays in the form.

## Behavioural evidence

- `backend/apps/ai/extraction/tests/test_llamaextract_client.py` (7, `httpx.MockTransport`). Covers:
  - the exact request: the parse job, fixed schema, citations and confidence on;
  - a failed job's message not leaking;
  - 503, 429 and connection errors as unavailable;
  - the time budget;
  - only extract credits reported.
- `backend/apps/documents/tests/test_manuscript_metadata.py` (8, real Postgres, committed transactions). Covers:
  - a LlamaParse read queues one reading of that parse;
  - none is queued when LlamaExtract is unset, or for a local read;
  - the reading names the parse job and is admitted and settled (15 credits → 18,750 µUSD);
  - consent withdrawn before sending is not sent, and its reservation is released;
  - an unpriced reading is refused;
  - a vendor failure is stored without its message;
  - a replacement during the reading keeps the late result out.
- `backend/apps/records/test_metadata_llamaextract.py` (21, IR-833's owner-only REST seam). Covers:
  - provenance, and a region found across two columns;
  - no citation; cited text not in the parse; an unreported confidence;
  - threshold unset vs set, low confidence, a confident title with no citation or unfound text, and an overlong title — none of them filled in;
  - malformed values, and nothing but the five fields;
  - no leak of the vendor payload, job IDs, credits or the file name;
  - pending, a dead reading falling back, failure falling back, no reading, and a previous revision's reading never shown;
  - a gate that now refuses gives `unsupported`;
  - a non-owner gets 404.
- `frontend/src/features/publish/PublishDialog.test.tsx`, "read by LlamaExtract (IR-846)" (4): page and quote; "Check this" with no number shown (and axe); Show in PDF moving the reader to the page with one highlight; no Show in PDF without a page.

**Deliberately changed tests.** Three IR-833 assertions expected "Found in your PDF, page N". They now expect "Found on page N", the wording this ticket asks for. No author-control assertion changed.

**Not recorded.** The LlamaExtract payloads in `apps/ai/extraction/tests/llamaextract_vendor.py` are **authored** from LlamaIndex's documented v2 response format (`/llamaparse/extract/api`, `/llamaparse/extract/guides/response-format`, read 2026-11-03), shaped to the `two_columns` recording. They are not a recording. The ticket asks for recorded output extending IR-849. That needs a development key and spends credits; it is a follow-up.

## Executed checks

Backend single files ran in a throwaway container from the local `ir-834-backend` dev image, against its Postgres, with only CI's environment variables. All passed:
- the three files above;
- `test_metadata_autofill.py` and `test_metadata_suggestions.py` (IR-833, unchanged behaviour);
- `test_offcampus_extraction.py` (IR-850), `test_selection.py`, `test_celery_routing.py`, `test_limits.py` and `test_enum_vocabulary.py`.

`makemigrations documents --check` reports no changes.

**After review (second commit).** The fixes for the code review — startup check, claim-timed staleness (`started_at`, added to the unmerged migration `0020`), fallback on an empty reading, the value check before auto-apply, wide-screen focus — were **not run locally**: Docker was unavailable. The changed Python byte-compiles; the tests are left to CI. The migration has not been tried on a copy of a realistic database.

The frontend tests were **not run locally**: this machine has no complete `vitest` install. They and the full suites are left to CI.

## Not done here

- **Price (ADR-056 open condition 3) is not confirmed.** `AI_ADMISSION_METADATA_CREDITS_PER_PAGE` is required with no default. LlamaIndex's pricing page listed 15 credits a page for the `agentic` extract tier on 2026-11-03; that is not a written confirmation. It is not yet in IR-851's cost per paper.
- **Not checked against the vendor:**
  - that LlamaExtract accepts a parse job whose uploaded file IR-841 has already deleted (decision 7) and which ran with `disable_cache`;
  - how long the parse job stays readable.
  A recording would show both.
- No measured `PUBLISH_AUTOFILL_MIN_CONFIDENCE`; auto-apply stays off until one is chosen.
- Browser checks (keyboard-only run, narrow viewport, contrast) are not recorded.
