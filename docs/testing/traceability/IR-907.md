## IR-907

**Requirement:** **For each cell of the UI states matrix, a Playwright test forces the state by intercepting the request (delay, empty body, error status, aborted event stream, 403 or 404 after a permission is withdrawn) and asserts what the user sees and can do next; an interrupted Ask IRIS stream shows an interrupted state with a working retry** — no FR- id; subtask of IR-895. Supports **NFR-U3**, which is unchanged

**Design:** Jira IR-907 · [`../../ui-ux/17-ui-states-matrix.md`](../../ui-ux/17-ui-states-matrix.md) · [`../../adr/061-request-timeout-cancellation-and-retry.md`](../../adr/061-request-timeout-cancellation-and-retry.md) · [`../../../e2e/README.md`](../../../e2e/README.md)

**Implementation:** all in the smoke tier (`e2e/smoke/`, which gates every frontend PR; no application code changed).
- `forced-states.spec.ts` runs every entry of `support/states.ts` (IR-908's catalogue, which now also names the one read that decides each state, what it answers when it works, and what then proves the screen drew it). **Loading**: the read is held, not failed; a placeholder shows, no sibling state shows and no retry is offered; released, the content replaces it. **Empty**: the empty words, no retry, and the screen's next step where it has one. **Error** (500): says so, offers Try again, which reads once and brings the content. **Interrupted**: a real request timeout (`makeReadsTimeOut`, scoped to the read under test), Retry and not Try again, nothing retried by itself (ADR-061), Retry reads once and brings the content. **Revoked** (403 and 404): the not-available screen, no retry, the way out where there is one; a second test per view compares the visible words of the 403 and 404 screens and fails if they differ (IR-153). Two further tests withdraw access after the reader has been in the product: Discover then a Record that now answers 404 when the card is opened, and an open Conversation that now answers 403 when its address is reloaded (a fresh read, not a re-read inside the page).
- `forced-cells.spec.ts`: the cells that need a second read or another fixture. Discover's filter that matches nothing (and Clear filters), a failed Load more and a timed-out one (the list stays, Try again loads the rest); Saved's empty copy and a save the reader can no longer read; Ask IRIS's conversation list failing and timing out (in place, with Try again or Retry), a new chat's opening, and an answer with nothing to cite; My Reviews' In review and Done tab empties; the review tracker's and timeline's empty copy.
- `ask-iris-stream.spec.ts`: the Ask IRIS event stream delayed, cut, failed and ended. A held stream shows "Waiting…" and then the answer. Request-bound: cut after some text (kept, "cut off" notice, composer free, asking again works), a stream with no answer in it, a 503, a connection reset. Queued run: a dropped connection reconnects from the last event id and finishes; reconnects that bring nothing stop after three; a run that failed and a run that expired (`run_failed`) say why and **Retry starts a new linked run that answers**, once per click; a run the reader stopped; a Retry the server refuses keeps its Retry and works on the next try; reopening a Conversation whose last run ended unanswered shows why with a working Retry.
- `forced-coverage.spec.ts` with `support/matrix-proofs.ts`: reads the matrix document. A cell not marked N/A needs a proof (a catalogue state, or a named test found on a `test(` line; it proves the test exists, not that it passes), a cell marked N/A has none, and a row the proofs do not know fails. The matrix document can no longer drift from the tests silently, which IR-906 recorded it could.
- `support/open-screen.ts`: `makeReadsTimeOut` and `openScreen`'s `timeOut` take `{ only: path }` so only the read under test times out; `makeLaterReadsTimeOut` does the same for a page already open (Load more). `axe-states.spec.ts` uses it too.

**Test:** the specs above. Checked to fail on a defect: with Discover's success answer emptied, its loading, error and interrupted tests fail; with a matrix cell changed from N/A to implemented, `forced-coverage` fails naming the cell; the matrix was restored.

**Evidence:** 2026-11-08, local, headless Chromium, `CI=true` (2 workers), `npm run build` in `frontend/` then the smoke tier in `e2e/`. Whole tier, before the fix below: 383 tests, 382 passed, 1 failed. The failure was `paper-view · review tracker · interrupted`, which passes alone: the 300 ms timeout cap applied to every read, so on a loaded machine an unrelated Paper View read timed out as well and a second "Try again" appeared. The cap is now scoped to the read under test; `axe-states` had the same exposure (one failure in a loaded run) and uses it too. After the fix: the four forced specs run twice over, 226 passed; `axe-states` 47 passed. `tsc --noEmit` clean in `e2e/`. The whole tier was not re-run after the fix and this change has not run on GitHub Actions

**What this does not show:**
- **The backend.** Every answer is the test's. It proves how the interface reads a 403, a 500 or a timeout, not that the API sends them.
- **A mid-body connection reset.** A route cannot reset a connection halfway through a body. "Cut" is the server closing the stream without a final event, which the client reads the same way (`answerStream.ts`); a reset is forced only before any body.
- **A Retry on a request-bound answer that was cut off.** With `AI_DURABLE_ASK` off (the default; ADR-040 is Proposed) a cut-off answer keeps its text and says it was cut off, and the reader can ask again by sending the question; there is no Retry control. Retry exists for a queued run that ends unanswered. The ticket's done condition ("an interrupted Ask IRIS stream shows an interrupted state with a working retry") is therefore proved for the queued path and **not** for the default request-bound one. The test records what the interface does today; whether it should offer a Retry is a product decision
- **Withdrawal after an act.** Paper View also falls to not-available when a re-read after a download request, document request or embargo change finds access gone (matrix, Paper View); those need fixtures this tier lacks and are not forced. The review panels do not report a lost Record to Paper View (the matrix's known gap), and the tracker and timeline have no revoked test because the matrix marks the cell N/A
- Surfaces outside the matrix (the runtime reader behind `AI_RUNTIME_READER`, writes, Review analytics, Admin, Publish, Settings)
- A fixed 750 ms wait stands in for "nothing retried by itself"; it is evidence, not proof
- Each state is forced once, with a few hand-built rows, at 1280 px
