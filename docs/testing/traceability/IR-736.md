## IR-736 — Continue research across repeated compactions and incompatible native state

**Basis and scope.** IR-736 under IR-715; authority ADR-049 §19–20 and the ticket's acceptance criteria. IR-732 to IR-735 and IR-754 each shipped their own feature tests. This ticket owns the cross-compaction and provider-compatibility integration, and it found and closed two real gaps while writing it. It adds no new route, table or control. Quality of a real model's summary, paid capacity and human-reviewed long-context answers stay with IR-755.

**Two defects it fixes.**
- **A changed prefix or tool schema did not make saved opaque state incompatible.** A checkpoint's artifacts were guarded only by the pin's version strings. ADR-049 §20 says a changed prefix or tool schema can invalidate signed continuation even when the bytes are copied unchanged, and the pin's versions are a convention, not the bytes. `ai/agent/checkpoint.py` now stores a digest of the instructions and tool schemas the history was sent under (`prefix_digest`, format `agent-checkpoint-3`), and `_Run._resume` rebuilds from the originals when it differs. A `-1` or `-2` body is rebuilt, never misread, so a rollout rebuilds in-flight runs once. A body saved without a digest is never resumed.
- **Evicted text was still counted as shown.** `ManuscriptRead.visible` was set when a read was packed and never reduced, so after a compaction condensed the exchange that held a paper, the run still reported those passages as shown to the model. `Investigation.reshown` now recomputes visibility from the tool results still in the history after a committed compaction (`ai/agent/tools.py`, called from `_Run._compacted`). A refused or stale handoff changes nothing, since the history is unchanged. The delivered `reading_coverage` fact gains `not_in_context`, the number of passages read but not in the model's context, only when that is more than zero. `shown_facts` passes it through (`ai/runs/store.py`), so a reopened Turn says the same. Existing facts and their tests are unchanged.

**What else is proved without a change.** Resume, rebuild, capability, model-pin and handoff-revalidation behaviour already existed from IR-724, IR-727, IR-734 and IR-735. The new tests exercise them together across several compactions.

**Tests.**
- `apps/ai/tests/test_ai_runtime_long_context_contract.py` (20 tests; no database; recording provider; in-memory research stand-ins). A small `Thread` driver keeps Turns, state and the newest handoff between runs as a claim would:
  - one Conversation carries a 30-passage paper through an automatic compaction, a second Turn, a manual compaction and a third run with an automatic compaction. The middle fact (page 5) and the late contradiction (page 10) are both cited at their canonical pages. The exact old figure comes from `recover_turn` on the original Turn, not the summary. The reopened run opens with the handoff and only the later Turn, with shown order and the exclusion preserved and no passage handles in the handoff. Every original Turn is still stored.
  - evicted passages are reported as read but not in context, and the citation still binds the canonical passage; a refused (`stale`) handoff changes nothing and leaves the text in front of the model;
  - a worker killed after a signed artifact resumes with it when nothing changed, and rebuilds portably from the handoff, the later Turn and the question when the instructions, a tool schema or the pin changed, with the step not renewed and no artifact sent;
  - a withdrawn capability stops before anything is sent, while a pin that requires none still compacts and continues;
  - a model whose window cannot hold the Conversation, and one with no verified capacity, refuse before sending; a model with verified capacity continues after the handoff's Turns and sources are rechecked; a run pinned to one model is never answered by a worker serving another (`RunService.execute` ends it `unavailable`);
  - a compaction the allowance cannot pay for is skipped; every request sent across the whole Conversation fit its model's verified capacity with every reserve held back;
  - the reopened fact carries `not_in_context` only when it happened.
- `apps/ai/evaluation/fixtures/long_context_contract_v1.json` and `apps/ai/evaluation/tests/test_long_context_contract_fixture.py` (4 tests). Six cases (L01–L06) in the shape of `general_tools_contract_v1.json` (pack status `deterministic_contract_not_quality_evidence`, synthetic paper set with a digest). Each case asserts request fit, original allowance, atomic revision and citations, and names the executable tests that prove it; the test fails if a named test does not exist.

**Independent demonstration.** `test_two_automatic_compactions_and_a_manual_one_keep_the_task_the_order_and_the_exclusion` carries one synthetic investigation through three compactions and asks for the late contradiction and the old exact value. `test_a_takeover_under_a_changed_prefix_or_schema_continues_portably_from_the_handoff` then invalidates the native prefix, schema and pin in turn and shows the portable continuation.

**Evidence (2026-11-05).** Run locally with another worktree's backend environment and throwaway settings values:
- the 20 new contract tests and the 4 pack tests pass;
- all dependency-free AI-runtime contract and public-projection suites (299 tests) pass;
- `ai/tests` (75, without the embedding contract file) pass;
- flake8 is clean on the changed files.

CI is the gate for everything that needs PostgreSQL and the frontend.

**Not done here.**
- **No database test.** The ticket asks for restricted-role PostgreSQL where permissions, leases or races are claimed. This change claims none: the store, grants, fences and migrations are untouched, and `shown_facts` is a pure function. The DB behaviour of handoffs, recovery and manual compaction stays with IR-734, IR-735 and IR-754's DB suites. That means reopened history across two compactions is shown against the in-memory stand-in, not against PostgreSQL.
- **No live effect against a paid provider.** IR-725's guard still withholds any request carrying a tool result, and the disclosure decision is Jive Tyler I. Revalde's (ADR-049 amendment §4). A deterministic provider proves contracts, never summary quality, recovery by a real model or capacity. Those are IR-755's.
- **The digest covers instructions and tool schemas, not the model's hidden prefix.** A vendor-side change to a signed artifact's meaning under identical bytes cannot be seen here; the pin's model, endpoint and dialect remain the guard for that.
- **The `not_in_context` count includes passages the packer withheld.** Those were inspected but never shown, so they are counted with the evicted ones. The frontend does not render it yet.
- **A single handoff body is not rewritten when the model changes.** The summary is portable text and is revalidated against the reader's access, but it was written by the earlier model. Human review of that is IR-755's.

**Status.** Implemented; awaiting review.
