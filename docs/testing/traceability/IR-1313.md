## IR-1313

**Requirement:** A filter box keeps one width. It does not change when its options arrive, when a parent choice reloads them (Discover People's College reloads Department), or when an option is chosen, so nothing beside it moves. On a phone the boxes still fill their row. No FR- id.

**Cause:** a native `<select>` with no set width is as wide as its longest *current* option. Discover People's three selects had only a `min-w-*`; the Calls Area, Audit log Event type and My Library Folder selects had no width at all.

**Design decision (Ashlee Sean, 2026-11-24): fit, no cut.** The ticket asked for an 18 rem cap with an ellipsis on longer labels. That conflicts with DESIGN.md's Full Text Rule (IR-1218/IR-1219): text is never cut except in seven listed places, and its guard test `src/test/fullTextRule.test.ts` fails on a new `truncate`. So:

- a box whose options are a **fixed list** gets a width from `sm` up that holds its longest label whole, measured in Chromium;
- a box of **names people type** (an Area, up to 200 characters; a reader's folder, up to 60) is 18 rem (`sm:w-72`). A longer name is clipped closed by the native select with no ellipsis, read in full in the open list, and the box carries `title` with the chosen name;
- below `sm` every box fills its row. On a 360 px phone, College's longest name (400 px) is still wider than the row, and the native select clips it closed as it did before this change.

AC 2's ellipsis is therefore **not** built. No allowed cut was added to DESIGN.md.

**Implementation (frontend only):**

| Box | File | Width from `sm` | Longest label, natural width |
|---|---|---|---|
| Discover People: College | `features/discover/DiscoverPeopleResults.tsx` | `sm:w-[26rem]` (416 px) | "College of Management, Business & Accountancy", 400 px |
| Discover People: Department | same | `sm:w-64` (256 px) | "English & Applied Linguistics", 249 px |
| Discover People: Role | same | `sm:w-36` (144 px, its old minimum) | "All roles", 103 px |
| Audit log: Event type | `features/audit/AuditLogPage.tsx` | `sm:w-80` (320 px) | "Review Threads Closed by Decision", 291 px alone (the widest of the 100 `EVENT_TYPE_CHOICES`) |
| Calls & Conferences: Area | `features/opportunities/CallsAndConferencesPage.tsx` | select `sm:w-72` (288 px) | typed; the longest on the dev database is "Artificial Intelligence" (23 characters, about 190 px) |
| My Library: Folder | `features/library/ReadingPanel.tsx` | select `sm:w-72`; the new-folder field the same | typed, up to 60 characters (416 px) |

- The People selects stay bare native selects (same height, padding and label). Each label is `w-full` plus its `sm:` width, and each select is `w-full`. The `min-w-*` classes are gone. College and Department carry `title` with the chosen name.
- `components/ui/Select.tsx`: with `inline`, the control's wrapper is `min-w-0 flex-1`, so it takes the rest of its row. The caller then sizes the row: Calls' and Folder's wrappers are `w-full sm:w-auto`, so on a phone the select fills the row beside its label. Inline selects in an auto-width toolbar (Sort) are unchanged; the sweep below measures Sort at 134 px before and after.
- The Users list Role (`w-44`) and Workflow analytics Office (`w-full sm:w-48`) already had fixed widths and are unchanged.
- `docs/ui-ux/01-design-system.md`: the `Select` row records the filter-width rule.

**Test:**

- Unit (vitest): `DiscoverPage.test.tsx` "gives each People filter a fixed width that holds its longest name, and names the choice on hover"; `CallsAndConferencesPage.test.tsx` "keeps the Area filter one width, and names the chosen Area on hover"; `AuditLogPage.test.tsx` "keeps the Event type filter one width and names the chosen type on hover"; `MyLibraryPage.test.tsx` (Folder and the new-folder field carry `w-full sm:w-72`); `Select.test.tsx` "fills the rest of its row when inline, and only then". jsdom draws no layout, so these check classes and `title`.
- Browser (Playwright smoke tier, kept): `e2e/smoke/filter-widths.spec.ts`. At 360 and 1280 px, with the API mocked using the real reference data (accounts migration 0003's Colleges and Departments, the widest audit event types, the six review offices), a 60-character folder name and a 78-character Area, it:
  - reads each filter select's `getBoundingClientRect().width` before its list arrives (the response is held back), after, and after choosing every option in turn; for People, after choosing every College, which reloads Department, and every Department under each;
  - asserts the width never changes by more than 0.5 px, and that the page does not scroll sideways;
  - at 1280 px, asserts each fixed-list box is at least as wide as its own natural width (a clone with `width: auto`), so its longest option is not cut.
  - Covered: Discover People (College, Department, Role), Calls Area, Audit log Event type, Users list Role (RDCO and System Admin), Workflow analytics Office, and My Library Saved papers Folder and Sort.
