# IR-834 evidence — authenticated Publish PDF preview

**Ticket:** IR-834 — Show an authenticated PDF preview beside Publish Details on every screen size  
**Date:** 2026-11-02  
**Author:** Lee Jasmin Adolfo  
**Baseline:** `main`

## What was verified

IR-834 adds the shared authenticated PDF reader to Publish Details. Wide layouts place the
server-accepted Manuscript beside the existing editable metadata form. Narrow layouts expose
labelled **Details** and **Preview** controls without replacing the existing Upload → Details →
Review & submit journey.

The preview deliberately reuses `PaperPdfReader`, whose fetch seam is
`recordsApi.manuscriptBlob(recordId, { signal })`. It does not render the dropped local `File`,
does not point an iframe at storage, and does not add a new file authorization path.

A rejected replacement keeps the preceding accepted Manuscript. A successful replacement bumps
the accepted-source generation and remounts the shared reader; its existing cleanup aborts stale
requests and destroys obsolete PDF documents.

## Security / source identity

- Only the server-accepted source is previewed.
- Draft URL possession does not bypass the existing manuscript endpoint authorization.
- The preview reuses the authenticated API client and existing reader error/retry behavior.
- Rejected replacements retain the preceding accepted source.
- Successful replacement remounts the reader on the accepted-source generation boundary.
- Existing reader tests cover authorization/fetch failure, session changes, in-flight abort and
  obsolete-document cleanup.
- No raw `/media/` or storage URL is introduced.

This aligns with the accepted threat model's protection against reading a record/file by guessing
its id: object visibility and authenticated file routes remain the authorization boundary.
