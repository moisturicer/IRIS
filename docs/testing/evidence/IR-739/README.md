## Executed (2026-11-05)

- **New tests: 50 passed** — `test_space_activation.py` 37, `test_space_activation_races_db.py` 10 (independent threads and connections, `transaction=True`), `test_ir739_runtime_record_vectors_db.py` 3 (restricted `iris_ai_runtime` login under a verified reader grant).
- **Test-first failures worth recording.** The first run of the activation test found that the index-health check reported recall 0.000 on a four-row corpus: vectors rolled back by earlier tests stay in the HNSW graph and fill a small scan (the reason several existing suites truncate). The new suites now start the indexes empty (`fresh_vector_indexes` in the package conftest). The first race run found a real ordering defect in a *test* (the late paper had not been built into the pending space, so the promotion in the helper thread was refused and the writer saw an active space); the thread's error is now asserted, not discarded. After the readers moved, ~25 existing tests failed because their fixtures seeded only the legacy table; see "Existing tests changed" below.
- **Regression, passed with no failures** (run in groups, serial, on a fresh test database): retrieval (two-stage, visibility, reranking, fusion), similarity, figure descriptions never reaching a reader, proposal visibility, pending-space build, backfill and promotion, research tools (find_records, duplicates), embargo every-way-out, chunk embedding, research read policy / grants / reads (40), Ask IRIS / conversations / memory HTTP, one-retrieval-stack, vector dimensions, index health, embedding space, enum vocabulary, the role-scope guards in `apps/tests/test_parallel.py` (`test_role_consumers_share_one_scope...`, `test_all_current_research_role_consumers_are_grouped`). One failure in that last group was the repository's "one research-read entry point" guard catching my probe's direct `visible_to`; fixed by routing it through `research_records`, rerun green.
- **Migrations `ai/0041` and `ai/0042` on a copy of the development database.** A custom-format dump of the dev database (21 Records, `ai` at `0038`, spaces: retired `text-embedding-3-small`, active `voyage-context-4`) was restored into a separate database in the private container; the original was only read. `manage.py migrate ai` applied `0039`–`0042` cleanly, `migrate ai 0040` unapplied `0042` and `0041`, re-applying gave the same state (`iris_research_read` policy on `ai_recordspaceembedding`, empty `ai_embeddingspaceactivation`). The copy holds no vectors and no chunks, so this proves the schema steps on a realistic database, not data behavior.
- **Operator command on that copy.** `promote_embedding_space --space 1 --dry-run` refused the retired 1536-wide space with three coded reasons and exited non-zero; `--rollback --dry-run` reported there is no recorded previous revision.
- `flake8` (the repository's F-code configuration) is clean on every changed Python file.

## Existing tests changed, deliberately

- `test_backfill_and_promotion.py::test_a_complete_space_promotes_and_retires_the_previous_one` filled only passage vectors, which no longer counts as complete (IR-752 recorded that promotion would have to require summaries). It now runs `build_pending_space` and passes a provider naming the space's model.
- `test_pending_space_build.py::...name_the_space_keyed_table` listed the modules allowed to name the table "until IR-739 moves the readers"; it now lists `record_vectors.py`, `similarity.py` and `space_activation.py`.
- Seven fixtures (`corpus.make_record`, two-stage, visibility, reranking, fusion, similarity, figure, proposal visibility) seeded the legacy `RecordEmbedding` only; they now go through `seed_record_vector`, which also writes the keyed row, because the readers they exercise moved. `test_similarity` keeps its "older model" case legacy-only (`keyed=False`). Two truncations and `_unindexed` in the embargo test include the new table. `test_research_read_policy_db.py` lists the new protected table.

## Not verified

- **CI has not run.** The full backend suite was not run locally (an attempted serial run of `apps/ai` was stopped at ~20% as too slow, per the repo rule that CI is the gate). `xdist` is not installed in the local environment, so four tests in `apps/tests/test_parallel.py` that spawn `-n` subprocesses cannot run here; they are untouched by this ticket and CI has the plugin.
- **No real corpus, no real model.** The dev copy has no chunks or vectors. Index health on a large corpus (HNSW recall at depth) is unmeasured; the check runs on the space's own rows and on a tiny fixture the planner may not use the index.
- **Two real worker processes** are not used; races are independent threads with their own PostgreSQL connections.
- **The runtime function test** runs `research_record_vectors` as a restricted login, but the `semantic_search` tool built on it is not driven end to end here (it needs a live embedding provider, which is withheld).
- **Throughput and lock-wait behaviour at scale**: the 10-second lock timeout is a constant, not a measured value.
- Independent human review and CI remain required.
