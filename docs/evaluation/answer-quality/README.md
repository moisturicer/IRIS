# Answer quality: Django `lanes-v1` against the runtime agent (IR-956)

This is how IR-955 decides whether Ask IRIS switches to the runtime agent. One frozen set of 108 questions goes through both engines on paid model calls. Every answer is scored automatically, and the report says **pass** or **fail** against IR-955's bar. Nobody signs, approves or adjudicates anything. [ADR-049 §Amendment 2026-11-07](../../adr/049-dedicated-ai-runtime-and-local-research.md) is the authority.

Proxy corpus only: the 40 arXiv papers are never a finding about CIT-U research.

## The bar

The agent passes when all four of these hold:

1. Its overall correctness matches or beats Django `lanes-v1`.
2. Its overall citation support matches or beats Django `lanes-v1`.
3. It has **zero access leaks**.
4. No family is more than ten points below Django, in correctness or in citation support.

## The set

[`answer-quality-v1.json`](answer-quality-v1.json) is generated by [`build_set.py`](build_set.py) from [`corpus.json`](corpus.json), the exact Record titles. It has twelve families:

| Family | n | Source |
|---|---|---|
| F01 single fact | 10 | `proxy_starter` exact-term |
| F02 meaning only | 10 | `proxy_starter` mechanism questions sharing no content word with their paper or passage |
| F03 multi-paper comparison | 8 | `proxy_starter` cross-paper plus three new pairs built from existing labels |
| F04 exact metadata count | 8 | `conversation_set_v1` A06 plus the category totals |
| F05 listing | 8 | categories, `conversation_set_v1` A03, titles naming dark matter |
| F06 naming a paper | 10 | short, partial and misspelled names (`conversation_set_v1` A04) |
| F07 late detail in a long Manuscript | 10 | new: chunk text from the second half of ten long papers (pages 12–41) |
| F08 multi-turn follow-up | 10 | `proxy_starter` follow-up-after-grounded, with a grounding first turn |
| F09 compaction then exact-detail recovery | 8 | `proxy_starter` mechanism questions in IR-753's L04 shape |
| F10 unanswerable or out of corpus | 10 | `proxy_starter` off-corpus-research; must be refused |
| F11 Paper Chat scoped to one Record | 8 | `proxy_starter` questions asked inside their paper (`conversation_set_v1` A11) |
| F12 two readers with different access | 8 | three questions about reader A's unpublished paper asked by both readers, plus one public control pair |

**Labels.** Every case's last turn is the scored question. Its `expect` holds:

- the expected Records;
- the expected pages, each with the quote that puts the fact there;
- a reference answer or an exact count;
- `refuse` when the reader should be told there is no evidence.

An agent drafted the labels; the owner may correct them. On 2026-11-07 every one of the 77 page labels was checked against the development database's chunk text: each quote is on its stated page. Two `proxy_starter` labels sit in a chunk that starts one page earlier, so a citation reports the earlier page. Those two carry `also: [1]` rather than an edited page.

Pages are labelled only where a passage states the answer. Counting (F04), listing (F05) and naming (F06) questions have no single page. They are scored by the exact count, by the titles listed or cited, and by the expected Record cited.

**What the set does not prove:**

- **F09** asks the runtime to compact through its own route. Django has no compaction, so that turn is recorded as `not_supported` and Django answers from its usual history.
- **F07**'s pages are late in the text, but a long paper is not a long context. Nothing here stresses a model's context window.

## Freeze

**Frozen 2026-11-08** in [`answer-quality-v1.lock.json`](answer-quality-v1.lock.json). The owner chose the grader: `anthropic/claude-haiku-5.5`. It is reached through the `answer` profile's own vendor account, OpenRouter, so admission charges one account.


```bash
python manage.py eval_answer_quality --set ../docs/evaluation/answer-quality/answer-quality-v1.json --validate
```

```bash
python manage.py eval_answer_quality --set ../docs/evaluation/answer-quality/answer-quality-v1.json --write-lock ../docs/evaluation/answer-quality/answer-quality-v1.lock.json --grader-model <model>
```

The lock is a SHA-256 over the questions, labels, rubric (`aq-rubric-1`) and grader model. Every scoring step refuses a set, rubric or grader that differs from it. An existing lock is never rewritten with different content. To change the set, raise `VERSION` in `build_set.py` and freeze it under a new file.

## Before the paid run

The run checks each of these and refuses to send anything until all hold:

- **Catalogue.** The database publishes exactly the 40 corpus papers, each title on one Record. Reader A and reader B can both read all of them. `seed_demo` also publishes 8 records, so a database that holds them fails this check: the count labels assume 40.
- **Private paper.** "Proving and Improving the Platonic Representation Hypothesis with JEPAs" exists unpublished. It is readable by reader A (its owner) and not by reader B. It is chunked and embedded, which in development means using IR-317's disclosure bypass.
- **Readers.** `IRIS_EVAL_TOKEN` holds reader A's JWT and `IRIS_EVAL_TOKEN_B` reader B's.
- **Admission.** `AI_PROVIDER_ADMISSION=enforce`, with a **fresh, dedicated** campaign key that the runtime deployment shares.
- **Django settings.** `AI_DURABLE_ASK` is off and `AI_EVIDENCE_DECISION=off`.
- **One model.** The runtime answers with the same model as Django's `answer` profile, passed as `--runtime-model`.
- **One campaign.** The runtime charges the same campaign key, under the same per-run ceiling, because the budget gate reads Django's. After collection the run checks the runtime's charged attempts. If the runtime answered but charged nothing to this campaign, or answered with any model other than `--runtime-model`, that is a condition problem, and a condition problem fails the verdict.

## The run

```bash
python manage.py eval_answer_quality --set ../docs/evaluation/answer-quality/answer-quality-v1.json --lock ../docs/evaluation/answer-quality/answer-quality-v1.lock.json --grader-model <model> --run --runtime-url <reader origin> --runtime-model <model>
```

**Collection.** Each case goes through Django and then through the runtime before the next case starts, so a stop affects both engines alike. Before a case starts, its worst case is compared with what is left of the campaign. That worst case is every turn of both engines plus two grading calls, each at the per-run ceiling. A case that might not fit is not sent, and it and every later case are reported as not run and scored as failures.

**Grading.** The pinned grader sees:

- the question and the earlier questions;
- the reference;
- the answer;
- only the cited passages from Records the reader could read.

A reply that breaks the rubric is retried once and then left ungraded. Any ungraded answer blocks a pass.

**Output.** The run writes `docs/evaluation/runs/<stamp>-IR-956-answer-quality-<id>.json` (rows, access, grades, scores, verdict) and a `.md` report beside it. The report has a table per family and per engine: correctness, citation support, page accuracy, refusal accuracy, leaks, failures, cost per question and p95 latency. It ends with the families that decided the verdict.

**Afterwards:**

- `--rescore <run.json>` grades only what was left ungraded and rewrites the report.
- `--reuse-django <run.json> --run …` collects the agent arm alone and keeps the earlier Django answers. It refuses if the set, access state or answer model changed. This is for rerunning the agent once IR-886 lands.

## Scoring rules

| Measure | Rule |
|---|---|
| correctness | `refuse`: the engine refused (Django `no_results`, or the grader says it declined). Count: the exact number appears in the answer, as digits or a word up to fifty. Otherwise the grader's correct / partial / incorrect = 1 / 0.5 / 0. A refused answerable question scores 0. A failure scores 0 |
| citation support | supported cited claims ÷ all claims the grader lists. Uncited claims count against it. Not measured for refusal questions |
| page accuracy | expected (Record, page) pairs cited ÷ expected pairs |
| leaks | a cited Record the reader cannot read, plus every unreadable title named in the answer |
| p95 latency | nearest rank over every question's scored turn. Measured from submit, so it includes the runtime's queue |
