# ADR-049: Dedicated AI runtime with local authorized research

## Status

**Accepted design — 31 October 2026.** The owner accepted interview decisions 1–16, then instructed: “skip the grilling. Choose all recommended choices and proceed with spec and tickets under the AI/RAG epic”. This records the resulting synthesis, including the recommended remaining choices. It approves the design and backlog, not implementation completion, data deletion, paid inference, provider use, deployment, or unconfigured production limits.

Supersedes [ADR-059](059-dedicated-ai-runtime-direction.md) as the consolidated design. Implementation belongs to five specs under IR-146: IR-712 Authorized Evidence; IR-713 AskRun execution; IR-714 Conversation research; IR-715 context and compaction; IR-716 research publication and upgrades. The [spec/backlog index](../superpowers/specs/2026-10-31-ai-runtime/README.md) maps their 26 subtickets and dependencies. Existing IR-250 remains a blocker for ordinary real-Record disclosure enablement; unknown institutional facts are not relaxed by the runtime move.

## Context

Ask IRIS needs detailed research, useful full-Manuscript reading, long Conversations, compaction, and independent scaling/upgrades. The present PLAN/ANSWER handoff rebuilds answer context, retains only the latest native tool exchange, and combines small history/read/Passage limits with several unrelated token allowances. Merely selecting a million-token model or changing web frameworks does not solve these constraints.

Moving unrestricted retrieval into FastAPI would bypass Django's institutional access rules. Keeping each tool behind a Django request preserves that coupling. The chosen design moves execution and tools while concentrating current access enforcement and durable state ownership.

## Decision

### Ownership and deployment

1. Django owns accounts, authentication, authoritative Records, Manuscripts and review workflow. The AI runtime owns Conversations, Turns/citations, AskRuns, task progress, compact handoffs, provider attempts and derived research data after cutover. Each dataset has one migration owner and one authoritative writer. Cross-owner account/Record deletion creates durable cleanup work and immediate access denial; no competing writes to institutional data are introduced.
2. FastAPI hosts AI request/progress handling; independently scalable workers execute agent work. Ingestion workers are separate from interactive work. A disconnect unsubscribes, while explicit Stop cancels. The existing browser origin remains the entry point through a reverse proxy; Django is not the per-tool or large-context proxy. The gateway remains private to the deployment; no new public host or permissive CORS is required.
3. Begin with one PostgreSQL deployment, separate logical ownership and restricted runtime roles. Redis transports bounded queued work and progress notifications; PostgreSQL is the durable authority. Queue notification is not proof that work was committed. Use committed work/outbox records with idempotent delivery rather than cross-process transactions. Do not add another database or search platform without measured need.
4. Existing development Conversations may be discarded through a separately executed, explicitly scoped cutover procedure. Preserve Records, Manuscripts, accounts, workflow/audit history, paid-attempt accounting and required evaluation artifacts. Historical development Conversation links do not require compatibility. No data is deleted as part of spec/backlog publication.

### Authorized Evidence and trusted identity

5. Establish one institutional research-read policy in PostgreSQL, used by both runtimes, with row-level protection as the baseline. Preserve current intended role/ownership behavior through parity tests before switching readers. Protect dependent content/metadata/vector relations, aggregates and full reads, not only the Record row. Application roles do not own protected tables, bypass row security, or access disclosure signing keys. Migration/maintenance roles remain separate from runtime credentials.
6. Django remains the identity issuer. A dedicated, short-lived signed research grant binds deployment/audience, reader, Conversation/AskRun, effective Record scope, expiry and authorization generation. It does not carry a permanent copied role/Record allowlist. Use a separate issuer key and a bounded verification implementation shared with the database; only Django and the protected database verifier can access an HMAC signing secret. The AI runtime can transport the grant but cannot mint one. Signature verification occurs inside the trusted database access mechanism; an unsigned session variable or user-ID argument never establishes identity.
   Django's ordinary authenticated Record reads use request-scoped identity with an explicit read purpose, without requiring a nonexistent Conversation/AskRun. AI reader grants require the actual run binding and cannot be replayed for another purpose. Ingestion uses a separately issued, job-scoped work grant bound to a committed outbox item, specific Manuscript revision and permitted processing purpose; it is not an all-reader or row-security-bypass account. Current source/disclosure rules still govern outbound processing.
7. Bind the verified grant to each short database transaction; policies derive the principal/scope only from the verified claims. Reject absent, malformed, expired, foreign-deployment, revoked or scope-mismatched grants. Protect verifier functions and their search path/privileges. Database pools cannot retain a previous reader's identity. Renewal is a control-plane operation, not a per-tool round trip: Django revalidates current account/run scope, and renewal never extends the AskRun's allowance. If renewal fails, stop new paid work when authorization expires. A compromised AI runtime holding legitimate grants remains within the explicit trusted-runtime threat model; signing is not a claim that it cannot misuse already authorized data.
8. Reader access and provider disclosure are separate. Unknown consent/IP/embargo facts refuse transmission. Before every outbound physical attempt—including embeddings, reranking, compaction and retries—recheck relevant current access, source/disclosure dependencies and provider policy. Access changes invalidate affected active context, cache entries, plans, summaries and opaque continuation. Reconstruct from allowed material or stop safely; do not merely remove citations. Enforcement occurs at verified read/send/commit boundaries, not as an impossible promise to recall already-sent text or atomically revoke an external request in flight.
9. The model sees application-defined, read-only research tools and scoped handles, never credentials, reader-identity arguments or arbitrary SQL. Paper Chat remains on its selected Record unless the reader explicitly widens it. Denied, withheld and missing research do not expose different clues about private material. Exact counts use authorized database populations; semantic screening is a labelled subset, never an exhaustive count by inference.

### AskRun execution and allowance

10. One AskRun coordinates original deadlines, queue admission, leases, checkpoints, cancellation, all paid physical attempts and final commitment. Use short transactions; no transaction or pool connection stays open during provider inference. Persist an ordered exchange checkpoint and source references after completed steps. Reauthorize recovered evidence, restore all spent/reserved allowance, and fence superseded workers. Commit the final Turn, Conversation revision and terminal result atomically under one AI owner.
11. Missing usage and uncertain remote outcomes retain conservative reservations. Every retry is another physical attempt within the same allowance. Recovery may repeat unrecoverable work but cannot reset spending or promise exactly-once provider billing. Idempotency prevents duplicate terminal delivery. Stop blocks further tool/provider admissions and state advancement; an already-sent provider request may finish and be charged. **Amended by IR-726: the reader's lifecycle.** Stop, reconnect and Retry are three different acts. A reconnect continues the existing run: `GET /runs/{id}?after=N` (reader protocol only) replays the run's journal past position `N` as allowlisted entries (a position counts only what the reader may see, never the operator's raw events) (lifecycle names, plan, context and compaction outcome; never tool calls, model attempts, recovery or reason codes) and returns the new `cursor`; it needs the same ownership, Conversation and Paper Chat scope as any read and renews nothing but the grant. A Retry is `POST /runs/{id}/retry`: only for the reader's own run that ended `cancelled`, `expired` or `failed` with the Conversation still at the revision it asked against and no run active in it. It is a new AskRun linked by `retry_of`, admitted like any submission (queue bounds, its own deadline, the configured allowance, its own pin and ledger key), so the first run's allowance, charges and attempts are never renewed, shared or reduced; asking twice finds the first retry. Redelivery and reconnect never start a new run.
12. Protect capacity for short interactive requests, apply bounded per-reader/conversation queues and fair scheduling, and separate ingestion. Deep research cannot starve. Deployment profiles explicitly configure deadlines, token/cost/attempt/concurrency caps and reserves; missing required values refuse paid enablement. Measure ordinary and deep workloads separately rather than imposing one short deadline on both.

### One model Conversation and answer assurance

13. One named AGENT responsibility interprets the request, maintains an optional bounded task list, calls local tools, assesses evidence and drafts the answer in one ordered model/tool Conversation. Remove mandatory RESOLVE/PLAN/ANSWER handoffs and hidden SCREEN/BRIEF inference from the core tool path. Embedding/reranking may remain dedicated retrieval operations. Cached briefs are optional derived material with source links and never trigger another writer silently.
14. Preserve complete assistant/tool-call/result groups and compatible opaque artifacts. Pin model, adapter/dialect, tool contract, prompt, protocol and state formats per run. Tools may be batched where safe, inside shared scope/admission. Application no-progress, step, elapsed-time and spending bounds remain authoritative. At the gathering limit disable further research in a provider-compatible way and reserve one final answer plus at most one actionable repair.
15. Final validation checks source identity/version/current access, citation bindings, typed numbers/counts and completeness claims. Repair feedback goes to the same model Conversation, not a separate mandatory writer. Deliver independently supported parts where safe. No algorithmic check proves all semantic claims true; IR-605's human review remains necessary. Final factual prose is delivered atomically after validation; activity/task progress can stream earlier.
16. Default depth follows the request; an optional “be more thorough” instruction/control can request a larger configured profile, without selecting an engine, provider or permission scope. Ask one focused clarification only when ambiguity materially blocks useful progress. Tools remain autonomous inside the approved allowance. Plans report task status, not verified research truth or raw reasoning. No per-tool confirmation is required for permitted read-only institutional research.

### Context, compaction and retention

17. Budget the actual complete serialized request against verified model/endpoint capacity, including instructions, schemas, history, evidence, opaque artifacts, framing and provider-specific output/thinking accounting. Separate context occupancy, cumulative run allowance and stored Conversation size. Keep conservative spend reservation units distinct from token estimates. A million-token endpoint is supported where verified; it is neither an assumed universal capacity nor a requirement to fill the window.
18. Load whole available Manuscript text in document order when useful and affordable; otherwise return source-version-bound continuations with explicit covered/missing ranges. Retain page/Passage bindings while deduplicating overlap. Whole extracted text does not mean every original Figure or Formula was interpreted. Provenance survives active-context eviction; evicted text is not claimed to remain model-visible.
19. Automatic pre-overflow compaction and a manual compact action use a portable structured handoff with recent Turns, current goal/preferences, shown order, selections/exclusions, plan, supported findings, original Turn/source references and unresolved limitations. Originals remain recoverable under access/deletion rules. Compaction is lossy paid work under the same allowance. Commit it only if the source revision is still current; failure preserves the preceding valid context. No unbounded repeated compaction/retry cycle. **Amended by IR-754: a manual compact action is a run of its own**, admitted only where an Ask would be (no active run in the Conversation, the revision the reader saw), with its own deadline and allowance, no question and no Turn. It uses the automatic path's summarizer, admission, handoff and commit, so it cannot spend or extend an investigation's budget. Where the summary cannot be committed the run ends `unavailable` and the preceding context stands; a repeated click is one run. `capabilities.manual_compaction` is true only for an AGENT with a configured compaction rule.
20. Provider-native compaction is optional behind capability-tested adapters, never required for portability. A changed prefix/tool schema/model can invalidate signed continuation even if copied byte-for-byte. Rebuild incompatible or access-stale artifacts instead of forwarding them. Switching models happens only through explicit supported reconstruction, never silent per-round fallback into a smaller window or incompatible opaque state.
21. Preserve new Conversation history until explicit owner deletion or a documented deployment retention rule applies. Derived summaries, plans, indexes and native state follow deletion/invalidation dependencies. Paid audit retains the minimum non-content accounting required by deployment policy. Do not invent retention durations, delete institutional history, or expose raw reasoning to fill UI panels. Reader progress, context estimate and analytical summary are separate channels.

### Publication, upgrades, evaluation and cutover

22. Django publishes committed Manuscript/version/deletion/access facts through an outbox. AI-owned ingestion creates immutable extraction/chunk/embedding revisions idempotently; stale or duplicate work cannot supersede a newer Manuscript. Queries use active revisions only. Access denial is based on current canonical institutional facts, not delayed projection events. Notify and reconcile invalidation rather than treating queue delivery as current permission.
23. Preserve the existing extraction approach and Embedding Space invariants while moving execution. Build pending spaces/revisions, validate coverage/dimensions/retrieval, then promote atomically. Both Record- and Passage-level vectors must support space identity before parallel model upgrades. Do not mix embeddings or dimensions or mutate the active index in place to simulate a rollout. Keep a compatible previous revision for deliberate rollback, subject to current access/deletion.
24. Extend IR-605's authenticated reader collection, manifests, independent human review and scoring. Record a distinct engine identity for the new runtime. Separate matched-condition architecture comparisons from larger-allowance capability reports and model comparisons. Add reviewed/versioned long-context, compaction, revocation and interrupted-research cases; preserve held-out freeze and original evidence. Three repetitions, cold/warm separation, failed attempts, conservative missing usage and at least ten distinct cases before reporting a family remain required.
25. Use the existing proposed quality objectives as the selected initial acceptance profile: task completion at least 90%; claim, citation and applicable page support at least 95%; no access/disclosure breach. Apply them per reported repetition/family with the scorer's existing denominators, publish uncertainty and inconclusive/missing families, and do not treat point thresholds as statistical proof. Matched-condition aggregate metrics must not regress versus the frozen baseline. A lowered family minimum or fake/AI-only reviews cannot pass. Predeclare model, corpus, data policy, workload, latency/cost limits and complete usage before live collection; actual funding/provider/data transmission and production capacity values still need authorized operational approval.
26. Prove database/worker races with real PostgreSQL and independent processes; verify reader UI/replay/export and accessibility; load-test bounded pools and queues with ordinary/deep/ingestion mixes. Fake providers prove contracts, not vendor capacity or answer quality. Record queue-inclusive p95 latency, tool/model time, context memory, connections/lock pressure and cost per successful task. Compare against the frozen baseline and approved deployment profile; missing required evidence blocks enablement.
27. After the safety, quality, capacity and operator checks pass and a human release owner approves, switch new runs once. Drain/fence old runs, transfer migration/writer ownership, and retire the old runtime path. Keep a version-compatible deployment rollback, not two permanent implementations or a reader-facing engine switch. The development-Conversation reset is a separately scoped operation. Implementing this backlog does not itself authorize rollout or paid evaluation.

## Alternatives and consequences

- Keeping everything in Django minimizes migration but couples AI execution/dependencies and retains the context redesign work.
- FastAPI calling Django for every tool is a possible extraction stage but retains per-tool coupling; it is not the chosen destination.
- Direct unrestricted SQL or duplicated Python access rules are rejected because they bypass or drift from institutional permissions.
- Separate databases now would isolate load but add replication, deletion and revocation lag before the bottleneck is measured.

The chosen design buys locality and leverage at the Evidence, AskRun, Conversation/context and publication seams. Costs include policy/migration work, durable state, larger-context memory and spending, adapter compatibility, and operational load tests. No performance gain has yet been measured.

## Reconciliation

- **ADR-059 (written as ADR-048):** superseded by this consolidated design; preserve its interview history.
- **ADR-014/017:** replace the stateless gateway/no-retrieval/no-database restriction with the constrained AI runtime above. Retain trusted identity, private deployment, no permissive CORS and appropriate async hosting. Django no longer carries per-tool evidence payloads.
- **ADR-024:** supersede Django-only embedding execution for the target runtime. Preserve embedding semantics, disclosure, idempotency and shared paid limits.
- **ADR-026:** replace compulsory question rewriting and retrieval-only older memory with the agent's own query formation plus recoverable compact handoffs. Original Turns and current-access checks remain.
- **ADR-036/042:** replace PLAN/ANSWER orchestration with a named AGENT responsibility and same-model finalization/repair; retain explicit task/data policy and provider compatibility. Amend reader progress to permit concise task lists, context estimates and compaction status; preserve raw-reasoning/tool-trace exclusion, source assurance and atomic factual delivery.
- **ADR-040/041:** adopt the relevant bounded durable execution/admission requirements expressed here, but do not retroactively accept all old proposal details or their unapproved numeric settings.
- **ADR-013/015/016/019:** preserve Passage/page provenance, contextual/asymmetric embedding, source versions and Conversation ownership; execution ownership changes as above. Research transmission permission remains fail-closed.

Current code retains its existing behavior until implementation and controlled cutover. The five specs specify acceptance behavior; Jira tracks delivery rather than replacing this decision authority.

## Amendment — 2026-11-04 (IR-884, IR-885): default depth, resume, export and disclosure ownership

**Status: Accepted 2026-11-04. Decider: Jive Tyler I. Revalde, owner of the AI runtime.** These settle the questions raised by the parent checks on IR-714 and IR-724. The decisions above stand except where this says otherwise.

1. **Deep is the default research depth.** This replaces the first clause of §16, "Default depth follows the request". A question runs the deep profile unless the reader chooses ordinary for it, and a request that names a depth keeps it. Deep stays inside every configured bound, and no engine, provider or permission choice is added.
   - **Gain:** a reader gets the fuller investigation without asking for it.
   - **Cost:** most runs now take longer and may spend more. `RUNS_DEEP_CONCURRENCY` must stay below `RUNS_WORKER_CONCURRENCY`, so it now caps most of the load and the slots it keeps free sit idle unless readers choose ordinary. §12's capacity evidence must treat deep as the normal load. A deep deadline longer than the reader grant now reaches ordinary use; IR-880 lets a running run follow its renewed grant, so such a run continues only while its reader keeps reconnecting and ends `unauthorized` at its next read or admission once they stop.
2. **Resume stays in scope and is delivered by IR-724.** IR-714's criterion that tool exchanges persist and resume stands, because §10 and §14 require it. IR-724 implements it under IR-713: a fenced checkpoint after each step, with call ids and opaque artifacts, and an allowance restored from the shared ledger. **Limit:** IR-725's guard withholds any request carrying a tool result from a paid provider, so resuming past a tool result is proven only without admission.
   - **Checkpoint format:** `agent-checkpoint-3` since IR-736, which adds a digest of the instructions and tool schemas the history was sent under: opaque state may depend on them as well as on the pin, so a body saved under other bytes is rebuilt, never replayed. `-2` (IR-734) added the compact handoff a run's history opens with (its revision, the Turns it compacts and its body); a `-1` or `-2` body is rebuilt, never misread. It was `agent-checkpoint-1` (`FORMAT` in `ai/agent/checkpoint.py`), stored per running run in `iris_ai.run_checkpoint` (migration `0013_checkpoint.sql`) as `fence`, `step` and a `body`. The body holds the ordered Conversation with its stable call ids and opaque artifacts, the Investigation's source pointers, the task and context it answers, its pin and Bounds, and what it spent. A replacement restores it only while all of that still matches and every recovered source reauthorizes. It is content, so it is removed when the run ends. A changed format needs a new name, and this record updates with it.
3. **Export belongs to IR-740, with no new format.** The runtime has no reader export route, and `ai/runs/public.py` only states that export would share the reopen projection, so "exported" cannot be verified yet.
   - IR-740 carries IR-731's AC 5 by extending IR-605's existing `eval_replay_conversations` run file with the runtime's engine identity. A fake-provider run stays contract evidence, which `eval_campaign --counted` already refuses as quality evidence.
   - IR-740 also carries what remains of IR-731's AC 3 and AC 4: A01–A15 through the runtime, and the replayed and exported projections.
   - **Gain:** one evaluation format and one owner. **Cost:** IR-714's privacy criterion covers live and reopened answers until IR-740 lands.
4. **Jive Tyler I. Revalde owns the disclosure decision that would let the AI runtime send Record evidence to a paid provider.** This names the owner only; the decision is not made. No Record evidence may be sent on the strength of this amendment, and `ai/admission/guard.py` keeps refusing it (§8). IR-827 (vendor no-training evidence) and IR-791 (the disclosure check reads the Contact person's answer) are preconditions, not the decision.

## Amendment — 2026-11-07 (IR-886): search by meaning and metadata

**Status: Decisions given by Jive Tyler I. Revalde, owner of the AI runtime, to an AI assistant in chat on 2026-11-07, and recorded here at his direction.** They settle the four decisions IR-886 left open. The decisions above stand except where this says otherwise.

1. **One search tool.** The `research-5` tool version offers one `search` that combines keyword and meaning-based results, with optional Area (classification), PSCED area, record type and completion-year filters validated as `count_records` validates them. There is no separate semantic tool.
   - **Gain:** the model has no retrieval strategy to choose wrongly. **Cost:** it cannot run one signal alone.
2. **Reranking is available behind a setting.** `RUNS_RERANK_MODEL` names a Voyage rerank model; empty means off. A rerank is admitted against the run's allowance like any provider attempt, and passage text is sent only when the send guard admits every candidate's source. Under the current guard that means only sources in an approved development proxy manifest, so in production no rerank is sent and the result says `withheld`.
   - **Gain:** Django measured most of its retrieval gain here (proxy recall@10 0.712 to 0.885). **Cost:** one more paid operation per search, and no gain at all until the disclosure decision in the 2026-11-04 amendment allows Record text to reach the reranker.
3. **On by default.** New AGENT runs are pinned to `research-5`, and search by meaning runs whenever a Voyage key and the AGENT admission profile are configured. **This departs from ADR-033's off-until-measured rule for the runtime, at the owner's direction.** The comparison against keyword-only search IR-886 asks for has **not been run**; it is recorded as outstanding, not as passed.
   - **Gain:** readers get meaning-based search immediately. **Cost:** no evidence yet that it helps on the labelled question set, and a regression would reach readers before a measurement could show it.
4. **Both vector reads, fused with keyword results by rank.** A paper-first read (the 20 nearest Records by Record vector, then their Passages) and a flat read (the nearest permitted Passages anywhere) are merged with the keyword list by rank position with no weights, as Django's `fuse_by_rank` does. Both reads reuse one query vector.
   - **Gain:** a Passage whose paper's abstract does not resemble the question can still be found. **Cost:** one more vector read per search, and flat and paper-first results compete for the same slots, so the net gain is unmeasured.

Both vector reads order the rows of the policy-filtered `research_vectors` / `research_record_vectors` functions, so they are exact scans: no HNSW index, and so no `ef_search` depth, can cut a filtered read short. IR-886's tests record the `EXPLAIN` evidence. Runs pinned to `research-1` through `research-4` keep their tools.

## Amendment — 2026-11-07 (IR-955, IR-956): automatic answer-quality evaluation

**Status: Proposed 2026-11-07, pending the owner's confirmation.** It records decisions the owner, Jive Tyler I. Revalde, already made in IR-955; an AI assistant wrote it down, and an AI does not accept an ADR. This amendment writes them into §24–26 so the ADR and IR-956 agree. §27 (the switch) is IR-957's to amend. Where this conflicts with §24–26, this wins.

1. **§24, how answers are collected and scored.**
   - One frozen set of twelve question families is collected through both engines: Django `lanes-v1` and the runtime agent. Each family has at least eight questions. The families and the labels are in [`docs/evaluation/answer-quality/`](../evaluation/answer-quality/README.md).
   - Each engine is run **once**. Both runs use the same answer model, corpus, readers and access state. Failed, capped, cancelled, timed-out and not-run questions count as failures.
   - Scoring is **automatic**. Exact checks cover cited Record and page hits, exact counts, correct refusals and access leaks. A pinned model grader with a fixed rubric judges correctness and whether each claim is supported by the passage it cites. The grader sees only what the reader could read.
   - **Dropped:** independent human review, two-person adjudication, named label review, three repetitions, and the ten-case family minimum. Human spot-checks are allowed, never required.
   - **Kept:** the runtime's distinct engine identity, failed attempts counted as failures, and the freeze. The freeze is a checksum over questions, labels, rubric and grader model, and a changed set is a new version.
2. **§25, the acceptance bar.** The agent passes when all of these hold:
   - it matches or beats `lanes-v1` on overall correctness;
   - it matches or beats `lanes-v1` on overall citation support;
   - it has **zero access leaks**;
   - no family falls more than ten points below `lanes-v1` in correctness or in citation support.

   This replaces the fixed 90%/95% thresholds and the per-repetition reporting. The report shows uncertainty only as per-family counts. It is a point comparison, not a statistical proof. Spend runs through provider admission and stays inside the campaign ceiling: a question whose worst case would not fit is not sent, and the report lists it as not run.
3. **§26, what the report covers.** Per family and per engine, the report gives:
   - correctness, citation support, page accuracy and refusal accuracy;
   - leak count and failure count;
   - cost per question and p95 latency including queueing.

   §26's race, UI, accessibility and load-test evidence is unchanged and stays outside this measurement.
   - **Gain:** one command, one paid run per engine and a verdict with no signing step.
   - **Cost:** a model grades answer correctness, so the verdict can be no more reliable than that grader. The grader is pinned and its rubric is frozen, so its bias is at least the same for both engines. One run per engine also cannot separate a real difference from run-to-run variation.

## Amendment — 2026-11-08 (IR-994): follow-ups, exact counts and listings reach the model

**Status: Decisions given by Jive Tyler I. Revalde, owner of the disclosure decision (2026-11-04 amendment), to an AI assistant in chat on 2026-11-08, and recorded here at his direction.** IR-956's paid run found 42 of the agent's 49 failed turns refused at the send guard (`source_unavailable`): every follow-up, every exact count and most listings. The decisions above stand except where this says otherwise.

1. **A Turn keeps every source its answer could draw on.** At delivery, the run stores every source its history carried (read and cited, read and not cited, and the sources of the earlier answers it was given) in `iris_ai.turn.sources`. A later run sends that answer as history with those sources, and the send guard rechecks each one's approval and the reader's access exactly as it does a search result.

   - **Gain:** listings are exact rather than a search sample. **Cost:** one more tool for the model to choose between.

## Amendment — 2026-11-09 (IR-995): withhold instead of failing, forgiving names, Paper Chat

**Status: Requested by Jive Tyler I. Revalde to an AI assistant in chat on 2026-11-09 ("do all 6"), and recorded here at his direction.** IR-956's paid rerun on IR-994 code lost about 40 of 108 questions to mechanical causes: whole runs ended at the send guard, names did not match, answers were cut to fragments, and Paper Chat never said which paper it was about. The decisions above stand except where this says otherwise. Nothing here sends anything the guard did not already allow.

1. **A withheld or empty result is a status, not a refusal.** A search whose every paper the send may not carry (IR-889) reaches the model as `no_match` with reason `withheld`; a result that left only some papers out keeps the rest and says `withheld`. A named paper that matched nothing reaches the model as a bare `no_match`. Both pass the guard as content-free controls; `withheld` joins the fixed control values.
   - **Gain:** one unsendable paper or a missed name no longer ends the run. **Cost:** the model learns that something was left out, never what, and may answer from less.
2. **Names match whatever their case, hyphens or punctuation.** A taxonomy filter (Area, PSCED area, record type) and a title phrase compare after folding every run of punctuation and spaces to one space, so "Hardware Architecture" finds `hardware-architecture` and "TTM Bench" finds `TTM-Bench …`. A name that still matches nothing returns the titles holding most of its distinctive words as `close` choices for the model to confirm, never a silent pick. The answer check compares quoted titles and filter names the same way. Django's `apps.ai.research.titles` keeps its stricter matching, so the two runtimes now differ here.
   - **Gain:** named papers and categories are found as readers say them. **Cost:** a close choice can be the wrong paper; the model is told it is a choice, and its answer names the paper it used.
3. **Runs pinned to `research-7` get a second repair** before an answer is cut to its supported sentences, only if the run's allowance still fits it. Which check failed stays in the worker log (`agent draft refused` / `agent repair refused`), never in the run's journal, which a reader's run status shows (IR-729).
   - **Gain:** fewer fragment answers. **Cost:** up to one more model call per failing answer.

1. **Prompt-cache hits are recorded (built, always on).** The chat-completions dialect reads `usage.prompt_tokens_details.cached_tokens` into the model turn. The charge is **never** discounted for a cache hit, and the reservation never assumes one.

   - OpenAI-family models already cache a repeated prompt prefix of 1,024 tokens or more on their own. IRIS cannot turn that off. Recording the hits only makes it visible.
2. **A per-run cache key (built, off). Decision needed.** `AGENT_LLM_PROMPT_CACHE=run` sends `prompt_cache_key = iris-run-<run id>`, so one run's gathering turns, which share a growing prefix, are routed to the same cache. The key never spans runs or readers. Blank or `off` sends nothing.
   - **Gain:** more cache hits within a run. **Cost:** on the configured route, none was found.
