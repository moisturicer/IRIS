# IR-741: Produce an honest release-evidence report with explicit missing gates

**Jira:** [IR-741](https://citiris.atlassian.net/browse/IR-741)

## Parent

[IR-716](https://citiris.atlassian.net/browse/IR-716) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A release owner receives one reproducible quality/safety/performance/cost report that refuses to call missing or incomparable evidence a pass.

## Acceptance criteria

- [ ] Score the selected 90% task-completion and 95% claim/citation/applicable-page objectives per reported repetition/family with existing denominators and Wilson intervals; require three repetitions and ten distinct cases per reported family.
- [ ] Compare matched-condition aggregate metrics with the frozen baseline and keep expanded capability/model results separate. Missing review, insufficient families and incomparable manifests remain explicit.
- [ ] Require recorded access/disclosure, real PostgreSQL/independent-worker, browser/accessibility and workload evidence; any access/disclosure breach blocks readiness regardless of average quality.
- [ ] Preflight a declared workload and authorized latency/cost profile; report ordinary/deep queue-inclusive p95, tool/model time, memory, connections/lock pressure and total cost per successful task, including failures and conservative unknown usage.
- [ ] Exercise the report with passing, failed, breached, mismatched and not-measured fixtures. Fake values never become measured production evidence; missing operational caps or paid/provider/data approvals block live collection.
- [ ] Emit a versioned machine-checkable readiness manifest with evidence references and human-review gaps, usable by cutover preflight. Actual campaign collection is IR-755.

## Blocked by

- [IR-740](https://citiris.atlassian.net/browse/IR-740)

Prerequisites are recorded as native Jira blocking links. Pull only when all prerequisites are complete; ready-for-agent describes specification quality, not permission to bypass a blocker.

## Independent demonstration

Generate reports from preserved baseline and synthetic result fixtures, omit a worker/browser result, inject a breach and unknown usage, and observe accurate blocked readiness rather than a green summary.

## Scope boundary

Split report/gate implementation from live campaign execution. This task can finish while feature work continues because it must correctly report missing evidence.

## Spec coverage

[IR-716](https://citiris.atlassian.net/browse/IR-716) user stories: 13, 15, 17, 18, 19, 20, 23. This is specified implementation work, not evidence that those stories are implemented.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
