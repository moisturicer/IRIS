# IR-725: Admit and account for every outgoing provider attempt

**Jira:** [IR-725](https://citiris.atlassian.net/browse/IR-725)

## Parent

[IR-713](https://citiris.atlassian.net/browse/IR-713) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A bounded run can send an authorized model or retrieval request only after shared budget admission, and every retry remains visible in its total spending.

## Acceptance criteria

- [ ] Use one shared PostgreSQL reservation/settlement authority for each model, embedding, reranking, repair, compaction, retry and permitted fallback attempt; transport consumes current disclosure authorization from IR-720.
- [ ] Disable hidden SDK retries or admit each physical send explicitly. Two independent processes competing for the last allowance cannot both overspend it.
- [ ] Reported usage settles the reservation; missing usage, timeout and unknown remote outcome retain a conservative amount. Worker death is not proof that an attempt was free.
- [ ] Missing required profile, deadline, attempt/token/cost/concurrency cap, revoked access, cancellation or exhausted protected reserve prevents transport before a request is sent.
- [ ] Expose purpose/version/usage/reservation evidence without protected prompt bodies or opaque payloads. Preserve the current accounting semantics and an additive ownership migration rather than a duplicate ledger.

## Independent demonstration

Through a bounded run with a recording fake transport, race two processes for a final reservation, force a retry and unknown-usage timeout, then inspect the safe cost report and original remaining allowance.

## Scope boundary

Own physical-attempt transport/accounting integration. Concrete compaction and repair callers must use this contract in their own feature tickets.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
