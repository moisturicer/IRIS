# IR-752: Build a new Embedding Space while current search stays usable

**Jira:** [IR-752](https://citiris.atlassian.net/browse/IR-752)

## Parent

[IR-716](https://citiris.atlassian.net/browse/IR-716) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

An operator builds a pending embedding upgrade alongside the active one while readers continue to search the active compatible vectors.

## Acceptance criteria

- [ ] Expand Record-level vectors to explicit space-keyed storage alongside the existing Passage-space identity; preserve current search during additive migration/backfill.
- [ ] Build pending Record and Passage vectors with pinned embedding/query-document semantics, dimensions and source revisions without overwriting active vectors.
- [ ] Current queries use the active compatible space only. Partially built or incompatible pending vectors cannot leak into search, counts or similarity results.
- [ ] Restart/redeliver a bounded build safely, retain completed charged work and enforce current source/disclosure and shared admission at each attempt.
- [ ] Report readiness/coverage and dimension/retrieval checks using existing operator surfaces; this ticket cannot activate a pending space. Record migration verification on a realistic synthetic database copy.

## Independent demonstration

Create two deterministic embedding identities, partially build the second, search as a reader and restart the build; show unchanged active results and isolated pending Record/Passage vectors.

## Scope boundary

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
