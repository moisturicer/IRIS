# IR-742: Rehearse one-writer cutover and version-compatible rollback

**Jira:** [IR-742](https://citiris.atlassian.net/browse/IR-742)

## Parent

[IR-716](https://citiris.atlassian.net/browse/IR-716) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

An operator can rehearse the switch and rollback on a disposable copy, with tooling that refuses a live cutover without passing evidence and human release approval.

## Acceptance criteria

- [ ] Prepare compatible reader-before-writer format migration, per-run version pins, draining/fencing and exactly one migration/writer authority for each dataset.
- [ ] Rehearse new-run routing and rollback against a disposable realistic copy; refuse unsupported in-flight formats/models/native state instead of silently corrupting a Conversation.
- [ ] Cutover preflight requires a passing measured readiness manifest from IR-755 plus named human release approval. A missing, stale, forged or failed report blocks live execution.
- [ ] Define and rehearse the scoped development-Conversation reset in dry-run only, enumerating preserved Records/Manuscripts/accounts/workflow/audit, paid-attempt accounting and required evaluation artifacts.
- [ ] Plan the contract/removal phase after all new callers are migrated: retire old execution and old storage only then; keep a compatible deployment rollback, not permanent dual reader engines.
- [ ] No live deployment, deletion, traffic switch, production embedding promotion or retirement is executed by this preparation ticket. Record rehearsal checks and the operator's explicit remaining release actions.

## Independent demonstration

On a disposable copy, rehearse drain/one-writer switch/rollback, reject an incomplete readiness manifest, and produce a deletion dry-run that excludes all protected institutional and audit data.

## Scope boundary

Preparation can run before live campaign collection. Production execution remains gated by the campaign manifest and release owner, rather than blocking preparation work on measurements it can safely report as missing.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
