# IR-727: Answer a direct question through the pinned AGENT provider contract

**Jira:** [IR-727](https://citiris.atlassian.net/browse/IR-727)

## Parent

[IR-714](https://citiris.atlassian.net/browse/IR-714) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

An authenticated direct question completes through one named AGENT responsibility and reopens with the same model/protocol identity.

## Acceptance criteria

- [ ] Carry the original request and pinned model/endpoint, adapter/dialect, prompt/tool/public/state versions and data policy through a deterministic authenticated direct-question run.
- [ ] Expand the existing provider interface additively so current callers remain green. Represent assistant text, complete parallel tool groups, matching IDs, stop reasons and opaque continuation without dropping or reordering items.
- [ ] Length-truncated, reasoning-only, malformed or tool-only output is not accepted as a final answer. Unsupported capabilities return a safe unavailable result rather than silently selecting a smaller/incompatible model.
- [ ] Private continuation artifacts can round-trip only to a compatible endpoint; the public response, saved transcript and diagnostics contain no raw/opaque provider payload.
- [ ] The direct-question integration uses a recording deterministic adapter until IR-725 and IR-732 gate real transport. No unchecked live provider route is added.

## Independent demonstration

Submit and reopen a direct question with a scripted provider, then exercise parallel-call/opaque-artifact fixtures through the same typed adapter and reject unsupported pins.

## Scope boundary

Provider-contract prefactor/first direct-answer slice. The local tool loop is IR-728; existing callers are retired only under controlled cutover.

## Spec coverage

[IR-714](https://citiris.atlassian.net/browse/IR-714) user stories: 1, 3, 6, 10, 12, 17, 20. This is specified implementation work, not evidence that those stories are implemented.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
