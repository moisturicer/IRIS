# IR-719: Find and read permitted Passages through local research tools

**Jira:** [IR-719](https://citiris.atlassian.net/browse/IR-719)

## Parent

[IR-712](https://citiris.atlassian.net/browse/IR-712) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

An authenticated research request can find permitted Records and read page-bound Passages locally, without a Django request for each tool.

## Acceptance criteria

- [ ] Search and bounded read/outline/page operations use the shared Evidence authority; a scripted authenticated request returns Record and Passage references bound to the exact Manuscript revision and page.
- [ ] Selected-Record handles belong to the run and scope; forged, expired or foreign handles and attempted Paper Chat widening disclose no unrelated Record.
- [ ] Tools return original evidence and explicit success/no-match/unavailable/partial states. They never call hidden SCREEN, BRIEF, resolver or writer inference; embedding/reranking remain separately declared provider operations.
- [ ] Every tool result records inspected coverage and source dependencies. A source replacement invalidates a stale read handle rather than silently resolving it to a different revision.
- [ ] Capture local tool traffic to prove no per-tool Django HTTP dependency. Research-provider paths remain unavailable until disclosure and spending gates are installed; deterministic keyword/read fixtures prove this slice without paid inference.

## Independent demonstration

Through the authenticated request seam with a scripted transport, find one permitted paper, open a Passage at its page, then attempt to read another reader's paper and reuse a handle in a second run.

## Scope boundary

Reuse existing retrieval and read contracts rather than rebuilding ranking. Exact metadata counts/resolution are split into IR-750; context-sized full reads belong to IR-733.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
