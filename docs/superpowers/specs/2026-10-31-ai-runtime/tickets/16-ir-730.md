# IR-730: Follow research progress and control depth from the reader screen

**Jira:** [IR-730](https://citiris.atlassian.net/browse/IR-730)

## Parent

[IR-714](https://citiris.atlassian.net/browse/IR-714) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A reader follows a concise research task list, sees queued/running/context-estimate states and can Stop or request more thorough work without choosing an engine.

## Acceptance criteria

- [ ] Ask IRIS and Paper Chat render persisted bounded task IDs/status/revisions from the actual loop; simple requests can omit a plan, and generic activity never fabricates completed research or percentages.
- [ ] Live, reopened and reconnected views agree on task state, safe context estimate and run outcome; estimates are labelled and unknown capacity is not displayed as a million tokens.
- [ ] Existing Stop/reconnect controls use the versioned run contract; requested thoroughness changes only the configured bounded depth, not access, selected-Record scope or provider.
- [ ] Keyboard/screen-reader and narrow-layout checks cover progress, Stop, busy/error states and the persistent mistake/citation notice.
- [ ] Live/history/replay/export projections exclude raw reasoning, model/provider IDs, tool arguments/results and debug codes. Render compaction controls only when the manual-compaction feature is available.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
