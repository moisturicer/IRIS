# IR-735: Recover original details after compaction and respect deletion

**Jira:** [IR-735](https://citiris.atlassian.net/browse/IR-735)

## Parent

[IR-715](https://citiris.atlassian.net/browse/IR-715) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A reader asks for an exact earlier detail after compaction; the same agent checks the authorized original Turn/source rather than guessing from the summary.

## Acceptance criteria

- [ ] Expose bounded run/owner-authorized recovery of original Turns and current permitted source references through the existing tool contract.
- [ ] Restored details use stable original identity/page/source bindings; summary text alone is never evidence for a quoted exact value. Shown paper order, exclusions and preferences remain consistent.
- [ ] Check current account/Conversation/source access before recovery and the next send/commit. Revoked or replaced material cannot reappear from handoffs, detail indexes, plans or opaque state.
- [ ] Conversation/account deletion invalidates/removes content-bearing derived state idempotently according to policy; minimum required non-content spend audit is not erased.
- [ ] Publish safe estimated context/compaction state for the reader contract without raw reasoning, private source identifiers or opaque payloads.

## Independent demonstration

Compact a Conversation, ask for a precise value from an older Turn, then revoke the source and delete a test Conversation; verify permitted recovery and denial across live/history/export.

## Scope boundary

Own bounded exact-detail recovery, derived-content cleanup and context-status producer. Manual UI compaction and native-compatibility integration remain separate.
