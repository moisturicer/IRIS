# IR-722: Submit and reopen one AI-owned research run

**Jira:** [IR-722](https://citiris.atlassian.net/browse/IR-722)

## Parent

[IR-713](https://citiris.atlassian.net/browse/IR-713) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A reader submits a question once, sees its owned run state and reopens exactly one committed Turn even when the submission is repeated.

## Acceptance criteria

- [ ] The authenticated submit/status/reopen surface creates AI-owned AskRun/Conversation state using a deterministic result executor, with one authoritative migration/writer owner in the new path.
- [ ] Duplicate request identities return the same run; another reader cannot inspect, mutate or cancel it. Concurrent Conversation revisions and ordinal-sensitive follow-ups return a recoverable conflict.
- [ ] Final Turn, citations, Conversation-state revision and terminal journal commit atomically. A transaction failure or terminal cancellation cannot leave a partial or duplicate answer.
- [ ] Persist the original deadline and bounded allowance plus the lease/fencing/version contract. Missing production limits do not silently enable paid work; provider transport is outside database transactions.
- [ ] Conversation/account deletion immediately fences access and future state advancement; content cleanup follows the documented retention rule while minimum required non-content attempt accounting survives.
- [ ] Use additive schema/route expansion until release transfer; Django remains the current writer outside this isolated target path. Do not switch two writers onto the same dataset.

## Independent demonstration

Submit twice with one idempotency identity, reopen the result, attempt a foreign-owner request and race two final commits in separate PostgreSQL connections; observe one coherent Turn.

## Scope boundary

Own run admission, terminal commitment and deletion fencing. Queue execution, real provider transport and durable exchange recovery are subsequent slices.

## Delivery and evidence

Include the minimal persistence, authenticated entry point, public projection or operator surface, and behavioral tests needed for this outcome. Reuse existing reader components where no new control is needed. Each feature must land with its own applicable tests; later integration tickets do not postpone them.

Use real restricted-role PostgreSQL and independent workers where database permissions, leases, races or shared limits are claimed. A deterministic provider proves contracts, never paid capacity or human-reviewed quality. Record actual checks, failures and unavailable environments.

Keep prerequisites independently green through additive expansion, controlled migration and final contraction. Preserve current institutional authority, one writer per dataset, source/disclosure rules and the original AskRun allowance. Ticket publication does not authorize a live provider campaign, deployment, traffic switch or data reset. A PR and independent human approval remain required.
