# IR-729: Correct an invalid draft once before delivering the answer

**Jira:** [IR-729](https://citiris.atlassian.net/browse/IR-729)

## Parent

[IR-714](https://citiris.atlassian.net/browse/IR-714) under [IR-146](https://citiris.atlassian.net/browse/IR-146). Authority: ADR-049 and the accepted parent specification. Do not close or modify the parent.

## What to build

A reader receives a supported final answer after one bounded correction when a citation, calculated number or completeness claim is invalid.

## Acceptance criteria

- [ ] Validate current source identity/version/access, Passage/page bindings, typed facts/counts and exhaustive-reading claims before factual prose is delivered.
- [ ] Return actionable validation feedback to the same ordered AGENT Conversation; permit at most one repair and charge it through the original allowance/reserved capacity.
- [ ] If repair fails, preserve independently supported units with an honest limitation where safe, or return the appropriate safe failure. Do not loop judges/writers or claim semantic truth is mechanically proven.
- [ ] Recheck authorization/source state before final commit; a stale/revoked source fences delivery instead of being repaired into a plausible unsupported answer.
- [ ] Live delivery and reopened answer/citations agree; no unvalidated factual tokens, raw validation codes or hidden tool/provider state appear in progress or history.

## Independent demonstration

Make a scripted agent draft a bad page citation and a wrong typed count, then correct them once; repeat with a second invalid draft and with revocation before commit.

## Scope boundary

Own final assurance and bounded repair. Human semantic review remains part of IR-605; it is not replaced by this validator.
